# Работа с репозиторием

- При продолжении задачи сначала прочитайте `WORK_STATE.md`, затем проверьте `git status` и последние коммиты. Состояние файлов и Git важнее старого чата.
- Читайте `CONTRIBUTING.md` и только относящиеся к задаче разделы `docs/repository-guide.md`. Не загружайте всю документацию, исходники, логи или бинарные данные в контекст.
- Делите большую задачу на законченные этапы. После каждого обновляйте `WORK_STATE.md`: что сделано, что проверено, следующий шаг, ограничения. Держите его коротким; подробная история — в коммитах.
- Если публикация разрешена пользователем, сохраняйте проверенные этапы отдельными коммитами в согласованной ветке. Не переписывайте историю и не меняйте `master` без явного задания.
- При уборке проверяйте импорты, динамические пути, точки входа фреймворка, CI, скрипты и документацию. Отсутствие импорта само по себе не доказывает ненужность файла.
- Сохраняйте миграции, тесты, эксплуатационные инструменты и оба поддерживаемых контура сборки. Сомнительные кандидаты оставляйте с коротким объяснением.
- Графика нового мира: готовые PNG в `art/world/prototype/`, ручной экспорт в одноимённые WebP в `public/world/prototype/`. `world:export` обновляет данные, не сжимает изображения. Подробности — `art/README.md`.
- Не меняйте `grid-world` в рамках текущей уборки. Не трогайте пользовательские правки и не выполняйте деплой без задания.
- Выводите краткий результат проверок; большие логи сохраняйте локально. Не выдавайте прежние проверки за проверки текущего коммита.
- Сборку и тесты, читающие `dist/`, запускайте последовательно: `npm test` собирает Sites, затем выполняет веб-тесты. Параллельная пересборка может удалить файлы, которые тест ещё читает.
