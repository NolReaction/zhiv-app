# Изображения: что редактировать

Основной источник новой карты — **`art/world/prototype/forest-ground.png`**, 2560 × 2560 пикселей. Основная игра и `/prototype/tiled-world` используют один полный экспорт **`public/world/prototype/forest-ground.webp`**. Отдельных уменьшенных карт, детальных полян и участков со старыми постройками нет.

## Обновление карты

Текущий мастер — PNG; обновление фона хранится в том же файле. Редактируйте карту целиком, сохраняя квадратный холст. В каталоге должен быть ровно один `forest-ground.png`, `.jpg` или `.jpeg`; несколько версий скрипт отклоняет. После установки зависимостей через `npm ci`, из корня проекта:

```bash
node scripts/prepare-world-assets.mjs
npm run world:export
npm run world:check
npm run dev:local
```

`prepare-world-assets.mjs` создаёт WebP в полном разрешении, проверяет точное совпадение декодированных пикселей с исходником после учёта EXIF-ориентации и обновляет `features/world/runtime-art.json`. Скрипт не обрезает карту, не уменьшает её и не меняет исходник; WebP не добавляет потерь. Четыре совместимых поля реестра — `map`, `mapPreview`, `homePreview`, `homeDetail` — указывают на один файл с версией содержимого в `?v=`.

`world:export` читает готовый WebP, обновляет его физические размеры в Tiled и версию URL в данных сцены. Он **не перекодирует изображения и не меняет логические координаты**. `world:check` только проверяет файлы. После обновления метаданных закройте и снова откройте карту в Tiled, чтобы не сохранить поверх неё старую копию из редактора.

Проверяйте большую карту и круглый вид на узком и широком экране. В Git сохраняются изменённые мастера, WebP, `features/world/runtime-art.json`, `world/tiled/forest.tmj` и `features/world/tiled/forest.generated.json`.

## Пиксели изображения и координаты мира

Полное изображение имеет размер **2560 × 2560 пикселей**, логический мир — **1254 × 1254**. Увеличение разрешения изображения не меняет масштаб мира. Круглая камера показывает центральную поляну, размеченную прямоугольником `focus` в `world/tiled/forest.tmj`; отдельный рисунок для неё не нужен.

В Tiled размечены фон, фокус, герой, дом 1–5, мастерская 0–2, шахта 0–1 (`quarry`), лесной участок 0–1 (`woodlot`), маяк 0–1 и мост 0–1, отдельные площадки земли, куст, корзинка, костёр, свободная земля, препятствия, вода, свет и места обитания. Мохлик строит путь по навигационной геометрии; нарисованная на фоне дорожка сама по себе проходимость не задаёт. Старые линии `Routes` сохранены для сравнения и отдельных сценариев — это не основной поиск пути.

После замены фона сверьте границы воды, коллизии, входы и контакт объектов с землёй. Посадки птиц и маска земляных брызг используют сведения о рисунке и требуют отдельной сверки — [атмосфера](../docs/game/world-atmosphere.md). Смена оттенка или рисунка не переносит эти точки автоматически.

Проверенная версия фона для наземных брызг и посадок птиц указана в `features/world/forest-ground-layout.json → image`. Скрипт подготовки изображений намеренно не обновляет её: сначала сравните маску земли и места посадок с новым рисунком, скорректируйте при необходимости, затем укажите актуальный URL с `?v=` из `runtime-art.json`. `world:check` проверяет согласованность экспорта Tiled, но не подтверждает эту ручную разметку; регрессии птиц и земли входят в `npm test`.

## Дом и другие изображения

Пять изображений дома — `public/world/prototype/home-level-1.png` … `home-level-5.png`. Копий этих мастеров в `art/` сейчас нет; перед существенной работой сохраните мастер в `art/world/prototype/`. Все уровни подключены в Tiled; каждый получает свой рисунок, рамку, коллизию и точки. `initialLevel` младшего размещённого уровня задаёт начальный вид предпросмотра, DEV позволяет проверить остальные; в игре используется подтверждённый уровень аккаунта.

`prepare-world-assets.mjs` экспортирует только фон. Для нового здания подготовьте файл в `public/world/prototype/`, добавьте его во встроенный набор Tiled, затем выполните `world:export`; PNG, WebP и JPEG поддерживаются. Подробно — [мастерская зданий](../docs/game/building-workbench.md). В основной игре полученное улучшение дома, мастерской, шахты или лесного участка выбирает соответствующий рисунок и геометрию; если точного рисунка нет, остаётся ближайший доступный младший. Страница предпросмотра меняет только визуальный уровень.

Другие подключённые рисунки в `public/world/prototype/`:

| Объект | Файлы и состояние |
|---|---|
| Мастерская | `forest-workshop-level-0.png` … `forest-workshop-level-2.png` |
| Шахта (`quarry`) | `quarry-lvl-0.png` — заброшенный вход; `quarry-lvl-1.png` — открытый вход. Экономические уровни 2–5 используют внешний вид 1; старших рисунков нет |
| Лесной участок (`woodlot`) | Один `shelter.png` для состояний 0 и 1. Работа участка определяется экономическим уровнем, а не заменой PNG |
| Маяк | `lighthouse-level-0.png`, `lighthouse-level-1.png` |
| Мост | `bridge-level-0.png` — короткий сломанный береговой конец; `beams.png` — отдельные обломки; `bridge-level-1.png` — целый мост |

Рисунки имеют прозрачный фон и связаны с `siteId` в Tiled. У маяка и моста ещё нет экономического восстановления; в игре остаётся начальное состояние 0. Оба состояния можно примерить в DEV и `/prototype/tiled-world`. Открытая шахта не включает интерьер, а целый мост не открывает путь через реку. Поворот задаётся объектом карты, исходный PNG не поворачивается и не переписывается.

Земля под зданиями хранится отдельно в terrain: `house-ground-1.png`, `house-ground-2.png`, `workshop-ground.png`, `quarry-ground.png`, `lighthouse-ground.png`. Площадка может состоять из нескольких копий изображения со своими размерами и поворотами. Общая земля сохраняется при переключении уровня. Для детали одного состояния задайте на её размещённом объекте пару `siteId` (**string**) + `level` (**int**): например, `bridge-debris` с `beams.png` показывается только при `bridge: 0`. На плитке terrain в наборе остаётся только `role: terrain`; условие относится к конкретному размещению. [Как переместить комплект моста](../docs/game/building-workbench.md#переставить-шахту-лесной-участок-или-мост).

Домам не нужно запекать тень, свет окна или дым в изображение: их рисует код по рисунку и разметке текущего уровня. Оставляйте прозрачный фон и размещайте маркеры окна/дымохода в соответствующей папке уровня.

Стык с картой оформляется контактной и короткой направленной тенью. Дополнительные камушки, трава, мох и щепки кодом не добавляются. После замены рисунка проверьте игровой вид днём и ночью, в круге и на большой карте.

## Куст

`art/world/prototype/bushv1.png` — пользовательский мастер с прозрачностью; копия для браузера — `public/world/prototype/bushv1.png`. Куст **размещён** на слое `Bushes`: изображение `clearing-bush-image`, размер 80 × 80; контур `clearing-bush` связан с ним через `imageId`. Фон под ним не содержит старого куста.

PNG содержит зелёный куст без ягод. Рост плодов, земля, влажность, контактная тень и шелест рисуются кодом. Ствол и древесные корни под листвой не дорисовываются: куст опирается на землю нижним краем кроны. Перекрытие Мохлика листвой использует прозрачность изображения, поэтому контур не нужно обводить по каждому листу. После замены PNG проверьте основание, силуэт, точки полива/подхода и прятки. [Как поставить куст и связать контур](../docs/game/clearing-garden.md#разместить-новый-куст-в-tiled).

При правке мастера куста обновите и браузерную копию: скрипт подготовки фона её не копирует. Корзинка и костёр целиком рисуются кодом; их положение задаётся точками `Garden` и `Campfires` в Tiled, отдельных PNG для них нет.

## Иконки предметов и находок

Единый набор покрывает товары экономики, коллекционные находки, предметы гардероба и обе валюты; соответствие каталогам проверяет `tests/item-icons.test.mjs`. Компоненты [`ItemIcon` и `CollectionIcon`](../features/items/item-icon.tsx) рисуют SVG на холсте 48 × 48: в кладовой, рецептах, ценах, наградах, рынке и `/branch` один предмет выглядит одинаково. Находки выбираются по `find.id`, чтобы разные камни, листья и раковины сохраняли собственный рисунок, даже если в старом каталоге совпадает `symbol`.

| Что редактировать | Исходник |
| --- | --- |
| Сырьё и урожай | [`art-natural.tsx`](../features/items/art-natural.tsx) |
| Изделия, стройматериалы и припасы | [`art-crafted.tsx`](../features/items/art-crafted.tsx) |
| Коллекционные находки | [`art-collection.tsx`](../features/items/art-collection.tsx) |
| Одежда и снаряжение | [`art-equipment.tsx`](../features/items/art-equipment.tsx) |
| Рыба: общие силуэты и палитры | [`fish-species.ts`](../features/world/fish-species.ts), SVG — [`fish-icon.tsx`](../features/world/fish-icon.tsx), Canvas — [`fish-sprite.ts`](../features/world/fish-sprite.ts) |
| Модели удочек: форма ствола, рукоять, катушка, крепления | [`fishing-rod-art.ts`](../features/world/fishing-rod-art.ts), SVG — [`fishing-rod-icon.tsx`](../features/world/fishing-rod-icon.tsx), Canvas — [`fishing-rod-painter.ts`](../features/world/fishing-rod-painter.ts) |
| Хлебная наживка и коробочка с червячком | [`item-icon.tsx`](../features/items/item-icon.tsx) |
| Валюты и общая SVG-обёртка | [`item-icon.tsx`](../features/items/item-icon.tsx) |

Эти исходники — мастера векторных иллюстраций. Отдельный PNG/WebP-экспорт и запуск `world:export` для них не нужны. В SVG нет внешних загрузок и повторяющихся идентификаторов градиентов; силуэт, контур и цвет должны читаться на тёмных панелях при 16–24 px. Детали коллекций проверяйте также при 48 px. Название и количество остаются текстом рядом; декоративная картинка скрыта от скринридера, самостоятельная получает `label`. Не подменяйте предмет иконкой действия: кирка обозначает добычу, сама руда имеет собственный рисунок. Карта Tiled и её графика к этому набору не относятся.

Одежда имеет два представления: карточка в `art-equipment.tsx` и надетый предмет в [`pixel-sprite.ts`](../features/mochlik/pixel-sprite.ts). Жёлудевая и вязаная шапочки, лунный венок, речной и лунный шарфы, лесной платок различаются силуэтом и деталями. Венок показывает полумесяц только спереди; платок завязывается сзади. Вересковый, морозный и медный мох дополняют прежние оттенки. Все шесть палитр задаёт [`appearance-palette.ts`](../features/mochlik/appearance-palette.ts): тело и отдельно анимируемые лапы при рыбалке и готовке используют один цвет.

При изменении одежды проверяйте перед, спину, оба профиля и наклон в исходных 48 px и при увеличении. Головной убор не должен закрывать глаза, одежда — менять точку опоры. Во сне остаётся прежний свёрнутый силуэт без аксессуаров. Проверки рига находятся в `tests/mochlik-sprite.test.mjs`; каталог, стоимость и владение одеждой задаются отдельно от рисунков.

## Плёска

Плёска целиком рисуется кодом в **`features/world/plesk-sprite.ts`**, на пиксельном холсте 48 × 48, как главный Мохлик. Внутренний ID `plesk` и имена файлов сохранены. У героини короткая округлая мордочка, кремовые щёки и цветок-заколка у анатомически левого виска, ниже уха; при боковом повороте дальняя заколка скрывается головой. Оба уха сохраняют собственный силуэт и внутреннюю часть. Геометрия плеча, локтя и ладони ограничивает длину лапы, в том числе в приветствии и при вытягивании рыбы. Меняйте палитру, форму тела и отдельные движения головы, лап и хвоста в этом исходнике. `pleskSpriteRig` хранит опору ног, цветок, ладони и точки хвата; `plesk-painter.ts` размещает жительницу и её тень в мире, затем рисует пальцы поверх рукояти. Восемь шаговых поз, заброс, вытягивание и укладка меняют геометрию тела. Кэш содержит не больше 256 поз.

Общий `features/world/fishing-props.ts` рисует удочку, леску, поплавок, рыбу и корзинку по точкам рук Плёски или Мохлика. Варианты проверки лески, поклёвки, борьбы и срыва согласуют тело со снастями; размер рыбы меняется, корзина наполняется после укладки. Древко не поворачивает внутрь через лицо при близком поплавке; к воде направлена гибкая леска. `fishingCatchFrame` и `fishingBasketFishCenter` задают общий перенос `reel → catch → pack`: рыбка непрерывно приходит к свободной ладони и опускается за переднюю часть корзинки. Не рисуйте второй экземпляр рыбы при смене стадии; сохраняйте размер и конечную точку на стыке. Удочка остаётся в другой лапе, а передний слой пальцев только обхватывает предмет. Портрет торговки тоже строится из программного спрайта. Растровый атлас не используется; новых PNG/WebP и экспорта графики для изменения персонажа не нужно. После правки проверьте **DEV → Плёска**: все действия и четыре направления, опору лап, хват, сторону цветка и масштаб настоящей карты. «Показать все занятия» проверяет рисунок, а «Свободное поведение» — решения её AI. [Поведение, DEV и разметка мест](../docs/game/forest-residents.md).

## Модели удочек

[`fishing-rod-art.ts`](../features/world/fishing-rod-art.ts) задаёт нормализованную геометрию пяти моделей. Камышовая имеет узлы ствола и простую намотку; Речная — тонкие секции, цельную пробковую рукоять и небольшую округлую катушку в тёплой латунной палитре; Приливная — массивные бирюзовые секции, раздельную рукоять и глубокую подвесную катушку с дужкой. Ивовая использует изогнутую деревянную основу, фигурные крепления и большую круглую медную катушку; Звездопадная — звёздные крепления и фиолетовую основу. Отличия сохраняются без цвета. `fishingRodAppearance` остаётся поставщиком палитры, а `fishingRodShapes` определяет сами детали; одной смены цвета или дополнительных полосок недостаточно для новой модели.

[`FishingRodIcon`](../features/world/fishing-rod-icon.tsx) использует эти части в SVG для прилавка, коллекции и выбранной снасти перед поездкой. [`drawFishingRod`](../features/world/fishing-rod-painter.ts) получает от рига неизменные `grip`, `tip` и `reel`, строит локальную ось и рисует те же детали на Canvas. Размеры и изгибы не должны переносить руку или точку крепления лески. Общая рыбацкая стойка уменьшает детали катушки через `detailScale`; тот же масштаб получает точка её вращающейся ручки. Длина удилища и положение кончика при этом сохраняются. Товарные SVG используют исходные пропорции. Нельзя возвращать в товарные карточки одинаковую пиктограмму действия вместо модели. Иконка имеет `label` для самостоятельного изображения; рядом с текстовым названием остаётся декоративной.

После правки проверьте светлый и тёмный фон, SVG при 24/44/64 px и реальные размеры персонажей 36/50, изгиб на поклёвке, оба направления, нахождение снасти в руке и рядом с корзиной. `tests/fishing-rod-art.test.mjs` проверяет разные силуэты, безопасный неизвестный ID, фиксированную точку конца удочки, общую геометрию SVG/Canvas и отсутствие внешних ассетов. Цены, владение и бонусы задаются отдельно в экономическом каталоге.

## Рыбы и подготовка готовки

[`fish-species.ts`](../features/world/fish-species.ts) — единый мастер двенадцати видов рыб из экономического каталога. `fishShapes` задаёт нормализованные эллипсы, плавники, полосы и палитры; `fish-sprite.ts` и `FishIcon` используют те же детали. Рыба смотрит вправо, её полный радиус с качанием хвоста и контуром меньше `0.87 × size`. Этот запас нужен подводным маршрутам, чтобы хвост не пересекал `WaterExclusions`. Подводная версия приглушает палитру и мелкие детали. Маски воды и прозрачность задаёт `forest-water-life.ts`; сама иллюстрация не управляет временем или наградами.

При правке проверьте рыбу на крючке, в ладони, в корзине, на прилавке и под водой. `species` определяет текущий улов, `basketSpecies` — уже уложенный: начало нового заброса не должно менять старую рыбу в корзине. Миниатюры должны различаться силуэтом при 8–24 единицах, а SVG — при 16–64 px. Проверки находятся в `tests/fish-species.test.mjs`, `tests/fishing-props.test.mjs` и `tests/item-icons.test.mjs`. Серверную редкость и цены меняйте в экономическом каталоге, а не в рисунке.

Реквизит [DEV-готовки](../docs/game/cooking.md) также программный: низкая доска, нож, котелок, ложка и миска в [`forest-cooking-painter.ts`](../features/world/forest-cooking-painter.ts). Четыре стадии используют существующее тело и одежду Мохлика, короткие лапы и общие точки инструмента. Это 30-секундная репетиция анимаций без рецептов, затрат продуктов и результата в инвентаре; отдельные растровые ассеты не требуются.
