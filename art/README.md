# Изображения: что редактировать

Для нового мира редактируйте **`art/world/prototype/*.png`**. Каждый PNG уже содержит ровно тот участок, который рисует приложение. Экспортируйте его целиком в одноимённый WebP в **`public/world/prototype/`**. Дополнительной нарезки, скрытого смешивания или автоматического сжатия больше нет.

## Новый мир: семь пар PNG → WebP

| Имя без расширения | Что изображено | Текущий размер PNG и WebP |
| --- | --- | --- |
| `forest-ground` | Общая карта без заменяемого дома и мастерской | 1254 × 1254 |
| `home-level-1` | Участок с домом первого уровня | 568 × 536 |
| `home-level-2` | Тот же участок, второй уровень дома | 568 × 536 |
| `home-level-3` | Тот же участок, третий уровень дома | 568 × 536 |
| `workshop-empty` | Участок до строительства мастерской | 664 × 600 |
| `workshop-level-1` | Тот же участок, первый уровень мастерской | 664 × 600 |
| `workshop-level-2` | Тот же участок, второй уровень мастерской | 664 × 600 |

Например: `art/world/prototype/home-level-2.png` → ваш экспорт → `public/world/prototype/home-level-2.webp`.

PNG можно редактировать и сжимать самостоятельно. Они не загружаются браузером. Сохраняйте пропорции холста и положение основания, двери, тени и краёв участка. Можно пропорционально увеличить разрешение; это не увеличивает здание на карте. Для согласованного рисунка применяйте одинаковый масштаб детализации ко всем состояниям здания.

После замены WebP:

```bash
npm run world:export
npm run world:check
npm run dev:local
```

Открыть `http://localhost:3000/prototype/tiled-world`. `world:export` читает ваши готовые WebP, обновляет их размеры в Tiled и версии URL в данных сцены. Он **не меняет PNG/WebP и не выполняет компрессию**. `world:check` только проверяет файлы. После изменения размеров закройте и снова откройте карту в Tiled, чтобы не сохранить поверх обновлённой разметки старую копию из редактора.

Непропорциональное изменение холста отклоняется проверкой. Если в рисунке сдвинут вход или изменена форма здания, связанные точки и контуры нужно поправить в Tiled; если изменена земля у границы участка, проверьте стык с `forest-ground`. Программная проверка не оценивает художественные стыки.

В Git сохраняются изменённые PNG, WebP, `world/tiled/forest.tmj` и `features/world/tiled/forest.generated.json`. ZIP больше не нужен. Команда `world:assets` и прежний скрипт автоматической нарезки удалены.

## Обычная игра: отдельные три исходника

Эти файлы находятся в **`art/world/main/`** и относятся к существующей игре, а не к странице прототипа:

| PNG | Назначение |
| --- | --- |
| `forest-map.png` | Прежняя большая карта с домом в рисунке |
| `home-clearing.png` | Прежняя детальная домашняя поляна |
| `boat-wreck.png` | Разбитая лодка с прозрачным фоном |

Обычная игра пока использует WebP из `public/world/runtime/`. Их понятные имена: `forest-map`, `forest-map-preview`, `home-clearing`, `home-clearing-preview`, `boat-wreck`; за именем следует хеш содержимого для кеша. Эти файлы остаются, пока прототип не интегрирован в основную игру. Хеш автоматически меняет `node scripts/prepare-world-assets.mjs`; этот отдельный скрипт перекодирует изображения обычной игры и не запускается при `world:export` или обычной сборке. Для текущей работы над новым миром запускайте только команды из предыдущего раздела.

## Остальные используемые изображения

- `public/world/routes/trail.webp` — лесная тропа на экране прогулки.
- `public/achievements/` — семь медалей; имена соответствуют ID достижений и используются динамически.
- `public/icon.svg`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` — иконки сайта и установленной PWA.
- `docs/game/concepts/` — два изображения концептов, показанные в документации.
- `docs/game/images/` — снимки редактора и прототипа из инструкции; приложение их не скачивает.

## Что изменилось при уборке

Семь редактируемых PNG нового мира подготовлены из исходных пикселей прежнего рецепта **до сжатия в WebP**, а не восстановлены из сжатых файлов. Их повторный экспорт с прежними настройками даёт те же байты всех семи существующих WebP. В этой уборке рабочие WebP только переименованы: внешний вид сцены не менялся.

Пять прежних полных художественных заготовок и рецепт их нарезки убраны из рабочего дерева. Они доступны в истории на коммите [`ffd97ca`](https://github.com/NolReaction/zhiv-app/tree/ffd97ca868365e257b6eabe0fed52334a2f86a0a/world/tiled/art), а также в ранее переданном архиве. Заново копировать их в проект не нужно.

Удалена `river.webp`: текущая рыбалка рисует берег основной карты и не использует эту старую отдельную иллюстрацию. Старые URL переименованных файлов больше не входят в ветку; при будущем развёртывании нужна новая версия клиента. В `master` эта уборка не перенесена.
