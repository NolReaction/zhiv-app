# Изображения: что редактировать

Основной источник новой карты — **`art/world/prototype/forest-ground.png`**, 2560 × 2560 пикселей. Основная игра и `/prototype/tiled-world` используют один полный экспорт **`public/world/prototype/forest-ground.webp`**. Отдельных уменьшенных карт, детальных полян и участков со старыми постройками нет.

## 3D-достопримечательности Земли

Девять исходных GLB находятся в `art/earth/models/<id>/source.glb`, конфигурация каждого — рядом в `model.json`. Восемь новых моделей пользователь создал в Tripo; их исходники общим размером 44 032 592 байта сохранены без изменений. Ссылки на источник для собственных моделей не требуются, сторонние авторы и лицензии им не назначались. Прежняя атрибуция Эйфелевой башни сохранена.

```bash
npm run earth:models:prepare -- --all
npm run earth:models:check -- --all
```

Подготовка создаёт `public/earth/models/<id>/{overview,detail}.elm` и `features/earth/data/*-model.json`; raw GLB в `public/` не копируется и браузером не загружается. Башня сохраняет ELM1; новые восемь используют ELM2 с UV, нормалями, baseColor/normal/metallicRoughness. Бюджеты — 6000/24000 треугольников; размеры текстур — 256/128/64 на обзоре и 1024/512/256 вблизи. PBR-карты сохраняются в lossless WebP, цвет — WebP quality 85. Shader использует упрощённый статичный свет без IBL и динамических теней.

Меняйте исходник и конфигурацию, затем сохраняйте их вместе с обоими подготовленными LOD и manifest. Расположение, художественный масштаб и поворот меняются отдельно через **DEV 3D**, без повторной подготовки. Подробности и допустимый профиль GLB — [3D-модели Земли](../docs/development/earth-models.md).

## Обновление карты

Текущий мастер — PNG; обновление фона хранится в том же файле. Редактируйте карту целиком, сохраняя квадратный холст. В каталоге должен быть ровно один `forest-ground.png`, `.jpg` или `.jpeg`; несколько версий скрипт отклоняет. После установки зависимостей через `npm ci`, из корня проекта:

```bash
node scripts/prepare-world-assets.mjs
npm run world:export
npm run world:check
npm run dev:local
```

`prepare-world-assets.mjs` создаёт WebP в полном разрешении, проверяет точное совпадение декодированных пикселей с исходником после учёта EXIF-ориентации и обновляет `features/world/runtime-art.json`. Скрипт не обрезает карту, не уменьшает её и не меняет исходник; WebP не добавляет потерь. Четыре совместимых поля реестра — `map`, `mapPreview`, `homePreview`, `homeDetail` — указывают на один файл с версией содержимого в `?v=`.

`world:export` читает готовый WebP, обновляет его физические размеры в Tiled и версию URL в данных сцены. Он **не перекодирует изображения и не меняет логические координаты**. `world:check` только проверяет файлы. После обновления метаданных закройте и снова откройте карту в Tiled, чтобы не сохранить поверх неё старую копию из редактора.

Проверяйте большую карту и круглый вид на узком и широком экране. В Git сохраняются изменённые мастера, WebP, `features/world/runtime-art.json`, `world/tiled/forest.tmj` и `features/world/tiled/forest.generated.json`.

## Пиксели изображения и координаты мира

Полное изображение имеет размер **2560 × 2560 пикселей**, логический мир — **1254 × 1254**. Увеличение разрешения изображения не меняет масштаб мира. Круглая камера показывает центральную поляну, размеченную прямоугольником `focus` в `world/tiled/forest.tmj`; отдельный рисунок для неё не нужен.

В Tiled размечены фон, фокус, герой, дом 1–5, мастерская 0–2, шахта 0–5 (`quarry`), маяк 0–1, мост 0–1, рынок, караван, доска заказов и дом Лопоуха 1–2, отдельные площадки земли, куст, корзинка, костёр, свободная земля, препятствия, вода, свет и места обитания. Мохлик строит путь по навигационной геометрии; нарисованная на фоне дорожка сама по себе проходимость не задаёт. Старые линии `Routes` сохранены для сравнения и отдельных сценариев — это не основной поиск пути.

После замены фона сверьте границы воды, коллизии, входы и контакт объектов с землёй. Посадки птиц и маска земляных брызг используют сведения о рисунке и требуют отдельной сверки — [атмосфера](../docs/game/world-atmosphere.md). Смена оттенка или рисунка не переносит эти точки автоматически.

Проверенная версия фона для наземных брызг и посадок птиц указана в `features/world/environment/weather/forest-ground-layout.json → image`. Скрипт подготовки изображений намеренно не обновляет её: сначала сравните маску земли и места посадок с новым рисунком, скорректируйте при необходимости, затем укажите актуальный URL с `?v=` из `runtime-art.json`. `world:check` проверяет согласованность экспорта Tiled, но не подтверждает эту ручную разметку; регрессии птиц и земли входят в `npm test`.

## Земля под домом: компактные файлы для браузера

`public/world/prototype/house-ground-1.png` и `house-ground-2.png` остаются исходными PNG. Tiled и браузер используют соседние `house-ground-1.webp` и `house-ground-2.webp`: полное разрешение и все RGBA-пиксели, включая прозрачные, совпадают с PNG. Экспорт без потерь уменьшает каждый файл примерно на 29%; размер объектов и разметка мира не меняются.

После изменения этих двух PNG выполните:

```bash
node scripts/prepare-world-ground-assets.mjs
npm run world:export
npm run world:check
```

Скрипт сначала проверяет оба результата и точное совпадение пикселей, затем сохраняет WebP. В Git входят исходные изменённые PNG, оба WebP и штатный экспорт Tiled. `prepare-world-assets.mjs` по-прежнему занимается только фоном леса; другие рисунки он не перекодирует.

## Дом и другие изображения

Пять изображений дома — `public/world/prototype/home-level-1.png` … `home-level-5.png`. Копий этих мастеров в `art/` сейчас нет; перед существенной работой сохраните мастер в `art/world/prototype/`. Все уровни подключены в Tiled; каждый получает свой рисунок, рамку, коллизию и точки. `initialLevel` младшего размещённого уровня задаёт начальный вид предпросмотра, DEV позволяет проверить остальные; в игре используется подтверждённый уровень аккаунта.

`prepare-world-assets.mjs` экспортирует только фон. Для нового здания подготовьте файл в `public/world/buildings/<siteId>/`, добавьте его во встроенный набор Tiled, затем выполните `world:export`; PNG, WebP и JPEG поддерживаются. Подробно — [мастерская зданий](../docs/game/building-workbench.md). В основной игре полученное улучшение размещённого дома, мастерской или шахты выбирает соответствующий рисунок и геометрию; если точного рисунка нет, остаётся ближайший доступный младший. Экономика снятого с карты лесного участка работает через панель хозяйства. Страница предпросмотра меняет только визуальный уровень.

Рисунки имеют прозрачный фон и связаны с `siteId` в Tiled. Экономическое восстановление маяка и моста переключает их состояния 0/1. Варианты построек также можно примерить в DEV и `/prototype/tiled-world` только при development-запуске; в production панель и страница закрыты. Открытая шахта не включает интерьер, а целый мост не открывает путь через реку. Поворот задаётся объектом карты, исходный PNG не поворачивается и не переписывается.

Дом Лопоуха имеет два визуальных уровня: при закрытом `woodlot` 0 рисунок скрыт, уровни 1–2 используют дом 1, полученный `woodlot` 3 и выше — дом 2. Главный дом игрока не переключает этот рисунок. Существующие рецепты, очередь и экономические уровни участка сохраняются; отдельный анимируемый верстак остаётся будущим объектом. Рынок и палатка Листохвоста имеют состояния 0/1 без отдельной стройки. Дом Шишколапа сохраняет один уровень без улучшений.

Земля под зданиями хранится отдельно в terrain: `house-ground-1.png`, `house-ground-2.png`, `workshop-ground.png`, `quarry-ground.png`, `lighthouse-ground.png`. Площадка может состоять из нескольких копий изображения со своими размерами и поворотами. Общая земля сохраняется при переключении уровня. Для детали одного состояния задайте на её размещённом объекте пару `siteId` (**string**) + `level` (**int**): например, `bridge-debris` с `beams.png` показывается только при `bridge: 0`. На плитке terrain в наборе остаётся только `role: terrain`; условие относится к конкретному размещению. [Как переместить комплект моста](../docs/game/building-workbench.md#переставить-шахту-лесной-участок-или-мост).

Лавка собрана в `Buildings/Pleska/Shop-lvl-1`: PNG лежит в `Shop-image`, коллизия, область нажатия и маска `plesk-shop-silhouette-level-1-1` — в `Shop-tracing`, опора, вход и остановки продавца/покупателя — в `Shop-anchors`. Полигон проходимой полянки `pleska-cleaning` (объект 427) также находится в `Shop-tracing`; дополнительный подход — отдельный `WalkAreas/plesk-shop-approach`. Отдельного terrain-рисунка земли у лавки нет. При переносе лавки переносите и внешний подход. После масштабирования рисунка поправьте связанные контуры, точки и глубину маски `frontY`; после замены PNG проверьте, что маска не закрывает прозрачные места. `prepare-world-assets.mjs` этот файл не меняет; достаточно `world:export` и `world:check`. [Размещение прилавка](../docs/game/forest-residents.md#прилавок-и-подход).

Дом Шишколапа собран в `Buildings/Shishkolap`: общая земля находится в `House-ground`, единственный уровень — в `House-lvl-1`. Его слои `House-image`, `House-tracing` и `House-anchors` содержат рисунок, контуры и точки; пользовательский PNG и земля сохраняют авторский размер и положение. Здесь размечены опора, вход, порог, область нажатия, коллизия, место отдыха `builder-rest` и маска стен/крыши `builder-home-silhouette-level-1-1`. Маска повторяет непрозрачный контур дома, оставляет дверь и вырез крыльца открытыми и действует при визуальном уровне 1; собственный рисунок дома она не закрывает. Дерево `shishkolap-tree` перекрывает здание общей маской `Occluders`, а не частью изображения дома. При переносе или изменении размера рисунка переносите и сверяйте все связанные маркеры и маску дома вместе; контур дерева правьте отдельно. Скрипт подготовки фона этот PNG не меняет. [Точки дома и сон строителя](../docs/game/tiled-editor.md#дом-шишколапа).

Домам не нужно запекать тень, свет окна или дым в изображение: их рисует код по рисунку и разметке текущего уровня. Оставляйте прозрачный фон и размещайте маркеры окна/дымохода в соответствующей папке уровня.

Стык с картой оформляется контактной и короткой направленной тенью. Дополнительные камушки, трава, мох и щепки кодом не добавляются. После замены рисунка проверьте игровой вид днём и ночью, в круге и на большой карте.

## Торговый пароход

Единственный мастер — `public/world/ships/trade-ship.png`, прозрачный PNG 1774 × 887, предоставленный пользователем и сохранённый без перекодирования. Отдельной копии в `art/` нет. `prepare-world-assets.mjs` этот файл не меняет; к Tiled корабль пока не привязан.

[`trade-ship-sprite.ts`](../features/world/objects/trade-ship/trade-ship-sprite.ts) размещает PNG в боксе 800 × 500, сохраняет пропорции и зеркалит носом влево. Базовая калибровка 0.12 радиана задаёт ровную стоянку; поверх неё рейс добавляет наклон по часовой стрелке при подходе с выравниванием у причала и поворот против часовой стрелки после прямого отхода вправо. Это поворот PNG в плоскости Canvas, пиксели мастера при нём не меняются. Дверь и корпус — одно изображение; анимация двери, калитки и сменного груза пока не добавлена. Вода, контактная тень и пар рисуются отдельно.

[`trade-ship-gangway.ts`](../features/world/objects/trade-ship/trade-ship-gangway.ts) рисует деревянный мостик шириной 14 мировых пикселей двумя проходами. Опора рисуется до PNG; короткая часть после PNG лежит на палубе и соединяет настил с проходом. Шарнир — исходная точка `1008/353`, длина палубной опоры калибруется точкой `1008/409`; при стоянке `705/1102/310` береговой конец находится в `850/1138`. Шарнир следует качанию через общий `tradeShipSpritePose`, береговая опора неподвижна. Короткий палубный конец продолжает обе стороны рампы по одной линии, с тонкой контактной тенью вместо отдельной накладки. После остановки мостик выдвигается за 2.4 секунды; в DEV-рейсе перед отходом убирается за 2 секунды. Он виден в общей сцене и режимах стенда «На карте»/«Рейс», но не входит в крупный вид и PNG-экспорт. Дополнительный растровый ассет не нужен; навигацию персонажей эта визуальная опора пока не меняет.

[`trade-ship-lighting.ts`](../features/world/objects/trade-ship/trade-ship-lighting.ts) задаёт свечение настоящих стёкол и фонарей, мягкие пятна на палубе и короткие отражения. Свет рисуется после общего ночного затемнения, сохраняет рамы и использует тот же transform, что PNG. Корпус и свет на нём качаются вместе; отражения остаются на воде.

При замене PNG обновите URL с версией содержимого и размеры/привязки в `TRADE_SHIP_SPRITE`, сверяйте `TRADE_SHIP_GANGWAY_RIG`, стёкла/фонари и весь корпус в пути по настоящей водной маске. Положение относится к общему боксу, а не к обрезанному контуру изображения. Проверьте обе части мостика, опору на палубе, неподвижный берег и уборку до движения. В обычной игре первое прибытие открывает полученный маяк; независимый пробный рейс доступен через **DEV → Сцена → Погода → Приплыть / Отойти / У причала / К кораблю** и `/prototype/trade-ship`. [Устройство и ограничения](../docs/game/trade-ship-prototype.md).

## Куст

`art/world/prototype/bushv1.png` — пользовательский мастер с прозрачностью; копия для браузера — `public/world/prototype/bushv1.png`. Куст **размещён** на слое `Bushes`: изображение `clearing-bush-image`, размер 80 × 80; контур `clearing-bush` связан с ним через `imageId`. Фон под ним не содержит старого куста.

PNG содержит зелёный куст без ягод. Рост плодов, земля, влажность, контактная тень и шелест рисуются кодом. Ствол и древесные корни под листвой не дорисовываются: куст опирается на землю нижним краем кроны. Перекрытие Мохлика листвой использует прозрачность изображения, поэтому контур не нужно обводить по каждому листу. После замены PNG проверьте основание, силуэт, точки полива/подхода и прятки. [Как поставить куст и связать контур](../docs/game/clearing-garden.md#разместить-новый-куст-в-tiled).

При правке мастера куста обновите и браузерную копию: скрипт подготовки фона её не копирует. Корзинка и костёр целиком рисуются кодом; их положение задаётся точками `Garden` и `Campfires` в Tiled, отдельных PNG для них нет.

## Иконки предметов и находок

Единый набор покрывает товары экономики, коллекционные находки, предметы гардероба и обе валюты; соответствие каталогам проверяет `tests/item-icons.test.mjs`. Компоненты [`ItemIcon` и `CollectionIcon`](../features/items/item-icon.tsx) рисуют SVG на холсте 48 × 48: в кладовой, рецептах, ценах, наградах, рынке и `/branch` один предмет выглядит одинаково. Находки выбираются по `find.id`, чтобы разные камни, листья и раковины сохраняли собственный рисунок, даже если в старом каталоге совпадает `symbol`.

Эти исходники — мастера векторных иллюстраций. Отдельный PNG/WebP-экспорт и запуск `world:export` для них не нужны. В SVG нет внешних загрузок и повторяющихся идентификаторов градиентов; силуэт, контур и цвет должны читаться на тёмных панелях при 16–24 px. Детали коллекций проверяйте также при 48 px. Название и количество остаются текстом рядом; декоративная картинка скрыта от скринридера, самостоятельная получает `label`. Не подменяйте предмет иконкой действия: кирка обозначает добычу, сама руда имеет собственный рисунок. Карта Tiled и её графика к этому набору не относятся.

Одежда имеет два представления: карточка в `art-equipment.tsx` и надетый предмет в [`pixel-sprite.ts`](../features/mochlik/pixel-sprite.ts). Жёлудевая и вязаная шапочки, лунный венок, речной и лунный шарфы, лесной платок различаются силуэтом и деталями. Венок показывает полумесяц только спереди; платок завязывается сзади. Вересковый, морозный и медный мох дополняют прежние оттенки. Все шесть палитр задаёт [`appearance-palette.ts`](../features/mochlik/appearance-palette.ts): тело и отдельно анимируемые лапы при рыбалке и готовке используют один цвет.

При изменении одежды проверяйте перед, спину, оба профиля и наклон в исходных 48 px и при увеличении. Головной убор не должен закрывать глаза, одежда — менять точку опоры. Во сне остаётся прежний свёрнутый силуэт без аксессуаров. Проверки рига находятся в `tests/mochlik-sprite.test.mjs`; каталог, стоимость и владение одеждой задаются отдельно от рисунков.

## Плёска

Плёска целиком рисуется кодом в **`features/world/characters/plesk/plesk-sprite.ts`**, на пиксельном холсте 48 × 48, как главный Мохлик. Внутренний ID `plesk` и имена файлов сохранены. У героини короткая округлая мордочка, кремовые щёки и цветок-заколка у анатомически левого виска, ниже уха; при боковом повороте дальняя заколка скрывается головой. Оба уха сохраняют собственный силуэт и внутреннюю часть. Геометрия плеча, локтя и ладони ограничивает длину лапы, в том числе в приветствии и при вытягивании рыбы. Меняйте палитру, форму тела и отдельные движения головы, лап и хвоста в этом исходнике. `pleskSpriteRig` хранит опору ног, цветок, ладони и точки хвата; `plesk-painter.ts` размещает жительницу и её тень в мире, затем рисует пальцы поверх рукояти. Восемь шаговых поз, заброс, вытягивание и укладка меняют геометрию тела. Кэш содержит не больше 256 поз.

Общий `features/world/activities/fishing/fishing-props.ts` рисует удочку, леску, поплавок, рыбу и корзинку по точкам рук Плёски или Мохлика. Варианты проверки лески, поклёвки, борьбы и срыва согласуют тело со снастями; размер рыбы меняется, корзина наполняется после укладки. Древко не поворачивает внутрь через лицо при близком поплавке; к воде направлена гибкая леска. `fishingCatchFrame` и `fishingBasketFishCenter` задают общий перенос `reel → catch → pack`: рыбка непрерывно приходит к свободной ладони и опускается за переднюю часть корзинки. Не рисуйте второй экземпляр рыбы при смене стадии; сохраняйте размер и конечную точку на стыке. Удочка остаётся в другой лапе, а передний слой пальцев только обхватывает предмет. Портрет торговки тоже строится из программного спрайта. Растровый атлас не используется; новых PNG/WebP и экспорта графики для изменения персонажа не нужно. После правки проверьте **DEV → Плёска**: все действия и четыре направления, опору лап, хват, сторону цветка и масштаб настоящей карты. «Показать все занятия» проверяет рисунок, а «Свободное поведение» — решения её AI. [Поведение, DEV и разметка мест](../docs/game/forest-residents.md).

## Модели удочек

[`fishing-rod-art.ts`](../features/world/activities/fishing/fishing-rod-art.ts) задаёт нормализованную геометрию тринадцати моделей. Камышовая имеет узлы ствола и простую намотку; Речная — тонкие секции, цельную пробковую рукоять и небольшую округлую катушку в тёплой латунной палитре; Приливная — массивные бирюзовые секции, раздельную рукоять и глубокую подвесную катушку с дужкой. Ручьевая — короткую деревянную основу, зелёную обмотку и компактную катушку. Ивовая использует изогнутую деревянную основу, фигурные крепления и большую круглую медную катушку; Звездопадная — звёздные крепления и фиолетовую основу. Привозная Походная использует складные соединения и плоскую катушку; Болотная — раздвоенную рукоять-ветку и открытую катушку-колесо; Сумеречная — тонкую основу и корпус катушки в форме полумесяца. У новых Поплавочной, Хищной, Зеркальной и Глубинной собственные рукояти и катушки: прикреплённый пробковый поплавок, зубчатое колесо, плоский шестигранный корпус и тяжёлая закрытая катушка. Их рукоятки катушек следуют прежней общей траектории лапы. Отличия сохраняются без цвета. `fishingRodAppearance` остаётся поставщиком палитры, а `fishingRodShapes` определяет сами детали; одной смены цвета или дополнительных полосок недостаточно для новой модели.

[`FishingRodIcon`](../features/world/activities/fishing/fishing-rod-icon.tsx) использует эти части в SVG для прилавка, коллекции и выбранной снасти перед поездкой. [`drawFishingRod`](../features/world/activities/fishing/fishing-rod-painter.ts) получает от рига неизменные `grip`, `tip` и `reel`, строит локальную ось и рисует те же детали на Canvas. Размеры и изгибы не должны переносить руку или точку крепления лески. Общая рыбацкая стойка уменьшает детали катушки через `detailScale`; тот же масштаб получает точка её вращающейся ручки. Длина удилища и положение кончика при этом сохраняются. Товарные SVG используют исходные пропорции. Нельзя возвращать в товарные карточки одинаковую пиктограмму действия вместо модели. Иконка имеет `label` для самостоятельного изображения; рядом с текстовым названием остаётся декоративной.

После правки проверьте светлый и тёмный фон, SVG при 24/44/64 px и реальные размеры персонажей 36/50, изгиб на поклёвке, оба направления, нахождение снасти в руке и рядом с корзиной. `tests/fishing-rod-art.test.mjs` проверяет разные силуэты, безопасный неизвестный ID, фиксированную точку конца удочки, общую геометрию SVG/Canvas и отсутствие внешних ассетов. Цены, владение и бонусы задаются отдельно в экономическом каталоге.

## Рыбы и подготовка готовки

[`fish-species.ts`](../features/world/activities/fishing/fish-species.ts) — единый мастер двенадцати видов рыб из экономического каталога. `fishShapes` задаёт нормализованные эллипсы, плавники, полосы и палитры; `fish-sprite.ts` и `FishIcon` используют те же детали. Рыба смотрит вправо, её полный радиус с качанием хвоста и контуром меньше `0.87 × size`. Этот запас нужен подводным маршрутам, чтобы хвост не пересекал `WaterExclusions`. Подводная версия приглушает палитру и мелкие детали. Маски воды и прозрачность задаёт `forest-water-life.ts`; сама иллюстрация не управляет временем или наградами.

При правке проверьте рыбу на крючке, в ладони, в корзине, на прилавке и под водой. `species` определяет текущий улов, `basketSpecies` — уже уложенный: начало нового заброса не должно менять старую рыбу в корзине. Миниатюры должны различаться силуэтом при 8–24 единицах, а SVG — при 16–64 px. Проверки находятся в `tests/fish-species.test.mjs`, `tests/fishing-props.test.mjs` и `tests/item-icons.test.mjs`. Серверную редкость и цены меняйте в экономическом каталоге, а не в рисунке.

Реквизит [DEV-готовки](../docs/game/cooking.md) также программный: низкая доска, нож, котелок, ложка и миска в [`forest-cooking-painter.ts`](../features/world/activities/cooking/forest-cooking-painter.ts). Четыре стадии используют существующее тело и одежду Мохлика, короткие лапы и общие точки инструмента. Это 30-секундная репетиция анимаций без рецептов, затрат продуктов и результата в инвентаре; отдельные растровые ассеты не требуются.
