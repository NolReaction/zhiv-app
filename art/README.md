# Изображения: что редактировать

Основной источник новой карты — **`art/world/prototype/forest-ground.jpg`**, 2560 × 2560 пикселей. Основная игра и `/prototype/tiled-world` используют один полный экспорт **`public/world/prototype/forest-ground.webp`**. Отдельных уменьшенных карт, детальных полян и участков со старыми постройками нет.

## Обновление карты

Текущий мастер — JPG; обновление фона хранится в том же файле. Редактируйте карту целиком, сохраняя квадратный холст. В каталоге должен быть ровно один `forest-ground.png`, `.jpg` или `.jpeg`; несколько версий скрипт отклоняет. После установки зависимостей через `npm ci`, из корня проекта:

```bash
node scripts/prepare-world-assets.mjs
npm run world:export
npm run world:check
npm run dev:local
```

`prepare-world-assets.mjs` создаёт WebP в полном разрешении, проверяет точное совпадение декодированных пикселей с исходником после учёта EXIF-ориентации и обновляет `features/world/runtime-art.json`. Скрипт не обрезает карту, не уменьшает её и не меняет исходник. Уже имеющиеся потери JPG не восстанавливаются; WebP не добавляет новых потерь. Четыре совместимых поля реестра — `map`, `mapPreview`, `homePreview`, `homeDetail` — указывают на один файл с версией содержимого в `?v=`.

`world:export` читает готовый WebP, обновляет его физические размеры в Tiled и версию URL в данных сцены. Он **не перекодирует изображения и не меняет логические координаты**. `world:check` только проверяет файлы. После обновления метаданных закройте и снова откройте карту в Tiled, чтобы не сохранить поверх неё старую копию из редактора.

Проверяйте большую карту и круглый вид на узком и широком экране. В Git сохраняются изменённые мастера, WebP, `features/world/runtime-art.json`, `world/tiled/forest.tmj` и `features/world/tiled/forest.generated.json`.

## Пиксели изображения и координаты мира

Полное изображение имеет размер **2560 × 2560 пикселей**, логический мир — **1254 × 1254**. Увеличение разрешения изображения не меняет масштаб мира. Круглая камера показывает центральную поляну, размеченную прямоугольником `focus` в `world/tiled/forest.tmj`; отдельный рисунок для неё не нужен.

В Tiled размечены фон, фокус, герой, все пять уровней дома, куст, корзинка, костёр, свободная земля, препятствия, вода, свет и места обитания. Мохлик строит путь по навигационной геометрии; нарисованная на фоне дорожка сама по себе проходимость не задаёт. Старые линии `Routes` сохранены для сравнения и отдельных сценариев — это не основной поиск пути.

После замены фона сверьте границы воды, коллизии, входы и контакт объектов с землёй. Посадки птиц и маска земляных брызг используют сведения о рисунке и требуют отдельной сверки — [атмосфера](../docs/game/world-atmosphere.md). Смена оттенка или рисунка не переносит эти точки автоматически.

Проверенная версия фона для наземных брызг и посадок птиц указана в `features/world/forest-ground-layout.json → image`. Скрипт подготовки изображений намеренно не обновляет её: сначала сравните маску земли и места посадок с новым рисунком, скорректируйте при необходимости, затем укажите актуальный URL с `?v=` из `runtime-art.json`. `world:check` проверяет согласованность экспорта Tiled, но не подтверждает эту ручную разметку; регрессии птиц и земли входят в `npm test`.

## Дом и другие изображения

Пять изображений дома — `public/world/prototype/home-level-1.png` … `home-level-5.png`. Копий этих мастеров в `art/` сейчас нет; перед существенной работой сохраните мастер в `art/world/prototype/`. Все уровни подключены в Tiled; каждый получает свой рисунок, рамку, коллизию и точки. `initialLevel` младшего размещённого уровня задаёт начальный вид, DEV/предпросмотр позволяет проверить остальные.

`prepare-world-assets.mjs` экспортирует только фон. Для нового здания подготовьте файл в `public/world/prototype/`, добавьте его во встроенный набор Tiled, затем выполните `world:export`; PNG, WebP и JPEG поддерживаются. Подробно — [мастерская зданий](../docs/game/building-workbench.md). Покупки улучшений дома к этой мастерской пока не подключены.

Домам не нужно запекать тень, свет окна или дым в изображение: их рисует код по рисунку и разметке текущего уровня. Оставляйте прозрачный фон и размещайте маркеры окна/дымохода в соответствующей папке уровня.

## Куст

`art/world/prototype/bushv1.png` — пользовательский мастер с прозрачностью; копия для браузера — `public/world/prototype/bushv1.png`. Куст **размещён** на слое `Bushes`: изображение `clearing-bush-image`, размер 80 × 80; контур `clearing-bush` связан с ним через `imageId`. Фон под ним не содержит старого куста.

PNG содержит зелёный куст без ягод. Рост плодов, земля, влажность, корни, тень и шелест рисуются кодом. Перекрытие Мохлика листвой использует прозрачность изображения, поэтому контур не нужно обводить по каждому листу. После замены PNG проверьте основание, силуэт, точки полива/подхода и прятки. [Как поставить куст и связать контур](../docs/game/clearing-garden.md#разместить-новый-куст-в-tiled).

При правке мастера куста обновите и браузерную копию: скрипт подготовки фона её не копирует. Корзинка и костёр целиком рисуются кодом; их положение задаётся точками `Garden` и `Campfires` в Tiled, отдельных PNG для них нет.
