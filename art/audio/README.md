# Исходники звука

Здесь хранятся исходные записи, монтажные проекты и доказательства происхождения. Браузер получает только подготовленные файлы из [`public/audio/`](../../public/audio/README.md). Каталог подключений — [`features/audio/catalog/audio-catalog.json`](../../features/audio/catalog/audio-catalog.json).

Сейчас в каталоге намеренно **84 пустых варианта, 35 звуковых событий и 11 профилей**. Файлы музыки, окружения и голосов ещё не выбраны; автоматической загрузки из внешних библиотек нет. Пустой `pending` не является ошибкой и не запрашивается браузером. Проверка готовности содержимого: `npm run audio:check -- --require-ready`; этот режим требует заполнить каждый вариант, включая второстепенные.

## Организация материалов

Для принятой записи используйте постоянный ID, например `workshop.woodworking.01`:

- `masters/<asset-id>.<original-extension>` — нетронутый оригинал; сохраняйте доступное исходное качество.
- `edited/<asset-id>.wav` — очищенный и смонтированный вариант без потерь.
- `projects/<asset-id>/` — проект редактора и промежуточные дорожки, если они нужны для воспроизведения монтажа.
- `licenses/<asset-id>/` — текст/копия условий, сведения об авторе и страница источника на дату получения.

Не храните в Git личную речь, случайные чужие голоса или материалы, на публикацию которых ещё нет прав. Перед добавлением исходника проверьте размер; большие многодорожечные проекты можно хранить отдельно, оставляя в этой папке точное описание и способ получить оригинал.

Начинать можно с одной дневной темы и по одному варианту остальных звуков. Незаполненные варианты продолжат молчать. Нужен оригинальный файл и ссылка на его страницу с условиями использования. Для собственной записи — имя автора, дата, согласованное право использования и сохранённый оригинал. Выбранное название лицензии не подтверждает права автоматически: происхождение проверяется человеком.

## Монтаж перед экспортом

1. Сохраните нетронутый мастер. Из него создайте отдельную монтажную копию.
2. Уберите лишнюю тишину и случайные шумы; не срезайте начальную атаку инструмента или голосовой реакции.
3. Для короткого эффекта проверьте начало и конец на щелчки. Микрофейды добавляйте по необходимости.
4. Для петли подберите стык, согласуйте уровень и фон с обеих сторон, прослушайте несколько повторов. Автоматический crossfade не гарантирует хороший ритм у молотка или пилы. Петлю экспортируйте целиком или задайте `loopStart` / `loopEnd` в секундах **относительно экспортированного файла**. Эти границы поддерживаются только декодированными эффектами, не потоковой музыкой.
5. Сохраняйте различие динамики: UI, вода, голоса и музыка не должны получать одинаковую громкость автоматически. В каталоге есть отдельный `gainDb`, в настройках — громкость каждой группы. Сначала уберите клиппинг в мастере, затем сводите слои на слух.
6. Пространственный одиночный источник обычно лучше подготовить в моно. Широкий фон леса и музыка могут быть стерео. Проверяйте итог в обоих вариантах прослушивания.

## Предсказуемый экспорт

Скрипту нужны `ffmpeg` и `ffprobe` в `PATH`. Он читает существующий каталог, проверяет соответствие ID и вида звука, не меняет оригинал, не перезаписывает готовые экспорты и не меняет `status` в каталоге. Уровень сохраняется, если явно не передать `--gain-db`.

```bash
# Проверить параметры и пути без создания файлов.
node scripts/prepare-audio.mjs --source art/audio/edited/river.01.wav --asset river.01 --kind loop --mono --dry-run

# WAV PCM 16 bit / 48 kHz: короткая петля без задержки сжатого кодека.
node scripts/prepare-audio.mjs --source art/audio/edited/river.01.wav --asset river.01 --kind loop --mono

# Эффект с явным ослаблением на 3 dB.
node scripts/prepare-audio.mjs --source art/audio/edited/ui.click.01.wav --asset ui.click.01 --kind effect --gain-db -3

# Музыка: Opus 128 kbit/s + AAC .m4a 160 kbit/s как запасной формат.
node scripts/prepare-audio.mjs --source art/audio/edited/music.day.01.wav --asset music.day.01 --kind music
```

`effect` и `loop` ограничены 30 секундами; музыка — 15 минутами. Эффекты и петли декодируются в память, музыка воспроизводится потоково. Практическая цель для окружения — короткие петли 5–20 секунд. При 48 kHz 20 секунд моно после декодирования занимают около 3,84 MB; стерео — вдвое больше. Бюджет кеша общий для всех эффектов, поэтому даже помещающийся по отдельности файл не всегда оставляет достаточно места соседним источникам.

Скрипт **не исправляет стык**, не убирает шум, не нормализует громкость и не оценивает звучание. `--dry-run` проверяет исходный файл через `ffprobe`, но не запускает кодирование. Экспорт использует локальный `ffmpeg` без shell-команд; имена файлов передаются отдельными аргументами. Для замены уже выпущенного файла добавьте новый вариант с новым ID/именем, чтобы избежать старого кеша.

## Подключение принятой записи

После прослушивания замените один существующий слот каталога. Например, для собственной записи с выбранным автором разрешением:

```json
{
  "id": "river.01",
  "src": "/audio/loop/river.01.wav",
  "status": "ready",
  "license": {
    "name": "Название выбранной лицензии или разрешения",
    "url": "https://example.org/license",
    "author": "Имя автора записи",
    "sourceUrl": "art/audio/masters/river.01.wav",
    "acquiredAt": "2026-10-08",
    "changes": "Нарезка, стык петли, моно, экспорт PCM 16 bit 48 kHz",
    "attribution": "Текст указания авторства согласно условиям либо пояснение об отсутствии требования"
  }
}
```

Это **образец полей, не готовое разрешение**: замените данные, включая адрес условий. Для библиотечной записи `sourceUrl` — точный адрес её страницы. Сохраните разрешение рядом с оригиналом. Для Opus/Ogg/WebM требуется `fallbackSrc` с `.m4a`, `.mp3` или `.wav`. Оба файла должны существовать локально в `public/audio/`; внешние URL, обход каталогов и символические ссылки в экспортируемых путях не принимаются.

```bash
npm run audio:check
node --test tests/audio-catalog.test.mjs
```

Проверка читает каталог и файлы без изменений, контролирует ссылки, пределы параметров микшера и полноту сведений об авторстве. Она не декодирует медиа и не подтверждает юридическую действительность лицензии. Финальная проверка файла — прослушивание, стык повторения, относительная громкость в игре, iPhone/PWA и возврат после блокировки экрана.
