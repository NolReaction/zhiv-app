# Engine: ядро, редактор и пример сцены

[Запуск](README.md) · [Управление редактором](../game/engine.md) · [Карта файлов проекта](../repository-guide.md)

Engine состоит из библиотеки Canvas 2D и приложения редактора. Лесная карта — данные и рисунки примера. Такое разделение позволяет использовать рендер в другом браузерном приложении, передав свою сцену и её оформление, и развивать редактор без зависимости от игрового аккаунта.

## Три владельца

| Владелец | Расположение | Что менять здесь |
| --- | --- | --- |
| Ядро | `packages/engine/src/` | Координаты и преобразования, границы предметов, перекрытие, PNG, композиция земли, свет, Canvas-кэши |
| Редактор | `apps/engine/src/editor/` | Документ, проверки импорта, история, жесты, выбор, браузерное сохранение, кнопки и панели |
| Лесной пример | `apps/engine/examples/forest/` | Раскладка реки и троп, исходная растительность, варианты рисунков, каталог предметов и настройки примера |

Например, чтобы изменить рисунок лесного дерева, ищите его описание в примере. Чтобы исправить наложение любых двух предметов, начинайте с ядра. Чтобы добавить поле в инспектор или изменить Undo, нужен редактор. Перенос дома на карте через интерфейс меняет документ пользователя, а не исходную раскладку примера.

Ядро не импортирует React, Next, контроллер редактора, лесной пример, `features/world`, API или аккаунт. Пример описывает содержимое через контракты ядра. Редактор соединяет документ, пример и рендер; страницы-хосты только создают редактор и передают параметры размещения.

В исходниках ядра относительные импорты указывают `.ts`, например `./objects.ts`: так Next/Turbopack и Vite читают существующие исходные файлы. При сборке TypeScript 5.9 с `rewriteRelativeImportExtensions: true` заменяет расширения на `.js` в выходном JS, сохраняя переносимый ESM-пакет. Алиас `@/` соединяет исходники редактора и примера внутри репозитория; потребитель собранной библиотеки импортирует `@zhiv/engine`. Рисунок конкретной игры передавайте через контракт/preset.

`npm run architecture:check` проверяет и этот участок: ядро не выходит за `packages/engine/src`, редактор зависит от своего кода, ядра и собственных примеров, пример — от своих данных и ядра. Запреты учитывают также type-импорты и циклы; Next и продуктовые модули не становятся зависимостью редактора. Основной хост может размещать редактор в своих страницах.

## Что передаётся рендеру

**Сцена** содержит текущие предметы, размер мира, seed, слои, папки, пользовательские PNG, землю и свет. **Preset** описывает, как рисовать и получать исходное содержимое этой сцены. Камера сообщает, какой участок показывать, не меняя мировые координаты.

| Контракт | Смысл |
| --- | --- |
| `EngineObject` | ID, тип из каталога, точка опоры, масштаб, поворот, вариант, слой/папка и состояния предмета |
| `ObjectCatalog` / `ObjectDefinition` | Границы, рисунок, глубина, проверка попадания и условная высота тени для известных типов |
| `EnginePreset` | Каталог, начальные/генерируемые предметы, определение земли и способ её рисования |
| `TerrainDefinition` | Базовое поле земли: вода, тропы и другие параметры; конкретная река не зашита в ядро |
| `CanvasFactory` и загрузчик изображений | Создание рабочих Canvas и чтение PNG средствами хоста |

Preset не хранит выбор, курсор, историю, вкладки или пользователя. Это описание содержимого. Если нужна другая карта, передайте другое определение земли и исходные предметы. Если нужен новый программный предмет, добавьте его в каталог и задайте рисунок/границы. Сами по себе другие имена файлов или перенос папки не меняют карту.

Общее ядро сейчас поддерживает материалы травы, тропы, песка и воды; оформление задаётся `TerrainPainter`. Для нейтрального примера доступны `EMPTY_TERRAIN_DEFINITION` и `SOLID_TERRAIN_PAINTER`. Это позволяет проверить свой каталог без подключения лесной реки, троп или рисунков.

Ядро принимает размеры сцены как данные. Лимиты общего контракта — до 8192 по каждой стороне и до 64 млн пикселей; они не означают, что редактор уже предлагает все эти размеры или что телефон выдержит такую сцену. Лесной документ сохраняет прежнюю карту 1600→2400→3200×1600.

## Публичный API

После `npm run build:engine` браузерный потребитель импортирует библиотеку через `@zhiv/engine`. Публичная точка входа — `packages/engine/src/runtime.ts`; `.js` и `.d.ts` собираются в `packages/engine/dist`. Внутренние пути редактора и примера не являются API npm-пакета.

Основная фабрика — `createScenePainter(makeCanvas, preset, onAssetsChanged?, loadImage?)`. Она получает фабрику Canvas и preset явно. `SceneRenderOptions` описывает текущий кадр: обязательные размеры `width`/`height`, seed и предметные правки, а также PNG, слои, папки, землю и свет. Рамки выбора, курсор и прочие направляющие редактора необязательны.

| Метод результата | Назначение |
| --- | --- |
| `paint(context, viewBounds, options)` | Нарисовать кадр сцены для указанного участка мира |
| `objects(options)` | Получить предметы с учётом исходного содержимого и текущих правок |
| `prepareAssets(assets)` | Подготовить PNG перед использованием |
| `diagnostics()` | Получить диагностические счётчики кэшей и подготовки |
| `dispose()` | Освободить рабочие кэши при уходе со сцены |

В коде хоста, где уже подготовлены Canvas, preset и данные сцены:

```typescript
import { createScenePainter } from "@zhiv/engine";

const painter = createScenePainter(createCanvas, scenePreset, requestRepaint);
painter.paint(context, viewBounds, currentScene);

// При уходе со сцены:
painter.dispose();
```

`requestRepaint` нужен, чтобы хост мог перерисовать кадр после асинхронной подготовки изображения. Изменив камеру или данные, хост вызывает `paint` снова; постоянно работающий цикл библиотека не запускает. Canvas-кэши принадлежат экземпляру painter, а документ и история — его потребителю.

`viewBounds` измеряется в мировых координатах и помогает выбрать видимые предметы/участки. Размер экранного Canvas, DPR и преобразование камеры на `context` устанавливает хост перед вызовом `paint`. Для первого кадра без камеры можно использовать Canvas размером со сцену, единичное преобразование и границы от `(0, 0)` до её ширины/высоты.

При изменении предмета создавайте новую запись и новую коллекцию с этой записью: например, новый объект с изменённым X и новый массив `planted` или `Map` `modified`. Кэши используют ссылки на записи и коллекции. `objectRevision` и `previewRevision` дополнительно обозначают новые версии законченных данных и временного превью; движение камеры не требует новой геометрической версии.

В лесном примере адаптер `createForestPainter` сохраняет прежнюю сигнатуру, связывая общий painter с `DEFAULT_FOREST_PRESET` и высотой 1600. Переключатель лесной растительности превращается в общий `objectFilter`. Имена `ForestScene`/`ForestController` в редакторе сохранены для совместимости текущего документа; они не означают, что публичное ядро импортирует лесную карту.

## Документ и сохранение

`apps/engine/src/editor/scene/editor-scene.ts` владеет JSON v5, чтением v1–v4, ограничениями и историей. `input/controller.ts` переводит жесты в законченные изменения, `controller-autosave.ts` объединяет браузерные записи. Рендер получает текущие данные, но не записывает localStorage и не обращается к серверу.

`ForestControllerOptions` позволяет передать `storage`, `storageKey`, `createCanvas` и загрузчик PNG. По умолчанию используется localStorage текущего origin и ключ `zhiv:prototype:procedural-forest:scene:v1`; `storage: null` отключает браузерное сохранение. `createSceneStorageAdapter(storage, key)` предоставляет чтение/запись конкретного документа. Эти параметры принадлежат редактору, а не библиотеке рендера.

Другое приложение может выбрать собственный ключ хранения. Другое origin не получает доступ к прежнему localStorage: данные переносятся через экспорт/импорт JSON. Автоматического переноса на новый адрес и сетевого хранилища на этом этапе нет. Исходные PNG остаются встроенными data URL, без повторного сжатия при переносе или изменении размера предмета.

Общий рендерный контракт и формат лесного документа — разные границы. Возможность настроить runtime через preset не означает, что старый JSON автоматически понимает произвольные типы предметов новой игры. Для нового формата документа нужны явные правила валидации и миграции.

## Самостоятельный запуск и страницы-хосты

`apps/engine/src/main.tsx` создаёт React-root редактора; Vite собирает workspace `@zhiv/engine-lab` в `apps/engine/dist`. Библиотека `@zhiv/engine` версии 0.1.0 собирается отдельно в `packages/engine/dist`. Оба пакета пока закрытые (`private`), это не публикация в npm.

Компонент `ProceduralForestPreview` принимает параметры размещения: `backLink` или `onBack`, заголовок документа и `sampleImage`. Самостоятельный пример передаёт PNG дома из `/examples/forest/home-level-1.png`. Основной хост может передать свой адрес PNG и ссылку «В приложение»; ядро этих адресов не знает. Стили редактора изолированы и не требуют глобального CSS основной игры.

Основные `/engine` и `/prototype/procedural-forest` размещают общий редактор через тонкие обёртки. Они не создают вторую копию движка или отдельный формат сохранений. На одном origin обе страницы работают с прежним ключом; самостоятельный порт 5174 хранит свою копию.

## Подключить к другому проекту

Начните с отдельной тестовой сцены в браузерном проекте: задайте её размер, каталог предметов, базовую землю и фабрику Canvas. Подключите собранный ESM-пакет, нарисуйте один кадр, затем добавьте камеру и обновление сцены. React-редактор для такого использования не обязателен. Освобождайте кэши при уходе со сцены; они не являются сохранёнными данными карты.

Для основной игры следующим шагом нужен явный адаптер: текущая Tiled-сцена, изображения уровней, персонажи и состояние мира должны преобразовываться в контракты Engine. Перенос файлов редактора этого адаптера не создаёт. Игровой runtime сейчас продолжает использовать существующие модули.

Вход, пароль, права администратора и серверное хранение также подключаются хостом отдельным этапом вместе с `master`. Локальная Vite-сборка — инструмент разработки; она не даёт согласования на публичное размещение и не реализует защиту доступа.
