# Проекты Engine: создание, сохранение и перенос

[Запуск](README.md) · [Управление на карте](../game/engine.md) · [Архитектура](architecture.md) · [Диагностика](diagnostics.md)

Текущий Engine — редактор Canvas 2D с отдельными проектами. У каждого проекта своё имя, размер, шаблон, предметы, земля, свет и PNG. Проекты сохраняются локально в IndexedDB этого браузера; основной игровой аккаунт и сервер в этом не участвуют.

## Создать и организовать проекты

Откройте **Проекты → Новый проект**, заполните **Название проекта**, **Тип сцены**, **Ширину сцены** и **Высоту сцены**, затем нажмите **Создать проект**. Например, создайте «Тест PNG» типа «Пустая сцена» размером 640×480 и загрузите свою картинку клавишей `7`.

Размер задаётся в единицах мира, а не размером окна браузера. Имя содержит 1–100 символов; размеры — целые числа от 1 до 8192 по стороне, произведение не больше 64 млн пикселей. Эти пределы проверяют данные, но не обещают одинаковую скорость на всех устройствах.

| Шаблон | Исходный размер | Содержимое |
| --- | --- | --- |
| **Лес** (`forest-v5`, версия 1) | 1600×1600 | Существующие река, тропы, деревья, кусты, камни и постройки |
| **Пустая сцена** (`empty-v1`, версия 1) | 1024×768 | Свободная рабочая область; можно добавлять ящики, маячки и собственные PNG |

Оба шаблона допускают свои размеры. Палитра и свойства предметов берутся из каталога выбранного шаблона: в пустой сцене нет скрытой генерации леса. Поворот, размер, папки, слои, земля и свет работают через общий редактор.

В **Сохранённых проектах** доступны **Открыть**, **Название → новое название → Применить**, **Копия** и кнопка корзины. Копия получает другой ID и открывается для самостоятельных дальнейших правок. Одинаковые PNG могут использовать общий ресурс в хранилище; изменение предмета в копии не перемещает предмет оригинала.

Корзина показывает подтверждение **Удалить проект / Оставить проект**. Удаление проекта и его неиспользуемых PNG нельзя вернуть через историю правок сцены. Резервную копию сохраняйте через **Скачать текущий JSON** в этом диалоге или **Документ → Скачать сцену**.

При переключении редактор сначала ждёт сохранения текущих законченных правок. Ошибка сохранения оставляет прежний проект открытым. Незаконченный жест не считается сохранённой правкой; отмените или завершите его перед операцией с проектом.

## Почему старый лес остаётся на месте

В JSON v6 поле **`baseObjects`** содержит снимок исходных предметов проекта. Генератор запускается при создании исходного содержимого, а при обычном открытии используется сохранённый снимок. Поэтому изменение генератора в следующем коммите не переставляет деревья уже существующего проекта.

**`presetId` + `presetVersion`** выбирают каталог и оформление, с которыми работает документ. Неизвестный шаблон или его версия отклоняются при открытии; редактор не подменяет их новым лесом. Для смены правил шаблона требуется явная совместимость, а не только похожее имя.

Команда расширения вправо добавляет новый участок, сохраняя прежние записи базы; **Сбросить предметы** возвращает предметы к сохранённой базе. Смена seed/новая расстановка — явное создание нового исходного содержимого, которое сбрасывает предметные правки. Земля, свет, PNG, слои и папки при этом сохраняются. Эти действия можно отменять в текущей истории.

## Два представления одного проекта

| Представление | Что содержит |
| --- | --- |
| Документ в памяти и переносимый JSON v6 | Полную сцену и исходные PNG как `assets[].dataUrl` |
| Запись IndexedDB | Манифест сцены и метаданные PNG со ссылками `resourceKey`; исходные байты PNG находятся отдельно в `Blob` |

IndexedDB использует БД `zhiv:engine:projects`, версию 1 и хранилища `projects`, `resources`, `metadata`. PNG адресуются по SHA-256 исходных байтов. Сохранение положения или имени обновляет манифест, сохраняя уже существующие PNG. Удаление очищает только ресурсы, на которые больше не ссылается ни один проект.

Для хеширования PNG нужен Web Crypto: запускайте редактор через HTTPS или localhost. При недоступном хранилище или хешировании интерфейс сообщает об ошибке; полный JSON остаётся доступным для экспорта.

Манифест и необходимые ресурсы записываются одной транзакцией. В верхней панели **Сохранено** появляется только после завершения записи последней версии документа; **Сохранение…** означает ожидание/запись, **Ошибка сохранения** — отсутствие подтверждения. Нажатие на этот статус запрашивает сохранение или повтор. Если во время записи появилась новая правка, её ещё нужно сохранить; подтверждение старой версии не считается подтверждением новой. Обычные правки объединяются с небольшой задержкой около 250 мс.

Если этот же проект изменён или удалён в другой вкладке, устаревшая запись отклоняется. Сначала экспортируйте свою несохранённую сцену. **Открыть сохранённую версию** показывает выбор: **Скачать резервную копию JSON**, **Заменить текущую сцену** или **Оставить правки**. Замена возвращает сохранённую версию и начинает новую историю; ошибка чтения оставляет текущий документ. Автоматического слияния правок разных вкладок нет.

## Переносимый JSON v6

Формат плоский: свойства проекта и сцены находятся в одном объекте. Например, этот документ описывает пустую сцену без PNG и предметов:

```json
{
  "version": 6,
  "id": "project:example",
  "name": "Рабочая сцена",
  "presetId": "empty-v1",
  "presetVersion": 1,
  "seed": 0,
  "width": 1024,
  "height": 768,
  "baseObjects": [],
  "planted": [],
  "removed": [],
  "modified": [],
  "assets": [],
  "layers": [
    { "id": "world", "name": "Мир", "visible": true, "locked": false }
  ],
  "folders": [],
  "terrain": { "baseTrails": true, "cells": {} },
  "lighting": {
    "enabled": false,
    "ambient": 1,
    "ambientColor": "#ffffff",
    "sunAngle": 135,
    "sunElevation": 45,
    "sunIntensity": 0.4,
    "sunColor": "#fff3d8",
    "shadowOpacity": 0.3,
    "shadowSoftness": 8,
    "points": []
  }
}
```

`planted` — добавленные предметы, `removed` — ID исключённых предметов из `baseObjects`/`planted`, `modified` — новые значения уже существующих предметов с тем же ID и типом. Ссылки на предметы, PNG, слои и папки проверяются; повторные ID, потерянные ссылки и циклы папок отклоняются. Исходные и изменённые предметы не заменяются новой генерацией при импорте.

PNG в переносимом `assets` имеет поля `id`, `name`, `dataUrl`, `width`, `height`. Встроенный `dataUrl` содержит исходные PNG-байты; размер и поворот предмета не пересжимают файл. Внутренний `resourceKey`, БД, время сохранения, история, камера, раскрытие папок и диагностические замеры в переносимый JSON не входят.

Скачанный файл называется `engine-<название проекта>.json`, поэтому переименование проекта меняет имя следующего экспорта. Неподходящие для имени файла символы заменяются, а название сокращается до 64 символов.

Лимит JSON — 32 МиБ. До 25 000 исходных и 5000 добавленных предметов, до 32 слоёв, 128 папок, 20 000 клеток правок земли и 32 местных источников света. Один PNG — до 5 МиБ, 4096 по стороне и 16 млн пикселей; весь проект — до 32 PNG, 16 МиБ их исходных байтов и 32 млн пикселей. Сжатый размер PNG и память декодированной картинки — разные величины. Если экспорт превышает лимит JSON, показывается ошибка и документ остаётся в памяти; уберите лишние ресурсы/предметы и повторите экспорт.

## Старые сцены v1–v5

Старый формат лесной сцены остаётся поддерживаемым: seed, ширина, предметные правки, PNG, слои, папки, земля и свет читаются прежним валидатором и миграциями. Его высота фиксирована — 1600; новые метаданные проекта и `baseObjects` в нём отсутствуют. [Описание прежнего формата](../game/procedural-forest-test.md#прежний-формат-v1v5).

При импорте v1–v5 создаётся документ v6 с шаблоном `forest-v5`, версией 1 и снимком прежнего исходного леса. Все прежние правки и PNG сохраняются; историческое исключение — удаление программного дома-пня из v1. После этого **Скачать сцену** экспортирует v6.

На том же origin прежний localStorage `zhiv:prototype:procedural-forest:scene:v1` читается для **однократного переноса** в проекты. Проект и метка `legacy:<старый-ключ>` записываются одной транзакцией. При ошибке/квоте/отмене транзакции метка не появляется и исходная сцена остаётся. После успеха старый JSON также не удаляется; метка предотвращает повторное создание проекта, даже если перенесённый проект затем удалить.

Это перенос старого browser-сохранения в новую БД, а не ежедневная синхронизация старого localStorage с проектом. Если БД недоступна при первом переносе, проверенная старая сцена остаётся доступной в памяти для редактирования и экспорта. Исходный JSON можно также импортировать вручную.

## Если сохранение недоступно

При отказе IndexedDB, заполнении квоты или блокировке другой вкладкой сцена остаётся в памяти для редактирования и экспорта. Предупреждение означает, что текущая работа ещё не подтверждена хранилищем. В **Проектах** нажмите **Скачать текущий JSON**, затем **Повторить сохранение**; при сообщении о занятом хранилище закройте старую вкладку редактора.

Перед закрытием страницы ждите **Сохранено** или скачайте JSON. Браузер может показать предупреждение о несохранённой работе, но асинхронная запись во время закрытия/pagehide не гарантирует её сохранность. Очистка данных сайта удаляет локальные проекты; отдельный JSON позволяет восстановить работу.

## Перенос между адресами

Origin определяется протоколом, именем хоста и портом. `localhost:3000`, `localhost:5174`, `localhost:4174` и `127.0.0.1:5174` имеют разные хранилища. На каждом origin свои проекты и своя метка миграции.

Чтобы перенести работу, на исходном адресе нажмите **Скачать сцену**, а на новом — **Открыть сцену** или **Проекты → Импортировать JSON как новый**. Импорт создаёт отдельный проект с новым ID, сохраняя содержимое файла; существующая работа не подменяется тем же ID. JSON включает PNG, поэтому отдельная папка картинок не требуется. Автоматической синхронизации между браузерами, устройствами и сервером сейчас нет.

Перед созданием импортированного проекта все PNG последовательно проходят полную проверку контрольных сумм CRC и растровых данных. Ошибка любого изображения или отмена импорта сохраняет прежний документ и не создаёт новый проект.
