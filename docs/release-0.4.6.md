# 0.4.6 — статус, приватность и личный код

## Изменения

- Общий тумблер людей и групп; исправлено сложение CSS translate/transform.
- Последняя серверная отметка остаётся на экране во время любой серии нажатий.
- Личный статус до 120 Unicode-символов: создание, изменение, очистка. Статус не создаёт отметку и не меняет счётчики.
- Один доступ от отправителя к получателю независимо от числа личных связей/групп. Группа меняет доступ всем своим текущим участникам; отдельный человек — только себе. При различающихся настройках группа показывает «Часть участников». Другие участники не получают доступ автоматически.
- После повторного включения доступны только новые отметки и новые изменения статуса.
- Сюжетные тексты удалены. Нажатия, уровни, серии и эффекты сохранены. Старые поля формата v3/идентификаторы событий читаются только для совместимости.
- Восстановление через друзей удалено из приложения и API; старые запросы отменяет миграция V12. Применённые миграции V1–V9 не изменяются.

## Личный код восстановления

«Профиль → Код восстановления → Создать код». Пользователь сохраняет случайный 256-битный код вне приложения, подтверждает сохранение и активирует его. Прежний код при замене перестаёт действовать.

На новом устройстве — «У меня уже есть код восстановления». После успешного восстановления все прежние сессии данного профиля отзываются. Данные другого случайно созданного профиля не смешиваются и не удаляются. Использованный код нельзя активировать снова; приложение предлагает создать новый.

Сервер хранит только SHA-256 с разделением назначений для кода. Код не попадает в URL, журналы, localStorage или service worker. Повтор потерянного HTTP-ответа в течение 10 минут возвращает ту же сессию только с тем же случайным секретом запроса; другая попытка код повторно не использует. Отозванную сессию повтор не оживляет.

Без сохранённого кода и без открытой сессии вернуть профиль нельзя. Поддержка/друг не могут обойти это правило.

## Подготовка к тестовому серверу

См. [test-server-0.4.6.md](test-server-0.4.6.md). Это подготовка репозитория, не аренда или развёртывание Selectel.

Нужны HTTPS и один постоянный домен. PWA и разные браузеры могут хранить разные сессии; код даёт явный вход, но не объединяет браузерные хранилища. Вход по коду — восстановление с отзывом прежних сессий, а не добавление второго устройства.

## Границы проверки безопасности

Проверяются собственный код и изолированные тестовые данные: авторизация, Origin/CSRF, одноразовость, гонки восстановления, приватность, старые периоды доступа, валидация статуса и секреты в окружении. Это не полноценный независимый пентест и не обещание отсутствия всех уязвимостей.

Production-процесс не использует dev API, не получает административный пароль БД, не выполняет миграции, работает не от root; БД и API не публикуют порты наружу. Коды и cookies не записываются в журналы. Обновлены Next/React и production-транзитивные зависимости.

Инструменты разработки Sites/Drizzle имеют отдельные замечания npm audit; они не входят в standalone runtime VPS. Не открывайте dev-сервер/инструменты миграции в интернет.
