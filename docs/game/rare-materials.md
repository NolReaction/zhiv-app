# Реликвии для поздних улучшений

[Экономика](economy-foundation.md) · [Математика](economy-mathematics.md) · [Общий каталог](../../apps/api/src/main/resources/world/economy-catalog.json)

В каталоге экономики v15 реализованы три особых материала. Случайные находки в вылазках открываются после получения дома 3; древнее ядро седьмого подарка одноразовой цепочки доступно и раньше. Первые два улучшения дома обходятся обычными ресурсами.

| Материал | Применение сейчас |
| --- | --- |
| Живая смола (`living_resin`) | 1 для дома 4; суммарно 3 для кладовой 4–10 |
| Древнее ядро (`ancient_core`) | 1 для дома 5; суммарно 6 для кладовой 4–10 |
| Лунный кристалл (`moon_crystal`) | 1 для дома 5; суммарно 3 для кладовой 4–10 |

Кладовая имеет десять уровней. Уровни 2 и 3 требуют дом 2 и 3 соответственно; уровни 4–6 — дом 4, уровни 7–10 — дом 5 и указанные в каталоге производства. Предыдущий уровень, материалы, монеты и свободный строитель нужны по-прежнему. Уровни 4–10 вместе требуют 12 реликвий, обычные изделия и 273 000 монет. Вместимость растёт по 50, от 50 до 500; затраты и таймеры по уровням — в [таблице расширений](rewards-and-relics.md#десять-уровней-кладовой). Расширения дают удобство и не входят в обязательные условия улучшения дома или производств.

Одна реликвия занимает одну единицу общей кладовой, включая выставленное на обмен имущество. `category: special`, `baseSellPrice: 0`, `tradable: false` запрещают обычную денежную продажу: реликвии нельзя продать местному покупателю или выставить за монеты. Их источники и способы обмена:

- Подтверждённые исследования Мохлика и шахтёра после дома 3.
- Последняя проектная поставка дома 3 гарантирует одну смолу для дома 4; проект дома 4 — одно ядро и один кристалл для дома 5. Это одноразовые гарантии, независимые от случайных находок.
- Седьмой подарок даёт одно ядро за всю одноразовую цепочку аккаунта. Восьмого подарка и повторяемого подарочного источника нет.
- Листохвост с дома 3 продаёт один или два вида в личной дневной поставке, по одной штуке за 150 видимых жемчужин. Повторное открытие лавки не меняет поставку.
- С дома 4 Листохвост меняет две одинаковые реликвии и 20 000 монет на одну выбранную другого вида. Дневного лимита нет; каждый обмен уменьшает число находок на одну. Счётчики случайной добычи, поставка и репутация не меняются. [Условия и серверные проверки](economy-v15-relic-exchange.md).
- Обмен между игроками даёт одну реликвию за другую с дома 3 и восстановленного моста. Для каждого участника действует предел одного завершённого обмена в сутки UTC; дом 3 обменивается с домом 3, дома 4–5 — между собой. [Витрина и резерв](rewards-and-relics.md#обмен).

Достижения, обычное производство и декоративные анимации реликвий не создают. Плёска их не продаёт.

Мост доступен для восстановления с дома 2 и после получения результата открывает рынок игроков. Маяк доступен с дома 3; после его получения запускается [первое прибытие парохода](trade-ship-prototype.md#первое-прибытие-в-игре). Торговые заказы и награды корабля пока не подключены. Для домов 3 и 4 эти объекты добровольны, а перед улучшением дома до уровня 5 нужно получить оба восстановления. Их текущие стройки не требуют реликвий. [Условия позднего этапа](fourth-house-economy.md).

## Время и случайность

У профиля есть два независимых закрытых счётчика подтверждённых часов: `rareDropState` для Мохлика и `minerRareDropState` для шахты. Сервер равномерно выбирает целое число секунд от 48 до 144 часов включительно и независимо один из трёх типов с вероятностью `1/3`. Средний интервал каждого потока равен 96 часам. Счётчик Мохлика общий для его маршрутов, включая рыбалку со снастями; у шахты отдельный поток с теми же интервалами. Дорогой или короткий маршрут не даёт отдельного броска. До дома 3 часы не накапливаются.

Задания с `activity: "mining"` сохраняют `actorId: "miner"` и идут одновременно с походом или рыбалкой Мохлика. Их подтверждённые часы относятся только к счётчику шахты. Для обоих потоков право начинается с дома 3: второй этап на доме 2 не накапливает часы реликвий. Старые задания без `actorId` остаются работами Мохлика и используют его прежний поток; старые production-задания получают только сохранённые награды. [Правила независимой шахты](second-house-economy.md#шахта-работает-независимо-от-мохлика).

При успешном **старте** сервер сохраняет результат в уже оплаченном задании: обычные `rewards` и необязательный `rareDrop` с длительностью и выбранным предметом. При **получении** списывается только сохранённая длительность этого задания, включая применённое при старте ускорение. Простой после таймера не учитывается. Отмена, повтор команды, ошибка вместимости или чужой запрос не двигают счётчик и не перевыбирают предмет. После выдачи следующий случайный интервал уменьшается на перерасход предыдущей поездки. Длительность каждой действующей вылазки меньше минимального интервала, поэтому в одной поездке не бывает более одной реликвии.

48–144 часа — границы внутреннего порога, а не обещание точной даты получения. Результат выдаётся после завершения пересёкшей порог работы и ручного получения. Среди текущих доступных маршрутов самая длинная работа Мохлика занимает час, шахтёра — 20 минут; старые уже оплаченные маршруты сохраняют свои сроки. Если готовый результат долго не забирать, календарная задержка не ограничена этими длительностями.

Для одного определённого вида в одном потоке ожидание порога равно `96 × 3 = 288` часам исследований; для полного набора трёх видов — `96 × 3 × (1 + 1/2 + 1/3) = 528` часам. Срок конкретного вида сверху не ограничен: могут повторяться другие виды. Эти ожидания не складываются как три независимые производственные стоимости. Деление на суммарное время двух потоков даёт лишь ориентир пропускной способности, а не точную дату от нового профиля: начальные пороги и границы получений независимы. Обмен позволяет использовать повторы; монетная цена из этих часов не выводится. Календарное прохождение оценивается [отдельными сценариями v15](economy-v15-final-simulation.md) с посещениями, запасами, стройками и выбранной стратегией.

## Сохранения и защита

`rareDropState` и `minerRareDropState` хранятся только в серверном состоянии JSONB/DEV и не входят в `EconomyView`; клиент не выбирает ни начальный счётчик, ни RNG. Для DEV используется `node:crypto.randomInt`, для Kotlin — `SecureRandom`. `requestId` служит идемпотентности и не влияет на выпадение. Старые задания без `rareDrop` завершаются по записанным наградам и не получают задним числом часы или реликвии; уже оплаченные стройки завершаются по сохранённым затратам и условиям.

Объединение профилей сначала требует завершить или отменить их задания. Для каждого работника отдельно из счётчиков двух аккаунтов сохраняется **больший остаток вместе с его типом**; при равенстве — целевой профиль. Один существующий счётчик сохраняется без изменений. Часы не складываются, порог не приближается, новый случайный результат не создаётся. Это консервативное правило может отбросить часть частичного прогресса, но не позволяет выбирать ближайшее выпадение объединением аккаунтов.

Новые поля необязательны для старых сохранений; новая миграция для самих реликвий и обмена 2:1 не требуется. Сервер и клиент с новым каталогом выпускаются вместе; откат старого строгого декодера на состояния с новыми полями требует отдельного плана совместимости.
