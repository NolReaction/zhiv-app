# Реликвии для поздних улучшений

[Экономика](economy-foundation.md) · [Математика](economy-mathematics.md) · [Общий каталог](../../apps/api/src/main/resources/world/economy-catalog.json)

Реализованы три особых материала. Они появляются после получения дома 3; первые два улучшения дома обходятся обычными ресурсами.

| Материал | Применение сейчас |
| --- | --- |
| Живая смола (`living_resin`) | 1 для дома 4 и 1 для кладовой 3 |
| Древнее ядро (`ancient_core`) | 1 для дома 5 и 1 для кладовой 4 |
| Лунный кристалл (`moon_crystal`) | 1 для дома 5 и 1 для кладовой 5 |

Одна реликвия занимает одну единицу общей кладовой, включая выставленное на обмен имущество. `category: special`, `baseSellPrice: 0`, `tradable: false` означают отсутствие обычной денежной продажи. Реликвии нельзя купить у Плёски, продать местному покупателю или выставить за монеты. Получение — подтверждённые исследования, древнее ядро в каждом седьмом подарке за вход и обмен реликвиями между игроками. Достижения, производство и декоративные анимации их не создают. Мост, маяк и ограниченный торговец за жемчуг остаются будущими задачами, без включённых сейчас требований или магазина.

## Время и случайность

У профиля есть один закрытый счётчик подтверждённых часов исследований. Сервер равномерно выбирает целое число секунд от 48 до 144 часов включительно и независимо один из трёх типов с вероятностью `1/3`. Средний интервал равен 96 часам работы Мохлика. Счётчик общий для всех маршрутов, включая рыбалку со снастями; дорогой или короткий маршрут не даёт отдельного броска. До дома 3 часы не накапливаются.

С 2026-10-06 новая добыча в шахте запускается как занятие Мохлика и тоже пополняет этот счётчик после успешного получения. Одновременно добывать и идти в другой поход нельзя. Старые производственные задания каменоломни завершаются по сохранённым наградам: часы и реликвии к ним задним числом не добавляются. Сценарии до объединения шахты сохранены как история; их поток находок нельзя переносить на новые правила.

При успешном **старте** сервер сохраняет результат в уже оплаченном задании: обычные `rewards` и необязательный `rareDrop` с длительностью и выбранным предметом. При **получении** списывается только сохранённая длительность этого задания. Простой после таймера не учитывается. Отмена, повтор команды, ошибка вместимости или чужой запрос не двигают счётчик и не перевыбирают предмет. После выдачи следующий случайный интервал уменьшается на перерасход предыдущей поездки. Самый длинный маршрут сейчас 16 часов, меньше минимального интервала, поэтому в одной поездке не бывает более одной реликвии.

48–144 часа — границы внутреннего порога, а не обещание точной даты получения: результат выдаётся после окончания пересёкшей порог поездки, максимум ещё через её 16 часов. Для одного определённого вида ожидание порога равно `96 × 3 = 288` часам исследований; для полного набора трёх видов — `96 × 3 × (1 + 1/2 + 1/3) = 528` часам. Срок конкретного вида сверху не ограничен: могут повторяться другие виды. Эти ожидания относятся к общему потоку находок и не складываются как три независимые производственные стоимости. Обмен позволяет использовать повторы; монетная цена из этих часов не выводится. Реальная календарная прокачка оценивается отдельной симуляцией с посещениями, запасами, стройками и часами исследований.

## Сохранения и защита

`rareDropState` хранится только в серверном состоянии JSONB/DEV и не входит в `EconomyView`; клиент не выбирает ни начальный счётчик, ни RNG. Для DEV используется `node:crypto.randomInt`, для Kotlin — `SecureRandom`. `requestId` служит идемпотентности и не влияет на выпадение. Старые задания без `rareDrop` завершаются по записанным наградам и не получают задним числом часы или реликвии; уже оплаченные стройки не требуют новых материалов.

Объединение профилей сначала требует завершить или отменить их задания. Из двух закрытых счётчиков сохраняется **больший остаток вместе с его типом**; при равенстве — целевой профиль. Один существующий счётчик сохраняется без изменений. Часы не складываются, порог не приближается, новый случайный результат не создаётся. Это консервативное правило может отбросить часть частичного прогресса, но не позволяет выбирать ближайшее выпадение объединением аккаунтов.

Новые поля необязательны для старых сохранений; новая миграция для самих реликвий не требуется. Сервер и клиент с новым каталогом выпускаются вместе; откат старого строгого декодера на состояния с новыми полями требует отдельного плана совместимости.
