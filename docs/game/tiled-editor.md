# Карта Мохлика в Tiled

[Навигация по документации](../README.md) · [Устройство мира](world-foundation.md) · [Освещение](world-lighting.md) · [Погода и живность](world-atmosphere.md)

Исходник сцены — `world/tiled/forest.tmj`, проект редактора — `world/tiled/forest.tiled-project`. Геометрия мира хранится в Tiled; приложение получает проверенный файл `features/world/tiled/forest.generated.json`. Этот файл генерируется автоматически.

В Tiled уже размечены фон, дом первого уровня с входом и контурами, область круглой камеры `clearing-focus`, положение/размер Мохлика, вода с исключениями и источники света. Маршрутов пока нет; игровые улучшения и новые путешествия временно отключены. Размер рабочей области — 1254 × 1254 логических единиц; полное изображение — 2560 × 2560 пикселей. Размер клетки 1 × 1 служит единицей измерения, раскладывать рисунок по клеткам не требуется. Координаты и размеры объектов вводите в единицах мира 1254 × 1254, а не в пикселях исходного рисунка.

Редактируемый PNG — `art/world/prototype/forest-ground.png`. Команда `node scripts/prepare-world-assets.mjs` экспортирует его целиком в `public/world/prototype/forest-ground.webp` без потерь и уменьшения. Затем выполните `npm run world:export` и `npm run world:check`. Круглая камера использует тот же файл. [Каталог и порядок редактирования](../../art/README.md).

`world:export` читает готовые изображения, обновляет размеры файлов в Tiled и версии URL в данных сцены. `world:watch` автоматически переносит сохранённую разметку в приложение; исходный `.tmj` он не переписывает. Обе команды оставляют неизменный сгенерированный файл без повторной записи. PNG и WebP они не меняют и не сжимают. `world:check` проверяет соответствие без записи файлов.

## Открыть и проверить

1. Установите [Tiled](https://www.mapeditor.org/). Нативная проверка выполняется в Tiled 1.12.2.
2. Откройте `world/tiled/forest.tiled-project`, затем `forest.tmj` из дерева проекта. Файлы изображений должны оставаться в `public/world/prototype/`. В панели набора изображений уменьшите масштаб, если крупный фон занимает всю панель.
3. При необходимости отключите показ сетки и заблокируйте фон замком у слоя **Terrain**, чтобы случайно его не сдвинуть. Для перемещения используйте инструмент **Select Objects** (`S`). Изображения вставляются инструментом **Insert Tile** (`T`), точки — `I`, полигоны — `P`, редактирование вершин — `E`. Удерживание `Ctrl` переключает привязку к сетке. [Инструменты Tiled](https://doc.mapeditor.org/en/stable/manual/objects/).
4. Сохраните карту. Из корня репозитория запустите наблюдение в отдельном терминале:

   ```bash
   npm run world:watch
   ```

   Во втором терминале запустите приложение:

   ```bash
   npm run dev:local
   ```

5. Откройте `/prototype/tiled-world` и основной экран мира. Измените объект в Tiled, нажмите **Save** и дождитесь сообщения `Exported` в первом терминале. Dev-сервер подхватит JSON через HMR. При обычном сохранении одинаковых данных появится `output unchanged`. Проверьте общий вид, положение и размер Мохлика, круглый вид поляны и её рамку в режиме разметки.
6. Перед коммитом выполните `npm run world:check`. Вместе с исходником сохраняйте обновлённый `forest.generated.json` и изменённые изображения. Остановить наблюдение можно через `Ctrl+C`.

Наблюдение сразу проверяет карту, затем ждёт сохранений, включая сохранение Tiled через временный файл и переименование. Если карта содержит ошибку, терминал показывает её место, приложение продолжает использовать последний корректный экспорт. Исправьте карту и сохраните снова: наблюдение восстановится без перезапуска. Комбинация `--watch --check` не поддерживается.

Для основного `forest.generated.json` обязательна точка `role: spawn`: её удаление вызывает ошибку и сохраняет последний корректный экспорт приложения.

Для разового переноса достаточно `npm run world:export`. После изменения самого изображения вручную экспортируйте WebP и выполните эту команду; наблюдение отслеживает только `.tmj`, а метаданные изображений не обновляет. Если экспорт обновил размеры набора, заново откройте карту в Tiled перед дальнейшим редактированием.

Временный файл `*.tiled-session` хранит открытые вкладки и состояние редактора; в Git он не нужен. [Проекты и сессии Tiled](https://doc.mapeditor.org/en/stable/manual/projects/).

## Слои и свойства

Слои фона, зданий, камеры, персонажа и маршрутов — **Object Layer**, порядок рисования — **Manual** (`draworder: index`). Их имена можно менять: назначение определяется пользовательским свойством `role`. Исключения — именованные `Water`, `WaterExclusions` и `Lights`: назначение определяется именем слоя/группы, внутри разрешены вложенные группы (см. ниже). Фоновые объекты должны предшествовать зданиям. Перед сохранением для экспорта включите видимость всех слоёв и объектов; непрозрачность должна быть 100%.

Дом использует `site` и связанные маркеры; фон, круг и персонаж — `terrain`, `focus` и `spawn`. Пустые списки зданий и маршрутов допустимы. Роли ниже описывают поддерживаемый контракт, а не список автоматически создаваемых объектов.

| Объект | Форма | Свойства |
| --- | --- | --- |
| Фон | Изображение из набора | `role: terrain` |
| Постоянное место здания | Одно изображение | `role: site`, `siteId`, `label`, `initialLevel` |
| Точка опоры | Точка | `role: anchor`, `siteId` |
| Вход | Точка | `role: entry`, `siteId` |
| Совместимый маркер фонаря здания | Точка, необязательная | `role: light`, `siteId`; для новых источников используйте `Lights` |
| Область нажатия | Замкнутый полигон | `role: hitArea`, `siteId` |
| Геометрия препятствия | Замкнутый полигон | `role: collision`, `siteId` |
| Область круглой камеры | Один квадратный прямоугольник | `role: focus` |
| Положение и размер Мохлика | Одна точка | `role: spawn`, `size` (текущее значение 56) |
| Маршрут | Незамкнутая линия | `role: path`; имя объекта — ID маршрута; `siteId` необязателен |

Тип всех перечисленных свойств — **string**, кроме `initialLevel` (**int**) и `size` (**float**; экспортёр также принимает **int**). В свойствах карты задано `worldId: forest` типа **string**. Идентификаторы пишутся латиницей в нижнем регистре; допустимы цифры, дефис и подчёркивание. Для каждого здания обязательны ровно одна точка опоры, один вход и по одному полигону `hitArea` и `collision`. Полигоны должны быть простыми: без самопересечений, повторных вершин и прохода назад по уже проведённому ребру.

Координаты изображений обозначают верхний левый угол: у встроенного набора **Forest image collection** значение **Object Alignment** должно оставаться **Top Left**. Это существенно: стандартное выравнивание Tiled для ортогональной карты другое. Вершины полигона хранятся относительно его собственной позиции; экспортёр переводит их в общие координаты мира. [Формат JSON](https://doc.mapeditor.org/en/stable/reference/json-map-format/).

## Вода и исключения

Границы эффектов реки задаются только в `forest.tmj`. Отдельной водной маски в коде и привязки к версии изображения нет. Цвет и форма дождевых кругов сохранены; узкие места могут получать уменьшенные круги. Каждый участок воды имеет собственные потоки попаданий: после затухания точка меняется, внутри одной анимации остаётся неподвижной. Полный размер всплеска проверяется по точным контурам один раз при подготовке сцены, поэтому подробные листья не требуют повторной обрезки каждого штриха.

| Слой или группа | Содержимое | Значение |
| --- | --- | --- |
| `Water` | Замкнутые полигоны, например `river-main` | Поверхность воды |
| `WaterExclusions` | Замкнутые полигоны или вложенные объектные слои `Leaves`, `Leaves-groups`, `Rocks`, `Bushes` | Участки без водных эффектов |

Оба имени чувствительны к регистру. `Water` и `WaterExclusions` могут быть обычными объектными слоями либо группами с вложенными группами и объектными слоями; друг в друга их вкладывать нельзя. Имена вложенных слоёв нужны для организации. Свойство `role` не нужно. Для водных объектных слоёв подходят и **Top Down**, и **Manual**.

Имя полигона — уникальный ID внутри поверхности или исключений (`river-main`, `leaf-1`, `rock-1`); допустимы строчные латинские буквы, цифры, дефис и подчёркивание. Для безымянного объекта экспортёр использует его числовой ID из Tiled. Не меняйте смещение/параллакс групп и не вращайте объекты; перед экспортом включите видимость и полную непрозрачность.

Перекрывающиеся водные полигоны объединяются. Исключения вычитаются независимо от направления обхода и могут перекрываться между собой или частично выходить на берег — их пересечение тоже остаётся сухим. Самопересечения одного полигона, повторные вершины и выход за границы карты проверка отклоняет. Уже обойдённые основным контуром берег и причал повторно исключать не нужно.

При `npm run world:watch` сохранение контуров обновляет `forest.generated.json` и эффекты в игре. Для разового обновления — `npm run world:export`, затем `npm run world:check`. Для проверки включите дождь/ливень и день/ночь в DEV большой карты. Если водных поверхностей в разметке нет, речные эффекты не рисуются; дождь в воздухе и лужи работают как раньше. При изменении рисунка берега или перемещении фонового изображения сверяйте и переносите водные контуры в Tiled вместе с ним.

## Ночь и источники света

В **Lights** уже стоят домашний фонарь и три факела. Для нового источника дублируйте Point, дайте уникальное имя и поставьте точку в центр лампы/пламени. `kind` выбирает `lantern`, `torch` или `glow`; `radius`, `intensity`, `color`, `flicker` управляют светом. `role` не нужен. Сохраните при запущенном `world:watch` и проверьте **DEV → Ночь**.

[Полная инструкция по освещению](world-lighting.md): типы свойств, ограничения, добавление источника с нуля, привязка к дому, расположение кода и проверка. Свет рассчитывает приложение; Tiled показывает точки. При перемещении дома переносите `home-lantern` отдельно вместе с его маркерами.

## Поляна, Мохлик и маршруты

Выделите `clearing-focus` и меняйте его **X**, **Y**, **Width**, **Height**. Это рамка настоящей круглой камеры: центр круга совпадает с центром прямоугольника, а диаметр — с его стороной. Ширина и высота должны быть равны; текущий размер — 300 × 300. Углы рамки в круг не попадают. Передвигайте рамку, чтобы выбрать участок поляны; уменьшение стороны приближает рисунок в круге. Весь квадрат должен оставаться внутри карты. Сохранение меняет и прототип, и круглый вид в приложении.

Выделите точку Мохлика с `role: spawn` и переместите её инструментом **Select Objects**. Точка находится под ногами героя. Свойство `size` типа **float** (допустим и **int**) задаёт размер героя в единицах мира; в текущей карте — `56`. Увеличение `size` увеличивает только Мохлика, сохраняя точку под ногами; масштаб карты не меняется. Это свойство точки, а не ширина и высота объекта: точка остаётся точкой. Изменения положения и размера применяются к Мохлику в прототипе и основном мире; отдельный PNG героя для этого не нужен.

### Короткие прогулки возле дома

В объектном слое **Routes** уже есть три заготовки. Они начинаются у `mochlik-spawn`; Мохлик идёт по линии, выполняет действие на последней точке и возвращается тем же путём. Путешествия в другие части карты этим не включаются.

| Объект | Конечная точка X, Y | Действие | Пауза |
| --- | --- | --- | --- |
| `clearing-look` | 578, 644 | Осмотреться | 5 с |
| `clearing-sniff` | 558, 676 | Обнюхать траву | 4 с |
| `clearing-rest` | 632, 704 | Отдохнуть | 7 с |

**Как поправить готовую линию:**

1. Откройте `world/tiled/forest.tmj`, выберите **Routes**, затем нужный объект по имени в списке объектов.
2. Нажмите **E — Edit Polygons**. Перетаскивайте вершины, по которым должны проходить **ноги** Мохлика. Двойной щелчок по отрезку добавляет вершину для плавного обхода. Не переносите всю линию вместо отдельной вершины.
3. Первую вершину оставьте на `mochlik-spawn` — сейчас это X `598.491243496739`, Y `690.043232944969`. Программа допускает погрешность до одной единицы и совмещает начало с точкой героя. Если переносите самого героя, перенесите начала всех его маршрутов.
4. В **Properties → Custom Properties** меняйте конечное действие и время по таблице ниже. Имя объекта — уникальное, латиницей, например `clearing-groom`; `role` и `behavior` оставьте прежними.
5. Сохраните карту. В отдельном терминале должен работать `npm run world:watch`; для разовой проверки выполните `npm run world:export`, затем `npm run world:check`.
6. Проверьте поляну в круге главного экрана и на большой карте: движение, остановку, возврат, день и ночь. В `/prototype/tiled-world` можно выбрать линию и проверить её геометрию; живое чередование прогулок и действий смотрите в основном приложении.

| Свойство объекта | Тип в Tiled | Значение |
| --- | --- | --- |
| `role` | string | `path` |
| `behavior` | string | `clearing` — включает прогулку в основной игре |
| `activity` | string | `look` — осмотреться; `sniff` — обнюхать; `groom` — привести себя в порядок; `rest` — отдохнуть |
| `pauseSeconds` | float или int | От 2 до 20 секунд на последней точке |

`activity` и `pauseSeconds` необязательны, но работают только при `behavior: clearing`. Без `activity` герой осматривается; без `pauseSeconds` длительность слегка меняется между повторами, а отдых ночью длиннее. Для предсказуемой ручной настройки задавайте оба свойства. Не добавляйте `speed`, `loop` и произвольные свойства: экспортёр их отклонит. `siteId` нужен только для связи с уже размеченным зданием, домашним прогулкам он не требуется.

**Для новой линии** проще продублировать готовый маршрут, дать другое имя и поправить вершины. С нуля: выберите **Insert Polygon** (`P`), начните в точке героя, поставьте ещё 1–3 вершины и закончите **Enter**, не замыкая контур. Добавьте свойства из таблицы. Инструменты и клавиши описаны в [руководстве Tiled](https://doc.mapeditor.org/en/stable/manual/objects/#edit-polygons).

**Границы прогулок:** держите все отрезки на свободной траве возле дома. Текущий предельный радиус от точки героя — `89.6` единицы мира (`min(focus.width × 0.3, actor.size × 1.6)`). Герой целиком должен помещаться в круге; линии не должны пересекать коллизии зданий или воду. Рисованные кусты и камни без отдельной коллизии программа не распознаёт — обходите их вручную и оставляйте место для тела, не только для ног. Небезопасные линии игра пропускает; если подходящих нет, Мохлик выполняет действия у точки появления. Длинные маршруты в открытый мир пока не настраивайте.

Если линия не используется, откройте **DEV → Лесные сценки → Маршруты полянки**: там показаны готовые линии и причина, по которой остальные пропущены. Для прогулок включите «Автоматические сценки», снимите паузу и выберите «Обычное поведение» в списке поз.

Tiled показывает координаты логической карты `1254 × 1254`; пересчитывать их в пиксели исходного рисунка не нужно. В JSON вершины записаны относительно X/Y объекта — редактор делает это сам. Источник линий — `forest.tmj`, экспорт и проверка свойств — `scripts/lib/tiled-world.mjs`, поведение — `features/world/clearing-activity.ts`. `forest.generated.json` вручную не меняйте.

Обычный `role: path` **без** `behavior: clearing` остаётся линией для прототипа/будущей игровой логики и не запускает домашнюю прогулку. Строительство, создание вещей и новые путешествия остаются отключены.

## Переместить здание после новой разметки

Выделите его изображение и все связанные маркеры с тем же `siteId`, затем переместите их вместе. Источники в `Lights` не имеют `siteId`: также перенесите соответствующий фонарь вручную. Отдельно подправьте подходящий маршрут. Проверьте прямоугольник `clearing-focus`, если место должно попадать в круглый вид. Все точки и границы должны оставаться внутри карты.

Масштаб изображения меняйте пропорционально. Например, удвоение размера исходного изображения не требует удвоения рамки здания в мире. Ширина и высота спрайта, точка опоры, вход и контуры относятся ко всему зданию, а не к отдельному уровню. После перемещения проверьте каждый вариант улучшения.

Если изображение здания включает непрозрачную землю, для переноса нужно вручную согласовать её края с новым окружением и при необходимости изменить `forest-ground.png`. Перемещение в Tiled само по себе эту художественную работу не выполняет.

## Изменить или добавить уровень на следующем этапе

Для нового здания нужны совместимые рисунки и новая разметка. На карте должно размещаться одно изображение каждого здания; остальные варианты хранятся в наборе, их не нужно накладывать друг на друга на сцене. Переключать подготовленные уровни для проверки можно через DEV; подключение игрового прогресса — отдельный этап.

1. Измените нужный PNG в `art/world/prototype/`. Для нового уровня добавьте отдельный PNG с понятным именем, например `home-level-4.png`. Для всех вариантов одного здания сохраняйте пропорции холста, масштаб деталей, основание, вход и положение света. Самостоятельно экспортируйте целое изображение в одноимённый WebP в `public/world/prototype/`.
2. Откройте редактирование встроенного **Forest image collection**. Для нового варианта добавьте WebP и задайте свойства плитки: `role: siteState` (**string**), `siteId` (**string**), `level` (**int**) и `label` (**string**). Номер уровня в пределах здания должен быть уникальным. При обновлении существующего файла его ссылка в наборе остаётся прежней.
3. Чтобы посмотреть вариант в редакторе, выделите размещённое изображение здания; в наборе щёлкните нужный вариант правой кнопкой и выберите **Replace Tile of Selected Objects**. Проверьте, что позиция и размеры объекта сохранились.
4. Начальный уровень приложения задаёт свойство `initialLevel` размещённого объекта. Выбранная для просмотра плитка в Tiled сама по себе его не меняет. Значение должно соответствовать существующему уровню каталога.
5. Сохраните карту, выполните `npm run world:export` и `npm run world:check`, затем проверьте все уровни в браузере. В Git сохраните PNG, WebP, `world/tiled/forest.tmj` и `features/world/tiled/forest.generated.json`.

Можно пропорционально увеличить разрешение PNG и WebP: здание сохранит размер в координатах мира. `world:export` обновит метаданные изображения, сохранив рамку размещённого объекта. После этого закройте и снова откройте карту в Tiled, чтобы не записать поверх обновления старую копию из редактора. Непропорциональное изменение холста проверка отклоняет. Если рисунок сдвигает вход или меняет контур постройки, поправьте связанные точки и полигоны в Tiled; стыки земли проверяйте визуально.

## Проверка через DEV

Запустите `npm run dev:local` или `npm run dev:lan`. После входа в приложение кнопка **DEV** доступна рядом с кругом и на большой карте. `world:watch` нужен только при правках Tiled.

- Погода: авто, ясно, морось, дождь, ливень; отдельно день/ночь, живность и лужи после дождя. Кнопка «Сценарий с птицами» перебирает шесть визитов длительностью до 34 секунд: пару зарянок, стаю ласточек, одиночную синицу, погоню, тройку зябликов и перелёт синиц между кронами. Птицы входят и выходят за границами карты, группы летят с небольшими задержками. На деревьях осматриваются, чистят перья и подпрыгивают. После смены фона точки посадки требуют сверки.
- Вода: короткие прозрачные капли в воздухе, отражения и двойные круги в существующих лужах; на большой карте — блики течения и меняющиеся дождевые попадания на обоих рукавах реки. Контуры `Water` и `WaterExclusions` из Tiled исключают сушу, причал, камни и растительность; их сохранение через `world:watch` обновляет границы эффектов. Новые лужи не добавлены.
- Земля: отдельные короткие брызги, 2–4 разлетающиеся капли и быстро исчезающий влажный след без водных колец. Точки меняются на открытых полянах и тропах, в том числе при выключенных лужах. `forest-ground-layout.json` содержит проверенные участки фона `fedcfbd622df`; при замене картинки их нужно сверить заново. Поверх них применяются текущие водные контуры, границы зданий и исключения грибов. Это отдельная разметка земли, она не заменяет воду из Tiled.
- Лесные сценки: игра с бабочкой или светлячком, поедание гриба, ускоренный рост грибов из маленьких. Поедание готовит один гриб для предпросмотра, наград нет. Автоматические сценки можно выключить; «Отменить сценку» возвращает покой и также выключает их. В режиме живности «Авто» партнёр ручной сценки появляется в любое время; при «Выключить» кнопка недоступна.
- Мохлик: 25 поз, разовый запуск или повторение, четыре направления, масштаб и примерка одежды. Это проверка кадров на месте; движение по маршрутам проверяется в `/prototype/tiled-world`.
- Постройки: список зданий и доступные уровни берутся из Tiled. После добавления новых `siteState` и экспорта они появятся в панели. Переключатели теней и разметки помогают проверить основание, вход и коллизии.
- После ручного запуска DEV остаётся открытой; «Повторить» доступно и в открытой панели. По желанию включите «Сворачивать при запуске». Пауза, «Меньше движения» и скрытый Мохлик блокируют соответствующие анимации с пояснением. Закрытие панели оставляет выбранный вид. **Сбросить вид**, перезагрузка или смена аккаунта возвращают обычную сцену.
- **+50 искр, дерева и камня** — существующая команда локального API, отдельно от визуального предпросмотра. Она изменяет тестовый баланс; сброс вида не отменяет выдачу. На сервере без `devTools` кнопка недоступна.

Панель и ручные команды сцены включены только в development. Изображения, Tiled-файлы, инвентарь и уровни аккаунта визуальные переключатели не меняют. Источники света новой карты работают; игровые улучшения и запуск новых путешествий пока отключены.

## Поддерживаемая часть Tiled

Экспортёр принимает конечную ортогональную карту, встроенные наборы отдельных изображений и описанные выше объекты. Он проверяет ссылки на здания, наличие обязательных маркеров, свойства и их типы, размеры файлов, пропорции, границы мира и пути внутри `public/`.

В этой версии не поддерживаются внешние наборы и шаблоны, группы вне `Water`/`WaterExclusions`/`Lights` и тайловые слои, поворот и отражение изображений, смещения и параллакс слоёв, анимации плиток, тонирование, пониженная непрозрачность слоёв и объектов, а также скрытые объекты. Прозрачные пиксели внутри самого PNG или WebP допустимы. Не добавляйте произвольные пользовательские свойства: неизвестное поле вызывает понятную ошибку проверки. Это ограничение экспортёра приложения, а не редактора Tiled.

## Нативная проверка Tiled

Историческая проверка первоначального прототипа выполнялась в Tiled 1.12.2: семь изображений, два здания, шесть состояний и маршрут `home-walk` прошли нативный экспорт и растеризацию. Она не подтверждает нативную проверку текущего состояния карты с новым домом, водой и `Lights`. Размер исходного рисунка — 2560 × 2560 px; координаты карты — 1254 × 1254.

Снимок ниже относится к первоначальной проверке; показанные в редакторе старые имена файлов предшествуют уборке.

![Дом, точки входа и света, контуры и маршрут в настоящем редакторе Tiled](images/tiled-editor-screenshot.webp)

Обычный рабочий цикл использует сохранённый `.tmj` напрямую. Дополнительно можно проверить его собственным экспортёром и растеризатором Tiled. Следующие команды рассчитаны на Linux/macOS; каталог `tmp/tiled` — временный.

```bash
mkdir -p tmp/tiled
tiled --project "$PWD/world/tiled/forest.tiled-project" \
  --export-map json "$PWD/world/tiled/forest.tmj" \
  "$PWD/tmp/tiled/forest-roundtrip.tmj"
tmxrasterizer --no-smoothing \
  --show-layer Terrain \
  "$PWD/world/tiled/forest.tmj" "$PWD/tmp/tiled/forest-native.png"
node scripts/tiled-world.mjs tmp/tiled/forest-roundtrip.tmj \
  tmp/tiled/forest-roundtrip.generated.json
```

Используйте абсолютные пути при нативном экспорте: в проверенной версии относительный путь назначения может неверно пересчитать ссылки на изображения. Возврат кода 0 сам по себе не доказывает наличие всех изображений; проверьте повторный импорт нашим экспортёром и полученный рисунок. Сравнивать исходный и повторно сохранённый `.tmj` побайтно не нужно: Tiled меняет порядок свойств и формат записи чисел.

На Linux без графической сессии нативному Tiled требуется виртуальный дисплей, например `xvfb-run`. [Экспорт Tiled](https://doc.mapeditor.org/en/stable/manual/export/).
