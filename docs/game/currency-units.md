# Номинал монет и жемчуга

С этого этапа 0.6.7 одна прежняя единица каждой валюты равна **10 новым**. Это изменение счётных единиц: количество предметов, длительность работ и покупательная способность сохранены. Первичный источник — `currencyScale: 10` в [каталоге экономики](../../apps/api/src/main/resources/world/economy-catalog.json), денежные функции TypeScript/Kotlin и миграция V40.

| Пример | Прежний номинал | Новый номинал |
|---|---:|---:|
| Дом 2, монеты | 150 | 1 500 |
| Дом 5, монеты | 42 000 | 420 000 |
| Ускорение за каждые начатые 5 минут | 1 жемчужина | 10 жемчужин |
| Полный круг дневных наград, монеты | 50 | 500 |
| Полный круг дневных наград, жемчуг | 3 | 30 |
| Все ступени достижений, жемчуг | 43 | 430 |

Для любого прежнего денежного баланса или цены `m` новое значение равно `10m`. Для продажи стопки сначала применяется прежнее округление, затем масштаб: `10 × floor((basePrice / 10) × quantity × payoutBps / 10000)`. Простое округление уже увеличенной суммы давало бы дополнительный доход на дешёвых товарах. Комиссия рынка и минимальные денежные шаги сохраняют прежний смысл. Количество предметов никогда не умножается на десять.

Ускорение стоит `10 × ceil(remainingSeconds / 300)`, а не `ceil(remainingSeconds / 30)`: сохраняются прежние пороги списания. Новый круг подарков даёт 30 жемчужин, то есть те же 15 минут стройки. Полная сумма достижений 430 жемчужин соответствует тем же 3 часам 35 минутам. Ежедневные награды остаются ручными; новая шкала не выдаёт их повторно.

## Существующие данные

V40 переводит сохранённые кошельки, денежные суммы оплаченных работ и активных лотов. Маркер масштаба защищает от повторного пересчёта, а ревизия хозяйства меняется, чтобы запрос из старой вкладки не прошёл как новая операция с ценой другого масштаба. Конверсия не меняет награды предметами, сроки работ, счётчики редких находок или количество улова.

Исторические проводки и квитанции сохраняют исходные числа вместе с `currency_scale`. При чтении денежная часть проецируется в текущий номинал; повтор запроса не начисляет кошелёк заново. Это позволяет сопоставлять старые операции с новыми в админке, сохраняя исходную запись для аудита. DEV повторяет конверсию и правила округления.

Обновлять web и API нужно согласованно. Старый клиент не понимает новый каталог и не должен продолжать приём денежных команд. Схема БД и данные после V40 не совместимы с откатом только бинарника API: для отката нужен совместимый код либо согласованное восстановление backup. Само обновление не требует сброса аккаунтов.

## Проверки

Нужны проверки заполненного профиля и активного задания, повторной конверсии, старой квитанции, активного лота и исторической продажи, крайних денежных сумм, прежних порогов ускорения и точного округления продажи/комиссии. Для математических сценариев бюджет жемчуга также увеличивается в десять раз. Результаты текущего этапа и ограничения локальной среды — в [WORK_STATE.md](../../WORK_STATE.md).
