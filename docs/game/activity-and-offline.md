# Активность, AFK и потеря связи

Контур активной игры отделён от входа в аккаунт. Авторизация, восстановление доступа и чтение профиля не требуют активной игровой сессии. Новые игровые записи разрешает серверный сеанс, связанный с текущим аккаунтом и его cookie. [Релиз 0.6.7](../releases/release-0.6.7.md), [аналитика](../operations/admin-panel.md).

## Что видит игрок

Через **5 минут без пользовательского ввода** игра приостанавливается и показывает компактное «Игра на паузе» поверх уже открытого экрана. Карта, камера и выбранное меню сохраняются, но управление и отрисовка сцены приостановлены. Продолжение требует кнопки «Продолжить» и успешной сверки с сервером; ошибка связи после нажатия не снимает паузу. Анимации жителей, обновление таймеров и фоновые запросы не считаются действиями. Авторизация и оплаченные задания сохраняются, их сроки не сдвигаются.

При потере сети уже открытая игра не заменяется экраном подключения: по центру экрана появляется полупрозрачный значок Wi-Fi с мягким мерцанием. Он не перекрывает управление за пределами своей кнопки; подробности и повтор проверки открываются по нажатию. Reduced motion отключает мерцание. В поддерживающих Popover API браузерах значок рисуется в верхнем слое, оставаясь внутри текущей модальной области фокуса, поэтому открытое боковое окно его не сдвигает и не обрезает. В старых WebView без Popover API это пассивный индикатор поверх экрана: он не забирает фокус из окна, автоматическое восстановление связи продолжается. Можно просматривать сохранённые данные и ставить поддерживаемое производство в локальную очередь; покупки, продажи, получение наград и остальные серверные действия ждут подтверждённого соединения. Первый вход без загруженного мира по-прежнему показывает подключение.

В видимой вкладке связь восстанавливается автоматически с ограниченной частотой, соблюдением `Retry-After` и одной попыткой одновременно. Сначала клиент подтверждает игровой сеанс, сверяет прежние команды и читает актуальное состояние. Старые данные не означают, что покупка или награда подтверждены. Настоящий ввод при просмотре игры без сети также учитывается при отсчёте бездействия; первый случайный ввод уже после пятиминутной границы не возобновляет AFK. После явного возврата неудачную попытку можно повторять автоматически, но новая граница AFK снова требует кнопки. Скрытая вкладка не продолжает автономную жизнь леса.

Нельзя превращать неопределённый сетевой результат в новую покупку. Клиент сохраняет исходное тело отправленной команды и requestId, повторяет их до квитанции или однозначного отказа, затем читает актуальное состояние. Не очищайте хранилище браузера и не создавайте новый requestId для разрешения потерянного ответа. Прежние квитанции экономики и очередь команд мира остаются в sessionStorage вкладки. Новый журнал производства хранится отдельно в localStorage аккаунта; смена аккаунта не отправляет команды прежнего игрока.

Приватные снимки экономики, рынка и обмена содержат `ownerPublicId`. Клиент сверяет его с владельцем открытой сессии перед публикацией; смена cookie в другой вкладке не подставляет чужие объявления и дневной оборот в старый профиль. Приватные API используют `no-store`, Service Worker не обрабатывает `/api/` и не возвращает оттуда записи прежнего offline-кеша. Перевод системных часов не меняет серверные сроки: клиентский таймер после сверки использует монотонное время, выдачу подтверждает сервер.

## Отложенное производство

Журнал принимает не более **12** запусков известных нерыбных рецептов, по одному запуску на слот. Шахта и рецепты с рыбой в эту очередь не входят. Каждое принятое намерение сначала записывается в браузер; карточка показывает предмет и «Сохранено». Локальное отображение резервирует необходимые запасы и слоты, но не начисляет результат и не запускает серверный таймер. Получать или отменять такой неподтверждённый результат нельзя. Время производства начинается после принятия команды сервером; ожидание сети его не сокращает.

Для записи нужен доступный localStorage и единственный владелец журнала через Web Locks на время сессии аккаунта. Без хранилища или блокировки остаются обычные подтверждаемые действия при наличии связи. Журнал `zhiv:economy:production:v1:<owner>` содержит намерения и последний проверенный снимок. После перезагрузки снимок используется только для предварительного отображения: первое серверное чтение заменяет его даже при меньшей ревизии. Локальные данные проходят проверку формата и владельца и не считаются доказательством запасов или наград.

Активный presence-сеанс нужен для доставки, а не для сохранения поддерживаемого намерения. При восстановлении связи уже отправленная команда повторяется неизменной; следующие намерения получают актуальную ревизию после её подтверждения. Завершает сверку чтение сервера. AFK и скрытая вкладка не принимают новые локальные действия.

## Серверный протокол

`POST /api/v1/presence` принимает `{kind, presenceId, sequence, active}`. `presenceId` — UUIDv4 на одну активную сессию вкладки; `sequence` увеличивается при следующих сообщениях. Ответ содержит серверные часы, статус и сроки. Клиент передаёт `X-Game-Presence` в игровых записях.

| Сообщение | Значение |
|---|---|
| `resume`, sequence 0, active true | Начало с новым UUID. Повтор старого запроса не продлевает и не возрождает истёкший сеанс |
| `heartbeat`, следующая sequence | Подтверждение связи примерно раз в 30 секунд. active true только при новом пользовательском вводе |
| `suspend`, следующая sequence, active false | Закрытие активного сеанса при уходе/скрытии; отсутствие ответа компенсируется истечением срока |

Сервер завершает право игровых записей через 300 секунд без ввода или 90 секунд без подтверждения связи. Отсутствующий, чужой, приостановленный или истёкший ID даёт `GAME_SESSION_INACTIVE` / 409. Идентификатор связан также с конкретным сеансом авторизации: чужой cookie не может использовать его. Проверка проходит до обработки игровой команды, включая повтор старой квитанции. После нового сеанса можно безопасно сверить прежний requestId.

Это защита от оставленной открытой игры и сигнал для наблюдения, а не доказательство отсутствия автокликера: браузер сообщает факт ввода, сервер самостоятельно считает сроки и длительность. Клиент не присылает число часов.

## Учёт времени и наблюдение

V45 добавляет `game_presence_clients`, `game_presence_accounts` и `game_presence_daily`. Учитываются только интервалы между подтверждениями живого сеанса. Будущий хвост времени не начисляется, разрыв длиннее срока связи не догоняется после возвращения. Короткие интервалы оцениваются с точностью частоты подтверждений: точный момент физического разрыва интернета сервер не знает.

Блокировка пользователя и объединение недавно подтверждённых интервалов (`tstzmultirange`) исключают двойное начисление пересекающихся вкладок/устройств. Поздний ответ более ранней вкладки сохраняет ещё не учтённый участок; старые интервалы за пределами окна связи убираются из рабочего объединения, а дневная сумма остаётся. Интервал пересекающий полночь делится по **UTC**. При превышении, строго **более 20 часов за день**, сохраняется дневная отметка и включается наблюдение. Автоматического бана нет. В админке видны дата, длительность и текущий статус наблюдения; это основание для ручной проверки. Историческое время до V45 не восстанавливается из кликов или времени изменения профиля.

Объединение аккаунтов переносит дневной максимум и существующие сигналы, без сложения возможного перекрытия; это консервативная нижняя граница. Старые активные сеансы обеих сторон приостанавливаются. Удаление аккаунта очищает его данные активности. Обычный сброс хозяйства не должен скрывать дневной сигнал.

## Персонажи и сохранения

Мохлик, Плёска и Шишколап используют общую активную сцену. Пауза прекращает их локальные шаги и встречи, а не проигрывает часы отсутствия одним большим шагом. При продолжении подтверждённые задания и сроки поступают из экономики; лесная память проходит свой протокол владельца и сверки. Внешний LLM не участвует, AI не выдаёт ресурсы.

Основные файлы: [`features/activity/`](../../features/activity/), [`features/economy/sync/session.ts`](../../features/economy/sync/session.ts), [`features/world/state/session.ts`](../../features/world/state/session.ts), [`forest-memory-sync.ts`](../../features/world/state/memory/forest-memory-sync.ts), [`Presence.kt`](../../apps/api/src/main/kotlin/ru/zhiv/presence/Presence.kt), [`JdbcPresenceRepository.kt`](../../apps/api/src/main/kotlin/ru/zhiv/db/JdbcPresenceRepository.kt).

## Проверка изменения

Проверяйте пять минут без действий и ввод перед границей, скрытие/возврат, две вкладки, потерю ответа покупки, перезагрузку с сохранённой командой, ошибку повторного чтения и смену аккаунта. Серверные проверки должны охватывать UTC полночь, ровно/больше 20 часов, повтор и перестановку sequence, чужой cookie, истёкший ID, обновление заполненной БД и параллельные вкладки. Полный порядок релизных проверок — в [документе релиза 0.6.7](../releases/release-0.6.7.md).
