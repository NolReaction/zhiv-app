# Лаборатория Phaser

Экспериментальная ветка `work/0.6.8-phaser` отделена от `work/0.6.8` на коммите `347e260`. Стенд позволяет проверить перенос существующей сцены в Phaser 4.2.1 и примерять расположение зданий. Основная игра продолжает использовать прежний рендер; прогресс аккаунта, экономика и серверные команды со стендом не связаны.

## Запуск

Из чистой рабочей копии репозитория:

```bash
git fetch origin
git switch work/0.6.8-phaser
npm ci
npm run dev:local
```

Откройте **http://localhost:3000/prototype/phaser-world**. Аккаунт не нужен. В DEV-панели мира также есть ссылка на Phaser. Если сервер выбрал другой порт, используйте адрес из терминала.

Для телефона запустите `npm run dev:lan`, подключите телефон к той же Wi-Fi-сети и откройте `http://<IP-компьютера>:3000/prototype/phaser-world`. Если Next блокирует источник, задайте `NEXT_ALLOWED_DEV_ORIGINS` по [инструкции локальной разработки](../development/local-development.md). Реальный iPhone особенно важен для проверки жестов, нагрева и восстановления после сворачивания.

В production маршрут по умолчанию возвращает 404. Для отдельной тестовой сборки можно явно установить `PHASER_LAB_ENABLED=1` при сборке и запуске. Это открывает только лабораторию, а не DEV API. Деплой этой ветки автоматически не выполняется.

## Первая проверка — 10 минут

1. Приблизьте дом и мастерскую, перетащите карту. На телефоне проверьте масштаб двумя пальцами и смену ориентации: объекты должны оставаться под пальцами, интерфейс — помещаться по ширине.
2. Включите сетку и геометрию. Сравните рисунок, точку опоры, вход и занимаемое место на земле. Верх крыши может выходить за контур препятствия: коллизия описывает основание, а не весь PNG.
3. Переключите визуальные уровни дома и мастерской. Изображение, вход и контуры должны обновляться вместе. Это примерка, ресурсами она не оплачивается.
4. В режиме прогулки нажмите на свободную дорожку, затем на здание. Мохлик должен идти по доступной земле к цели или входу. Недоступная цель должна давать понятное сообщение. Проверьте движение за деревьями и перед ними.
5. В режиме размещения передвиньте выбранный объект, попробуйте привязку к сетке и масштаб. Проверьте, что опора, вход, контур нажатия и препятствие следуют за рисунком. После перемещения снова попробуйте подойти к зданию.
6. Переключите день/ночь и контактные тени. Сравните, насколько здание связано с землёй. Ночное свечение пока не проверяет препятствия между фонарём и поверхностью.
7. Перезагрузите страницу: примерка уровней и расположения должна восстановиться. Экспортируйте черновик, сбросьте изменения и импортируйте файл обратно. Исходный Tiled-файл при этом не меняется.

Присылайте скриншот с включённой геометрией, название здания и уровень, браузер/телефон и короткое описание ожидаемого результата. При ошибке загрузки полезен её текст. Число FPS на стенде — локальный индикатор, а не обещание производительности на другом устройстве.

## Как собирать карту

Есть два разных режима работы:

| Задача | Где делать |
|---|---|
| Быстро сравнить масштаб и место одного уровня здания | В лаборатории; сохранить черновик JSON |
| Изменить карту для основной игры и обоих предпросмотров | `world/tiled/forest.tmj` в Tiled |
| Перенести весь комплекс со всеми уровнями и общими деталями | Группа здания в Tiled, включая разметку |
| Исправить перспективу, свет, рисунок крыши или материал | В исходном художественном ассете |

Сетка лаборатории — измерительная сетка с выбранным шагом в единицах мира. Текущая карта остаётся свободной композицией с полигонами; эксперимент не превращает её в строительную игру с покупкой клеток и правилами занятости. Размер изображения и площадь основания — разные величины.

Параметры примерки задают смещение и единый масштаб относительно **авторской точки опоры** конкретного уровня. Вход, порог и контуры преобразуются тем же способом. Разные уровни имеют отдельные настройки: удачная примерка первого уровня не должна незаметно искажать пятый.

Черновик содержит версию формата и отпечаток исходной сцены. После изменения карты или ассетов старый черновик отклоняется с объяснением: его координаты нельзя молча прикладывать к другой геометрии. Экспортируйте нужный вариант до правок Tiled. JSON лаборатории — файл примерки, **не формат Tiled**; он не импортируется в `.tmj` автоматически.

Для постоянной правки откройте `world/tiled/forest.tmj`, запустите во втором терминале:

```bash
npm run world:watch
```

Передвиньте нужную группу в Tiled, сохраните и дождитесь сообщения `Exported`. Перезагрузите лабораторию и проверьте результат без старой примерки. Перед коммитом выполните `npm run world:check`. Сгенерированный `features/world/tiled/forest.generated.json` вручную не редактируют. Подробная [памятка по слоям и группам](tiled-quickstart.md).

## Устройство кода

Всё специфичное для эксперимента находится в `features/world/phaser/`:

| Файл | Ответственность |
|---|---|
| `contracts.ts` | Параметры стенда, события и управление сценой |
| `model.ts` | Примерка геометрии, версии и проверка черновиков |
| `runtime.ts` | Жизненный цикл Phaser, камера и ввод |
| `presentation.ts` | Отдельные изображения, глубина, контактные тени и вечерний свет |
| `actor.ts`, `actor-navigation.ts` | Спрайты Мохлика и перемещение по существующей навигации |
| `phaser-world-lab.tsx`, CSS рядом | Интерфейс, локальное сохранение, импорт/экспорт |

Страница `app/prototype/phaser-world/page.tsx` проверяет доступность стенда. Phaser загружается динамически внутри клиентского эффекта; серверный рендер не обращается к `window`. Собственный аудиодвижок Phaser отключён: в проекте уже есть отдельная [звуковая система](audio-system.md).

Источник карты общий: `forest.tmj` → существующий экспорт → `forest.generated.json` → адаптер лаборатории → объекты Phaser. Лаборатория использует нынешнюю систему навигации и рисования Мохлика. Бизнес-правила при переносе рендера не дублируются.

Чтобы не хранить десятки больших PNG на GPU, загрузчик ограничивает разрешение отдельных объектов по их авторским размерам. Полноразмерный фон сохраняется; исходные файлы не меняются. Камера ограничивает плотность рендера значением DPR 2. Эти ограничения снижают расход памяти, но предельное приближение может смягчать детали. Окончательную оценку дают реальные телефоны.

## Границы этого этапа

- Рисунки взяты из существующей игры. Перенос в движок сам по себе не исправляет различающиеся перспективу, плотность деталей и запечённый в PNG свет.
- Контактные тени и вечерний свет помогают проверить композицию. Normal maps, рельефное освещение материалов, отбрасываемые от каждого фонаря тени и автоматическая нормализация ассетов пока не реализованы.
- Деревья, нарисованные на общем фоне, остаются частью фона. Авторские силуэты позволяют закрывать героя кроной, но отдельным переставляемым деревом такая крона не становится.
- Жизнь NPC, производство, сбор наград, погодные эффекты и звук основной игры здесь пока не перенесены. Прогулка предназначена для проверки сцены.
- Перемещение здания не расширяет доступные дорожки автоматически. Новое место должно лежать внутри подходящей `WalkArea`; иначе вход окажется недоступным.
- Отдельные источники `Lights` пока имеют мировые координаты и не привязаны к владельцу-зданию. При перестановке здания такой фонарь остаётся на месте; перенос его вместе со зданием нужно задавать в Tiled. Точки `light` внутри геометрии здания преобразуются вместе с ним.
- Если точный вход перекрыт, герой выбирает проверенную площадку подхода рядом и сообщает об этом. Мост и маяк могут оставаться недоступными в текущей разметке; обход коллизий ради демонстрации не включён.

Следующий полезный шаг после проверки — выбрать **одну мастерскую и окружающую её полянку** как эталон. Утвердить размер основания, ракурс, высоту героя и направление дневного света; затем готовить совместимые отдельные землю, растительность и части здания. Normal map имеет смысл добавлять к этому согласованному набору, когда появится материал, пригодный для меняющегося света.
