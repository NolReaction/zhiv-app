# Домики и улучшения: работа без правок кода

Можно добавлять рисунки зданий, расставлять их в Tiled и примерять уровни в браузере. Визуальный каталог берётся из карты автоматически. В основном приложении работает [экономика](economy-foundation.md): стройка за монеты и материалы с таймером, производство и исследования. У `home` подтверждённый уровень аккаунта выбирает рисунок, коллизию и вход; нажатия на `workshop` и `quarry` открывают их карточки хозяйства. У построенного здания открывается производство, у ещё не построенного или улучшаемого — требования и таймер. Сон работает у `siteId: home`; новая постройка сама по себе не становится вторым домом для сна.

## Размещённые руины

В `Buildings` подключены четыре постройки начального уровня `0`. Их положение, размер и угол берутся из Tiled.

| Папка | `siteId` | Рисунок |
|---|---|---|
| `Workshop → Workshop-lvl-0` | `workshop` | `forest-workshop-level-0.png` |
| `Lighthouse → Lighthouse-lvl-0` | `lighthouse` | `lighthouse-level-0.png` |
| `Bridge → Bridge-lvl-0` | `bridge` | `bridge-level-0.png` |
| `Quarry → Quarry-lvl-0` | `quarry` | `quarry-lvl-0.png` |

У каждой есть точки `anchor` / `entry` и контуры `hitArea` / `collision` в папке уровня. У каменоломни `hitArea` охватывает подъёмник, верёвку, камни и тележку; `collision` описывает только занятое место на земле, не всю высоту стрелы. `entry` находится южнее основания с запасом для Мохлика. Порога `doorway` нет: это открытая площадка, не пещерный вход. Это готовые размещения для сцены и предпросмотра; мастерская и каменоломня открывают соответствующий раздел хозяйства, восстановление маяка и открытие прохода по мосту ещё не реализованы. Разрушенный мост остаётся препятствием, новая проходимая область поверх реки не создаётся.

## Запуск

В корне проекта откройте два терминала:

```sh
npm run dev:local
```

```sh
npm run world:watch
```

Откройте `http://localhost:3000/prototype/tiled-world` (если сервер выбрал другой порт — используйте его). Вход в аккаунт не нужен. Панель **«Постройки и уровни»** показывает все размещённые здания и их рисунки; **«Показать на карте»** приближает здание (для `home` кнопка **«Показать поляну»** показывает область `focus`), **«Разметка»** показывает контуры. **«Сбросить вид»** возвращает `initialLevel`. Выбор здесь временный, после перезагрузки сбрасывается. Эта отдельная страница не читает и не изменяет уровень аккаунта.

Для проверки настоящей жизни, дня/ночи и подхода к дому откройте основное приложение → большую карту → **DEV**. Без предпросмотра дом использует подтверждённый сервером уровень. Включение предпросмотра зданий заменяет его только визуально; возврат к уровню аккаунта не списывает материалы и не отменяет стройку. Страница предпросмотра проверяет рисунки и разметку, а её маршруты — отдельные линии, не свободную навигацию Мохлика.

Все пять уровней проверяйте со свободной навигацией (`auto`, по умолчанию). Старый сравнительный режим `Routes` использует вручную нарисованную линию к входу первого уровня; при другой точке `entry` он отклоняет этот маршрут. Это ограничение старого режима, а не результат поиска свободного пути.

## Подготовка рисунка

- Мастер сохраняйте в `art/world/prototype/`, файл для игры — в `public/world/prototype/`. Для первых проб достаточно PNG с прозрачностью; WebP с прозрачностью можно экспортировать вручную позже. `world:export` картинки не перекодирует.
- Например: `workshop-level-1.png`, `workshop-level-2.png`, `workshop-level-3.png`. Один файл — одно состояние здания, не лист из нескольких домиков.
- Для уровней одного здания удобнее **одинаковый размер холста**, ракурс, масштаб деталей, положение основания и двери. Оставьте сверху место для будущей крыши. Не обрезайте каждый уровень по новому контуру: картинка начнёт прыгать.
- У каждого уровня может быть своя рамка, коллизия, область нажатия и точки. Дверь может менять место: перенесите `entry` и `doorway` и проверьте свободный подход. Единый ракурс и масштаб деталей всё равно помогают сохранить стиль.
- Используйте существующий дом и фон как художественный референс. Не добавляйте в изображение текст, рамку, фон-прямоугольник или нарисованный световой ореол. Непрозрачную землю вокруг дома придётся вручную состыковать с лесом.

## Первое новое здание — пример `workshop`

Объектные слои можно складывать в папки: `Buildings → Home-lvl-1 / Home-lvl-2 → Home-anchors / Home-image / Home-tracing`. В папке каждого уровня разместите ровно одну картинку здания; её плитка задаёт `siteId` и `level`. Маркеры с тем же `siteId` внутри этой папки автоматически относятся к этому уровню. Названия папок произвольные; пустые папки допустимы. Без папки у маркера можно явно задать `level` типа **int**.

1. Откройте `world/tiled/forest.tiled-project` → `forest.tmj`. Заблокируйте **Terrain**. Размер мира — **1254 × 1254**, это не пиксели исходного фона 2560 × 2560.
2. Откройте встроенный набор **Forest image collection** и добавьте изображение из `public/world/prototype/`. Оставьте **Object Alignment = Top Left**. Набор должен оставаться встроенным: внешние `.tsx` и шаблоны объектов экспортёр не поддерживает.
3. У **плитки в наборе** задайте четыре пользовательских свойства:

   | Свойство | Тип Tiled | Пример |
   |---|---|---|
   | `role` | string | `siteState` |
   | `siteId` | string | `workshop` |
   | `level` | int | `1` |
   | `label` | string | `Мастерская · уровень 1` |

4. В слое **Buildings** продублируйте изображение существующего дома **вместе с его точками и двумя полигонами**, переместите копии на свободное место. У всех копий замените `siteId: home` на `siteId: workshop`, а имена — на `workshop`, `workshop-anchor` и т. д. Исходный `home` оставьте. Скопированные контуры нужно подогнать под новый рисунок.
5. Выделите только скопированное изображение. В наборе нажмите правой кнопкой на новую плитку → **Replace Tile of Selected Objects**. Свойства **объекта на карте** должны быть `role: site`, `siteId: workshop`, `label: Мастерская` (все string), `initialLevel: 1` (int). Свойства объекта и плитки — разные; если Tiled показывает унаследованное `role: siteState`, задайте объекту собственное `role: site`.
6. Подстройте ширину/высоту картинки **пропорционально**, затем отдельно точки и полигоны. У копии квадратного дома рамка останется квадратной: если новая картинка другой пропорции, измените её рамку соответственно. У слоя оставьте **Draw Order = Manual**.

| Объект | Пользовательские свойства | Куда поставить / зачем |
|---|---|---|
| Изображение | `role: site`, `siteId`, `label`, `initialLevel` | Одно размещение на пару `siteId` + `level` |
| Точка опоры | `role: anchor`, `siteId` | У основания; ориентир опоры и разметки |
| Точка подхода | `role: entry`, `siteId` | Перед дверью на доступной земле, вне коллизии |
| Полигон нажатия | `role: hitArea`, `siteId` | Обвести видимый силуэт, чтобы выбирать здание |
| Полигон препятствия | `role: collision`, `siteId` | Занятое место **на земле**, не всю крышу |
| Точка порога, необязательная | `role: doorway`, `siteId` | Лапы на видимом пороге, внутри рамки изображения |
| Окно, необязательное | `role: window`, `siteId` | Полигон по внутреннему контуру окна; тёплый свет ночью |
| Дымоход, необязательный | `role: chimney`, `siteId` | Точка выхода дыма из трубы, внутри рамки изображения |

В таблице всё string, кроме `initialLevel` (int). Обязательны по одной опоре, точке подхода и обоим полигонам. Связь задаёт `siteId`, а не имя объекта. Для отдельных зданий нужны разные `siteId` и соответствующие плитки каталога; уровни одного здания используют общий `siteId` и разные `level`. Используйте ID вроде `workshop`, `storehouse`, `guest-house`; `home` сохраните за жилым домом, `world` не используйте — это команда камеры предпросмотра.

7. Сохраните карту. После добавления/замены **файлов изображений** выполните `npm run world:export`, затем `npm run world:check`. Если экспорт обновил размеры изображений в `.tmj`, заново откройте карту в Tiled, чтобы не затереть изменения старой открытой копией. `world:watch` следит за сохранением карты, не за PNG.
8. Проверьте здание в браузере. При ошибке экспорта остаётся последняя корректная карта — сначала прочитайте сообщение в терминале, исправьте и сохраните снова.

## Поворот здания

Изображение с `role: site` можно повернуть полем **Rotation** в Tiled, сохраняя **Object Alignment = Top Left**. У моста сохранён угол `346.507°` (то же направление, что `−13.493°`). Поворот учитывают рисунок, тень и рамка камеры, в том числе при переключении уровней.

Маркеры остаются отдельными объектами: после поворота картинки подгоните `hitArea`, `collision`, `anchor` и `entry` к её новому положению. Вершины полигонов задаются на карте, сам параметр **Rotation** у маркеров должен быть `0`. Повторно вращать уже подогнанный контур не нужно. Перемещайте готовое здание вместе со всеми маркерами его уровня.

Поворот фона и прочих объектов, а также отражения плиток пока не поддерживаются. Полная повёрнутая рамка картинки должна оставаться внутри карты.

## Добавить улучшение существующего здания

1. Добавьте картинку в набор: `role: siteState`, прежний `siteId`, новый `level` (**int**) и `label`.
2. Создайте папку уровня, например `Home-lvl-2`, и разместите в ней картинку с собственным `role: site`. `siteId`, `label` и `level` наследуются от плитки; повторять их на объекте не обязательно. Размер рамки может отличаться от первого уровня, но сохраняйте пропорции своего изображения.
3. В эту же папку скопируйте точки и полигоны первого уровня, затем подгоните под новый дом. Имена можно сохранить: важны `role` и `siteId`. У каждого уровня свои `anchor`, `entry`, `doorway`, `hitArea`, `collision` и при необходимости `light`, `window`, `chimney`.
4. Пока часть маркеров отсутствует, она наследуется от самого младшего размещённого уровня; маркеры вне папок без `level` общие. Это заготовка для редактирования: перед проверкой нового дома подстройте весь набор. Пустые слои второго уровня сами не создают новые контуры.
5. Начальный вариант для страницы предпросмотра задаётся `initialLevel` **изображения самого младшего размещённого уровня** (сейчас `Home-lvl-1`). В игре `home` использует подтверждённый уровень аккаунта, поэтому `initialLevel` не выдаёт улучшение. Например, для запуска со вторым домом у этого объекта поставьте `initialLevel: 2`. Такое же поле на изображениях старших уровней не переключает начальный вариант.
6. Экспортируйте карту и переключите уровни в предпросмотре / DEV. Вместе с картинкой меняются рамка, точки, нажатия и навигационная коллизия. DEV-переключение сбрасывает текущий маршрут, чтобы Мохлик не шёл по старой геометрии.

Можно по-прежнему добавлять вариант только в набор: тогда он использует общую рамку и разметку. `level: 0` допустим для стройплощадки, но сам по себе коллизию не убирает. Каталог совершенно нового здания требует размещения на карте.

## Тени, окна и дым

Тени рисуются кодом под PNG: плотная у основания, мягкая вокруг и короткая падающая вправо-вниз. Они учитывают прозрачность картинки и коллизию выбранного уровня; отдельный рисунок тени не нужен. Ночью падающая тень ослабевает. Для сравнения используйте переключатель теней в DEV.

Рендер дополнительно согласует цвет PNG с лесом: дерево, камень, кора и листва имеют мягкие профили в `forest-object-appearance.ts`. Внизу изображения появляются редкие травинки, щепки или камешки из `building-ground-details.ts`; места входа и вода исключены. Это оформление не меняет коллизии. У моста оно отключено, тень сохраняет разрыв между половинами. Исходные PNG не переписываются; обработка кешируется и одинакова в круге и на большой карте. В Tiled видны исходные картинки, программные эффекты оценивайте в приложении/предпросмотре.

В домах 3–5 уже размечено окно, в домах 4–5 — дымоход. В папке нужного уровня:

- В **Home-tracing** полигон `home-window`: `role: window`, `siteId: home`. Обведите внутренний край окна, оставляя раму и ставни снаружи. Эффект полупрозрачный; нарисованные переплёты остаются видны.
- В **Home-anchors** точка `home-chimney`: `role: chimney`, `siteId: home`. Поставьте её в отверстие трубы под колпаком. Дым поднимается из этой точки; дымоход отдельно рисовать кодом не нужно.

Допускается по одному маркеру каждого типа на уровень. У младших домов этих маркеров нет — эффекты им не добавляются при переключении со старшего. Геометрия эффектов наследуется по тем же правилам, что и остальные маркеры; держите окно и трубу в папках соответствующих уровней. После перемещения сохраните карту и выполните экспорт. Эти маркеры не меняют проходимость. Пауза останавливает дым, «Меньше движения» отключает его; свет окна остаётся статичным. Параметры эффекта — в `features/world/building-details.ts`.

## Как расставлять и что проверять

- Сначала разместите здания с запасом под максимальное улучшение, затем проверьте проходы. Тропы делайте заметно шире `actor.size × 0.2`: при размере 50 это **10 единиц**, радиус опоры — 5. Оставляйте дополнительное место визуально для тела. Не перекрывайте spawn и точки занятий.
- Для посещаемого места нужен доступ через **WalkAreas**; коллизии зданий обходятся автоматически. Сам рисунок дорожки не делает её проходимой. Новая дверь без игровой логики пока служит разметкой на будущее.
- У `home` сохраните доступный `entry`, порог `doorway` и короткий переход между ними (не более **33.6 единицы мира**, независимо от размера героя). После переноса проверьте сон и выход. Подробнее — [навигация](world-navigation.md#дом-и-куст-точный-переход-после-поиска).
- Если подход не получился, смотрите причину в DEV → **AI**: различаются неверный порог, недостаток места для опоры и отсутствие пути. После начала следующего занятия текущая причина обновляется; прежний отказ остаётся в журнале. DEV → **Отладка → Пути** проверяет входы и прежние маршруты выбранного уровня дома.
- Двигайте картинку и её маркеры вместе. Фонарь из **Lights** переносится отдельно; он не привязан к `siteId`. Свет общий для всех уровней — держите лампу в одном месте. [Параметры света](world-lighting.md).
- Порядок перекрытия зданий задаётся порядком объектов Tiled, автоматической сортировки по высоте нет. Не рассчитывайте на автоматическое скрытие Мохлика за крышей нового здания: это отдельная будущая логика. Старайтесь не перекрывать постройками друг друга и основные проходы.
- Глазики групп, слоёв и объектов управляют только видом в Tiled: можно скрыть маркеры и неиспользуемые уровни перед сохранением. Экспорт всё равно включает и проверяет их; выбранный игровой уровень определяет приложение. Для удаления объекта из игры удалите его разметку и связанные ссылки, одного глазика недостаточно. Непрозрачность оставляйте 100%, отражения выключенными. Вращать можно только изображения зданий (`role: site`); у маркеров поворот нулевой. Полигоны без самопересечений.
- Не добавляйте свойства `price`, `income`, `upgradeCost`, `maxLevel` и подобные: сейчас экспортёр их не принимает. Цены, время и материалы задаются в `apps/api/src/main/resources/world/economy-catalog.json`; `level` в Tiled выбирает рисунок и геометрию, а не выдаёт покупку. Пока стройка не завершена командой получения, игра использует прежний уровень дома.

Перед передачей работы сохраните в Git мастера, игровые картинки, `world/tiled/forest.tmj` и результат `features/world/tiled/forest.generated.json`. Последний файл руками не редактируйте. Короткий цикл проверки: экспорт → `world:check` → все уровни → круг и большая карта → DEV день/ночь → подход к дому.

Для обычного GPT можно дать эту инструкцию и референс дома: «Помоги подготовить три отдельных рисунка улучшений [здания] для мира Мохлика. Сохрани ракурс, масштаб деталей, одинаковый холст и прозрачный фон. Развивай крышу, материалы и украшения. Основание и дверь могут отличаться: для каждого уровня я размечу коллизию и вход в Tiled. Общий фонарь желательно оставить на прежнем месте». Это художественное задание; финальные размеры и совмещение проверьте сами в Tiled.

Полный контракт проекта: [справочник Tiled](tiled-editor.md). Стандартные действия редактора: [объекты и замена плиток](https://doc.mapeditor.org/en/stable/manual/objects/), [редактирование наборов](https://doc.mapeditor.org/en/stable/manual/editing-tilesets/).
