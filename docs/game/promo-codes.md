# Промокоды

Кнопка **«У меня есть промокод»** находится сверху магазина валют в мире. Игрок вводит код и получает подтверждение с точными монетами, жемчугом и предметами. Покупки за реальные деньги и обмен из прежней витрины пока недоступны.

## Управление из админки

Откройте **Админка → Промокоды**. Здесь можно создать акцию, указать подарок, начало и окончание действия, изменить существующий код, включить, выключить или удалить его. Изменения в production сохраняются в PostgreSQL и сразу действуют для новых активаций; пересборка и перезапуск сервера не требуются.

1. Введите сам код и понятное название подарка. Постоянный ID акции создаётся автоматически.
2. Укажите монеты, жемчужины и/или предметы. Валюты вводятся в видимых игроку единицах.
3. Задайте начало и окончание либо оставьте соответствующую границу пустой. Начало включительно, окончание не включительно; сервер сравнивает точные моменты времени. Интерфейс показывает часовой пояс рядом с полями времени.
4. Проверьте состав подарка и период, укажите причину изменения и сохраните. Одно получение на профиль сохраняется при редактировании награды и срока.

Выключение временно останавливает выдачу. **Удаление окончательное для этого ID**: акция пропадает из списка, но служебная запись и история выдач остаются. Существующие подарки не отзываются. ID удалённой акции и её последний код нельзя использовать для новой акции; для нового подарка нужны новые ID и код. Повтор сохранённого запроса после сетевого сбоя возвращает исходный результат и не создаёт вторую запись.

Два администратора не могут незаметно перезаписать изменения друг друга: сервер проверяет версию записи. При конфликте обновите список и повторно проверьте настройки. Список ограничен 1000 неудалённых акций, включая упакованные в JSON.

## Совместимость с серверным JSON

[`apps/api/src/main/resources/world/promo-codes.json`](../../apps/api/src/main/resources/world/promo-codes.json) остаётся источником исходных акций и резервом совместимости. Не изменённые через админку записи читаются из него при запуске. После первого изменения либо удаления через админку запись из БД имеет приоритет по `id`; последующий деплой JSON не отменяет это изменение и не восстанавливает удалённую акцию.

Этот список не входит в клиентский каталог экономики и не публикуется в `public/`. Пример `WELCOME-EXAMPLE` выключен: без изменения `enabled` никаких подарков по нему нет. Для обычной работы используйте админку; JSON пригоден для исходной конфигурации.

Один элемент массива `codes` выглядит так:

```json
{
  "id": "autumn-gift-2026-v1",
  "code": "AUTUMN-GIFT",
  "enabled": true,
  "title": "Осенний подарок",
  "startsAt": "2026-10-15T10:00:00+03:00",
  "endsAt": "2026-11-01T00:00:00+03:00",
  "reward": {
    "coins": 500,
    "pearls": 20,
    "items": { "wood": 5, "stone": 5 }
  }
}
```

- `id` - постоянное имя акции: 3-64 строчных латинских символа, цифры, `-`, `_`. **После выдачи не меняйте `id`**: именно он запрещает повторную выдачу. Новое `id` означает новый подарок для всех.
- `code` - код для игрока: 3-40 заглавных латинских букв, цифр, `-`, `_`. Ввод игрока нечувствителен к регистру; пробелы по краям убираются. Менять код при прежнем `id` можно, повторно подарок не выдастся.
- `enabled` - `true` включает, `false` выключает. Для остановки акции выключайте её; старую запись лучше сохранять.
- `title` - название подарка, 1-80 символов.
- `startsAt` и `endsAt` - ISO дата с часовым поясом, либо `null` без ограничения. Начало включительно, конец не включительно. Для Москвы используйте `+03:00`.
- `coins` и `pearls` - **числа, которые видит игрок**. `500` монет даёт ровно 500 монет; `20` жемчужин даёт 20 видимых жемчужин. Внутреннее хранение жемчуга сервер переводит сам. Не умножайте числа на 10 или 50.
- `items` - ID предмета и положительное целое количество. ID ищите в массиве `items` [каталога экономики](../../apps/api/src/main/resources/world/economy-catalog.json). Примеры: `fish`, `wood`, `stone`, `berries`. Пустой объект `{}` допустим, если есть валюта.

За одну акцию допускается до 1 000 000 монет, 10 000 видимых жемчужин и 10 000 предметов суммарно. Только целые количества. Нулевой подарок, неизвестный предмет, повтор `id`/кода и неправильные даты отклоняются админским API. Ошибка в упакованном JSON останавливает запуск API с ошибкой конфигурации. JSON не допускает комментариев и запятых после последнего поля.

## Как применить изменение JSON

1. Измените серверный JSON; для новой акции добавьте элемент в `codes`, разделяя элементы запятой.
2. Проверьте каталог: `node --test tests/promo-codes.test.mjs`. Перед выпуском прогоните API-тесты и обычные проверки проекта. Тест упакованного примера требует, чтобы учебная запись оставалась выключенной; собственные акции добавляйте отдельными элементами.
3. Соберите и обновите API обычным процессом проекта, затем перезапустите его. JSON читается при запуске; изменения через админку читаются из БД сразу. Первые выдачи используют V48, управление из админки — V51/V52 поверх V50 уведомлений.
4. В локальном Next DEV тот же JSON используется серверным обработчиком. После правки надёжнее перезапустить `npm run dev:local`.
5. Проверьте активацию на тестовом профиле и повторный ввод: подарок приходит один раз.

Не храните в этом файле платёжные секреты. Не переносите список промокодов в справку игрока или клиентский пакет. В Git видны коды из файла, поэтому доступ к репозиторию должен соответствовать доступу к акциям.

## Гарантии и ограничения

- Подарок выдаёт сервер одной транзакцией: кошелёк, кладовая, revision, чек команды и запись журнала. Передача собственного поля `reward` клиентом запрещена.
- Один профиль получает каждую акцию один раз. Повтор потерянного запроса использует тот же UUID и возвращает исходный чек, даже если акцию уже выключили или убрали из каталога.
- Переполненная кладовая или кошелёк не расходуют код. Сначала освободите место, затем повторите.
- При объединении аккаунтов переносятся все использованные акции, в том числе при совпавших UUID разных запросов. Подарки повторно не начисляются. Сброс хозяйства не удаляет ограничения на получение. Удалённый аккаунт не может выполнять запросы; служебная запись акции остаётся без текста кода и без имени пользователя. Ограничение относится к аккаунту, а не ко всем аккаунтам одного человека.
- Есть лимит 6 попыток в минуту. Сообщения отличают неверный, ещё не начавшийся, истёкший и уже полученный код. Не публикуется список существующих кодов или будущих наград.
- На клиенте незавершённый запрос сохраняется в `sessionStorage` текущего аккаунта, чтобы закрытие магазина и повторная проверка не создали новую выдачу.
- Управление проверяет действующий сеанс и серверный `ADMIN_PUBLIC_IDS`; записи требуют разрешённый Origin и ограничены частотой `admin-write`. Список доступен только администраторам, ответы помечены `no-store`.
- Создание, изменение и удаление записываются в общий неизменяемый журнал `admin_actions`: кто, что, причина, точные настройки и новая версия. UUID запроса общий для всех админских действий; повтор с другими параметрами отклоняется.
- Выдача и изменение определения синхронизированы транзакционной блокировкой каталога: после завершённого выключения или удаления новый запрос не получит старую награду. Уже начатая выдача может завершиться перед удалением; её чек и подарок сохраняются.

## Контракт админского API

- `GET /api/v1/admin/promos`: `{ serverTime, codes: [{ definition, version, redemptions, createdAt, updatedAt }] }`. `definition` имеет формат примера выше. Исходный JSON имеет `version: 0` и пустые даты создания/изменения.
- `POST /api/v1/admin/promos/manage`: `{ requestId, action, promoId, expectedVersion, reason, definition }`. `action` — `create`, `update` или `delete`; для создания `expectedVersion: 0`, для изменения и удаления — версия из списка. При удалении `definition` отсутствует или `null`. Причина — 8–240 символов. `definition.id` совпадает с `promoId`.
- Ответ: `{ requestId, action, promoId, version, createdAt, replayed }`. Потерянный ответ повторяется с тем же UUID и прежним полным запросом.
- `ADMIN_PROMO_VERSION_CONFLICT` требует перечитать список. `ADMIN_PROMO_EXISTS`/`ADMIN_PROMO_CODE_EXISTS` означают занятый ID/код. Удалённая акция отвечает `ADMIN_PROMO_NOT_FOUND` при попытке редактирования.
