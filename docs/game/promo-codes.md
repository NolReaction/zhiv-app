# Промокоды

Кнопка **«У меня есть промокод»** находится сверху магазина валют в мире. Игрок вводит код и получает подтверждение с точными монетами, жемчугом и предметами. Покупки за реальные деньги и обмен из прежней витрины пока недоступны.

## Где добавлять и менять

Редактируйте [`apps/api/src/main/resources/world/promo-codes.json`](../../apps/api/src/main/resources/world/promo-codes.json). Это серверный список. Он не входит в клиентский каталог экономики и не публикуется в `public/`. Пример `WELCOME-EXAMPLE` выключен: без изменения `enabled` никаких подарков по нему нет.

Один элемент массива `codes` выглядит так:

```json
{
  "id": "autumn-gift-2026-v1",
  "code": "AUTUMN-GIFT",
  "enabled": true,
  "title": "Осенний подарок",
  "startsAt": "2026-10-15T10:00:00+03:00",
  "endsAt": "2026-11-01T00:00:00+03:00",
  "reward": {
    "coins": 500,
    "pearls": 20,
    "items": { "wood": 5, "stone": 5 }
  }
}
```

- `id` - постоянное имя акции: 3-64 строчных латинских символа, цифры, `-`, `_`. **После выдачи не меняйте `id`**: именно он запрещает повторную выдачу. Новое `id` означает новый подарок для всех.
- `code` - код для игрока: 3-40 заглавных латинских букв, цифр, `-`, `_`. Ввод игрока нечувствителен к регистру; пробелы по краям убираются. Менять код при прежнем `id` можно, повторно подарок не выдастся.
- `enabled` - `true` включает, `false` выключает. Для остановки акции выключайте её; старую запись лучше сохранять.
- `title` - название подарка, 1-80 символов.
- `startsAt` и `endsAt` - ISO дата с часовым поясом, либо `null` без ограничения. Начало включительно, конец не включительно. Для Москвы используйте `+03:00`.
- `coins` и `pearls` - **числа, которые видит игрок**. `500` монет даёт ровно 500 монет; `20` жемчужин даёт 20 видимых жемчужин. Внутреннее хранение жемчуга сервер переводит сам. Не умножайте числа на 10 или 50.
- `items` - ID предмета и положительное целое количество. ID ищите в массиве `items` [каталога экономики](../../apps/api/src/main/resources/world/economy-catalog.json). Примеры: `fish`, `wood`, `stone`, `berries`. Пустой объект `{}` допустим, если есть валюта.

За одну акцию допускается до 1 000 000 монет, 10 000 видимых жемчужин и 10 000 предметов суммарно. Только целые количества. Нулевой подарок, неизвестный предмет, повтор `id`/кода и неправильные даты останавливают запуск API с ошибкой конфигурации. JSON не допускает комментариев и запятых после последнего поля.

## Как применить

1. Измените серверный JSON; для новой акции добавьте элемент в `codes`, разделяя элементы запятой.
2. Проверьте каталог: `node --test tests/promo-codes.test.mjs`. Перед выпуском прогоните API-тесты и обычные проверки проекта. Тест упакованного примера требует, чтобы учебная запись оставалась выключенной; собственные акции добавляйте отдельными элементами.
3. Соберите и обновите API обычным процессом проекта, затем перезапустите его. Каталог читается при запуске; горячего перечитывания на production нет. Для первого выпуска нужна миграция V48.
4. В локальном Next DEV тот же JSON используется серверным обработчиком. После правки надёжнее перезапустить `npm run dev:local`.
5. Проверьте активацию на тестовом профиле и повторный ввод: подарок приходит один раз.

Не храните в этом файле платёжные секреты. Не переносите список промокодов в справку игрока или клиентский пакет. В Git видны коды из файла, поэтому доступ к репозиторию должен соответствовать доступу к акциям.

## Гарантии и ограничения

- Подарок выдаёт сервер одной транзакцией: кошелёк, кладовая, revision, чек команды и запись журнала. Передача собственного поля `reward` клиентом запрещена.
- Один профиль получает каждую акцию один раз. Повтор потерянного запроса использует тот же UUID и возвращает исходный чек, даже если акцию уже выключили или убрали из каталога.
- Переполненная кладовая или кошелёк не расходуют код. Сначала освободите место, затем повторите.
- При объединении аккаунтов переносятся все использованные акции, в том числе при совпавших UUID разных запросов. Подарки повторно не начисляются. Сброс хозяйства не удаляет ограничения на получение. Удалённый аккаунт не может выполнять запросы; служебная запись акции остаётся без текста кода и без имени пользователя. Ограничение относится к аккаунту, а не ко всем аккаунтам одного человека.
- Есть лимит 6 попыток в минуту. Сообщения отличают неверный, ещё не начавшийся, истёкший и уже полученный код. Не публикуется список существующих кодов или будущих наград.
- На клиенте незавершённый запрос сохраняется в `sessionStorage` текущего аккаунта, чтобы закрытие магазина и повторная проверка не создали новую выдачу.
