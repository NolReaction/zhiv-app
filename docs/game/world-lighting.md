# Свет и тени

[Навигация по документации](../README.md) · [Устройство мира](world-foundation.md) · [Редактор Tiled](tiled-editor.md)

В **0.7.0** включён прототип 2.5D-света из `0.6.9-light` на существующем рисунке: отдельные объёмы перекрывают фонари и костёр, а направленный источник отбрасывает тени на размеченную землю. Пробный участок — центральная поляна: дом со всеми пятью состояниями, несколько деревьев и камень. Мохлик и жители получают движущиеся объёмы из текущих позиций. Это условная геометрия для освещения, которую можно постепенно уточнять. Гибридный редактор контуров/высот доступен только в DEV, затем правки переносятся в исходный Tiled.

День и ночь сохраняют общий рисунок. Круг, большая карта и Tiled preview используют фонари из экспорта и лампы активного рисунка здания; работающий костёр учитывает состояние производства. Карты без новой разметки продолжают использовать прежние световые пятна.

## Добавить источник в Tiled

1. Откройте `world/tiled/forest.tmj`. В **Lights** дублируйте подходящую точку или вставьте **Point**.
2. Дайте уникальное имя, например `bridge-torch-1`. Поставьте точку в центр лампы или пламени. Стойка факела рисуется ниже неё примерно на 17 единиц мира.
3. Задайте свойства из таблицы. `role` и `siteId` для объектов **Lights** не нужны; ширина и высота точки остаются нулевыми.
4. При запущенном `npm run world:watch` сохраните карту. В приложении откройте **DEV → Время суток → Ночь**. В `/prototype/tiled-world` включите ночной режим.
5. Проверьте день, ночь, круг, большой масштаб и общий обзор. Затем `npm run world:check`. Сохраняйте в Git и `.tmj`, и `features/world/tiled/forest.generated.json`.

| Свойство | Тип Tiled | Значение |
| --- | --- | --- |
| `kind` | string | `lantern`, `torch`, `glow`; по умолчанию `lantern` |
| `radius` | float | Радиус в единицах мира: больше 0, не больше 500; по умолчанию 70 |
| `intensity` | float | 0–2; по умолчанию 1. При 0 огонь и свет выключены, стойка факела остаётся |
| `color` | color | Непрозрачный цвет; также принимается string `#RRGGBB`. Яркость задаётся через `intensity` |
| `flicker` | float | 0–1; 0 полностью останавливает мерцание |
| `height` | float | Необязательная высота лампы над землёй: 1–200 вертикальных единиц мира. Без неё приложение подбирает высоту по источнику |
| `enabled` | bool | Необязательное включение источника, по умолчанию `true`. `false` выключает источник, сохраняя его запись и ID |
| `manualPosition` | bool | Необязательная ручная позиция, по умолчанию `false`. При `true` используется точка `Lights`, без автоматической привязки к лампе рисунка здания |

Значения цвета/мерцания по умолчанию:

| `kind` | Цвет | `flicker` | Что рисуется |
| --- | --- | --- | --- |
| `lantern` | `#ffd28a` | 0.04 | Свет поверх уже нарисованного фонаря; новый корпус не добавляется |
| `torch` | `#ffb45d` | 0.12 | Стойка днём и ночью; пламя и свет ночью |
| `glow` | `#8adbd0` | 0 | Цветное свечение без стойки |

**Lights** может быть объектным слоем либо группой с вложенными слоями `Torches`, `Lanterns`, `Glows`. У объектных слоёв допустимы **Manual** и **Top Down**. Имя `Lights` чувствительно к регистру. Разные группы метаданных не вкладываются друг в друга. Собственные смещения слоя, параллакс и неполная непрозрачность не поддерживаются. Глазики влияют только на редактор; выключайте источник через `intensity: 0`.

Точка **Lights** стоит на изображении лампы. Её опора на земле для расчёта теней — `(x, y + height)`, пламя остаётся в исходной точке. `height` — Custom Property типа **float**, а геометрические Width/Height самой точки остаются нулевыми.

Для известных PNG лампы привязываются к изображению через `siteImagePoint`: перенос, масштаб и поворот выбранного Tiled-уровня применяются также к свету. `home-lantern` следует нарисованному фонарю каждого из пяти уровней дома; его яркость, цвет и радиус по-прежнему можно задать в **Lights** (сейчас радиус 135). Пока `manualPosition` отсутствует или равен `false`, перенос этой точки не отделяет лампу от рисунка. При `manualPosition=true` свет использует авторские X/Y независимо от стекла и привязки к зданию. Для остальных изображений без такой привязки точки **Lights** остаются мировыми координатами. Для совместимости `role: light` + `siteId` вне **Lights** даёт обычный фонарь с радиусом 70; источник из **Lights** ближе 2 единиц к нему предотвращает дублирование. Новые источники удобнее делать через **Lights**.

Лампа, привязанная к зданию, пока не перекрывается объёмами **своего** здания: это приближение наружного фонаря, чтобы условный объём дома не погасил его целиком. Другие объекты её свет перекрывают. Собственную стену позади фонаря и самозатенение дома такой подход точно не воспроизводит.

## Разметка теней в Tiled

**Lighting** — обычная папка. Внутри **ShadowCasters** хранится геометрия, перекрывающая свет, внутри **ShadowReceivers** — поверхности, на которые проецируется тень. Обе сущности могут быть объектными слоями или папками с вложенными слоями; имена чувствительны к регистру. Они полностью самостоятельны и не читают `Occluders` или `TreeInteractions`.

1. В **ShadowCasters** инструментом **Polygon (P)** нарисуйте **проекцию объёма на землю** и задайте уникальный Name, например `oak-trunk`. Контур кроны на рисунке — вертикальный силуэт, его сюда копировать не следует. Для ствола нужен маленький контур у корней; для кроны — более широкий контур над той же опорой с положительным `baseHeight`.
2. Укажите обязательный Custom Property `height` (**float**). Это толщина объёма вверх от `baseHeight`, а не координата верхушки. Все высоты измеряются в вертикальных единицах мира; ширина/высота объекта Polygon остаются нулевыми.
3. В **ShadowReceivers** обведите видимую землю пробного участка. Дома, кроны и прочие передние поверхности обходите отдельными полигонами. В текущем прототипе этот участок принимает тени при `height: 0`.
4. Для состояния здания добавьте **обоим** соответствующим контурам `siteId` и `level`. Данные должны ссылаться на существующий визуальный уровень. При переключении уровня меняются объём и поверхность без изменения исходной карты.
5. Сохраните `.tmj`, выполните `npm run world:export`, затем `npm run world:check`. Экспорт сохраняйте вместе с картой.

| Свойство | Тип Tiled | Ограничение и значение по умолчанию |
| --- | --- | --- |
| `height` у caster | float | Обязательно: больше 0, не больше 300 |
| `baseHeight` у caster | float | Не меньше 0; по умолчанию 0. Сумма `baseHeight + height` не больше 400 |
| `opacity` у caster | float | 0–1, по умолчанию 1. Для полупрозрачной кроны можно уменьшить |
| `softness` у caster | float | 0–12, по умолчанию 2. Мягкость края статической тени |
| `height` у receiver | float | 0–300, по умолчанию 0. Высота горизонтальной принимающей плоскости |
| `siteId` + `level` | string + int | Необязательная пара: ID здания и существующий уровень его рисунка |

Имена — латинские строчные буквы, цифры, дефис или подчёркивание, начиная с буквы; уникальны внутри своего вида. `role` не нужен. Class/Type можно оставить пустым либо указать `ShadowCaster` / `ShadowReceiver`. Допускаются простые вогнутые полигоны; самопересечения, повторные вершины и нулевая площадь отклоняются. Лимиты: **128 casters**, **32 receivers**, **64 вершины** на контур. Для числовых свойств также принимается Tiled int.

Receiver задаётся **в координатах нарисованной поверхности на своей высоте**; caster — в проекции на землю. Геометрия умеет проецировать тень на заданную высоту, но **текущий рендер и готовая разметка рассчитаны на землю с `height: 0`**. Выбор видимой поверхности по глубине ещё не реализован: при наложении земли и поднятого receiver обе плоскости влияют на маску; направленная тень рисуется до зданий и перекрывается их PNG. Пока не размечайте крыши поверх земли как готовые принимающие поверхности. Освещение стен, наклонных крыш и самозатенение сложных зданий требуют отдельного этапа. Пустые слои добавляют пустые коллекции, глазики скрывают разметку только в Tiled.

## Сравнение в DEV

Откройте **Студию** кнопкой **Студия** рядом с **DEV**. При входе включаются тени, ночной предпросмотр и черновик; большая карта открывается при необходимости. **Вид и легенда** содержит день/ночь, направление и высоту солнца, качество и **Показывать рассчитанные тени** для сравнения A/B. **Черновик / Сохранённое** сравнивает текущие правки с последней подтверждённой разметкой файлов проекта; после автосохранения сравнение использует уже записанный результат. Если запись проекта недоступна, сохранённой основой остаётся экспорт, загруженный при запуске. В режиме **Сохранённое** редактирование заблокировано, черновик не удаляется. Разметку можно показать всю, только выбранную или скрыть. Дополнительные прежние настройки, включая **Ночь у костра** и тестовую лампу, остаются в **DEV → Сцена → Свет**. Это предпросмотр без изменения аккаунта; геометрию и источники черновика можно отдельно перенести в Tiled.

- **Направление** и **Высота солнца** управляют направленным источником; по умолчанию **225° / 40°**. Низкий источник удлиняет тень. Это ручная проверка, а не вычисление астрономического положения солнца.
- **Качество света**: **Бережный** (`low`) и **Детальный** (`high`), по умолчанию Бережный.
- В прежнем **DEV → Сцена → Свет** настройка **Контуры и высоты объектов** показывает принимающие поверхности, объёмы и высоты ламп; в студии используются собственные направляющие выбранного элемента.
- **Тестовая лампа** позволяет менять X, Y и высоту. Её X/Y задают **точку на земле**, в отличие от точки Lights в Tiled; светящаяся отметка находится на `y − height`.

Проверьте поворот и удлинение тени дома, отдельные тени ствола/поднятой кроны и движение тени Мохлика перед костром. Второй источник может подсветить тень первого: блокировка рассчитывается отдельно для каждой лампы.

## Ручная настройка в DEV

Студия — специальный режим редактирования над открытой картой. На компьютере дерево **Объекты** и **Свойства** расположены в отдельных панелях: выбор обновляет инспектор, список остаётся на месте. На телефоне панели переключаются вкладками. Поиск, фильтр, раскрытые папки и прокрутка списка сохраняются при переходе к свойствам. **Показать выбранное** раскрывает путь к элементу в списке, **Найти · F** направляет камеру к нему. Это DEV-инструмент; он не изменяет аккаунт.

Дерево группирует разметку в **Здания → название → уровень**, **Деревья → дерево → ствол/крона**, **Камни**, **Свои объёмы**, **Поверхности земли**, **Источники света** и **Удалённые / выключенные**. Поиск учитывает имя, ID и названия родительских папок; фильтры **Все / Объёмы / Свет / Земля / Правки** не превращают дерево обратно в длинный плоский список. Папки формируются по назначению разметки, не добавляют новые папки в Tiled.

### Что означают контуры

| Цвет | Что редактируется | Что меняется |
| --- | --- | --- |
| Фиолетовый | Объём `ShadowCaster` | Форма препятствия для света и его высота; он отбрасывает тень |
| Синий | Поверхность `ShadowReceiver` | Область земли, на которой принимаются рассчитанные тени |
| Золотистый | Источник `Lights` | Положение лампы, её высота и радиус светового пятна |

**Синие участки поляны — принимающая земля, а не части дома или препятствия для ходьбы.** Несколько полигонов позволяют обойти уже нарисованные дома, деревья и передние поверхности. Само разделение не задаёт отдельные типы света: соседние поверхности обычной земли работают на одной высоте 0. Обычно их границы должны покрывать нужную землю без случайных пробелов. Для исправления границы выберите поверхность в папке **Поверхности земли** и передвиньте точки инструментом **Контур · P**; для переноса целиком используйте **Двигать · G**. Высота поверхности 0 — обычная земля; поднятые поверхности пока экспериментальны, ограничения рендера описаны выше.

По умолчанию показывается выбранная разметка; синие поверхности остальных участков скрыты. В настройках вида можно показать все контуры, только выбранный или скрыть их, отдельно включить объёмы и поверхности. Скрытие направляющих не удаляет геометрию и не выключает тени.

### Редактировать и удалять

**Добавить элемент** создаёт объём тени или поверхность земли в центре свободной части карты. Новый прямоугольник служит начальной формой: поправьте его точки и высоту под рисунок. Источники ставятся на карту отдельно. Студия меняет только геометрию освещения и `Lights`; `Occluders`, `TreeInteractions`, игровые коллизии и PNG остаются прежними. Условия `siteId`/`level` существующих объектов сохраняются; новую привязку к состоянию здания задавайте в Tiled.

1. Выберите объём в дереве или инструментом **Выбрать · V** на карте. Для дома **Показать уровень N** включает соответствующий рисунок в DEV; аккаунт не меняется. На карте выбираются объёмы активного состояния здания. **Двигать · G** переносит весь контур.
2. Инструментом **Контур · P** перетаскивайте пронумерованные точки. У объёма основной контур задаёт горизонтальную проекцию на землю; если включён каркас, он показывает его высоту. В инспекторе **Выбранная точка**, **X точки / Y точки** позволяют ввести координаты. **Шаг** задаёт привязку: нет, 1, 5 или 10 единиц карты.
3. **Высота · H** меняет высоту и основание ручками на карте. Поля **Высота**, **Основание**, **Верх** задают толщину, низ и верх объёма. Например, основание 20 и высота 50 дают верх 70. Основание 0 означает объём от земли. Это единицы карты, не метры; размер PNG не меняется.
4. В **P** нажмите на ребро выбранного объёма или поверхности, чтобы добавить точку и сразу потянуть её. **Добавить точку** в инспекторе делит следующее ребро пополам; **Удалить точку** удаляет выбранную вершину. Допускаются 3–64 вершины внутри карты, без совпадений, самопересечений и нулевой площади. Неверная правка оставляет последнюю допустимую форму и показывает объяснение.
5. В разделе **Тень** задаются плотность 0–1 и мягкость 0–12. Для кроны используйте широкий контур над опорой с положительным основанием; для ствола — маленький контур от земли. Толщина объёма не больше 300, верх не больше 400.

**Удалить объём тени** убирает препятствие для света; дом или дерево на рисунке остаётся. **Удалить поверхность** убирает принимающую область, а не изображение земли. Исходная удалённая геометрия появляется в **Удалённые / выключенные**, где её можно восстановить до применения в проект; общее Undo/Redo также отменяет удаление. После записи удалённой геометрии в проект она уже отсутствует в его исходнике, но история текущей сессии позволяет отменить операцию и снова сохранить её.

Для нового источника выберите **Фонарь / Факел / Свечение** в **Объекты → Добавить элемент**, затем нажмите на карту инструментом **Источник · L**. X/Y источника — центр лампы или пламени, а не опора на земле; опора для теней находится на `y + height`. В **Свойствах** задаются включение, яркость 0–2, радиус больше 0 и не больше 500, цвет, высота 1–200 и мерцание 0–1. Высота необязательна: без неё действует подбор по типу/привязке источника. **G** перемещает источник, **H** меняет его высоту; ручка радиуса позволяет менять световое пятно. Перенос привязанной лампы, включая ввод X/Y, ставит `manualPosition=true`: свет больше не следует стеклу рисунка здания.

**Дублировать** создаёт отдельный источник с новым ID и ручной позицией. Удаление исходного источника сохраняет выключенную запись с `enabled=false` в **Удалённые / выключенные**; источник, ещё не записанный в проект, удаляется целиком. Удаление исходной записи через сырой JSON может вернуть автоматически добавляемую лампу здания, поэтому для отключения используйте `enabled=false`.

Перетаскивание пустого места или инструмент **Камера** перемещает карту; **Space** временно включает перемещение камеры поверх текущего инструмента. Колесо мыши и жест двумя пальцами меняют масштаб. Если второй палец появился во время правки, она отменяется и начинается жест камеры. Сочетания не перехватывают ввод в текстовых и числовых полях.

| Действие при фокусе на карте | Клавиши |
| --- | --- |
| Выбрать / двигать / контур / высота / новый источник | **V / G / P / H / L** |
| Временно перемещать камеру | Удерживать **Space** |
| Найти выбранный объём или источник | **F** |
| Отменить / повторить правку | **Ctrl/Cmd+Z / Ctrl/Cmd+Shift+Z** |
| Удалить выбранную вершину в P; без выбранной вершины — элемент | **Delete** или **Backspace** |
| Сохранить черновик и запросить запись в проект | **Ctrl/Cmd+S** |
| Отменить текущую правку; без активной правки закрыть студию | **Esc** |
| Сдвинуть вершину в P, объём в G или выбранный источник на шаг привязки (без неё — 1) | **Стрелки** |

В панели также есть **Отменить**, **Повторить** и сброс выбранного объёма, поверхности или источника. Объёмы, поверхности и источники используют общую историю Undo/Redo. Перетаскивание или изменение числового поля отменяется как одно действие; история содержит до 100 действий и не сохраняется после перезагрузки. В числовом поле **Enter** завершает ввод, **Esc** отменяет текущую правку поля.

### Как сохраняется работа

В студии видны **два независимых статуса**: черновик браузера и файлы проекта. Завершённая правка автоматически записывается в `localStorage` этого браузера; во время перетаскивания показывается ожидание, запись выполняется после завершения жеста. При ошибке хранилища статус сообщает об ошибке, доступна кнопка **Повторить сохранение черновика**. Черновик восстанавливается при открытии на той же исходной разметке; Undo/Redo сохраняется только в текущей сессии.

При `npm run dev:local` или локальном `dev:lan` студия подключается к `/api/dev/world-studio`. После завершённой правки и паузы около **800 мс** она автоматически обновляет **оба файла**:

- `world/tiled/forest.tmj` — исходную разметку Tiled;
- `features/world/tiled/forest.generated.json` — проверенный экспорт для игры.

**Проект сохранён** появляется после ответа сервера о записи; статус черновика сам по себе не означает запись `.tmj`. Запросы выполняются последовательно: правки, сделанные во время записи, ждут её подтверждения и сохраняются следующим запросом. **Сохранить сейчас** или **Ctrl/Cmd+S** завершает жест, сохраняет черновик и сразу запрашивает запись проекта. Флажок **Автоматически сохранять в проект** ставит запись файлов на паузу, не отключая черновик; ручное сохранение остаётся доступно. В Sites и при недоступном локальном endpoint остаются черновик и JSON, без обещания записи файлов.

Запись экспорта может вызвать обновление модулей Next без перезагрузки страницы — HMR/Fast Refresh. В локальном DEV рабочая сессия сохраняет выбор, Undo/Redo, инструмент и настройки предпросмотра; после обновления студия заново читает ревизию файлов. Собственная подтверждённая запись не сбрасывает сессию. Внешние изменения принимаются автоматически только при отсутствии несохранённых правок и активного жеста; иначе появляется конфликт. Кеш сессии находится только в открытом браузере и не используется при серверном рендеринге или в production. Полная перезагрузка страницы восстанавливает сохранённый черновик, но начинает новую историю Undo/Redo.

Изменения остаются в рабочей папке проекта; студия не делает Git-коммит, push, деплой или запись аккаунта. Перед работой сохраните и закройте карту в Tiled. Открытая несохранённая копия Tiled может позднее затереть новую `.tmj`; после работы студии откройте карту заново. Сохраняйте в Git `.tmj` вместе с `forest.generated.json` и проверьте `npm run world:check`.

Локальный endpoint работает только в development, с того же origin на localhost или частном адресе LAN, и пишет только эти фиксированные пути. Каждый запрос проверяет точную ревизию карты и `before`/`after` объектов; вся новая карта компилируется до записи. Замена каждого файла выполняется через временный файл и rename; при ошибке второй записи первая откатывается, если её ещё не изменил другой редактор. Это защита от ошибок записи, а не транзакция двух файлов на случай аварийного завершения процесса.

При конфликте с правками Tiled или другого окна появляется **В проекте есть другие правки**: запись останавливается, черновик остаётся в браузере. **Проверить и повторить** заново сверяет данные, не принуждает сервер перезаписывать конфликтующую версию. Сначала сохраните нужные правки в JSON и сверяйте их с актуальной картой; автоматического слияния и обхода проверки нет. Сетевая ошибка также сохраняет черновик; повтор запроса использует прежний ключ, чтобы не применять одну операцию дважды.

Чтобы принять файлы проекта при конфликте, выберите **Загрузить версию проекта**. После предупреждения **Скачать копию и загрузить проект** сначала скачивает полный снимок текущей работы или исходный текст непрочитанного черновика, затем запрашивает свежую версию. Только успешное чтение и проверка заменяет черновик; ошибка загрузки или новые правки во время запроса оставляют его на месте. **Оставить черновик** отменяет выбор, а **Проверить и повторить** само по себе не отбрасывает правки.

### JSON и ручное применение

**Сохранение и резервная копия → Скачать JSON** скачивает `world-studio-backup.json`: полный снимок текущих **объёмов, поверхностей и источников**, включая уже записанные в проект. Он не становится пустым после автосохранения. Формат снимка имеет `type: "world-studio-backup"`, `schemaVersion: 1`, ID и размеры карты; это самостоятельный формат, не прежний patch v1. PNG, коллизии и другие слои Tiled в него не входят.

**Загрузить JSON** принимает снимок или patch до 1 МБ. Снимок заменяет текущую разметку освещения после проверки ID/размеров карты, всех элементов, геометрии и условий уровней; восстановление можно отменить. При включённой записи проекта восстановленная разметка также попадёт в `.tmj` после обычного автосохранения. Перед заменой другой работы скачайте её копию.

**Скачать патч для Tiled** сохраняет отдельный `studio-patch.json` формата **v3**, который содержит только разницу с подтверждённым исходником: операции создания, изменения и удаления **объёмов, поверхностей и источников** с `before`/`after`. Для нового элемента `before=null`, для удаления `after=null`; исходная выключенная лампа остаётся записью `enabled=false`. Кнопка доступна при несохранённой разнице; после полного автосохранения patch пустой — полная копия хранится в снимке выше. Импорт файлов и браузерных черновиков **v1/v2** сохранён: v1 содержит обновления объёмов, v2 добавляет операции источников, v3 — операции объёмов и поверхностей.

Импорт patch проверяет исходные `before`, свободные ID создаваемых элементов и текущую разметку; устаревший patch отклоняется целиком. Сброс выбранного элемента возвращает текущую подтверждённую разметку проекта; после уже выполненного автосохранения более раннюю правку отменяйте через Undo текущей сессии или Git. Если браузерный черновик не удалось восстановить из-за конфликта, доступна **Скачать непрочитанный черновик**: исходный текст сохраняется до явного сброса или успешного импорта.

Если автосохранение проекта недоступно, примените JSON вручную:

1. Скачайте patch `studio-patch.json` и укажите его путь в команде. Полный `world-studio-backup.json` восстанавливается через **Загрузить JSON** в студии, CLI ожидает patch.
2. **Сохраните и закройте карту в Tiled.** После отдельных изменений Tiled сначала выполните `world:export` и сверяйте JSON с актуальной разметкой.
3. При желании проверьте файл без записи, затем примените его:

   ```bash
   npm run world:lighting:apply -- ./studio-patch.json --check
   npm run world:lighting:apply -- ./studio-patch.json
   npm run world:export
   npm run world:check
   ```

4. Откройте карту заново и обновите приложение. Если значения черновика уже совпадают с экспортом, старый черновик удаляется автоматически.

CLI читает актуальную `.tmj`, переносит полигоны и параметры `Lighting/ShadowCasters` / `Lighting/ShadowReceivers`, а также точки `Lights`, включая `enabled` и `manualPosition`. В v3 доступны создание и удаление полигонов; ID и условия существующих объектов сохраняются. Остальные слои не меняются. `--check` не записывает файл. Повтор уже применённого v3-файла допускается, только если текущие значения совпадают с его `after`; конфликтующая разметка не перезаписывается. Прежние v1/v2 сохраняют строгую проверку `before`.

## Как формируется кадр

1. Рисуются фон, вода и земля. На картах с новой разметкой направленный источник проецирует тени на `ShadowReceivers` перед зданиями.
2. Рисуются здания, стойки факелов, герой, бабочки и птицы.
3. Локальные источники получают собственные маски перекрытия; итоговое ночное освещение накладывается через `multiply`. При выключенном прототипе или отсутствии принимающих поверхностей `drawForestLighting` использует прежнюю общую текстуру: холодный тон `#2d3d62`, лунный градиент и цветные пятна.
4. Светлячки и воздушный дождь рисуются после затемнения. `drawForestLighthouseBeams` добавляет мягкие лучи маяка, `drawForestLightEmitters` — свечение стекла, огонь и небольшие ореолы; `drawBuildingDetails` — локальное тепло размеченных окон и дым из труб. Стекло осветляется полупрозрачным `screen`, поэтому рама и переплёт остаются видимыми.

Шахта уровня 1 получает свет точно в подвесном фонаре справа от входа. У мастерской визуального уровня 2 светятся фонарь и окно слева. Маяк уровня 1 испускает два противоположных луча: полный оборот занимает 36 секунд, направление сжато по вертикали под перспективу карты. Разрушенные варианты и мастерская без нарисованного фонаря не получают свет из работающего варианта. Это декоративный эффект, он не открывает будущие игровые функции маяка.

Луч — общая кешированная текстура 384×144; каждый кадр только два её поворота/масштабирования. Размытие и пересоздание холста в кадре не используются. Свет работает только ночью и плавно следует общей степени ночи. Пауза замораживает угол; «Меньше движения» оставляет статичные лучи без мерцания. Скрытие зданий скрывает также их лампы и лучи, даже если камера видит только конец луча.

Прежние декоративные тени домов в `grounding.ts` строятся по прозрачности PNG и нижней части коллизии. Контактная, окружающая и короткая падающая тени запекаются в две кешированные текстуры до 512 px; это отдельное приближение, его направление не связано с лампами. Геометрические тени прототипа рассчитываются в `forest-shadow-geometry.ts`.

Кэш геометрического света получает `geometryRevision`: неизменная геометрия возвращает готовые буферы без сериализации всех контуров на каждом проходе. Новая ревизия, смена коллекций, размеров сцены или режима теней зданий обновляет кэш; выбор объекта и вершины в редакторе ревизию не меняет. Старые вызывающие места без ревизии сохраняют проверку через сериализацию. Для движущихся персонажей известный выпуклый объём проецируется одним контуром вместо набора перекрывающихся треугольников; статические вогнутые формы по-прежнему учитывают выемки. Временный буфер локальной лампы ограничен её световым пятном и растёт до наибольшего использованного пятна; на каждом проходе очищается и копируется только текущая область.

Маски движущихся объёмов и итоговое поле света пересобираются при изменении влияющих источников/персонажей; неизменные данные возвращают готовый результат. Для локального света пропускаются пятна вне области камеры с запасом под края. Для направленных теней учитывается проекция объёма: персонаж вне экрана сохраняется в расчёте, если его тень может войти в видимую область. Камера не изменяет геометрию Tiled; это отсечение работы рендера с сохранением видимых теней, а не отключение жизни жителей вне экрана.

Окна 3–5 уровней светятся только внутри своего полигона, а дым 4–5 использует общий таймер сцены и маленькую кешированную текстуру: перекрывающиеся сегменты образуют непрерывную струю, узкую у трубы и расширяющуюся с рассеиванием выше. Плотность и изгиб плавно движутся вверх; нижний край ограничен выходом трубы. Пауза замораживает дым, reduced motion отключает его. При скрытии здания эффекты также исчезают.

В автоматическом режиме ночь — **19:00–07:00 по часовому поясу профиля**. Переход сглаживается общими часами сцены. Пауза останавливает эти часы, «Меньше движения» убирает мерцание. DEV переопределяет время только для предпросмотра.

Прототип использует **Canvas2D** и световые буферы с длинной стороной до **512 px** в low и **768 px** в high. Статические маски кешируются отдельно для источников, движущиеся персонажи добавляются к текущему кадру. Кэш ограничен и принадлежит сцене; перенос камеры не создаёт новую геометрию. Пиксели фона не считываются, копия всей исходной картинки для каждого источника не создаётся. Это геометрический расчёт теней от условных объёмов, а не WebGL2-рендерер.

У прежнего освещения отдельная текстура до 768 px и не более четырёх кешированных вариантов на сцену. Мерцают небольшие эмиттеры. При скрытии зданий в DEV привязанные источники и обычные точки внутри рамок зданий также скрываются.

## Частые изменения

- **Темнее весь лес:** меняйте базовую заливку и лунный градиент в `ambient` нового painter и в `lightTexture` прежнего режима. Сравнивайте одинаковый участок в круге и на карте; не добавляйте независимую тёмную заливку в каждом виде.
- **Слишком большой засвет от одного факела:** уменьшайте его `radius`, затем `intensity` в Tiled. Не меняйте общий ночной слой ради одной лампы.
- **Более спокойный огонь:** уменьшайте `flicker`. Форму пламени меняйте в `drawForestLightEmitters`; стойку — в `drawForestLightFixtures`.
- **Новый вид света:** добавьте значение в `WorldLight`, валидацию/defaults в `compileLight`, рисунок и тесты. Новое произвольное свойство Tiled без изменения экспортёра будет отклонено.

**Ограничения прототипа:** фон уже содержит нарисованное освещение и тени, которые не поворачиваются вместе с источником. Новая разметка покрывает пробный участок; за его пределами нет автоматически придуманных препятствий. Нет WebGL2, карт нормалей, освещения наклонных крыш/стен, отражений факелов в воде или света от каждой светлячковой особи. Лучи маяка остаются атмосферным эффектом и не обрезаются геометрией. `WaterExclusions` не блокирует свет, стойки факелов не добавляют коллизии. Для свободно меняющегося дневного солнца потребуется более нейтральный исходный рисунок.
