# Как развивать мир с фиксированными постройками

Статус: первый этап новой карты в `feature/mochlik-tiled-world`. Основная игра и `/prototype/tiled-world` используют один полный рисунок леса. Прежние постройки, метки, маршруты и эффекты скрыты; игровая модель и сохранённый прогресс не меняются. Прототип остаётся изолирован от серверных команд. Архитектура фиксированных участков ниже описывает следующие этапы.

## Вывод

Для нашего мира подходит **авторская карта с фиксированными участками и независимыми состояниями**. Земля, постройки, игровые данные и камера должны быть разными сущностями. Сетка 10×10 не нужна для улучшения домов: участок определяется смыслом объекта, его полной тенью и окружением, а не случайной границей квадрата.

Tiled подходит как визуальный редактор этой разметки. В нём можно видеть рисунок, размещать участки, задавать входы, выбирать состояния для просмотра и отмечать пути. Он сохраняет данные; загрузку изображений, клики, камеру и игровую логику выполняет приложение. В этом примере достаточно Canvas 2D без новой зависимости от игрового движка.

**На практике:** один раз подготовить место для дома → создать изображения его уровней в одинаковой рамке → описать их в Tiled → при улучшении заменить только состояние этого места. Добавление мастерской не требует новой версии всего леса.

## Что можно проверить сейчас

```bash
git switch feature/mochlik-tiled-world
npm ci
npm run world:check
npm run dev:local
```

Открыть `http://localhost:3000/prototype/tiled-world`. Для телефона в той же сети — `npm run dev:lan` и адрес компьютера с портом 3000. HTTPS и установленная PWA для самого примера не нужны.

1. Рассмотреть новую карту, переместить и приблизить её.
2. Сравнить центральную поляну в кружке с той же областью большой карты.
3. Включить разметку и проверить границу круглой камеры.
4. Сбросить вид или перезагрузить страницу: настоящий прогресс не меняется.

Карта для редактора: `world/tiled/forest.tiled-project`, затем `forest.tmj`. Полный порядок работы и настоящий снимок редактора — в [инструкции Tiled](tiled-editor.md).

## Состав сцены

| Часть | Что хранит | Когда меняется |
| --- | --- | --- |
| Земля | Лес, тропинки, постоянное окружение | При добавлении или переработке региона |
| Участок | Постоянный ID, рамка, точка опоры, вход, области клика и препятствия | При редактировании карты |
| Состояния участка | Изображения уровней одного дома | При добавлении новых улучшений |
| Прогресс игрока | Уровень каждого участка | После подтверждённой игровой команды |
| Камера | Положение и масштаб просмотра | При перетаскивании и увеличении |

Текущая сцена содержит фон и фокус центральной поляны `(455, 480, 350, 350)` в координатах мира 1254×1254. Построек и маршрутов пока нет. Физическое разрешение фона — 2560×2560; оно не меняет логический масштаб мира.

Будущий рисунок участка может включать небольшой кусок земли. Это удобно для фиксированных мест: можно менять корни, тень, крыльцо, кусты и сам дом одновременно. Такая картинка непрозрачна и готовится для конкретного места. Перетащить её на другую поляну технически можно, но подходящий фон и стыки придётся подготовить заново.

Если позже понадобятся проходы за стенами, высокие деревья перед персонажем или отдельные анимации двери, соответствующий участок надо разделить на землю, объект с прозрачностью и передний план. Не требуется заранее вырезать каждый куст всего леса. Перед включением движения нужны новые проверенные маршруты; прежняя домашняя тропа удалена. Полигоны препятствий не превращают растровый лес в полноценную навигационную карту.

## Как добавлять новое место

1. Выбрать площадку и самый большой допустимый размер будущего улучшения.
2. Зафиксировать рамку, перспективу, направление света, масштаб деталей и неизменный вход.
3. Подготовить пустое/начальное состояние и нужные улучшения. Внешняя кромка каждого состояния должна совпадать с окружением; внутри картинка полностью заменяет прежний вид.
4. Добавить изображения и участок с новым ID в Tiled, отметить вход, область клика и препятствия. Движение добавлять только по визуально проверенному пути.
5. Выполнить экспорт и проверить оба вида, крайние уровни, стыки и ночь.
6. При интеграции в основную игру связать постоянный ID участка с существующей серверной моделью и командой улучшения.

Художественная подготовка остаётся реальной работой. Редактор помогает хранить расположение и свойства, но не рисует совместимые дома автоматически. Подробные запросы, источники и ограничения новых рисунков: [дом](tiled-home-art-prompts.md), [мастерская](tiled-workshop-art-prompts.md).

## Редактирование изображений и разметки

Источник карты — `art/world/prototype/forest-ground.png`. Полный экспорт без потерь — `public/world/prototype/forest-ground.webp`. Отдельных уменьшенных карт и детальных полян нет. Размеры и порядок работы описаны в [каталоге изображений](../../art/README.md).

```bash
# После изменения PNG — полный экспорт без потерь:
node scripts/prepare-world-assets.mjs
# После экспорта изображения или изменения карты Tiled:
npm run world:export
# Проверка соответствия JSON, Tiled и изображений без изменения файлов:
npm run world:check
```

`world:export` обновляет метаданные размеров в `forest.tmj` и ссылки с хешами в `forest.generated.json`, не меняя и не перекодируя PNG/WebP. Пропорциональное увеличение разрешения сохраняет размеры здания на карте; изменение пропорций отклоняется. После обновления размеров переоткройте карту в Tiled. В Git сохраняйте изменённые PNG, WebP и оба файла разметки.

| Файл / каталог | Роль |
| --- | --- |
| `art/world/prototype/` | Единственный PNG карты для редактирования; браузер его не загружает |
| `public/world/prototype/` | Единственный WebP карты для редактора, основной игры и прототипа |
| `world/tiled/forest.tmj` | Авторская разметка и каталог состояний |
| `scripts/tiled-world.mjs` | Экспорт метаданных и строгая проверка без обработки изображений |
| `scripts/lib/tiled-world.mjs` | Проверка и перевод поддерживаемого формата Tiled |
| `features/world/tiled/forest.generated.json` | Проверенные данные приложения, не редактируются вручную |
| `features/world/tiled/renderer.ts` | Единая сцена, две камеры, загрузка, освещение и движение |

Компилятор намеренно поддерживает ограниченный набор возможностей Tiled. Он отклоняет неподдерживаемые трансформации, внешние шаблоны, неоднозначную геометрию и отсутствующие/повреждённые изображения. Он не проверяет художественные стыки и не обязан понимать произвольные `.tmj` из других игр.

Старые изображения дома и мастерской удалены из текущей сцены; новая карта взята из предоставленного PNG без изменений рисунка. Прежние заготовки и рецепт нарезки доступны в [истории `ffd97ca`](https://github.com/NolReaction/zhiv-app/tree/ffd97ca868365e257b6eabe0fed52334a2f86a0a/world/tiled).
## Загрузка, браузер и масштабирование

Текущий фон имеет разрешение 2560×2560. Полный WebP без потерь занимает 3 842 008 байт; это единственный файл карты, общий для обоих видов. Первое открытие загружает полное изображение, уменьшенной стартовой копии нет. Простое увеличение числа пикселей при будущей переработке новых деталей не добавляет.

На странице есть начальный экран загрузки и повторная попытка. Обе камеры используют одно загруженное изображение. В чистой сцене нет анимаций; перерисовка нужна при изменении камеры, размера окна или разметки. Поддержка состояний участка в загрузчике сохраняется для следующего этапа.

Ссылки содержат хеш изображения в `?v=`, поэтому новая версия имеет новый URL. В пределах страницы работает общий кеш изображений. Service worker сохраняет загруженные версии карты отдельно от обновлений оболочки; полный офлайн-сценарий прототипа требует отдельной проверки навигации и доступности его модулей.

При росте региона можно разделить **землю** на загружаемые части и выбирать видимые камерой. Это отдельная оптимизация памяти и загрузки, она не должна определять границы домов. Сейчас одна небольшая карта не требует такого усложнения. Сохранённые ID и формат состояния остаются прежними при будущей смене способа отрисовки.

Ориентация в примере не блокируется и принудительно не меняется: страница адаптируется к размерам окна. Наличие горизонтального режима не требует поворачивать компьютерный интерфейс. Возможность принудительной блокировки в вебе зависит от браузера и режима запуска; это отдельное продуктовое решение после проверки на реальных устройствах.

## Что переносить в основную игру следующим этапом

1. Согласовать художественный вид уровней и размеры изменяемых участков по этому примеру.
2. Подготовить реальные уровни: производственная модель уже допускает дом 1–5 и мастерскую 0–3. В новой карте состояния ещё не размещены. Нельзя обрезать существующий прогресс до набора готовых рисунков.
3. Подключить единую сцену к действующим данным, а затем вернуть в неё нужные погодные эффекты, предметы и взаимодействия. Кружок и открытая карта должны использовать один источник состояния.
4. Отдельно определить цель игрового цикла и переработать HUD/первое обучение. Новый формат карты облегчает развитие контента, но сам по себе не отвечает пользователю, зачем заходить в мир.

Переход на Phaser, KMP или нативную оболочку не является обязательным условием этой архитектуры. Данные разметки и рисунки можно сохранить при смене платформы; React-интерфейс и Canvas-реализацию при нативной переписи придётся адаптировать или заменить. Решение о платформе имеет смысл принимать после проверки самого игрового опыта, а не ради возможности заменить дом на карте.

Результаты проверок и их границы: [отчёт](tiled-world-validation.md).
