# Гардероб

«Ещё → Гардероб» разделён на «Мои вещи» и «Магазин». Категории — шапки, шарфы, мох; поиск по названию и фильтр монет/жемчуга. Примерочная рисует обычный спрайт без отдельного цикла анимации. Карточки расположены в две колонки, вкладки поддерживают клавиши стрелок, Home и End. Одежда не даёт преимуществ и не занимает кладовую.

Источник — [catalog.json](../../apps/api/src/main/resources/world/catalog.json), поле `purchase: {currency, amount}`. Стартовые вещи и шляпа за прежнюю коллекцию не продаются. Прежнее владение сохраняется. Добавлены три оттенка мха, три головных убора и три шейных аксессуара; рисунки общие для примерки и игровых занятий. Ивовая удочка остаётся совместимой старой наградой, но не выводится как одежда.

`buy_wardrobe_item` использует `targetId=currency:itemId`, количество 1 и подтверждённую цену во внутреннем номинале (монеты ×10, жемчуг ×50). Жемчужная цена и баланс на экране равны половине внутренних чисел; команда получает полную внутреннюю цену, без потери точности. См. [денежные единицы](currency-units.md). Валюта входит в подпись запроса. Цена, владелец, ревизия, доступность вещи и отсутствие владения проверяются до списания. Общие квитанции хозяйства защищают повтор и конкуренцию запросов. Покупка не создаёт расходуемый товар, её нельзя перепродать или выставить на рынок.

Ktor хранит владение в `EconomyState.wardrobe`, в той же транзакции переносит его в `WorldState.inventory` и поднимает ревизию мира. Чтение мира восстанавливает проекцию; чтение экономики наследует старую одежду. Объединение аккаунтов соединяет наборы без возврата цены дубликатов. Поля JSON имеют значения по умолчанию, новой SQL-миграции нет. Старый endpoint `craft` остаётся закрыт репозиторием. Резервные копии включают оба исходных профиля.

Клиент ждёт подтверждённого владения, затем обновляет мир перед экипировкой. Потеря ответа использует штатный повтор команды; при ошибке обновления мира доступна отдельная повторная загрузка. Команда DEV `grant_wardrobe` существует только в локальном development API.

Основные файлы: `features/world/world-wardrobe.tsx`, `wardrobe.ts`, `features/economy/rules.ts`, `EconomyRules.kt`, `JdbcEconomyRepository.kt`, `JdbcWorldRepository.kt`. Проверки: `tests/wardrobe-purchase.test.mjs`, `EconomyWardrobeTest.kt`, `JdbcEconomyRepositoryIntegrationTest.kt`. Kotlin/JDBC требуют Java25, Gradle и тестовую БД; локальные TS-проверки их не заменяют.
