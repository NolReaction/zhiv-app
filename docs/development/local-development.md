# Локальная разработка и проверки

[Документация](../README.md) · [Архитектура](../architecture.md) · [Правила изменений](../../CONTRIBUTING.md)

## Быстрый старт

Нужен Node.js ≥ 22.13 (CI использует 24). Для Kotlin API — JDK 25 и Docker для PostgreSQL-тестов. Next-разработка работает отдельно от API и не требует PostgreSQL.

```bash
git status --short
git branch --show-current
npm ci
npm run dev:local
```

Откройте `http://localhost:3000`. Если порт занят, Next напечатает выбранный порт. `dev:mochlik` — alias того же Next-запуска. Локальный экран регистрации создаёт тестовый аккаунт; данные в памяти процесса и могут исчезнуть при перезапуске.

После изменения зависимостей используйте `npm ci` по lockfile. В управляемом Sites-окружении предусмотрен `npm run install:ci`: это Bash-скрипт с ограничением времени и проверкой архива Vinext. Он не обязателен для обычного Next-запуска на компьютере.

Next DEV-скрипты явно задают `NODE_ENV=development`, используют webpack и перед запуском сверяют установленные версии Next, React и ReactDOM с `package.json`. Поэтому унаследованное из терминала значение `production` или `test` не скрывает DEV-панель при локальной разработке. Несовпадение версий останавливает запуск с инструкцией переустановить зависимости; production-сборка сохраняет свой bundler. После `git pull` с изменёнными зависимостями сначала остановите прежний сервер через Ctrl+C, затем выполните `npm ci` и запустите его заново.

Перед запуском скрипт создаёт локальный `public/app-status.json` с ID `development` и тем же ID для клиентского кода. Проверка обновлений получает готовый статус вместо повторяющихся 404; прежний ID production-сборки или переменные терминала не запускают перезагрузку DEV. Файл исключён из Git, а команды production-сборки записывают собственный ID заново.

Дерево развития мира открывается отдельно: `http://localhost:3000/branch`. Страница доступна без аккаунта и в production-сборке. Перемещайте схему перетаскиванием, меняйте масштаб колесом или кнопками; поиск и нажатие на узел открывают условия, стоимость и новые возможности. Пунктир обозначает запланированные ветки мира. Это обзор правил, а не личный прогресс игрока.

## Телефон в той же сети

Создайте `.env.local` по [.env.example](../../.env.example), заменив адрес на активный IPv4 компьютера:

```dotenv
NEXT_ALLOWED_DEV_ORIGINS=192.168.1.20
NEXT_PUBLIC_APP_ORIGIN=http://192.168.1.20:3000
```

```bash
npm run dev:lan
```

DEV-сервер рассчитан на доверенную LAN. У студии записи карты нет отдельной авторизации; проверки Host/Origin не удостоверяют устройство или человека. Для работы только на компьютере используйте `dev:local`; не публикуйте DEV-сервер в интернет или недоверенную сеть.

На телефоне откройте `http://192.168.1.20:3000`. В `NEXT_ALLOWED_DEV_ORIGINS` указывается hostname/IP без протокола; несколько значений разделяются запятыми. Этот список дополняет разрешённые по умолчанию `localhost` и `127.0.0.1`, поэтому телефон и локальная вкладка компьютера могут работать одновременно. `NEXT_PUBLIC_APP_ORIGIN` содержит полный origin и используется для ссылок. При другом порте замените его и в адресе, и в настройке; после изменения env перезапустите Next.

Если прежняя версия пишет `Blocked cross-origin request ... /_next/hmr from "127.0.0.1"`, добавьте `127.0.0.1` через запятую: `NEXT_ALLOWED_DEV_ORIGINS="192.168.1.20,127.0.0.1"`, затем перезапустите сервер. Это проверка адреса для горячего обновления Next; она не определяет Git-ветку. `GET / 200` означает, что сама страница загрузилась.

Если не открывается: проверьте одинаковую сеть, актуальный IP, разрешение входящих соединений в firewall и изоляцию Wi-Fi-клиентов. `localhost` на телефоне — сам телефон. Обычный HTTP в LAN подходит для UI; проверка Service Worker/установки PWA требует localhost или HTTPS.

На обычном LAN HTTP браузер может не предоставлять Web Locks. Тогда локальная очередь производства без связи недоступна, а действия при работающем API подтверждаются обычными серверными запросами. То же ограничение действует во вкладке, где очередь уже занята другой вкладкой. Само отсутствие этой возможности не включает значок ошибки связи; реальные ошибки сети, записи на устройство и неподтверждённые действия продолжают отображаться.

### Ошибка «module factory is not available»

Это ошибка регистрации клиентского модуля Next, а не сообщение о повреждении экономики или сохранения. Проверьте версию Next в терминале и в браузерной ошибке: старый процесс, старые зависимости или граф горячего обновления могут давать разные наборы модулей. Остановите сервер через Ctrl+C, выполните `npm ci`, затем `npm run dev:lan` и обновите открытую на телефоне страницу. При локальном входе тестовый профиль хранится в памяти процесса: после перезапуска может понадобиться новый тестовый аккаунт.

Закрытая DEV-панель загружает только лёгкую кнопку; читы и диагностика импортируются по нажатию. Ошибка импорта или отрисовки показывается внутри DEV, сохраняя основной экран. Повторных автоматических перезагрузок нет. Service Worker включён только в production и сохраняет Next static только с `Cache-Control: immutable`; `no-cache`, `must-revalidate`, `no-store` и `private` исключены из кэша статических ресурсов, в том числе при чтении старых записей. Сообщение Next о service worker само по себе не доказывает, что worker участвовал в падении.

## Два контура сборки

| Назначение | Разработка | Сборка | Запуск сборки |
|---|---|---|---|
| Next/VPS | `npm run dev:local` или `dev:lan` | `npm run build:vps` | `npm run start:vps` |
| Sites/Vinext | `npm run dev` | `npm run build` | `npm run start` |

`dev:vps` также запускает Next на `0.0.0.0`, а не контейнеры. `build:vps` создаёт `.next/`; Sites создаёт `dist/`. Sites-скрипты используют Bash; на Windows для них нужен совместимый Bash/WSL. Не заменяйте один контур другим при релизной проверке.

Production-сборка Next сама не запускает Ktor. На VPS маршрутизацию обеспечивает [Caddy](../../deploy/Caddyfile). Без него локальный production API закрыт: `DEV_API_DISABLED` — ожидаемый ответ, а не сломанная БД. Переменная `ENABLE_DEV_API` не снимает эту защиту; локальную имитацию запускайте через `dev:local`/`dev:lan`. Проверка настоящих входа, прав и миграций выполняется через серверный стек; инструкции — [эксплуатация](../operations/operations.md).

## Карта и графика

### 3D-модели на Земле

После `npm run dev:local` откройте `http://localhost:3000/prototype/earth-models`. Страница показывает настоящую карту с башней без аккаунта и GPS; тот же редактор доступен через **DEV 3D** на обычной вкладке «Карта» в development.

Нажмите **«К объекту»**, затем **«Поставить на карте»** и выберите точку. Зелёную точку можно перетаскивать мышью; числовые поля меняют координаты, поворот, высоту и вертикальное смещение. Оранжевый круг показывает регулируемый радиус исключения объёмных зданий под моделью. Правки видны сразу, пересборка `.elm` не нужна.

Черновик сохраняется только в браузере разработки. **«Сохранить в проект»** записывает `features/earth/data/model-placements.json` через локальный dev-сервер Next или Vite, включая доверенную LAN. Кнопка позволяет повторить подключение после ошибки; причина остаётся видимой под ней. Пока DEV 3D открыт на обычной карте, панели близких/приватности и сообщения GPS скрыты, геопозиция приостановлена. Закрытие панели возвращает обычный режим. Панель также умеет импортировать JSON и сбрасывать значения к файлу проекта; сброс записывается в проект отдельным сохранением. Production использует опубликованный JSON, редактор и `/api/dev/earth-models` там закрыты. Подробности и ограничения импортёра — [3D-модели](earth-models.md#редактор-размещения-на-карте).

### Игровая карта Tiled

Во втором терминале:

```bash
npm run world:watch
```

Редактируйте `world/tiled/forest.tmj` и сохраняйте. Watcher обновляет [forest.generated.json](../../features/world/tiled/forest.generated.json) и сохраняет последний корректный результат при ошибке. Однократный экспорт — `npm run world:export`, проверка соответствия без записи — `npm run world:check`. Подробнее: [Tiled](../game/tiled-editor.md), [свет](../game/world-lighting.md).

DEV-панель и `/prototype/tiled-world` доступны только при `NODE_ENV=development`; в production страница прототипа возвращает 404. Тяжёлая часть панели загружается после нажатия **DEV** на главном экране или карте. Панель управляет тестовыми условиями сцены. Выдача тестовых ресурсов отдельно запрещена обработчиком команд и локальным хранилищем вне development. Проверьте и круг главной кнопки, и большую карту: они используют одни данные, но разную камеру.

Если заменили фон `art/world/prototype/forest-ground.png`, из корня выполните:

```bash
node scripts/prepare-world-assets.mjs
npm run world:export
npm run world:check
```

Первый скрипт создаёт полноразмерный WebP без дополнительных потерь; `world:export` обновляет метаданные изображений и сгенерированную сцену. Watcher следит за картой, не за исходными картинками. При изменении размеров изображений заново откройте `.tmj` в Tiled после экспорта. Форматы мастера, PNG объектов и файлы для коммита — [art/README.md](../../art/README.md).

### Разделы DEV

Панель открывается на **«Читах»**: готовое поселение и четыре сворачиваемых набора инструментов (валюта, предметы, постройки, таймеры). **«Герои»** содержит сценки Мохлика, анимации, примерку и Плёску; **«Сцена»** — сценарии, погоду, сад и визуальные уровни зданий; **«Отладка»** — мышление, разметку, пути и переходы приложения. Свет и пауза находятся над разделами просмотра. Стрелки, Home и End переключают вкладки, Tab переводит фокус в выбранный раздел.

### DEV → Читы

**«Готовое поселение»** задаёт точный уровень дома 1–5 и максимальные уровни остальных зданий, достижимые при нём по каталогу и зависимостям. Предварительный список показывает результат; это одна серверная команда `apply_settlement`, защищённая общим owner/revision/requestId. Она может понизить уровни, но сохраняет кошелёк, запасы, снасти, находки и рыночные резервы. Активные задания и незабранные результаты блокируют применение. Сама команда не выдаёт награды; последующая обычная проверка достижений учитывает тестовые уровни, как и после ручной смены постройки. Полученный сверх вместимости запас показывается обычным предупреждением DEV.

На главном экране и большой карте откройте **DEV → Читы** при `npm run dev:local` (или `dev:lan`). Здесь меняется настоящий снимок локального тестового профиля:

| Инструмент | Результат |
|---|---|
| Монеты / жемчуг | Выдача выбранной суммы в кошелёк |
| Предмет и количество | Категории, поиск и рисунок: материалы, рыба, наживки, реликвии |
| Удочки / крючки | Одна постоянная снасть или весь набор; выбор перед рыбалкой |
| Одежда | Одна вещь или весь гардероб без списания валюты |
| Постройка и новый уровень | Мгновенный уровень бесплатно, без требований соседних зданий; дом и кладовая минимум 1 |
| Ресурсы для следующего улучшения | Только недостающие монеты и материалы; обычные условия и таймер сохраняются |
| Убрать ожидание | Стройка, производство, разведка или все задания готовы к получению; результат забирается обычной командой |

Задания выбранного здания нужно получить перед прямой сменой его уровня. Выдача может переполнить кладовую: освободите место или увеличьте её уровень перед получением новых товаров. Визуальная примерка в «Зданиях» независима от прогресса; кнопка «Показывать уровни хозяйства» снимает её.

Выдача рыбы не записывает поимки и не раскрывает книгу; купленный/выданный набор не переписывает уже оплаченную вылазку. Снасти и одежда выдаются без количества, дедуплицируются и не занимают кладовую.

Изменения переживают перезагрузку страницы и не отменяются «Сбросом вида». Перезапуск локального API может удалить тестовый профиль: это память процесса, как и остальной DEV API. Повтор после потери ответа использует прежний идентификатор команды и не выдаёт ресурсы повторно.

Команды идут через отдельный `/api/v1/economy/dev` с проверками режима development, сеанса, origin, владельца, ревизии и идентификатора запроса. Production API и обычные игровые команды читы не принимают. Контракт — `features/economy/dev/dev-model.ts`, исполнение — `lib/dev/economy-store.ts`; проверки — `tests/economy-dev-cheats.test.mjs`, `tests/economy-dev-session.test.mjs` и `tests/world-dev-panel.test.mjs`.

### Тестовые друзья и их лавки

В **DEV → Боты** можно создать до пяти друзей для текущего локального профиля. Это отдельные аккаунты локального API с принятой дружбой, настоящими постройками, одеждой, заданиями, запасами и личными лотами. Панель доступна на главном экране и своей большой карте при `npm run dev:local` / `dev:lan`. Создание бота не меняет уровни и кошелёк игрока.

Быстрая проверка визита и покупки:

1. Создайте бота с домом 2 и выберите его в списке. Кнопкой «В гости» откройте обычный мир друга; он также появится в **Профиль → Друзья**.
2. В «Одежде персонажа» сохраните головной убор, шарф или цвет. «Поселение и постройки» меняет готовый набор улучшений или отдельное здание; эти изменения видны при настоящем визите.
3. В открытой «Личной лавке бота» выберите товар и количество. «Выдать недостающее для партии» пополнит только запасы бота, затем «Выставить лот» создаст настоящую партию по обычным ценовым правилам.
4. Для покупки собственному профилю нужны открытый рынок, деньги и свободное место. Кнопка «Открыть мои читы» ведёт к существующим инструментам игрока; они применяются отдельно. Денежный рынок общий для домов 2–5, но товар должен быть открыт покупателю. Для проверки можно купить доступное сырьё у бота другого уровня.
5. Нажмите «В гости», откройте лавку и купите партию своим персонажем. Покупка сразу появится в своей кладовой. После возврата обновите ботов: товар продан, но выручка ещё не в кошельке бота. В «Личной лавке бота» найдите имя покупателя и нажмите «Собрать»: бот получит монеты с обычной комиссией, место прилавка освободится.

Чтобы проверить собственную продажу без второго аккаунта:

1. Откройте свой рынок → «Моя лавка» → «Новая партия» и выставьте обычный доступный товар.
2. Вернитесь в **DEV → Боты**, обновите список и выберите бота с открытым рынком, монетами и местом в кладовой.
3. В разделе «Покупки у меня» выберите свой лот и нажмите «Бот покупает мой товар». Бот расходует свои монеты и получает настоящие предметы; команда проверяет принятую дружбу и доступ к вашему миру.
4. В своей «Моей лавке» появится имя бота. Нажмите «Забрать монеты», чтобы получить выручку. Повтор проверки потерянного ответа не создаёт вторую покупку или выплату.

В остальных разделах можно переименовать бота, закрыть его мир для друзей, выдать валюту/предметы, запустить обычное производство, стройку или вылазку, убрать ожидание и забрать результат. Обычные задания сохраняют игровые требования; для быстрой настройки уровней используйте готовое поселение. Сбор ягод остаётся отдельным действием: сначала отправить персонажа на сбор, затем получить результат. Удаление с подтверждением очищает только выбранного бота, его дружбу и лавку.

Боты и их сеансы хранятся на локальном API, без переключения аккаунта в браузере. Перезагрузка страницы их сохраняет, перезапуск сервера может удалить. После потери ответа «Проверить результат» повторяет прежний запрос, включая после перезагрузки страницы; до проверки новые команды заблокированы. В production инструменты и endpoint недоступны.

Контракт и клиент: `features/world/dev/dev-bot-model.ts`, `dev-bot-api.ts`, `dev-bot-session.ts`, `use-dev-bots.ts`; интерфейс: `world-dev-bots.tsx`; сервер: `lib/dev/bot-store.ts`, `app/api/v1/dev/bots/route.ts`. Проверки: `tests/dev-bots.test.mjs`, `dev-bot-session.test.mjs`, `world-dev-bots-ui.test.mjs`, `market-payout-dev.test.mjs` и общий production DEV guard.

### Тестовая геопозиция и отметки друзей

На вкладке **Карта → DEV Боты** создайте/выберите друга и нажмите **«Поставить в центр карты»** или **«Поставить рядом со мной»**. Одна команда включает точный показ только выбранного тестового бота его владельцу; после подтверждения панель закрывается и карта фокусируется на боте. Второй вариант требует свежей частной позиции через «Найти меня». Ваш реальный GPS и ваши разрешения обмена не меняются. Стрелки перемещают тестовый GPS на 100 м; координаты и погрешность доступны в раскрывающемся блоке. Эти ручные изменения сохраняют OFF/призрак. Передача ограничена обычным интервалом 30 секунд, до следующего обновления показан отсчёт. Автоматического движения и публикации в фоне нет.

**«Призрак»** оставляет последнюю разрешённую точку: перемещение тестового GPS после этого не меняет точку в «Близких». **«Обновлять»** явно публикует новое положение, **«Убрать»** отзывает доступ. «Точно / Примерный район» проверяет обычное округление. **«Отметиться»** отправляет отдельную отметку «Я живой» через обычный check-in; она не меняет геопозицию. «Показать» центрирует карту на доступной точке бота.

Панель требует активной сессии приложения для команд; чтение и обновление доступны отдельно. Синтетические координаты и pending-команды с ними хранятся только в памяти, не в URL, sessionStorage или журнале повторов. При потере ответа доступен точный повтор в текущей сессии; F5 очищает неподтверждённую геокоманду. Бот передаёт точку только своему владельцу по настоящей DIRECT-связи, с обычным TTL, consent, precision и отзывом доступа. Удаление бота/связи и reset очищают точки; production endpoint закрыт.

Реализация: `features/earth/dev/earth-dev-bots.tsx`, `bot-position.ts`, `lib/dev/bot-earth-store.ts`, `bot-earth-state.ts`. Команды `set_earth_position`, `set_earth_sharing`, `check_in` дополняют существующий `/api/v1/dev/bots`. Проверки: `tests/dev-bot-earth.test.mjs`, `earth-dev-bots-ui.test.mjs`, `earth-bot-position.test.mjs` и `dev-bot-session.test.mjs`.

### Проверить жизнь полянки

- **DEV → Сцена → Сценарии**: «Птицы на полянке», «Вечер у костра», «Дождливый вечер», «Уставший Мохлик». Сценарий задаёт условия и снимает паузу; панель остаётся открытой. Принудительный сценарий отключает запись дальнейшей симуляции в память аккаунта до новой обычной сессии; просмотр диагностики её не отключает.
- Для вариантов дома используйте «Постройки и уровни» в `/prototype/tiled-world`, затем проверьте настоящий подход и сон в основном приложении. У каждого из пяти уровней своя геометрия, которую нужно проверять со свободной навигацией `auto`.
- Для памяти аккаунта используйте два обычных браузера/профиля, без принудительных DEV-сценариев: сохранение, передача управления, перезагрузка, потеря сети. Локальный API проверяет протокол, но не заменяет PostgreSQL и проверку обновления заполненной БД.

Подробности: [DEV и Utility AI](../game/world-mind.md), [сад](../game/clearing-garden.md), [костёр](../game/campfire.md), [память между устройствами](../game/forest-memory-sync.md).

### Проверить рыбалку и поверхность воды

**DEV → Сцена → Сценарии → Мохлик на рыбалке** воспроизводит выход к берегу, заброс, ожидание, подмотку, укладку и возвращение без выдачи наград. Откройте большую карту: берег находится за пределами круга. На обычном масштабе проверьте хват удочки, тонкую леску, корзину на земле и контакт рыбы/лапы в переходах, затем повторите с паузой и reduced motion.

В **DEV → Сцена → Погода** «Течение и блики», «Бриз на воде» и «Рыбы в воде» независимы. «Ветер над водой» автоматически выбирает силу по погоде либо фиксирует штиль, лёгкий или сильный ветер. Переключение дня/ночи не меняет координаты воды. В **DEV → Отладка → Разметка → Границы воды** проверьте отсутствие волн/капель на камнях, листьях и причале. Эти настройки временные и не изменяют прогресс аккаунта.

## Проверки

Для обычной правки сначала выберите регрессию по [функции приложения](app-features.md) или по соответствующей странице мира. Не запускайте весь набор заново после изменения только текста документации.

Для короткого прогона от нового игрока остановите обычный DEV-сервер и выполните `node scripts/smoke-player.mjs`. Скрипт сам запускает Next на loopback (порт 3217, переопределение `PLAYER_SMOKE_PORT`), создаёт временный тестовый профиль, проверяет отметку, старт выращивания и рыбалки, повтор запросов, устаревшую ревизию, раннее получение и отмену. В конце процесс останавливается. Production URL скрипт не принимает; DEV-выдачи и ускорения не использует. Это HTTP/SSR-проверка, а не ручной браузерный прогон. Длительную прогрессию воспроизводит [расчёт пути игрока](../releases/player-journey-0.6.7.md).

```bash
npm run typecheck
npm run lint
npm run world:check
```

Полный веб-набор со свежей Sites-сборкой:

```bash
npm test
npm run build:vps
```

`npm test` выполняет `npm run build`, затем `node --test --test-concurrency=1 tests/*.test.mjs`. `npm run test:web` запускает только тесты и **не пересобирает** `dist/`. Часть тестов читает готовую сборку; после изменения runtime-кода она должна быть актуальной. Сборки и тесты, читающие `dist/`, выполняйте последовательно.

Для точечной проверки после актуальной Sites-сборки:

```bash
node --test --test-concurrency=1 tests/forest-lighting.test.mjs tests/new-map-scene.test.mjs
```

Серверный набор из корня репозитория:

```bash
cd apps/api
./gradlew --no-daemon test
```

В Windows используйте `gradlew.bat --no-daemon test`. Нужны JDK 25 и работающий Docker для integration tests. Пропущенная PostgreSQL suite не считается проверкой БД. Точные CI-gates описаны в [.github/workflows/ci.yml](../../.github/workflows/ci.yml): lint, types, обе сборки, веб-тесты, Ktor/PostgreSQL и Compose smoke на изолированных данных.

### Статус CI после нового коммита

CI объединяет запуски одной ветки через `concurrency` и `cancel-in-progress: true`. Новый push отменяет ещё идущую проверку предыдущего SHA. GitHub может показать красный значок и неполное число успешных jobs; откройте run именно этого коммита и проверьте `conclusion`. При `cancelled` журнал обычно заканчивается `The operation was canceled`, а затем останавливаются дочерние процессы. При `failure` нужно искать конкретный упавший шаг, assertion или ошибку сборки.

При сбое backend job сохраняет JUnit XML и HTML-отчёты в артефакт `backend-test-reports-<run_attempt>` на 7 дней. Он доступен на странице запуска CI. Проверки обновления до текущей схемы должны учитывать все доступные миграции через Flyway; фиксированный номер используют только для проверки конкретной исторической границы.

Оценивайте готовность по последнему SHA: успешный backend предыдущего коммита не завершает отменённые web/Compose, а отменённый старый run не определяет результат нового. Для выпуска нужны все gates выпускаемого SHA; повторять отменённый старый run при наличии более нового обычно не требуется.

## Быстрая диагностика

| Симптом | Что проверить |
|---|---|
| После перезапуска пропал локальный аккаунт | Это memory API. Создайте новый тестовый профиль; production-аккаунт хранится в PostgreSQL |
| UI работает, вход через провайдера недоступен | Локальный API не выполняет OAuth/SMTP; проверьте нужный серверный контур |
| Карта не обновилась | Ошибка в выводе `world:watch`, затем `world:check`; для нового изображения нужен отдельный WebP-экспорт |
| Корзинка исчезла после переноса в Tiled | Проверьте свободное место и доступный боковой подход у `Garden → berry-basket`; недоступный явный маркер не переносится автоматически |
| Мохлик ждёт, хотя путь свободен | Состояние синхронизации в «Как Мохлик?»: загрузка, offline или чужая аренда записи. Последняя показывает центральное окно «Полянка на паузе» с явной кнопкой «Продолжить здесь»; прежний запуск или другая вкладка также могут удерживать аренду |
| Свет не виден | DEV → Ночь, наличие точки `Lights`, `intensity`, радиус и её положение; [инструкция](../game/world-lighting.md) |
| Старые изображения после обновления | Сравните versioned URL/runtime-каталог; не начинайте с удаления всех пользовательских данных |
| Тапы ожидают подтверждения | Значок сервера/очередь, сеть, request ID; [разбор синхронизации](../game/game-sync-reliability.md) |
| API вернул 5xx | Сохраните request ID и используйте [инструкцию инцидентов](../operations/incident-response.md) |

После проверки просмотрите `git diff`, добавьте только относящиеся к задаче изменения и кратко обновите `WORK_STATE.md`. Публикация ветки и деплой — разные действия; команды обновления сервера не нужны для локальной правки.
