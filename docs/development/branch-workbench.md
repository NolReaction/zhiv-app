# Рабочая панель `/branch`

Панель администратора состоит из пяти разделов. Доступ контролируют маршрут и `features/progression/access`; UI не принимает решений об авторизации.

| Раздел | Содержимое | Код |
| --- | --- | --- |
| Каталог | Поиск, 24 товара на страницу, источники, применения, калькуляторы | `ui/catalog/` |
| Развитие | Открытия выбранного дома и поставки следующего уровня | `ui/development/` |
| Анализ | Цепочки, баланс, общий план, вылазки, прохождения | `ui/analysis/` |
| Награды | Жемчуг, рынок, расширения, предпросмотр магазина | `ui/rewards/` |
| Карта связей | Узлы, условия, этапы, поиск и масштабирование | `ui/world/` |

Все пути в таблице относительны к `features/progression/`. Чистые модели и расчёты находятся в `domain/`, общие компоненты справочника в `ui/shared/`, навигация и состояние страницы в `ui/shell/`. `branch-page.tsx` остаётся лёгкой точкой входа. `data/progression-scenarios.json` читает только серверный маршрут отчёта и инструменты проверки; клиентская модель сценариев содержит схему и функции, без импорта JSON.

Каждый верхний раздел загружается отдельным `React.lazy` импортом и размонтируется при уходе. Анализаторы устроены так же. Небольшие значения форм сохраняются в памяти текущей страницы, поэтому фильтры, дом, выбранный предмет, цели и запасы плана не сбрасываются при переходах. Полный отчёт загружается через `/branch/reports` только после открытия «Прохождение», с `no-store`, отменой запроса при уходе, обработкой отказа доступа и повтором.

Старые `#world` и `#economy-*` адреса поддерживаются адаптером. Новые адреса: `#catalog`, `#catalog/<itemId>`, `#development`, `#analysis`, `#rewards`, `#world`. Переход из рецепта или развития к предмету открывает каталог и переносит фокус на его карточку. Стрелки, Home и End переключают вкладки; Tab сохраняет обычный обход элементов.

## Что вызывало задержки

До разделения обе верхние панели и все пять анализаторов были смонтированы одновременно. Атрибут `hidden` скрывал их, но не отменял построение DOM, вычисления и React render. Изменение камеры мира перерисовывало в том числе скрытую экономику. Публичные импорты также сразу загружали внутренний отчёт и строили анализ производства.

Теперь каталог предварительно индексируется для поиска, списки имеют страницы, развитие показывает один дом. Слой узлов и связей мира мемоизирован, пути связей построены один раз. Панорамирование меняет только CSS transform через `requestAnimationFrame`; React обновляет масштаб, когда меняется его видимое значение. Независимые вкладки отсутствуют в DOM.

## Проверка

Измерено в одном Chromium, React development, 1280 × 900, с уменьшенным движением. Значения времени показывают сравнение одного окружения, не обещание производительности устройства пользователя.

| Сценарий | До | После |
| --- | ---: | ---: |
| DOM при открытии каталога | 14 560 | 861 |
| DOM на карте связей | 14 570 | 2 858 |
| DOM в «Анализ → Цепочки» | 14 560 | 325 |
| 12 wheel-событий с ожиданием кадра на карте | 1 688 мс | 203–289 мс |

Повторяемые проверки без сборки:

```sh
node --test tests/progression-ui.test.mjs tests/progression-economy-ui.test.mjs tests/progression-workbench-ui.test.mjs
BROWSER_EXECUTABLE_PATH=/path/to/chromium node scripts/check-branch-navigation.mjs
BROWSER_EXECUTABLE_PATH=/path/to/chromium node scripts/check-economy-workbench-layout.mjs
```

Первая браузерная проверка измеряет DOM, проверяет 320/1280 px, клавиатуру, восстановление фильтров, ссылки на карточки и отложенную загрузку отчёта, включая отказ и повтор. Вторая проверяет инструменты анализа, native CSV/JSON выгрузки, планирование и отсутствие переполнения на 320/1024 px. Для снимков задайте `BRANCH_SCREENSHOT_DIR` или `ECONOMY_SCREENSHOT_DIR` соответственно. Проверки используют локальную React-страницу; проверки настоящих прав администратора выполняются отдельно.
