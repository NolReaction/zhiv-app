# Память Node.js при проверках и сборке

Тяжёлые тесты сцены в 0.7.2 достигали стандартного лимита V8 около 2 GiB. Это отличалось от падения assertion: процесс завершался до результата проверки. Повтор с heap 3584 MiB проходил. Это не доказывает отсутствие утечки; рост потребления одного файла нужно отдельно исследовать, если он продолжится.

`npm run build`, `build:vps`, `typecheck`, `test:web`, `test:mail`, `test:security` и `test:targeted` используют общий `scripts/run-node.mjs`:

- Автоматический heap — не более **3584 MiB** и примерно **60%** доступного лимита памяти машины/контейнера. Ограничение контейнера учитывается через `process.constrainedMemory()`; резерв остаётся для native-памяти, дочерних служебных процессов и ОС.
- Это верхний предел V8 old space, а не заранее выделенная память и не предел всего RSS. На маленьком сервере лимит ниже; тяжёлая сцена всё ещё может не поместиться. Для проверок предпочтителен компьютер или CI с достаточной RAM.
- Явный `NODE_OPTIONS=--max-old-space-size=...` сохраняется. Без него можно задать `ZHIV_NODE_HEAP_MB=4096`; значения 256–65536 MiB. Явный override нужно выбирать по реальной RAM, а не увеличивать бесконечно.
- Тестовые файлы по умолчанию выполняются с `--test-concurrency=1`. Переданный явно параметр concurrency сохраняется.
- Флаг `--serial` ставит общую блокировку тяжёлых задач **одного checkout**. Второй build/typecheck/test ждёт первый, вложенный процесс использует его блокировку. Это защищает память и общий `dist/`. После выхода блокировка снимается; запись погибшего процесса удаляется при следующем запуске.
- Другие checkout, Gradle, браузер и внешние команды этой блокировкой не управляются. Не запускайте одновременно большие Node/Gradle прогоны на ограниченной машине.

## Короткая проверка изменений

```bash
npm run test:targeted -- tests/node-memory.test.mjs tests/reset-game-progress.test.mjs
npm run typecheck
```

Для сцены или другого конкретного файла:

```bash
npm run test:targeted -- tests/new-map-residents.test.mjs
```

`test:targeted` **не пересобирает приложение**. Если выбранный тест читает `dist/`, сначала выполните `npm run build`, дождитесь его завершения и затем запускайте тест. `npm test` по-прежнему делает сборку, после неё — полный веб-набор.

Произвольный диагностический Node-скрипт:

```bash
node scripts/run-node.mjs --serial scripts/audit-economy-progression.mjs
```

Переопределение на машине с достаточной памятью (bash):

```bash
ZHIV_NODE_HEAP_MB=4096 npm run test:targeted -- tests/new-map-residents.test.mjs
```

Для PowerShell: `$env:ZHIV_NODE_HEAP_MB="4096"`, затем обычная npm-команда. Удалить override: `Remove-Item Env:ZHIV_NODE_HEAP_MB`.

CI использует тот же launcher для веб-шардов и npm-команду typecheck. Автоматического повтора проваленных тестов с большим лимитом нет: ошибка теста или OOM остаётся видимой, код завершения сохраняется.
