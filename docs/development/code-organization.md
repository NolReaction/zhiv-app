# Организация кода

Проект организован по функциональным областям — **feature-based**. Крупные области разделяют UI, состояние, правила и интеграцию. Это договорённость о местонахождении кода и зависимостях, а не заявление о полном переходе на MVVM или Clean Architecture. Структура введена в рабочей 0.6.8 поверх 0.6.7; сохранены поведение приложения, серверные контракты, миграции, ресурсы и прежние реализации.

[Архитектура](../architecture.md) объясняет владельцев состояния и два контура сборки. [Путеводитель](../repository-guide.md) сопоставляет конкретные задачи и файлы. Этот документ помогает выбрать место для изменения и нового кода.

## Сначала область, затем ответственность

| Область | Что здесь искать |
|---|---|
| [`features/app/`](../../features/app/) | Общая оболочка, навигация, соединение аккаунта и игровых контроллеров |
| [`features/check-in/`](../../features/check-in/) | Кнопка отметки, календарь, серия дней и статус |
| [`features/account/`](../../features/account/), [`features/people/`](../../features/people/) | Аккаунт, авторизация, профиль аккаунта; друзья, группы, гостевой профиль |
| [`features/game/`](../../features/game/), [`features/activity/`](../../features/activity/) | Прогресс и награды; активный сеанс, AFK и доступность игры |
| [`features/world/`](../../features/world/) | Игровой мир, персонажи, сцена и игровые окна |
| [`features/economy/`](../../features/economy/) | Строительство, производство, предметы, торговля и их UI |
| [`features/audio/`](../../features/audio/README.md) | Каталог, микшер, загрузка, настройки, сигналы интерфейса и диагностика звука |
| [`features/mochlik/`](../../features/mochlik/) | Общая графика Мохлика и сохранённый прежний runtime |
| [`features/startup/`](../../features/startup/), [`features/updates/`](../../features/updates/) | Заставка и готовность ресурсов; новости и сведения о версии |
| [`features/admin/`](../../features/admin/) | Закрытые инструменты поддержки |
| [`apps/api/`](../../apps/api/) | Ktor, серверные правила, транзакции и PostgreSQL-миграции |

`app/` содержит точки входа Next/Vinext, layout, manifest и маршруты локального API. Само приложение собирает `features/app/app-shell.tsx`. Общие визуальные элементы принадлежат `components/`, контракты и помощники общего назначения — `lib/`. Функция, нужная одному экрану, остаётся рядом с ним: наличие двух вызовов ещё не делает её общей библиотекой.

## Игровой мир

| Папка внутри `features/world/` | Ответственность |
|---|---|
| `ui/profile/`, `ui/help/`, `ui/wardrobe/`, `ui/collections/` | Соответствующие игровые окна и их CSS |
| `ui/characters/`, `ui/journeys/`, `ui/hud/`, `ui/feedback/` | Диалоги жителей, прежние поездки, элементы поверх карты, уведомления и эффекты |
| `scene/` | Canvas, камера, подготовка графики, порядок рисования и сборка сцены |
| `simulation/` | Потребности, выбор действия, прерывания, движение Мохлика и жизнь полянки |
| `activities/` | Сад, рыбалка, готовка, костёр, каменоломня и переходы; логика занятия и его painter рядом |
| `characters/` | Плёска, Шишколап, совместное присутствие и разговоры |
| `navigation/` | Поиск пути, сглаживание, переходы и обход других жителей |
| `environment/` | `lighting/`, `weather/`, `water/`, `wildlife/` |
| `audio/` | Связь камеры, Tiled, погоды, производства и фаз действий с независимым звуковым движком |
| `state/` | Общая сессия и наблюдение; `memory/` — сохранение/аренда, `economy/` — представление подтверждённой экономики в сцене |
| `domain/` | Модель прежнего world snapshot, гардероб и книга находок |
| `tiled/` | Типы, экспортированная разметка, общий рендер и редакторский preview |
| `dev/` | Диагностика, управляемые сценарии и предпросмотры |
| `legacy/` | Сохранённые модули прежней карты; не считать неиспользуемыми только по названию |

В корне остаются точки соединения: `world-view.tsx`, `world-portal.tsx`, `use-world-portal.ts`, их общие стили и стабильные JSON-контракты. `scene/new-map-scene.ts` собирает текущий лес. `state/forest-session.ts` владеет общей симуляцией круга и большой карты; `state/session.ts` обслуживает другой контракт — гардероб и прежние поездки. Смешивать эти сессии нельзя.

## Экономика

| Папка внутри `features/economy/` | Ответственность |
|---|---|
| `domain/` | Модели, каталог и расчётные правила: валюты, стройка, рыбалка, еда, рынок |
| `sync/` | API, сессия, очередь команд, revision, повторы и React-контроллер |
| `integration/` | Связь экономики с игровым миром: уровни зданий, сбор сада |
| `ui/` | `construction/`, `market/`, `food/`, `fishing/`, `inventory/`, `production/`, `expeditions/`; общие части — `shared/` |
| `dev/` | Локальные пресеты и инструменты разработки |

Первичный источник цен, длительностей и требований — [economy-catalog.json](../../apps/api/src/main/resources/world/economy-catalog.json). TypeScript использует его для расчётов и локальной имитации; серверные [правила Ktor](../../apps/api/src/main/kotlin/ru/zhiv/economy/) подтверждают команды, а [репозитории](../../apps/api/src/main/kotlin/ru/zhiv/db/) выполняют транзакции. Новое экономическое правило проверяется в обоих исполнениях. Изменение CSS или положения кнопки не требует правки каталога.

После нажатия UI вызывает контроллер `sync/`, сессия отправляет команду и принимает подтверждённый снимок. `integration/` и `world/state/economy/` переводят этот результат в видимые уровни, стройку и занятия. Анимация завершения самостоятельно ресурсы не выдаёт.

## Пример: найти «Мой Мохлик»

Для текста, расположения блоков и оформления достаточно начать с [world-profile-menu.tsx](../../features/world/ui/profile/world-profile-menu.tsx) и [соседнего CSS](../../features/world/ui/profile/world-profile-menu.module.css). Настроение и друзья лежат в той же папке. Это отдельный экран от [профиля аккаунта](../../features/account/profile-view.tsx).

Дальше открывайте только владельца затронутой задачи:

| Задача | Владелец |
|---|---|
| Открытие, закрытие, заголовок и фокус общего окна | `features/world/world-view.tsx`, `world-map-hud.module.css`, `world.module.css` |
| Настроение или статус памяти | `features/world/state/use-forest-observation.ts`, `forest-observer.ts`, `state/memory/` |
| Уровень дома или количество исследований | `features/economy/sync/use-economy.ts` и подтверждённый снимок |
| Заполнение книги находок | `features/world/domain/collection-book.ts` |
| Имя, уровень, серия дней и список друзей | Данные передаются из `features/app/app-shell.tsx` через `world-portal.tsx` и `world-view.tsx` |

Профиль не создаёт второй кошелёк или отдельную копию памяти. Он показывает состояние их владельцев. Локальные вкладки и визуальный отклик кнопки остаются в компоненте; сложные общие расчёты выносятся в предметный модуль, а повторяемая подготовка экранного состояния — в соседний hook по мере появления такой необходимости.

## Направления зависимостей

- Компонент и `.module.css` размещаются рядом. Помощник только одного экрана остаётся там же; общий контроллер — в `sync/` или `state/` своей области.
- `domain/` не загружает React, визуальные компоненты и клиентские сессии. Он может использовать предметные модели другой области, общие каталоги и чистые функции; межмодульный импорт сам по себе не запрещён.
- `economy/sync/` не загружает UI. Общие состояния блокировки команд находятся в `sync/controller-state.ts`, визуальное оформление — в `ui/shared/`.
- Маршруты собирают приложение; feature-модули не импортируют маршруты или `AppShell`. Связь с оболочкой передаётся через данные и callbacks.
- Циклические runtime-импорты между feature-файлами запрещены. Типовые ссылки помечайте `import type`; это не разрешение скрывать фактическую зависимость выполнения.
- В одной папке используйте `./file`; между подсистемами — явный `@/features/...`. Импортируйте нужный файл, не создавайте общий `index.ts`, который реэкспортирует всё дерево.

`npm run architecture:check` разбирает реальные imports/exports, динамические импорты с постоянным путём и `require`, проверяет существование локальных целей и перечисленные runtime-границы. Проверка не доказывает отсутствие всех логических связей или правильность игровых правил. Она дополняет typecheck, lint и тесты.

Текущая структура допускает совместное расположение логики и painter внутри конкретного занятия. `world-view.tsx` и `app-shell.tsx` ещё остаются крупными точками сборки; их дальнейшее разделение выполняется по конкретной ответственности с проверкой поведения. Новый каталог без ясного владельца данных проблему не решает.

## Практический поиск и проверка

Из корня проекта:

```bash
# Найти все части игрового профиля.
rg --files features/world/ui/profile

# Найти видимый текст или точку открытия окна.
rg -n 'Мой Мохлик|WorldProfileMenu' features/world

# Найти обработку конкретной экономической команды у клиента и сервера.
rg -n 'claim_job' features/economy apps/api/src/main

# Проверить переносы, типы и границы.
npm run architecture:check
npm run typecheck
npm run lint
```

После перемещения файла обновляйте статические и динамические импорты, обращения тестов и скриптов к исходникам, документацию и точки входа. Сохраняйте имена API, ключи хранилищ, стабильные ID, миграции и формат данных. `world/tiled/forest.tmj` — исходник карты; `features/world/tiled/forest.generated.json` создаёт экспорт, не ручная правка. Оба контура сборки и полные проверки описаны в [CONTRIBUTING.md](../../CONTRIBUTING.md).
