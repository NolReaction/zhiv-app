# Страница приложения и установка PWA

`/site` — публичная презентация «Я живой»: отметки близким, интерактивная панорама полянки, видеопрогулка и установка на устройство. Не требует аккаунта, не создаёт игрока, не запускает симуляцию, не запрашивает разрешение на уведомления. Контент описывает возможности текущего `master`; восстановление моста и маяка не рекламируется как доступная игровая функция.

## Вход и маршруты

- `/` остаётся адресом игры. `features/app/game-entry.tsx` монтирует игровой runtime после `InstallationGate`: из настоящей PWA — сразу, из обычного браузера — после предложения установки или разрешённого прикладного перехода.
- «Продолжить в браузере» запоминается на текущую сессию вкладки (`sessionStorage`). При запрете хранилища работает память контроллера. Это выбор пользователя, а не доказательство установки.
- Возврат авторизации, приглашения, восстановление и переходы уведомлений не теряют исходные параметры. Обработку и проверку токенов по-прежнему выполняют существующие системы аккаунта.
- Инструкция повторно открывается в **Профиль → Настройки → Установить приложение** или на `/site#install`.
- Manifest общий для сайта и игры: `id: "/"`, `start_url: "/"`, `scope: "/"`, `display: "standalone"`. Установка с `/site` создаёт то же приложение и запускает игру, а не лендинг. Нельзя менять identity ради установки страницы.

## Владельцы и поведение

| Файл | Ответственность |
|---|---|
| `app/site/page.tsx` | Публичный маршрут, SEO/Open Graph, доступное масштабирование |
| `features/site/product-site.tsx`, `.module.css` | Презентация и адаптивная композиция |
| `features/site/site-demos.tsx` | Локальные демонстрации без серверных действий |
| `features/pwa/install-platform.ts` | Подсказки, определение браузера, ручной выбор инструкции |
| `features/pwa/install-controller.ts` | Состояние окна, одноразовое событие установки, допуск браузера |
| `features/pwa/install-provider.tsx` | Один контроллер на layout и React-подписки |
| `features/pwa/install-panel.tsx`, `installation-gate.tsx` | Инструкции и первый экран браузерного входа |
| `components/service-worker-registration.tsx` | Регистрация SW отдельно от необязательного прогрева игровой оболочки |

Нативная кнопка появляется только после реального `beforeinstallprompt`. Вызов `prompt()` выполняется непосредственно по нажатию, один раз на событие; отмена и ошибки сохраняют ручные инструкции. Принятый запрос и `appinstalled` не означают, что текущее окно уже стало PWA. Реальный режим определяется через `display-mode` и `navigator.standalone` для iOS. Отсутствие события установки не доказывает, что приложение нельзя установить или что оно уже установлено.

Нет универсального надёжного способа принудительно открыть установленную PWA из вкладки. После установки интерфейс просит запустить **значок «Я живой»**. Для встроенных браузеров предлагается внешнее открытие и копирование чистого адреса без токенов. Определение браузера — подсказка; пользователь всегда может изменить вариант вручную. Перенос сессии между браузером и приложением не обещается: нужен прежний способ входа, а для старого профиля — заранее сохранённый резервный код.

## Медиа и загрузка

`public/site/` содержит небольшой постер, две панорамы и 12-секундный MP4. [Источники и воспроизводимый рендер](../../public/site/README.md) — настоящий игровой compositor и текущие данные Tiled, без аккаунта. Видеопрогулка постановочная, со специально ускоренной сменой света. Видео отсутствует в DOM до нажатия, не скачивается автоматически и не начинает играть при прокрутке. Есть стандартные controls, пауза при скрытии страницы, ошибка/повтор. Вечерняя панорама загружается только по выбору пользователя. Демо отметки ничего никому не отправляет.

Большой фон игры убран из глобального preload и запрашивается при входе в игровой runtime; сам `AppShell` также загружается динамически после gate. На `/site` не запускается игровой контроль обновлений/техработ или запрет жестов масштабирования. SW регистрируется для возможности установки, но прогрев игровой оболочки начинается только при входе в игру. При отсутствии сети `/site` **не** подменяется кешированным игровым HTML; offline fallback сохраняется только у `/`.

## Проверка перед выпуском

Автотесты: `tests/pwa-install.test.mjs`, `tests/product-site.test.mjs`, `tests/game-entry.test.mjs`, `tests/pwa-contract.test.mjs`, `tests/browser-zoom-guard.test.mjs`, `tests/notifications.test.mjs`. Обязательны typecheck, architecture, lint и обе сборки.

Ручной проход на реальных устройствах:

1. Открыть `/site` на узком/широком экране; проверить чтение, увеличение текста, клавиатуру, reduced motion, три места карты, вечер, демо отметки и MP4/повтор при сетевой ошибке.
2. Открыть чистый `/` в браузере: увидеть установку, выбрать «Продолжить в браузере», перезагрузить вкладку. Игра должна остаться доступна.
3. Android Chrome: установить с `/site`, принять/отменить диалог, открыть со значка. iPhone Safari и Chrome: проверить «На экран Домой». Установленная PWA открывает игру без gate.
4. Проверить встроенные браузеры Telegram/ВК, Яндекс Android, ручной выбор инструкции, запрет sessionStorage и наличие ранее установленной копии.
5. Пройти авторизацию ВК/почтой, открыть приглашение и уведомление; убедиться, что исходная цель и аккаунт сохраняются.
6. Поставить приложение поверх прежней версии: проверить обновление SW, старый аккаунт и серверный прогресс. Автотесты не заменяют нативные системные окна установки.
