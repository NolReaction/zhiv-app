# Размер игры и загрузка лодочной рыбалки

Замер от 10 ноября 2026 года для ветки `work/boat-upgrades-ui`. Здесь 1 MiB равен 1 048 576 байт. Одна и та же графика входит в несколько строк таблицы, поэтому строки складывать нельзя.

| Что измерено | Размер | Что входит |
|---|---:|---|
| Рабочие исходники проекта | около 216 MiB | Код, тесты, документация, исходная графика и публичные файлы. Каталоги Git, зависимостей и сборок исключены |
| Публичные файлы готового клиента | 86,91 MiB | Весь `public/`, включая подготовленные при сборке файлы. Звук занимает 34,07 MiB, графика и сцены `world/` — 29,28 MiB, файлы `earth/` — 14,85 MiB |
| Файлы веб-приложения в образе VPS | около 184 MiB | Сумма `.next/standalone`, `.next/static` и `public` по `deploy/web.Dockerfile`. Базовая ОС, Node, образ Kotlin API и база исключены |
| Серверный пакет Sites | 140,90 MiB | Содержимое `dist/standalone`, включая Node-зависимости сервера и клиентские файлы |

## Упаковка

Сервер vinext 0.0.50 раздаёт статику из `dist/client` внутри standalone. При сборке он также копирует тот же `public` рядом с `server.js`. Скрипт `compact-sites-standalone.mjs` сверяет содержимое каждого файла и сохраняет весь каталог при расхождении или ссылке на файл за пределами ожидаемого пути. На проверенной сборке удалено 91 130 731 байт. После удаления каждый из 279 исходных публичных URL вернул те же байты через HTTP.

У `npm run build` включено штатное предварительное сжатие vinext. В этой сборке варианты Brotli, gzip и Zstandard созданы для 75 файлов JavaScript и 23 CSS. Они занимают 6,44 MiB. С учётом удаления дублей пакет занимает на 80,47 MiB меньше, чем те же файлы в штатной упаковке без сжатия. Для VPS действует отдельная сборка Next и сжатие в Caddy.

## Что получает браузер

В Chromium с пустым браузерным кешем один и тот же игрок открыл главный экран, пропустил обучение, вошёл на поляну, отремонтировал лодку и забросил удочку. Таблица показывает **дополнительный** трафик каждого шага в MiB. Учтены переданные байты успешных HTTP-ответов по `Network.loadingFinished.encodedDataLength`, включая ответы игрового API и фоновые запросы. Сравнение первых двух колонок выполнено на одной сборке, в контрольной копии для первой колонки удалены только варианты сжатия.

| Шаг | Без HTTP-сжатия, звук выключен | Со сжатием, звук выключен | Со сжатием, звук включён |
|---|---:|---:|---:|
| Открыть приложение до первого действия | 19,99 | 16,12 | 19,79 |
| Пропустить обучение и открыть поляну | 0,89 | 0,89 | 0,89 |
| Открыть мастерскую и получить ремонт | 0,75 | 0,75 | 0,88 |
| Перейти на реку | 7,78 | 7,78 | 4,11 |
| Первый заброс | 0,22 | 0,22 | 0,22 |
| **Всего до первого заброса** | **29,62** | **25,76** | **25,90** |

На всём маршруте одинаковые 125 запросов к файлам JS и CSS заняли **5,30 MiB без сжатия и 1,43 MiB со сжатием**. Chromium получил `Content-Encoding: zstd` и `Vary: Accept-Encoding` для 53 достаточно больших файлов; маленькие файлы сервер вернул как есть. Экономия по этим ресурсам составляет 73%, по всему маршруту при одинаково выключенном звуке — 13%.

Холодная загрузка всё ещё тяжёлая для мобильной сети. Один фон леса занимает 3,69 MiB, два слоя земли вокруг дома — ещё 2,61 MiB. Позже растёт доля длинных звуков. С сохранённым выключенным звуком прежняя схема `AudioRuntime.prepare` всё равно заранее получает закодированные файлы: в этом сеансе на звук пришлось 10,74 MiB. Поэтому выключение звука не служит режимом экономии трафика. На прибавку при открытии реки влияет и то, какие звуки браузер уже запросил на поляне. Для следующего сокращения мобильной загрузки измеримы два направления: более лёгкая текстура для малого стартового круга и отложенная загрузка длинных петель при выключенном звуке.

Условия измерения: локальный production-сервер Sites, Chromium, окно 1200×900, уменьшенное движение, ночь в часовом поясе игрока. Использовались тестовая учётная запись и обработчики DEV API с локальным хранилищем в памяти. Service Worker заблокирован для воспроизводимого сравнения чистой загрузки. Вес API включает локальные JSON-ответы; сжатие на VPS, PWA-кеш, погода, состояние игрока и уже прослушанная музыка могут изменить результат. Показатели описывают объём передачи, а не частоту кадров или время запуска на телефоне.
