# 3D-модели достопримечательностей

## Что работает сейчас

`features/earth/landmark-mesh.ts` строит девять собственных процедурных моделей. `landmark-mesh-layer.ts` рисует треугольники с цветами вершин через публичную проекцию MapLibre `projectTileFor3D`. Файлы GLB, glTF, OBJ и FBX приложение сейчас **не загружает**; текстур, PBR-материалов, скелетов и загрузчика внешних моделей в этом слое нет.

Модели привязаны к координатам из `landmark-catalog.ts`. Их основание — локальный ноль, оси — восток/север/вверх. Размер условно увеличен для обзора глобуса. Это не точный масштаб зданий: миниатюры исчезают к zoom 5.2, а с zoom 15 отдельно появляются экструзии реальных контуров OSM из `building-style.ts`.

У Эйфелевой башни сохранены отношение высоты к основанию около 2.64 и уровни площадок 57/115/276 м относительно высоты 330 м. Размеры взяты из [официальных данных башни](https://www.toureiffel.paris/en/the-monument/key-figures); геометрия оригинальная, упрощённая. Четыре изогнутые опоры, сквозные арки, диагональная решётка и короткая верхняя антенна делают силуэт узнаваемым с разных сторон. При zoom < 1.5 рисуется основа в 1258 треугольников, далее добавляются перила, горизонтальные связи и стойки до 1858 треугольников. Обзорная геометрия — точный префикс подробной; переключение меняет только число рисуемых вершин.

Весь текущий каталог занимает 361440 байт в одном статичном GPU-буфере, ниже проверяемого предела 400000 байт. Смена масштаба не загружает модели, не пересоздаёт вершины и не увеличивает этот буфер. Число одновременно видимых объектов, скрытие обратной стороны и освобождение ресурсов описаны в [устройстве карты](earth-map.md).

## Формат для передачи новых моделей

Для следующей интеграции передавайте **glTF 2.0 в одном `.glb`**, например `eiffel-tower.glb`. Это формат обмена для подготовки будущего адаптера, а не уже поддерживаемая загрузка в приложении. Ниже — требования проекта к удобному исходнику; числовые бюджеты не являются ограничениями стандарта glTF.

| Параметр | Требование к передаваемому файлу |
| --- | --- |
| Содержимое | Один памятник, без окружающего города, подиума для презентации, неба, камеры и источников света. Все буферы и изображения внутри GLB, без внешних URI. |
| Масштаб | Реальные метры: башня высотой 330 м имеет высоту 330 единиц. Не уменьшать объект до размера экранной иконки. |
| Оси и ноль | Правосторонняя система glTF, `+Y` вверх. Ноль в центре основания на земле, нижняя опорная плоскость `Y = 0`. Применить масштаб и вращение объекта перед экспортом. |
| Географический поворот | Приложить изображение вида спереди и отдельно указать направление фасада по компасу. Широту, долготу и поворот хранить в каталоге карты, не зашивать градусы в координаты вершин. |
| Геометрия | Статичные треугольники с корректными нормалями. Арки и просветы — настоящие отверстия. Удалить невидимые внутренние детали и дубликаты. Без анимации, rig, skin и morph targets. |
| Материалы | Предпочтительно цвета вершин или 1–4 непрозрачных материала с `baseColorFactor`. Без прозрачных картинок вместо ажурной геометрии. Не запекать на модель сильную тень от выдуманного солнца. |
| Текстуры, если нужны | Один атлас до 1024×1024 PNG/JPEG, встроенный в GLB. Нормали и мелкие PBR-карты пока не нужны. Текстурированная версия требует отдельной поддержки в адаптере. |
| Размер | Цель — до 1 МиБ на обзорный/региональный файл; будущая уличная версия до 2 МиБ. Реальный GPU-бюджет проверяется после декодирования, размер файла его не заменяет. |
| Расширения | Обычный core glTF 2.0. До согласования адаптера не использовать Draco, Meshopt, KTX2 или обязательные расширения материалов. |
| Сопроводительные файлы | Превью спереди, сбоку и в 3/4; реальные высота/ширина; число треугольников; автор, источник и условия использования. Исходный `.blend`, если есть, сохранить для правки. |

Для первой передачи достаточно одного хорошо узнаваемого GLB на **1500–3000 треугольников**, без текстур: Эйфелева башня с правильными пропорциями, четырьмя опорами, арками и решётчатой конструкцией. Не расходуйте полигоны на заклёпки, лестницы и интерьеры, которые не видны на масштабе карты.

При подготовке нескольких уровней детализации передавайте отдельные файлы с тем же основанием, ориентацией и реальным масштабом:

| Уровень | Планируемая роль | Целевой бюджет |
| --- | --- | --- |
| `overview` | Обзор глобуса, читаемый силуэт | 300–1500 треугольников, без текстур |
| `regional` | Более близкий обзор памятника | 1500–5000 треугольников |
| `street`, необязательно | Будущая модель в реальном масштабе рядом с OSM-зданиями | До 10000 треугольников |

Это предлагаемый профиль будущих ассетов. Существующие процедурные модели не обязаны иметь все три уровня; сейчас обзорный префикс есть только у Эйфелевой башни.

## Что потребуется для подключения GLB

Самого размещения файла в `public/` недостаточно. Первый небольшой адаптер можно сделать на этапе подготовки ресурсов: проверить glTF, применить узловые преобразования, пересчитать локальные оси и конвертировать разрешённую статичную геометрию в текущий формат `position + color`. Для перехода из glTF в локальные восток/север/вверх используется `[x, -z, y]`, затем явно заданный географический поворот. Цвета материалов можно перенести в вершины; это не будет полноценным PBR-рендером. Поддержку текстур следует добавлять отдельно с измерением памяти и качества.

Подробная уличная модель потребует отдельного режима масштаба в метрах вместо размера экранной миниатюры, плавной смены уровней, учёта перекрытия с экструзиями OSM и проверки опоры на рельеф. Для большого каталога нужен загрузчик только выбранных видимых объектов с отменой, ограничением одновременно декодированных моделей и освобождением GPU-буферов. Текущий фиксированный каталог не следует превращать в безлимитный кеш GLB.

До подключения конкретного ассета должны проходить проверки границ и конечности координат, размеров после декодирования, ориентации/геоякоря, отсутствия внешних запросов, повторной загрузки после потери WebGL-контекста и очистки сцены. В браузере нужны общий глобус, региональный ракурс, поворот/pitch, день/вечер, узкий экран и reduced motion. Отдельно сравнивать узнаваемость модели при фактическом экранном размере, а не только в редакторе на весь экран.

## Источники и проверки

- [Khronos glTF 2.0: система координат и единицы](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units), [контейнер GLB](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#glb-file-format-specification). GLB сам по себе не гарантирует отсутствие внешних ссылок: это дополнительное требование нашего профиля.
- [Официальный glTF Validator](https://github.com/KhronosGroup/glTF-Validator) проверяет структуру glTF/GLB. Успешная проверка формата не подтверждает читаемость модели и её соответствие бюджету карты.
- `node --test --test-concurrency=1 tests/earth-landmark-mesh.test.mjs tests/earth-landmark-layout.test.mjs tests/earth-landmarks.test.mjs`: геометрия, открытая арка, уровни детализации, неизменные якоря, отсутствие повторной загрузки GPU-буфера, скрытие и очистка.
