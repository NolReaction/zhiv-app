# Текущая архитектура

Документ описывает `feature/mochlik-world`. [Исходная архитектура ранних версий](history/architecture.md) сохранена отдельно.

## Два контура запуска

На VPS Caddy направляет страницу в Next.js, а `/api/v1/*` — в Kotlin/Ktor. Ktor проверяет права и команды, работает с PostgreSQL. Настройки находятся в `deploy/`.

При `npm run dev:local` Next.js использует маршруты из `app/api/` и адаптеры `lib/dev/`. Это имитация для разработки, данные хранятся в памяти. Она не заменяет production API. Дополнительный Sites-контур собирается через Vite/Vinext и `worker/`; PostgreSQL остаётся основной моделью данных серверного приложения.

## Разделы браузерного приложения

| Раздел | Ответственность |
|---|---|
| `features/check-in/` | Главный экран, отправка отметки, календарь, статус, простой вид |
| `features/account/` | Вход, профиль, способы доступа, восстановление |
| `features/people/` | Люди, группы и приглашения через интерфейс |
| `features/game/` | Игровые тапы, локальная очередь, серверный прогресс, уровни, достижения, рейтинг |
| `features/mochlik/` | Рисование героя, поведение, сон, свет, грибы, общее состояние живой сцены |
| `features/world/` | Камера и карта, переход, путешествия, здания, гардероб, коллекции |
| `features/admin/` | Закрытая панель, поиск пользователей, награды, диагностика |
| `features/app/` | Общая навигация |

`components/` содержит переиспользуемый интерфейс; `lib/` — общие API-контракты и функции. Между разделами используем явные импорты `@/features/...`; внутри — относительные.

## Владение состоянием

**Аккаунт и игровые награды** подтверждает сервер. Клиентская анимация, положение персонажа и время суток не изменяют счётчики наград сами по себе.

**Тапы** проходят через `features/game/use-game-progress.ts` и `game-sync.ts`. Незавершённая отправка сохраняется в журнале `game-sync-journal.ts`. Разбор отказов, повторов и блокировки одновременного ввода описан в [документе синхронизации](game/game-sync-reliability.md).

**Мир** получает серверный снимок через `features/world/use-world.ts`. Команды, их квитанции и версия состояния позволяют не применять покупку или получение награды дважды. Каталог `apps/api/src/main/resources/world/catalog.json` читают и TypeScript, и Kotlin.

**Живая сцена** использует `features/mochlik/session.ts`: кнопка и большая карта подключаются к одному состоянию поведения. Отрисовка не должна создавать вторые таймеры экономических наград или независимую копию аккаунта.

## Графика

Изображения находятся в `public/world/`, пути собраны в `features/world/art.ts`. Удалённая промежуточная `forest-world.webp` больше не нужна.

Текущий рендер ещё собирает большую карту из внешнего леса и живого центрального участка. `map-layout.ts` хранит координаты мира и метки, `home-layout.ts` — точки входа в дом, дверной проём и фонарь. Они теперь используются кодом, а не служат отдельной несвязанной документацией.

Переход к одной карте и отдельным спрайтам зданий выполняется по [плану](game/map-assets-plan.md). Перенос файлов в папки сам по себе не означает, что эта графическая миграция уже закончена.

## Изменения серверных правил

Схема текущей ветки включает миграции V1–V26 в `apps/api/src/main/resources/db/migration/`. Применённые миграции сохраняются неизменными. Для нового правила меняются Ktor, локальная имитация при необходимости, контракт ответа и проверка поведения.

Сначала сохраняем небольшой законченный коммит в feature-ветке. Выпуск в `master`, применение миграций и обновление сервера — отдельный этап после проверки.
