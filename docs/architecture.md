# Архитектура приложения

Текущее устройство приложения и Tiled-мира в рабочей ветке `work/0.6.7-building-levels`. Версии web/API остаются 0.6.6 до подготовки выпуска; наличие функции в ветке не означает её публикацию в `master`. Текущий этап и выполненные проверки — [WORK_STATE.md](../WORK_STATE.md), поиск файла — [путеводитель](repository-guide.md), запуск — [локальная разработка](development/local-development.md).

## Контуры запуска

| Контур | Страница | API и данные | Конфигурация |
|---|---|---|---|
| Локальная разработка | Next.js, `npm run dev:local` | `app/api/v1/` → `lib/dev/`, память процесса | [next.config.ts](../next.config.ts), `.env.example` |
| Sites | Vite/Vinext, `npm run dev` | Те же route handlers; это не PostgreSQL-сервер | [vite.config.ts](../vite.config.ts), [worker/index.ts](../worker/index.ts), `build/` |
| VPS | Caddy → Next.js | Caddy направляет `/api/*` в Ktor → PostgreSQL | `deploy/compose.yml`, `deploy/Caddyfile` |

В production локальный API всегда заблокирован: переменная `ENABLE_DEV_API` больше не открывает имитацию. Локальная имитация API в памяти процесса работает только в режимах `development`/`test`; реальные запросы `/api` обслуживает Ktor. [db/schema.ts](../db/schema.ts) — пустая заготовка Sites/D1; схема настоящего приложения находится в Flyway-миграциях `apps/api/`.

| Активное время, пути, текущие сценки, реплики и животные | [forest-session.ts](../features/world/forest-session.ts) для аккаунта и геометрии сцены | Один владелец обновляет состояние; круг и большая карта читают его; промежуточные анимации не сохраняются |

Не смешивайте [features/world/session.ts](../features/world/session.ts) (гардероб/прежние походы/HTTP) и [forest-session.ts](../features/world/forest-session.ts) (отрисовка/поведение). Старый [features/mochlik/session.ts](../features/mochlik/session.ts) не является владельцем текущего Tiled-леса.

Тап по кнопке и серверная отметка — разные события. Отметка имеет ограничение частоты и влияет на календарь/серию дней; игровые тапы идут пакетами и имеют отдельные подтверждения. Offline-оболочка PWA не означает успешную отправку отметки.

## Путь графики

1. Редактируемая сцена — `world/tiled/forest.tmj`; PNG/JPEG-мастера — `art/world/prototype/`; основной фон — `forest-ground.png`.
2. `world:export` проверяет Tiled и формирует [features/world/tiled/forest.generated.json](../features/world/tiled/forest.generated.json). WebP экспортируются отдельно: [арт-процесс](../art/README.md).
3. [presentation.ts](../features/world/presentation.ts) выдаёт единый `TILED_WORLD`. Круг и большая карта используют [new-map-scene.ts](../features/world/new-map-scene.ts), Tiled preview — общий renderer и те же данные.
4. Геометрия, свет и анимации работают в координатах мира; камера переводит их в координаты canvas. Основной новый лес рисуется Canvas 2D.

`WORLD_PRESENTATION.rebuilding = true` выбирает новый Tiled-лес и отключает прежние старты путешествий/крафт гардероба. Серверная экономика работает отдельно: строительство, улучшения, производство, исследования и рынок доступны через `EconomyPanel`. Коллекция, гардероб и старые поездки сохраняются; последние можно завершить. `streakDecor = false` скрывает прежнюю кастомизацию подарками.

## Границы живой сцены

`new-map-scene.ts` соединяет загрузку графики, команды UI и общий кадр. Логика поведения остаётся в контроллерах; функции рисования читают результат и не выбирают новое действие.

| Слой | Владелец / правило |
|---|---|
| Время и жизненный цикл | `forest-session.ts`: ключ аккаунта + fingerprint геометрии, один активный владелец; большая карта имеет приоритет над кругом |
| Намерения и прерывания | `forest-director.ts` согласует внимание, сад, предметы, птиц и сон; `forest-mind.ts` оценивает полезность, `forest-behavior.ts` выбирает доступную цель |
| Положение героя | `clearing-activity.ts`: движение и переходы; `navigation.ts` находит путь, `steering.ts` смягчает только безопасные повороты; `interaction-navigation.ts` проверяет пороги и прыжки |
| Предметы и растения | `forest-life.ts` — грибы/листик, `forest-garden.ts` — рост/влажность и корзинка; действие меняет урожай только после завершённой доставки |
| Животные | `forest-fauna.ts` — постоянные насекомые и резерв посадок; `forest-birds.ts`/`forest-bird-reactions.ts` — визиты птиц, наземное поведение и реакция на близость |
| Жители и общий проход | `builder-mind.ts`/`plesk-mind.ts` ведут жителей; `forest-resident-occupancy.ts` сообщает фактическую занятость, `resident-traffic.ts` проверяет шаг и безопасный обход. Подтверждённый заказ важнее свободной прогулки |
| Общение | `forest-social.ts` выбирает контекстные реплики из `forest-social-dialogue.ts`, ограничивает повторы и частоту. Свободный строитель может подойти к Мохлику; новое поручение отменяет встречу. История разговора живёт в общей сессии, не в кошельке или серверной памяти |
| Изображение | `tiled/renderer.ts`, `forest-*-painter.ts`, `pixel-sprite.ts`: общий порядок слоёв, координаты мира и прозрачность отдельных PNG |
| Сохранение | `forest-memory.ts` — безопасный снимок; `forest-memory-model.ts` — строгий контракт; `forest-memory-sync.ts` — загрузка, аренда, повторы и конфликты |

Utility AI и разговоры — локальные алгоритмы выбора, без LLM, промптов или сетевых запросов на каждую реплику. Пользовательские имена, статусы и обращения не становятся инструкциями персонажей. `forest-speech-painter.ts` рисует короткие облачка в координатах экрана после мира; локальный шрифт Pangolin загружается один раз, а ошибка оставляет системную замену. Рисование и доступное объявление реплик читают состояние, не запускают разговор повторно.

Сервер сохраняет состояние, но не симулирует закрытый лес. Пауза, скрытая вкладка и reduced motion не догоняют пропущенное время. Сетевое ожидание или чужая аренда также останавливают обычную симуляцию. DEV-сценарий отключает сохранение своей изменённой сессии; просмотр диагностики этого не делает.

[Память v2](game/forest-memory-sync.md) читает v1 и хранит сад без новой SQL-миграции поверх V31. Web и API должны обновляться вместе: старый клиент/сервер не понимает новый снимок. Аренда действует 90 секунд, обычное сохранение — каждые 15 секунд; повтор команды использует прежний `requestId`. Серверный снимок имеет приоритет над кэшем. Память не выдаёт ресурсы или награды.

## Геометрия, графика и безопасное расширение

- **Уровни зданий.** Обе камеры получают подтверждённые уровни отдельным `economyBuildings`. `economy-scene-state.ts → accountSceneLevels` связывает их с `siteId` и выбирает точный либо ближайший доступный младший авторский уровень; при отсутствии младшего — самый младший рисунок. Экономический уровень не меняется из-за отсутствия графики. Для места без экономического уровня сохраняется `initialLevel`, для дома предусмотрен прежний `houseLevel`. DEV-предпросмотр имеет приоритет и не покупает улучшение аккаунта. `tiled/preview-state.ts` строит эффективную сцену выбранных уровней: рисунок, рамка, входы, коллизия, свет и дымоход. `new-map-scene.ts` применяет её только после загрузки всего набора изображений; ошибка или устаревший ответ оставляют прежнюю рабочую сцену. Геометрия меняет fingerprint и пересоздаёт навигацию.
- **Стоящая корзинка.** `Garden → berry-basket` в Tiled задаёт низ по центру. Корзинка добавляет временное препятствие только текущей сессии; её подъём освобождает место. Нельзя записывать его в общий кеш навигации сцены. При прерывании перенос завершается безопасной постановкой; если места нет, корзинка остаётся в руках до безопасного выхода.
- **Куст.** `imageId` связывает полигон взаимодействия с отдельным PNG. Героя перекрывает альфа изображения; полигон задаёт взаимодействие и раскладку ягод. При переднем проходе неподвижный дубль куста исключается из фонового прохода, земля и тень остаются. Контур куста не заменяет `WalkAreas`/`Obstacles`.
- **Обработка рисунков.** `forest-object-appearance.ts` готовит кешированную копию PNG с мягкой коррекцией по материалу. Геометрия, исходные файлы и прозрачность не меняются; обработанный холст ограничен 1024 px по длинной стороне. Дополнительные камушки, щепки и растительность у оснований отключены по художественному решению. Тень использует исходную альфу, а свет/ночь применяются общим проходом после сцены; куст использует одну обработку в неподвижном и переднем проходах. Чтение пикселей выполняется при подготовке кеша, не каждый кадр.
- **Видимость редактора.** Глазики Tiled скрывают слои и объекты только при редактировании. Экспорт валидирует и включает скрытую разметку: уровни, коллизии, воду и места обитания. Видимость в игре задаётся выбранным состоянием объекта и настройками сцены.
- **Кеши.** Сцена считается неизменяемым снимком. Навигация и геометрия используют кеши по объекту сцены; выбранные уровни — ограниченный кеш эффективных сцен. Замена параметров требует новой сцены, а не мутации `TILED_WORLD`. Изображения обеих камер используют общий загрузчик `features/mochlik/assets.ts`; неудачная загрузка допускает повтор.
- **Декорация и экономика.** Рисунок ягод, костёр и птицы сами по себе не выдают товары. Серверный ягодный заказ связан с видимым ростом и стадией сбора, но инвентарь меняется только по подтверждённому `claim_job`. Остальные свободные занятия остаются декоративными. Tiled задаёт внешний вид; добавление PNG не создаёт производство. Береговое исследование показывает выход и рыбалку Мохлика; остальные исследования временно скрывают героя в обеих сценах; полученное улучшение здания выбирает доступную авторскую геометрию. Размечены дом 1–5, мастерская 0–2, заброшенная/открытая шахта 0–1 (`quarry`), лесной участок 0–1 с одним `shelter.png`, маяк 0–1 и сломанный/целый мост 0–1. Общая земля хранится отдельным terrain. Необязательная пара `siteId` + `level` на размещённом terrain-объекте или навигационном полигоне экспортируется в `when`; `previewWorldScene` фильтрует детали, области и препятствия по выбранному визуальному состоянию. Обломки моста и их блокер действуют только при `bridge: 0`. Восстановления моста и прохода через реку, как и интерьера шахты, ещё нет.
- **Объект и его действие.** `site-interactions.ts` связывает `home`, `workshop`, `quarry` и `woodlot` с действиями большой карты. Попадание в полигон и доступная с клавиатуры кнопка используют одну связь. `economy/world-adapter.ts` выбирает карточку стройки/таймера либо производство по подтверждённому уровню. Рендер не вызывает экономические команды и не меняет локально уровни. Маяк и мост пока остаются на авторском начальном уровне 0 без игрового восстановления; оба состояния 0/1 доступны в DEV и `/prototype/tiled-world`. Участок 0/1 использует один рисунок навеса, шахта 0/1 — заброшенный/открытый вход. Отсутствующий старший уровень заменяется доступным младшим рисунком того же здания, сохраняя экономический прогресс.

## Технические границы перед выпуском

Старый рендер и контуры Sites/Next остаются действующими зависимостями, даже если основной интерфейс использует Tiled. Их удаление требует отдельной проверки точек входа, веток `WORLD_PRESENTATION`, тестов, CI и серверного прогресса. `grid-world` — отдельный прототип и не входит в уборку текущего леса.

Крупные координаторы `clearing-activity.ts` и `forest-director.ts` остаются местами повышенного риска: новый тип занятия следует выделять в собственный модуль, сохраняя единственного владельца положения и общий механизм прерываний. Полное разделение существующих переходов — самостоятельный этап, а не условие переименования ветки. Оптимизацию кадра подтверждают профилем на телефоне; количество строк или прохождение тестов не доказывает FPS. Перед выпуском особенно проверяются обе камеры, дома 1–5, прерывания переноски, память на двух устройствах и обе сборки.

## Как менять поведение

Для изменения картинки достаточно сцены/рендера и актуального экспорта. Для изменения серверных правил нужны клиентский контракт, локальная имитация и Ktor. Изменение схемы БД требует новой миграции; расширение валидируемого снимка внутри существующего JSONB может требовать только новой версии контракта, как память v2 поверх V31. TypeScript и Kotlin читают общий [каталог экономики](../apps/api/src/main/resources/world/economy-catalog.json) для товаров, цен и производства; [прежний каталог мира](../apps/api/src/main/resources/world/catalog.json) сохраняет одежду, коллекции и совместимость старых поездок.

Веб-тесты проверяют UI/контракты/рендер/очередь, Kotlin-тесты — сервер, PostgreSQL integration tests — транзакции и миграции. Порядок — [проверки](development/local-development.md#проверки). Выпуск и сервер описаны отдельно в [эксплуатации](operations/operations.md).

Каталог новой экономики — [economy-catalog.json](../apps/api/src/main/resources/world/economy-catalog.json). Его версия 3 задаёт зависимости уровней/рецептов/маршрутов и вместимость склада. Сервер проверяет завершённые уровни; начатые работы хранят собственные стоимость, результат и сроки. Все предметы и резерв рынка занимают общую вместимость. Проверка каталога `npm run economy:check` выявляет циклы, недоступные материалы и сокращение минимального пути развития. Старый `catalog.json` сохраняет контракт гардероба и прежних коллекций. Производственные данные и резерв рынка не хранятся в памяти полянки.

Дневные выдачи и жемчуг за ступени имеют отдельные серверные квитанции V38; обмен реликвиями — V39. Все записи кошелька и инвентаря используют общую блокировку аккаунта. [Правила и ограничения](game/rewards-and-relics.md).

## Экономические команды и доверие

Браузер показывает предварительные условия, но подтверждение делает сервер. Команда включает `requestId`, `expectedRevision` и идентичность аккаунта; повторы возвращают сохранённый результат. Не доверяйте присланным балансам, наградам, времени клиента или выбранной в DEV геометрии.

- Один строитель и занятость Мохлика проверяются до списания. Каменоломня запускает вылазку героя; прежняя отдельная производственная очередь закрыта для новых работ. Параллельные места доступны только производственным зданиям и покупаются с ограничениями по дому.
- Ускорение стройки и обновление лавки используют общий тариф и шаг округления из каталога. `time-price.ts` / `EconomyTimePrice.kt` считают цену по оставшемуся времени. Подтверждённая пользователем сумма — верхняя граница: сервер может списать меньше, но не больше. Нулевое время не создаёт платной операции.
- Рынок и обмен реликвиями используют ограничения группы развития, дневного оборота и личной витрины. V43 хранит общий дневной оборот; сброс хозяйства его не очищает, слияние аккаунтов суммирует. Публикация, покупка, комиссия и возврат резерва выполняются транзакционно.
- Денежные величины API целочисленные: монеты ×10, жемчуг ×50; интерфейс показывает половину внутренних жемчужин. V40/V41 сохраняют масштаб старых квитанций. [Точное правило](game/currency-units.md) обязательно для DEV, админки и новых экранов.
- Гостевой профиль имеет отдельный read-only контракт и проверку связи/видимости. Он не раскрывает кошелёк, инвентарь, активные задания или снимок полянки. Админский доступ не переносится в публичный профиль.

Для новых полей проверяйте длину, допустимую форму и владельца на сервере; для поиска и сортировки — пределы и разрешённые значения. Текст пользователя выводится как данные, не HTML, SQL или инструкция. Закрытие DEV в production и проверка административной сессии сохраняются независимо от видимости кнопок. Подробности — [API и данные](development/backend-and-data.md), [приватность профилей](game/friend-profiles.md), [подготовка выпуска](releases/release-0.6.7.md).

Если позже появится внешний ИИ, пользовательские имена, статусы и обращения должны передаваться ему как недоверенные данные, отдельно от системных инструкций. Наличие текста не даёт права вызывать инструменты, читать секреты, менять кошелёк или выполнять административные действия. Проверки ввода и экранирование нужны уже сейчас; они не являются универсальной защитой будущего LLM-инструмента.
