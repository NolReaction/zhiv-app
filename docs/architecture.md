# Архитектура приложения

Текущее устройство приложения и Tiled-мира в рабочей ветке `work/0.6.7`. Версии web/API остаются 0.6.6 до подготовки выпуска; наличие функции в ветке не означает её публикацию в `master`. Текущий этап и выполненные проверки — [WORK_STATE.md](../WORK_STATE.md), поиск файла — [путеводитель](repository-guide.md), запуск — [локальная разработка](development/local-development.md).

## Контуры запуска

| Контур | Страница | API и данные | Конфигурация |
|---|---|---|---|
| Локальная разработка | Next.js, `npm run dev:local` | `app/api/v1/` → `lib/dev/`, память процесса | [next.config.ts](../next.config.ts), `.env.example` |
| Sites | Vite/Vinext, `npm run dev` | Те же route handlers; это не PostgreSQL-сервер | [vite.config.ts](../vite.config.ts), [worker/index.ts](../worker/index.ts), `build/` |
| VPS | Caddy → Next.js | Caddy направляет `/api/*` в Ktor → PostgreSQL | `deploy/compose.yml`, `deploy/Caddyfile` |

В production локальный API всегда заблокирован: переменная `ENABLE_DEV_API` больше не открывает имитацию. Локальная имитация API в памяти процесса работает только в режимах `development`/`test`; реальные запросы `/api` обслуживает Ktor. [db/schema.ts](../db/schema.ts) — пустая заготовка Sites/D1; схема настоящего приложения находится в Flyway-миграциях `apps/api/`.

## Кто владеет состоянием

| Состояние | Источник истины | Клиентская сторона |
|---|---|---|
| Аккаунт, отметки, приватность, статус | Ktor/PostgreSQL; локально — имитация | [lib/check-in-api.ts](../lib/check-in-api.ts), [lib/auth-api.ts](../lib/auth-api.ts) |
| Подтверждённые тапы, рекорды, достижения | Серверные квитанции | [game-sync.ts](../features/game/game-sync.ts) повторяет неподтверждённые пакеты из журнала |
| Монеты, товары, здания, заказы и рынок | Серверная экономика V32–V33 с `revision` | [economy/session.ts](../features/economy/session.ts): `requestId`, `expectedRevision`, точный повтор после потери ответа |
| Гардероб, коллекции, прежние походы | Прежний world snapshot | [world/session.ts](../features/world/session.ts), старые новые старты запрещены сервером |
| Геометрия карты, водная маска, свет | `world/tiled/forest.tmj` | Экспорт [forest.generated.json](../features/world/tiled/forest.generated.json), общий `TILED_WORLD` |
| Потребности, краткая память, безопасная позиция/сон, грибы и сад | Подтверждённый снимок `forest_memory` с отдельной revision и арендой записи | `forest-memory.ts` формирует снимок v2; `forest-memory-sync.ts` согласует его с API; localStorage — кэш |
| Активное время, пути, текущие сценки и животные | [forest-session.ts](../features/world/forest-session.ts) для аккаунта и геометрии сцены | Один владелец обновляет состояние; круг и большая карта читают его; промежуточные анимации не сохраняются |
| Вид интерфейса и анимационные эффекты | React и локальные настройки | Не начисляют серверные награды |

Не смешивайте [features/world/session.ts](../features/world/session.ts) (гардероб/прежние походы/HTTP) и [forest-session.ts](../features/world/forest-session.ts) (отрисовка/поведение). Старый [features/mochlik/session.ts](../features/mochlik/session.ts) не является владельцем текущего Tiled-леса.

Тап по кнопке и серверная отметка — разные события. Отметка имеет ограничение частоты и влияет на календарь/серию дней; игровые тапы идут пакетами и имеют отдельные подтверждения. Offline-оболочка PWA не означает успешную отправку отметки.

## Путь графики

1. Редактируемая сцена — `world/tiled/forest.tmj`; PNG/JPEG-мастера — `art/world/prototype/`; основной фон — `forest-ground.jpg`.
2. `world:export` проверяет Tiled и формирует [features/world/tiled/forest.generated.json](../features/world/tiled/forest.generated.json). WebP экспортируются отдельно: [арт-процесс](../art/README.md).
3. [presentation.ts](../features/world/presentation.ts) выдаёт единый `TILED_WORLD`. Круг и большая карта используют [new-map-scene.ts](../features/world/new-map-scene.ts), Tiled preview — общий renderer и те же данные.
4. Геометрия, свет и анимации работают в координатах мира; камера переводит их в координаты canvas. Основной новый лес рисуется Canvas 2D.

`WORLD_PRESENTATION.rebuilding = true` временно скрывает строительство и запуск новых путешествий, блокирует крафт; существующие поездки можно завершить. Коллекция, гардероб и старый прогресс сохраняются. `streakDecor = false` скрывает старую кастомизацию подарками. Наличие серверной команды не означает, что функция сейчас открыта в UI.

## Границы живой сцены

`new-map-scene.ts` соединяет загрузку графики, команды UI и общий кадр. Логика поведения остаётся в контроллерах; функции рисования читают результат и не выбирают новое действие.

| Слой | Владелец / правило |
|---|---|
| Время и жизненный цикл | `forest-session.ts`: ключ аккаунта + fingerprint геометрии, один активный владелец; большая карта имеет приоритет над кругом |
| Намерения и прерывания | `forest-director.ts` согласует внимание, сад, предметы, птиц и сон; `forest-mind.ts` оценивает полезность, `forest-behavior.ts` выбирает доступную цель |
| Положение героя | `clearing-activity.ts`: движение и переходы; `navigation.ts` находит путь, `steering.ts` смягчает только безопасные повороты; `interaction-navigation.ts` проверяет пороги и прыжки |
| Предметы и растения | `forest-life.ts` — грибы/листик, `forest-garden.ts` — рост/влажность и корзинка; действие меняет урожай только после завершённой доставки |
| Животные | `forest-fauna.ts` — постоянные насекомые и резерв посадок; `forest-birds.ts`/`forest-bird-reactions.ts` — визиты птиц, наземное поведение и реакция на близость |
| Изображение | `tiled/renderer.ts`, `forest-*-painter.ts`, `pixel-sprite.ts`: общий порядок слоёв, координаты мира и прозрачность отдельных PNG |
| Сохранение | `forest-memory.ts` — безопасный снимок; `forest-memory-model.ts` — строгий контракт; `forest-memory-sync.ts` — загрузка, аренда, повторы и конфликты |

Utility AI — локальный алгоритм выбора, без LLM или сетевых запросов на каждое решение. Сервер сохраняет состояние, но не симулирует закрытый лес. Пауза, скрытая вкладка и reduced motion не догоняют пропущенное время. Сетевое ожидание или чужая аренда также останавливают обычную симуляцию. DEV-сценарий отключает сохранение своей изменённой сессии; просмотр диагностики этого не делает.

[Память v2](game/forest-memory-sync.md) читает v1 и хранит сад без новой SQL-миграции поверх V31. Web и API должны обновляться вместе: старый клиент/сервер не понимает новый снимок. Аренда действует 90 секунд, обычное сохранение — каждые 15 секунд; повтор команды использует прежний `requestId`. Серверный снимок имеет приоритет над кэшем. Память не выдаёт ресурсы или награды.

## Геометрия, графика и безопасное расширение

- **Пять уровней дома.** `tiled/preview-state.ts` строит эффективную сцену выбранного уровня: рисунок, рамка, входы, коллизия, свет и дымоход. `new-map-scene.ts` применяет её только после загрузки всего набора изображений; ошибка или устаревший ответ оставляют прежнюю рабочую сцену. Геометрия меняет fingerprint и пересоздаёт навигацию. DEV-выбор уровня не покупает улучшение аккаунта.
- **Стоящая корзинка.** `Garden → berry-basket` в Tiled задаёт низ по центру. Корзинка добавляет временное препятствие только текущей сессии; её подъём освобождает место. Нельзя записывать его в общий кеш навигации сцены. При прерывании перенос завершается безопасной постановкой; если места нет, корзинка остаётся в руках до безопасного выхода.
- **Куст.** `imageId` связывает полигон взаимодействия с отдельным PNG. Героя перекрывает альфа изображения; полигон задаёт взаимодействие и раскладку ягод. При переднем проходе неподвижный дубль куста исключается из фонового прохода, земля и тень остаются. Контур куста не заменяет `WalkAreas`/`Obstacles`.
- **Кеши.** Сцена считается неизменяемым снимком. Навигация и геометрия используют кеши по объекту сцены; выбранные уровни — ограниченный кеш эффективных сцен. Замена параметров требует новой сцены, а не мутации `TILED_WORLD`. Изображения обеих камер используют общий загрузчик `features/mochlik/assets.ts`; неудачная загрузка допускает повтор.
- **Декорация и экономика.** Ягоды в корзине, костёр, птицы и состояние растений декоративные. Отдельная серверная экономика выдаёт товары только через подтверждённые заказы. Tiled задаёт внешний вид; добавление PNG не создаёт производство. Исследование из экономики временно скрывает героя в обеих сценах; готовый уровень дома выбирает авторскую геометрию.

## Технические границы перед выпуском

Старый рендер и контуры Sites/Next остаются действующими зависимостями, даже если основной интерфейс использует Tiled. Их удаление требует отдельной проверки точек входа, веток `WORLD_PRESENTATION`, тестов, CI и серверного прогресса. `grid-world` — отдельный прототип и не входит в уборку текущего леса.

Крупные координаторы `clearing-activity.ts` и `forest-director.ts` остаются местами повышенного риска: новый тип занятия следует выделять в собственный модуль, сохраняя единственного владельца положения и общий механизм прерываний. Полное разделение существующих переходов — самостоятельный этап, а не условие переименования ветки. Оптимизацию кадра подтверждают профилем на телефоне; количество строк или прохождение тестов не доказывает FPS. Перед выпуском особенно проверяются обе камеры, дома 1–5, прерывания переноски, память на двух устройствах и обе сборки.

## Как менять поведение

Для изменения картинки достаточно сцены/рендера и актуального экспорта. Для изменения серверных правил нужны клиентский контракт, локальная имитация и Ktor. Изменение схемы БД требует новой миграции; расширение валидируемого снимка внутри существующего JSONB может требовать только новой версии контракта, как память v2 поверх V31. Каталог мира общий для TypeScript и Kotlin: [apps/api/src/main/resources/world/catalog.json](../apps/api/src/main/resources/world/catalog.json).

Веб-тесты проверяют UI/контракты/рендер/очередь, Kotlin-тесты — сервер, PostgreSQL integration tests — транзакции и миграции. Порядок — [проверки](development/local-development.md#проверки). Выпуск и сервер описаны отдельно в [эксплуатации](operations/operations.md).

Каталог новой экономики — [economy-catalog.json](../apps/api/src/main/resources/world/economy-catalog.json). Старый `catalog.json` сохраняет контракт гардероба и прежних коллекций. Производственные данные и резерв рынка не хранятся в памяти полянки.
