# Вход: ВК и почта

На входе два основных действия: **«Войти через ВК»** и **«Войти через почту»**. Отдельного переключателя регистрации нет. Сначала проверяем владение VK ID или почтой. Если способ уже привязан — открываем прежний профиль; если нет — спрашиваем имя и создаём профиль после «Продолжить». До подтверждения личности сервер не сообщает, есть ли такой аккаунт.

Обычный вход создаёт отдельную HttpOnly-сессию и сохраняет остальные сеансы. Подписи, люди, группы и отметки остаются у прежнего `app_users.id`. Игровые рекорды, которые раньше хранились в браузере, остаются локальными.

## Сохранить старый профиль

В действующем профиле открыть «Профиль» → «Способы входа» → **«Привязать ВК»** или **«Привязать почту»**. После подтверждения тот же способ открывает этот профиль в других браузерах. Совпадение имён, username или адреса из другого провайдера не объединяет аккаунты.

Если прежний профиль закрыт везде, сначала использовать сохранённый резервный код, затем привязать ВК/почту. Восстановление кодом остаётся аварийной операцией с отзывом прежних сеансов. Без действующего сеанса, привязанного способа или резервного кода автоматически доказать владельца старого профиля нельзя.

## 1. Создать приложение VK ID

Использовать кабинет подключения **VK ID**, указанный в [официальном SDK](https://github.com/VKCOM/vkid-web-sdk), и создать приложение для веб-сайта.

| Настройка | Значение |
| --- | --- |
| Название | Я ЖИВОЙ |
| Адрес сайта / доверенный домен | `https://im-alive.ru` (если поле принимает только имя — `im-alive.ru`) |
| Redirect URI | `https://im-alive.ru/api/v1/auth/vk/callback` |
| Идентификатор приложения | Скопировать APP_ID в `VK_CLIENT_ID` |

Callback должен совпадать точно, включая путь и отсутствие завершающего `/`. Если кабинет требует дополнительные данные или публикацию приложения, закончить его процедуру перед общим запуском. Названия полей могут отличаться. Реальные требования кабинета и вход с данным APP_ID проверяются владельцем: интеграционные тесты не регистрируют приложение в VK.

Интеграция использует серверный Authorization Code + PKCE и `device_id`, проверяет `state`, затем сверяет ID в ответе `user_info`. Параметры обмена соответствуют [исходникам VK ID SDK](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts). `client_secret` в этом PKCE-потоке не используется; Telegram bot token сюда не подходит. Токены VK не сохраняются в браузере и не записываются в логи приложения.

## 2. Подключить отправку писем

Получателем кода может быть Mail, Яндекс и другой почтовый ящик. Для этого не нужен пароль от ящика пользователя. Приложению нужен **отправитель** писем.

Для этого VPS основной вариант — **Почтовый сервис Selectel**. У Selectel стандартные исходящие SMTP-порты 25/465/587 заблокированы по умолчанию; разблокировка доступна не для всех типов IP и серверов. Поэтому настройки личного Mail/Яндекса могут упереться в сетевой таймаут. [Ограничения портов](https://docs.selectel.ru/infrastructure/blocked-ports/).

В панели Selectel открыть **Продукты → Почтовый сервис**, создать ресурс `ImAlive`, подтвердить и добавить `im-alive.ru`. Для этого добавить TXT-записи в уже существующую DNS-зону:

| Имя | Значение |
| --- | --- |
| `im-alive.ru` | Ключ подтверждения владения из карточки ресурса |
| `selcloud._domainkey.im-alive.ru` | Значение DKIM из карточки домена |
| `_dmarc.im-alive.ru` | `v=DMARC1; p=quarantine;` — если записи ещё нет |
| `im-alive.ru` | `v=spf1 include:spf.mail.selcloud.ru ?all` — если SPF ещё нет |

Существующую A-запись сервера сохранить. SPF должен быть один: при наличии добавить `include:spf.mail.selcloud.ru` в текущую запись перед завершающим `all`, не создавать вторую. Если в существующей DMARC-записи стоит `p=none`, заменить его на `p=quarantine`, сохранив остальные параметры. Существующие `quarantine` и `reject` оставить. Дождаться подтверждения домена и взять SMTP-логин/пароль из вкладки «Информация» ресурса. Проверить тариф и лимиты в кабинете.

SMTP: `smtp.mail.selcloud.ru`, порт **1126 с обязательным STARTTLS**. Альтернатива — 1127 с TLS от начала соединения (`implicit`). Отправитель `login@im-alive.ru`; отдельный почтовый ящик на этом адресе создавать не требуется для отправки кодов. Все шаги и индивидуальные значения: [официальная инструкция Selectel](https://docs.selectel.ru/email-service/connect-email-service/).

### Если всё-таки использовать личный Mail или Яндекс

Сначала подтвердить доступность исходящего SMTP на VPS. Для Mail: `smtp.mail.ru:465`, `implicit`, полный адрес как SMTP_USER и SMTP_FROM, отдельный пароль приложения для отправки писем. [Инструкция Mail](https://help.mail.ru/mail/login/mailer/).

Для Яндекса: `smtp.yandex.ru:465`, `implicit`, полный адрес и пароль приложения «Почта»; разрешить почтовые программы в настройках ящика. [Инструкция Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

С личным ящиком отправитель должен соответствовать разрешённому адресу этого ящика. Не указывать `login@im-alive.ru`, если провайдер не разрешил отправку от домена. Обычный пароль аккаунта не использовать. Если порт недоступен — возвращаться к почтовому сервису Selectel, а не отключать TLS.

## 3. Настроить сервер

Сначала получить и проверить новый код из ветки `codex/0.5.0-privacy-and-people`; перед применением миграции сделать [проверенную резервную копию PostgreSQL](operations.md). GitHub-коммит сам не обновляет VPS. Для перехода с уже установленной V15 применяется только новая V16: добавляются VK и одноразовые подтверждения создания профиля. Старые миграции и пользовательские данные сохраняются.

После обновления checkout, на сервере в `~/zhiv-app`:

```bash
bash scripts/create-auth-secret.sh
nano deploy/.secrets/auth/smtp_password
chmod 444 deploy/.secrets/auth/smtp_password
nano deploy/.env
```

В редактор `smtp_password` вставить **только SMTP-пароль**, без `SMTP_PASSWORD=`, без кавычек. Скрипт требует стандартный OpenSSL, не требует Node на VPS, сохраняет существующий `code_secret` и не выводит секрет. На хосте `deploy/.secrets` закрыт правами 700, файлы доступны отдельному UID API через bind mount подкаталога `auth`. Если редактируется уже существующий файл 444, временно поставить 600 и после сохранения вернуть 444.

В существующем `deploy/.env` изменить соответствующие строки, сохранив DOMAIN и настройки БД. Не добавлять дубли:

```dotenv
VK_CLIENT_ID=APP_ID_ИЗ_VK_ID
TELEGRAM_CLIENT_ID=
TELEGRAM_CLIENT_SECRET_FILE=
SMTP_HOST=smtp.mail.selcloud.ru
SMTP_PORT=1126
SMTP_TLS_MODE=starttls
SMTP_USER=ЛОГИН_ИЗ_ПОЧТОВОГО_РЕСУРСА
SMTP_PASSWORD_FILE=/run/auth-secrets/smtp_password
SMTP_FROM=login@im-alive.ru
AUTH_CODE_SECRET_FILE=/run/auth-secrets/code_secret
```

Заменить два заглавных значения на свои. Если раньше был задан `TELEGRAM_CLIENT_SECRET` напрямую, тоже очистить его. Сам SMTP-пароль хранится в файле, не в `.env`. Секреты не отправлять в чат и не добавлять в GitHub.

Проверить конфигурацию и обновить контейнеры:

```bash
sudo docker compose --env-file deploy/.env -f deploy/compose.yml config --quiet
sudo docker compose --env-file deploy/.env -f deploy/compose.yml up -d --build api web caddy
sudo docker compose --env-file deploy/.env -f deploy/compose.yml ps -a
curl --fail --show-error --max-time 20 https://im-alive.ru/readyz
curl --fail --show-error --max-time 20 https://im-alive.ru/api/v1/auth/options
```

Ожидаются healthy API/web/БД, успешный выход migrate/provision, `{"status":"ready"}` и включённые `vk:true,email:true`. Флаги означают наличие конфигурации, **не доказательство реального входа или доставки письма**. После отключения Telegram ответ также содержит `telegram:false`. Не удалять PostgreSQL volume и не запускать `down -v` на рабочем сервере.

## 4. Проверить до объявления друзьям

1. В открытом старом тестовом профиле привязать ВК и почту. Сверить публичный ID, людей и отметки после входа во втором браузере; первый сеанс должен сохраниться.
2. С новой почтой получить код на реальные Mail и Яндекс. Имя должно появиться только после верного кода. Повторный вход с этим адресом должен сразу открыть прежний профиль.
3. Проверить неправильный код, повтор использованного кода и отмену VK. Они не должны создавать профиль. После обрыва ответа повторная попытка проверяет уже созданную сессию/подтверждение, прежде чем показывать ошибку.
4. Проверить настоящий полный вход через VK ID на iPhone PWA, внутри Telegram и в обычном браузере. Автотесты протокола не заменяют эту проверку: приложение в VK и сетевой доступ из Selectel ещё нужно подтвердить.
5. В «Устройствах» отозвать второй сеанс и проверить, что текущий остался активным.

VPN и прокси в этой конфигурации не используются. Установка PWA остаётся возможностью браузера, а не условием входа. Проверка сессии и выдача кодов не зависят от общего хранилища Safari и встроенного браузера.

## Защита и совместимость

Email-код действует 10 минут и привязан к начавшему запрос браузеру. Пять неверных попыток закрывают запрос; повторное письмо — не чаще минуты и пяти писем на адрес в час, дополнительно ограничен IP. В БД хранится HMAC кода, отдельный ключ — в файле. После подтверждения неизвестной личности сервер выдаёт одноразовый билет регистрации на 10 минут, привязанный к HttpOnly-cookie браузера. Создание профиля, сессии и погашение билета происходят в одной транзакции. Два подтверждения одной личности не создают два аккаунта.

Старый Telegram backend оставлен для перехода и уже привязанных идентичностей, но кнопка Telegram убрана. Перенос или объединение аккаунтов по непроверенным совпадениям не выполняется. Смена/отвязка способа входа остаётся отдельной будущей задачей с повторным подтверждением.
