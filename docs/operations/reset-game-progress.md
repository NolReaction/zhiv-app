# Новый игровой старт 0.7.2

Владелец выбрал полный **игровой** сброс при выпуске 0.7.2. Аккаунты, друзья, отметки «Я живой», статусы и геоданные сохраняются. Это отдельная административная операция: обычные миграции и `bash scripts/deploy-update.sh` её не запускают. Команды ниже подготовлены для окна выпуска; подготовка кода сама по себе не означает, что рабочая БД уже сброшена.

`reset-user-data.sh`, `reset-database.sh`, удаление PostgreSQL volume и `down -v` здесь **не подходят**: они удаляют аккаунты и связи друзей.

## Граница сброса

Полный проверяемый список — `scripts/reset-game-progress.sql`. Скрипт принимает схему **V81** с путём B49 → V50–V81 либо исторической цепочкой V1–V81. V79 расширяет ограничения достижений, V80 снижает стандартные цены Береста и расширяет прежний стандартный ассортимент с 67 до 69 товаров. Обе миграции не добавляют таблиц. Это проверка совместимости схемы, независимая от номера выпуска. Новый XP, сезон и ускорение находятся внутри JSON хозяйства: замена всего состояния удаляет их без отдельных таблиц. При добавлении миграции необходимо явно пересмотреть классификацию таблиц и обновить проверку; неизвестная схема или неуспешная миграция останавливает сброс. История Flyway не переписывается. Сброс очищает опубликованные рыболовные рекорды, отзывает согласие на их показ и увеличивает версию согласия, чтобы запрос из старой вкладки не мог включить публикацию снова.

| Данные | После сброса |
|---|---|
| Аккаунты, публичные ID, имена, аватары, язык, часовой пояс, текущие статусы | Сохраняются целиком |
| Способы входа, сессии, резервные коды, контакты восстановления, история объединений | Сохраняются |
| Друзья, группы, приглашения, избранное и личные имена | Сохраняются |
| Отметки «Я живой», получатели и время последней отметки | **Сохраняются** |
| Согласия на геопозицию, получатели и текущие/замороженные координаты | **Сохраняются**; обычные сроки хранения продолжают действовать |
| Кошельки, склад, постройки, производства, добыча, рыба/снасти, еда, заказы и корабль | Начальный набор, без прежних работ и имущества |
| Общий игровой XP и уровень, репутация, сезонный вклад и тап-ускорение | Начальное состояние; старые поля JSON не переносятся |
| Игровые предметы, коллекции, тапы, серии, рекорды, месячный рейтинг и игровое время онлайн | Очищаются; участие в рейтинге выключается |
| Игровые достижения и награды | Очищаются, кроме достижений защиты аккаунта и их квитанций |
| Обучение, семь подарков и приветственное письмо | Начинаются заново; письмо получает новый ID |
| Рынок, включая проданные лоты и несобранную выручку, обмены и игровые квитанции | **Полностью очищаются**; старую выручку после сброса забрать нельзя |
| Личные поставки/покупки Береста, первый выкуп и дневные лимиты | Начинаются заново; общие административные настройки Береста сохраняются |
| Уведомления об игре и приветственном подарке | Удаляются; сервисные письма и уведомления об отметках сохраняются вместе с историей доставки |
| Промокоды и активации, админские письма, модерация, баны, обращения, аудит безопасности | Сохраняются |

Начальное хозяйство создаётся штатным SQL-инициализатором: **100 монет, 0 жемчуга, 3 бревна, 5 камней**, дом, куст и кладовая первого уровня, вводный заказ. Новые поля приложения получают штатные начальные значения при чтении. Старые ресурсы не конвертируются.

Очистка — одна транзакция без `CASCADE` и удаления схемы. Полные строки сохраняемых таблиц сверяются до и после, включая `app_users`, отметки и геоданные; неожиданное изменение откатывает операцию. Резервные копии и аватары не удаляются. Копия по прежней политике не содержит эфемерных координат; при восстановлении backup они будут опубликованы устройствами заново.

## Однократность и старые вкладки

Фиксированный ID нового сброса — **`0.7.2`**. Запись о прежнем сбросе `0.7.1` остаётся в истории и не препятствует новому выпуску. После успешного выполнения повтор команды с ID `0.7.2` **не стирает новый прогресс и не повторяет стартовые подарки**.

Поколение прогресса повышается атомарно. Старые игровые запросы получают `GAME_PROGRESS_RESET`; клиент очищает игровые локальные данные соответствующего аккаунта, не удаляя cookies входа. Монотонные ревизии мира, хозяйства, лесной памяти и видимости рейтинга сохраняют защиту после удаления квитанций. Отдельная локальная/Sites база этой серверной операцией не очищается.

## Обновление и сброс в одном окне

Из чистого checkout проверенного релизного коммита:

```bash
cd ~/zhiv-app
bash scripts/deploy-update.sh --reset-game-progress-0.7.2
curl -fsS --max-time 20 https://im-alive.ru/readyz
```

Новая версия сначала собирается. Затем скрипт включает техработы, останавливает web/API, создаёт backup и проверяет его восстановлением **до миграций**. После миграций он создаёт копию обновлённой базы, восстанавливает временную БД и репетирует на ней тот же сброс с проверками сохранности. Только после успешной репетиции очищает рабочую БД и запускает сервисы.

Нужны Python 3 и место под копии/временное восстановление. Закрытые копии находятся в `../zhiv-backups`. Общая блокировка с deploy исключает параллельное обслуживание. Без флага сброса обычный deploy сохраняет прогресс. Старый флаг `--reset-game-progress-0.7.1` отклоняется, чтобы старая инструкция случайно не запустила новый сброс.

## Уже обновлённый сервер

Просмотр без изменений — режим по умолчанию:

```bash
bash scripts/reset-game-progress.sh --preview
```

Он выполняется в `READ ONLY`: проверяет схему, показывает только названия таблиц, количества строк и состояние сброса.

Явное выполнение:

```bash
bash scripts/reset-game-progress.sh --confirm-reset-game-progress
```

Скрипт останавливает Caddy/web/API, создаёт dump, проверяет восстановление и репетирует сброс во временной БД, затем применяет его к рабочей. После запуска проверяет `/readyz`. Миграции и сборка здесь не выполняются: соответствующие web/API и схема должны быть развёрнуты заранее.

## Проверка после запуска

У существующего пользователя должны сохраниться вход, друзья, отметки и статус. Хозяйство, XP, репутация, сезон, тапы и усиление начинаются заново; прежний рынок и выручка пусты, обучение доступно, подарок начинается с первого дня. Открытая до сброса вкладка переходит к новому поколению. Повтор команды сохраняет уже заработанный после сброса прогресс.

При ошибке не открывайте трафик и не повторяйте команды вслепую. Сохраните путь к backup и сообщение, произошёл ли COMMIT. Восстановление требует согласованной копии БД и соответствующей версии web/API; один откат Git базу не восстанавливает. [Эксплуатация](operations.md), [восстановление базы](reset-database.md#если-произошла-ошибка).

Проверки: `tests/reset-game-progress.test.mjs`, `tests/deploy-lifecycle.test.mjs`, клиентское поколение, `JdbcGameProgressResetIntegrationTest` и production Compose. Маленькие локальные проверки оболочки не заменяют настоящую PostgreSQL-репетицию на копии, которую выполняет серверная команда перед изменением рабочей базы.
