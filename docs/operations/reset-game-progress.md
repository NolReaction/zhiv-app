# Новый старт 0.7.1 с сохранением входов и друзей

Владелец выбрал общий перезапуск в выпуске **0.7.1**: очистить игру, историю отметок и рекорды, сохранив аккаунты, друзей и необходимые настройки. Это явная административная операция. Обычные миграции и `bash scripts/deploy-update.sh` сами её не запускают.

`reset-user-data.sh`, `reset-database.sh`, удаление PostgreSQL volume и `down -v` здесь **не подходят**: они удаляют аккаунты и связи друзей.

## Что очищается

Полный проверяемый список — в `scripts/reset-game-progress.sql`. Поддерживается только схема **V71**: новая база B49 → V50–V71 или существующая V1–V71. Неизвестные таблицы, неуспешные миграции и другая история останавливают операцию; история Flyway не переписывается.

| Данные | После сброса |
|---|---|
| Аккаунты, публичные ID, имена, аватары, язык и часовой пояс | Сохраняются |
| Способы входа, активные сессии, резервные коды, контакты восстановления, история объединения | Сохраняются |
| Друзья, группы, приглашения, избранное, личные имена | Сохраняются |
| Приватность, согласия на геопозицию, подписки и настройки уведомлений | Сохраняются; старые координаты удаляются |
| История отметок «я жив», получатели отметок, время последней отметки | Очищаются; новую отметку нужно сделать заново |
| Хозяйство, кошельки, склад, рыба и снасти, еда, заказы, постройки и текущие задания | Начинаются с начального набора |
| Коллекции, игровые предметы, клики, серии, рекорды, рейтинг и история времени онлайн | Очищаются; участие в рейтинге выключается |
| Игровые достижения и их награды | Очищаются; сохраняются только достижения защиты аккаунта и отметки об уже полученных за них наградах |
| Обучение, помощь первого сбора, подсказки жителей, локальные открытия и игровые очереди | Начинаются заново при подключении клиента |
| Семь подарков, награда обучения, приветственное письмо | Начинаются заново; новое приветственное письмо получает новый ID |
| Рынок, несобранная выручка, обмены, витрины, квитанции команд и игровые журналы | Очищаются |
| Старые уведомления об игре и отметках, история доставки | Очищаются, кроме квитанций доставки сохранённых писем; эти письма не дублируются |
| Промокоды и история их активаций | Сохраняются, чтобы ранее использованные коды не стали многоразовыми |
| Настройки соседа, поставки и покупки, квитанции, история выкупов и лимиты | Сохраняются; сброс не возобновляет первый быстрый выкуп и дневные бюджеты |
| Административные письма, модерация, баны, обращения, наблюдения и журналы безопасности | Сохраняются |

Сохранённая дружба сама по себе не возвращает старое достижение за друзей. Достижения привязанной почты и сохранённого резервного кода остаются связанными с реальной защитой аккаунта.

Начальное хозяйство создаётся штатным SQL-инициализатором: **100 монет, 0 жемчуга, 3 бревна, 5 камней**, дом, куст и кладовая первого уровня, вводный заказ на одну малину. Старые ресурсы не конвертируются. Выплаты за новое обучение требуют нового выполнения его условий.

Очистка выполняется одной транзакцией без `CASCADE` и удаления схемы. Полные строки сохраняемых таблиц сверяются до и после; в `app_users` разрешено изменить только время последней отметки. Неожиданное отличие вызывает откат. Резервные копии и файлы аватаров не удаляются.

## Однократность и старые вкладки

Сброс имеет фиксированный ID `0.7.1`. Таблица запусков записывает его атомарно с очисткой и повышением поколения прогресса. **Повтор той же команды не стирает новый прогресс и не выдаёт подарки повторно.** Для следующего общего перезапуска потребуется отдельное изменение и проверка; подменять ID вручную не следует.

API сообщает поколение через `/me`. Игровые запросы и отметки передают его обратно; старые вкладки получают конфликт `GAME_PROGRESS_RESET`. Клиент перед запуском игры очищает старые данные текущего аккаунта, начинает новое поколение локальных хранилищ и перезагружается при смене поколения. Авторизационные cookies сохраняются. Поздняя запись старой вкладки остаётся в прежнем хранилище и не восстанавливает игру.

Дополнительно сохраняются монотонные ревизии хозяйства, мира, лесной памяти и видимости рейтинга. Старые запросы не становятся новыми наградами после удаления прежних квитанций. Отдельная локальная/Sites база этой серверной операцией не очищается.

## Обновление и сброс в одном окне обслуживания

Из чистого checkout проверенного релизного коммита:

```bash
cd ~/zhiv-app
bash scripts/deploy-update.sh --reset-game-progress-0.7.1
curl -fsS --max-time 20 https://im-alive.ru/readyz
```

Скрипт собирает новую версию, включает техработы, останавливает web/API, создаёт итоговый backup и проверяет его настоящим восстановлением **до миграций**. Затем применяет миграции. До запуска приложения создаёт копию обновлённой базы, восстанавливает её во временную БД и выполняет на ней тот же reset с проверками сохранности. Только после успешной репетиции очищает рабочую БД и запускает сервисы.

Нужны Python 3 и свободное место под резервные копии и временное восстановление. Копии содержат аккаунты и прежние игровые данные; они хранятся закрыто в `../zhiv-backups`. Общая блокировка с deploy исключает параллельный запуск этих операций.

Без `--reset-game-progress-0.7.1` обновление сохраняет прогресс. Для этого выпуска использовать именно команду с флагом.

## Отдельный запуск на уже обновлённом сервере

Предварительный просмотр:

```bash
cd ~/zhiv-app
bash scripts/reset-game-progress.sh --preview
```

Это режим по умолчанию. Он использует `READ ONLY`, проверяет схему и выводит только названия таблиц, количество строк и состояние сброса, без содержимого аккаунтов и секретов.

Явное выполнение:

```bash
bash scripts/reset-game-progress.sh --confirm-reset-game-progress
```

Скрипт останавливает Caddy/web/API, создаёт dump, проверяет полное восстановление, репетирует очистку на временной базе и только затем применяет её к рабочей. После запуска проверяет `/readyz`. Миграции и сборка в этом режиме не выполняются: схема V71 и соответствующие web/API должны быть развёрнуты заранее. При повторе ID `0.7.1` новая игра сохраняется.

## Ошибки и проверка после запуска

При ошибке не отключать техработы и не повторять команды вслепую. Сохранить путь к backup и сообщение о том, был ли уже COMMIT. Восстановление старого прогресса требует восстановления всей согласованной копии и соответствующей версии web/API; записи после момента копии при этом теряются. Простое переключение Git обратно базу не восстанавливает. [Эксплуатация](operations.md), [восстановление базы](reset-database.md#если-произошла-ошибка).

После обслуживания проверить существующий аккаунт: вход сохранён, друзья на месте, отметок и рекордов нет, начальный склад и обучение доступны, рынок пуст, подарок начинается с первого дня. Открытая до сброса вкладка должна перейти к новому старту. Повтор команды должен сохранить уже заработанный после сброса прогресс.

Проверки в репозитории: `tests/reset-game-progress.test.mjs`, тесты клиентского поколения, `JdbcGameProgressResetIntegrationTest` и серверные тесты отказа старым поколениям. Production Compose воспроизводит миграцию и явный reset. Проверка на копии фактической production-БД происходит непосредственно в серверной команде. Уже принятое внешним push-сервисом сообщение до остановки API может доставиться в пределах своего TTL.
