# Закрытая панель управления

Панель `/admin` доступна на том же домене, что и приложение. Для im-alive.ru это **https://im-alive.ru/admin**. Панель работает с production API Kotlin и PostgreSQL. В локальном mock API и Sites права администратора не выдаются: административные запросы возвращают 503.

## Доступ

Сначала войдите в обычное приложение выбранным аккаунтом через существующий способ входа. Затем откройте `/admin` в **том же браузере**. Сеанс установленной PWA на телефоне может отличаться от сеанса Safari: при переходе в другой браузер нужно войти там отдельно.

Сервер проверяет действующую сессию и наличие точного публичного ID в `ADMIN_PUBLIC_IDS` при каждом запросе. По умолчанию список пуст: доступа нет ни у кого. Клиентский флаг, имя пользователя, заголовок запроса или знание адреса панели прав не дают. Администраторские аккаунты не зашиты в исходный код.

Код панели находится в публичном GitHub вместе с приложением. База, сеансы, список разрешённых администраторов и секрет мониторинга на GitHub не попадают. Защита строится на серверной авторизации. Оболочка страницы доступна посетителю, данные — только разрешённому аккаунту. Ответы не кэшируются; service worker не сохраняет панель и её API для работы офлайн. При 401/403 интерфейс очищает полученные данные.

## Первое включение на существующем VPS

Получите проверенный текущий выпуск из `master` в чистую рабочую ветку. Нужны Python 3, Docker Compose и право запускать `sudo docker`. Подставьте **свой ID из профиля**:

```bash
cd ~/zhiv-app
python3 scripts/configure-admin.py --public-id XXXX-XXXX-XXXX
bash scripts/deploy-update.sh
curl --fail --show-error --max-time 20 --output /dev/null --write-out 'Главная: HTTP %{http_code}\n' https://im-alive.ru/
curl --fail --show-error --max-time 20 https://im-alive.ru/readyz
```

`configure-admin.py` сохраняет существующие настройки, добавляет указанный ID к разрешённым, включает Compose profile `monitoring`, указывает внутренний Prometheus и создаёт случайный секрет. Повторный запуск сохраняет секрет; для нескольких администраторов повторите `--public-id`. Файл `deploy/.env` получает права 0600, родитель секретов — 0700. Файлы, смонтированные в непривилегированные контейнеры, доступны им на чтение; `umask 077` не ломает эти права.

`deploy-update.sh` проверяет чистоту отслеживаемых файлов и Compose, собирает образы, затем сохраняет PostgreSQL в `~/zhiv-backups` (при стандартном пути репозитория) и проверяет читаемость архива. После этого запускает сервисы и ждёт readiness. Общая маска — 022, маска резервной копии — 077. Сборка идёт до переключения сервисов; запуск миграции и обновление могут вызвать короткий перерыв. Проверка архива не заменяет периодическую пробную процедуру восстановления на отдельной базе.

В конце скрипт отдельно пересоздаёт Caddy, чтобы применились изменения маршрутов и HTTP-заголовков: само обновление файла не заставляет Compose перезапустить уже работающий прокси.

Журнал администратора и его неизменяемые квитанции хранятся в таблицах, введённых начиная с **V22**. Миграции сохраняют прежние выдачи и аудит. Резервная копия создаётся до применения новых миграций; скрипт обновления не выполняет сброс данных. Не переносите выборочные миграции из другой версии приложения.

## Что показывает панель

Рабочая ветка 0.6.7 содержит миграции до **V45**: память леса, хозяйство, рынок и обмен, достижения и подарки, номинал валют, торговые ограничения, контекст/индексы аналитики и серверный учёт активных игровых сеансов. Раздел «Экономика» читает действующие экономические данные; отдельного экрана управления памятью леса нет. Для карточек поручений жителей новая миграция не нужна. Полный порядок обновления — в [плане выпуска 0.6.7](../releases/release-0.6.7.md); правила обращений — в [обратной связи](../development/feedback.md), память — в [описании синхронизации](../game/forest-memory-sync.md).

Автообновление — каждые 30 секунд; во вкладке кликов — каждые 10 секунд, в аналитике хозяйства — раз в минуту. Журнал операций обновляется вручную, чтобы новые записи не сдвигали страницы. Только при видимой вкладке. Даты и интервалы статистики — UTC. При сетевой ошибке сохраняется последний снимок с предупреждением; прочерк в метриках означает отсутствие измерения, а не нулевую нагрузку.

**Определения статистики:**

- Активный пользователь — пользователь с сохранённой сервером отметкой за интервал. Простое открытие приложения не считается посещением.
- D1/D7 — доля зарегистрировавшихся в выбранном периоде, которые сделали отметку на следующий или седьмой календарный день после регистрации. В знаменатель попадают только пользователи, для которых этот целевой день уже полностью закончился по UTC. Это не показатель серии дней подряд.
- Регистрации и отметки вычисляются по сохранившимся данным. История, удалённая ранее штатными операциями или сбросом базы, не восстанавливается. Текущий список пользователей исключает удалённые аккаунты; сохранившаяся история может включать их активность.
- Игровые показатели используют серверные результаты, а не локальные счётчики телефона. Рекорд серии показан за всё время; тапы и участники месяца — за текущий месяц UTC.

## Аналитика игроков

В разделе «Экономика» три экрана: **«Аналитика»**, **«Хозяйства»** и **«Операции»**. Первый отвечает на вопросы о поведении и расходах, второй показывает текущее состояние, третий позволяет проверить конкретные проводки. Из списка хозяйств, карточки игрока и журнала можно перейти к его операциям.

В аналитике и журнале задаются даты включительно по UTC, поиск игрока и аудитория. Быстрый выбор — сегодня, 7, 30 или 90 дней; произвольный диапазон ограничен 366 днями. Изменённые условия применяются кнопкой «Применить фильтры». По умолчанию исключены **все** аккаунты из серверного списка администраторов; переключатель позволяет включить их. Полный корректный публичный ID означает точный поиск аккаунта, остальные строки ищутся буквально в имени/ID. Проценты и подчёркивания не становятся SQL-шаблонами.

- **Игроки с действиями** — уникальные участники подтверждённых экономических операций за период. Пассивное получение оплаты за лот или свой обмен не делает продавца активным. **Операции** включают такие поступления и движения резерва. Это не посещения, не время онлайн и не число кликов по интерфейсу.
- **Ресурсы** выбираются отдельно: монеты, жемчуг или конкретный предмет. «Получено» и «Потрачено» включают игровые и торговые поступления/списания, но исключают помещение товара в резерв и его возврат. «Чистое изменение» учитывает все четыре потока. Торговые переводы между игроками не равны созданию/уничтожению валюты. Таблица объясняет вид операции, объект, число игроков и категорию потока.
- **Стройки** разделены на начатые и завершённые: последнее включает получение результата и мгновенное завершение ускорением. «Первое строительство в сохранившейся истории» определяется по всей доступной истории каждого игрока, после чего выбираются первые старты, попавшие в период. Повторная стройка давно играющего участника не выдаётся за его первую. Неизвестный объект остаётся отдельной категорией; исторический уровень не вычисляется из нынешнего.
- **Еда и заказы жителей** — число реально списанных порций отдельно для Мохлика и строителя, уникальные игроки, сдачи заказов, фактически выданные монеты, бесплатные и платные замены с реальным расходом жемчуга. Порция считается при кормлении, даже если эффект ждёт следующего задания. Число съеденных блюд нельзя трактовать как число ускоренных заданий. Замена относится к убранной карточке; автообновление и отклонённые команды сюда не входят. Итоги считают уникальных игроков напрямую, без сложения игроков из разбивок. Сохранённый templateId даёт название заказа, награда берётся только из проводки; старые непрозрачные ID карточек без контекста показаны как неизвестный объект.
- **Присутствие и наблюдение** — подтверждённое сервером время и уникальные игроки за выбранные даты UTC. Вкладки одного аккаунта не удваивают время; паузы с разрывом связи более 90 секунд и завершённая AFK-сессия не добавляют его. Короткая задержка ответа неотличима от обычного интервала между подтверждениями. После пяти минут без действий игровая сессия завершается отдельно от входа в аккаунт. Свыше 20 часов за день UTC включает наблюдение, без автоматического бана. В таблице сохранены день, длительность, время сигнала и текущий статус наблюдения: ручное снятие не стирает прошлый сигнал. Показываются последние 100 дней с сигналом; для остальных сузьте даты или задайте ID. Общие показатели полные. Первый сохранившийся день измерений относится к выбранной аудитории; более раннее присутствие не восстанавливается. CSV выгружает точные секунды по дням, интерфейс показывает часы и минуты. Подтверждённое присутствие не доказывает непрерывные действия человека.
- **Уровни сейчас** отражают текущие хозяйства выбранных игроков независимо от дат операций. Отсутствующий профиль не приравнивается к нулевому прогрессу. Подпись и знаменатель отделяют эту сводку от истории.

График активности имеет раскрываемую таблицу точных значений. Выгрузки CSV содержат выбранную дневную/ресурсную сводку либо только видимую страницу журнала; жемчуг выгружается в отображаемом номинале, строки защищены от выполнения формул. В журнале есть фильтры операции, ресурса и направления. Направление относится именно к выбранному ресурсу: получение рыбы за монеты не является поступлением монет. При переходах между страницами сохраняется верхняя граница времени первой страницы; «Обновить» начинает новую выборку. Удаление аккаунта или сброс его истории всё же могут менять состав старой выборки.

### Первые шаги и причины проверить развитие

«Как начинают новые игроки» берёт аккаунты, **зарегистрированные в выбранный период UTC**, с текущими фильтрами имени/ID и аудитории. Их первые подтверждённые операции наблюдаются до времени снимка, в том числе после конца выбранного периода. Доля каждого шага считается от всех аккаунтов этой группы, включая ещё не заведших хозяйство. Первое занятие — вылазка, рыбалка или производство; первая стройка и её получение — отдельные шаги. Это независимые пути, а не последовательная воронка: отсутствие стройки не означает, что игрок не начал другое занятие.

Для достигших шага показана медиана времени от регистрации: половина этих игроков прошла его быстрее. Игроки без события не добавляют нулевое время; при отсутствии измерения показано «Нет измерения». Самое раннее сохранённое событие и число аккаунтов с историей помогают оценить покрытие. При сбросе, удалении истории или переносе аккаунта первый наблюдённый шаг может отличаться от первого реального. «Хозяйство заведено сейчас» и «Дом ≥2 сейчас» — текущие состояния этой же группы, **не исторические даты открытия мира или достижения уровня**. CSV содержит общий знаменатель, сырые секунды/пустые неизвестные значения, тип показателя, период регистрации и время наблюдения.

«Что стоит проверить у игроков» — текущий снимок **всей выбранной аудитории**, независимо от периода регистрации; поиск и исключение администраторов продолжают действовать. Показаны игроки с готовой работой/стройкой, не полученной более 24 часов, урожаем, ожидающим **начала** сбора более 24 часов, либо без подтверждённых экономических операций не менее 72 часов при наличии известной истории. Неизвестная история хозяйства учитывается отдельно и не приравнивается к 72 часам без действий. Пассивная продажа другим игроком и технические переносы не сбрасывают время последнего действия.

Эти причины не доказывают тупик, AFK или отсутствие в сети: хозяйство не отражает все взаимодействия в мире и ежедневные отметки. Один игрок может иметь несколько причин, поэтому показатели не складываются. Список ограничен 100 игроками с явной отметкой сокращения, общие показатели полные. «Хозяйство игрока» открывает существующий read-only снимок, «Операции игрока» — журнал по его точному ID; период журнала сохраняется, для старых действий нужно расширить даты. CSV выгружает показанный список с причинами, временем снимка и отметкой сокращения.

Новые данные передаются дополнительным полем `progression` существующего ответа аналитики; при его отсутствии/null клиент продолжает показывать прежние блоки. Новая миграция или запись событий при чтении не требуется. Основной экран и серверный AFK не изменены.

### Источники и ограничения

`GET /api/v1/admin/analytics` и `/analytics/events` читают `game_presence_daily` (с V45), `economy_ledger`, подписи принятых `economy_commands` и текущие `economy_profiles` в согласованной read-only транзакции. Каждая историческая строка приводится к нынешнему номиналу монет/жемчуга **до** суммирования. Перенос старой экономики, объединение аккаунтов, перенесённые квитанции и DEV-выдачи исключаются из игровых показателей. Права проверяются для каждого запроса; данные не записываются при чтении.

V44 добавляет индексы и небольшой `economy_ledger.context` с объектом и исходным действием. Контекст новых операций формируется сервером из подтверждённой команды/задания, включая рыбалку с отдельным случайным ID задания; приватные seed, будущие награды и полное состояние туда не копируются. Старые строки остаются с пустым контекстом и по возможности связываются с сохранёнными командами. Для некоторых прежних получений/отмен рыбалки точной связи нет — сумма учитывается, объект помечается неизвестным.

Блок покрытия показывает начало сохранившейся истории и количество операций без определённого объекта. Сбросы, удаления и часть истории объединённых аккаунтов не восстанавливаются. Пустой период означает отсутствие сохранившихся подтверждённых операций. Ответы ограничивают разбивки потоков, действий и заказов 1 000 группами с явным сообщением о сокращении; общие суммы остаются полными. При ошибке обновления старые данные показываются только для тех же фильтров и с предупреждением; потеря доступа очищает снимок.

Исходники: `admin-analytics-panel.tsx`, `admin-analytics-api.ts`, `admin-analytics-utils.ts`, `admin-gameplay-analytics.tsx`, `admin-progression-analytics.tsx`, `AdminAnalytics.kt`, `JdbcAdminAnalytics.kt`, `JdbcAdminProgression.kt`. Регрессии проверяют реальные PostgreSQL-агрегации, изоляцию доступа, исторические номиналы, точный поиск ID, первый старт до выбранного периода, сохранённый контекст рыбалки, неизменность данных при чтении, фильтры, страницы и смену аккаунта. Проверки новых шагов и списка развития включают совместимость старого ответа, неизвестную историю, знаменатель долей, CSV и переходы к игроку.

## Хозяйство игроков

Экран «Экономика → Хозяйства» читает текущую экономику PostgreSQL, а не прежние ресурсы `world` или локальную анимацию. Сводка охватывает все неудалённые аккаунты: сколько имеют сохранённое хозяйство, суммы монет/жемчужин, работающие и готовые задания, изменения за последние 24 часа и складские ограничения. Поиск по имени/ID и страницы относятся к списку ниже, не меняют общую сводку. Сортировки: последнее изменение, монеты, дом/завершённые вылазки, ожидающие задания. Один ответ содержит не более 100 игроков.

Карточка показывает кошелёк, предметы, все уровни построек, завершённые вылазки, снасти и коллекцию пойманной рыбы, снимки текущих заданий, запас бонусов еды и уже применённую еду в задании, сохранённые карточки доски с их первоначальными припасами/наградой и счётчиком замен, а также последние **30** экономических проводок. Даты, ингредиенты и награды берутся из сохранённого задания: действующий каталог даёт названия, но не заменяет ранее оплаченный результат. Проводки содержат знаковые изменения монет, жемчужин и предметов; это ограниченный журнал операций, не полная история посещений и не модель заработка.

Блок «Поручения жителей» показывает строительный заказ Шишколапа и вылазку Мохлика. Завершённая постройка продолжает занимать строителя до получения: причина блокировки видна сразу. Для работающего заказа показана динамическая цена ускорения **на время снимка**, без кнопки списания. Готовая вылазка отдельно сообщает о нехватке места. Эти карточки не выдают локальные анимации или положение героя за серверную активность. В рыбалке видны выбранные и доступные крючки, удочки и наживка; проводки обновления лавки и смены крючка имеют понятные названия.

«Снимок» — время ответа сервера. «Изменено» — `economy_profiles.updated_at`, то есть последнее изменение хозяйства, **не время последнего входа**. Чтение панели не создаёт отсутствующий профиль, не выполняет миграцию, не запускает и не получает задания. Отсутствующее хозяйство отмечается явно: его баланс неизвестен, а не равен нулю. Данные профиля, резерва и журнала читаются из одного согласованного снимка транзакции.

Работающие задания включают производство и уже начатый сбор ягод. Созревший урожай без отправленного Мохлика отмечается отдельно как «ждёт сбора»; он не считается готовой выдачей. Граница готовности определяется серверным временем, включая время самого сбора. Готовая работа остаётся в списке до подтверждённого получения.

Кладовая учитывает предметы на руках и резерв активных рыночных объявлений. «Награда не помещается» означает, что **конкретное** готовое задание превышает свободные места сейчас; несколько наград могут по отдельности помещаться и вместе превышать остаток. «Переполнение» показывает сохранённый объём сверх вместимости. Это факты для помощи игроку, а не доказательство читинга: автоматических блокировок, исправления запасов и выдачи валюты здесь нет.

Endpoints `GET /api/v1/admin/economy` и `GET /api/v1/admin/users/{publicId}/economy` используют ту же проверку действующей сессии, серверный allowlist, rate limit и `no-store`, что остальная панель. Частные семена розыгрыша, токены и данные входа не выдаются. В Next/Sites административный API по-прежнему отвечает 503. [Игровые профили друзей](../game/friend-profiles.md) — отдельная ограниченная проекция по принятой связи; они не открывают административные данные.

Исходники: `admin/AdminEconomy.kt`, `db/JdbcAdminEconomy.kt`, клиентские контракты `features/admin/admin-api.ts` и экраны `admin-economy-*`. Проверки: `AdminEconomyObservationsTest`, `JdbcAdminRepositoryIntegrationTest`, `tests/admin-economy-api.test.mjs` и проверки интерфейса хозяйства. Для PostgreSQL regressions нужны JDK 25, Gradle и Docker/Testcontainers; локальное чтение панели без production API не заменяет их.

## Пользовательский текст и смена аккаунта

Имена, обращения и причины из журнала показываются обычным текстом React: HTML, Markdown-ссылки и похожие на команды фразы не исполняются и не передаются LLM. Обратная связь дополнительно сверяет администратора перед чтением и сменой статуса, проверяет ID ответа и очищает снимок при потере доступа. Это защита от использования оставшейся открытой панели после смены аккаунта; обязательная авторизация остаётся на сервере. Повтор квитанции сохраняет более новый статус, если другой модератор уже изменил обращение.

Причины административных изменений проверяются на сервере и в форме: 8–240 символов, без управляющих символов и явных Unicode-команд изменения направления текста. Обычные кириллица, RTL-буквы и emoji допустимы. Старые записи аудита не переписываются. Проверки: `tests/admin-feedback-ui.test.mjs`, `tests/admin-api.test.mjs`, `AdminInputTest` и PostgreSQL-проверки отклонения причины без изменения данных.

## Завершение сеансов

Найдите пользователя → «Завершить сеансы» → введите его точный ID и причину от 8 до 240 символов → подтвердите. Не пишите в причине пароли, коды и личную переписку.

Действие завершает действующие сеансы входа на устройствах. **Это не блокировка аккаунта:** пользователь может войти заново. Данные, друзья и прогресс сохраняются. Собственные сеансы и сеансы других администраторов из панели завершить нельзя.

Операция и аудит записываются в одной транзакции. Повтор при потере ответа использует тот же ID запроса и возвращает прежнюю квитанцию; новый сеанс, созданный после операции, повторный запрос не завершит. Runtime-роль базы не может менять или удалять строки журнала. Администратор PostgreSQL с полномочиями владельца инфраструктуры остаётся доверенной стороной.

## Мониторинг и его границы

Профиль `monitoring` запускает Prometheus и node-exporter во внутренней Docker-сети. Порты 9090 и 9100 на хост не публикуются; Docker socket не подключается. Node-exporter читает `/proc`, `/sys` и корень хоста только для чтения и собирает ограниченный набор показателей. API выдаёт метрики только по случайному Bearer-секрету; Caddy дополнительно закрывает `/internal/*` и `/metrics` снаружи.

Первые измерения появляются после включения, обычно в пределах минуты. Истории нагрузки за время до установки не будет. Prometheus опрашивает сервисы каждые 15 секунд и хранит измерения до 14 дней, ограничивая блоки хранилища 1 ГБ. Оставьте минимум около 2 ГБ свободного места с запасом под WAL и служебные данные. Для Prometheus установлен предел памяти 384 МиБ и CPU 0,5 ядра, для node-exporter — 96 МиБ и 0,25 ядра. Реальная потребность зависит от нагрузки; на маленьком VPS следите за свободной памятью после включения.

CPU, RAM и диск относятся ко **всему VPS**, включая другие процессы. Метрики HTTP относятся к Kotlin API, а не ко всему трафику Caddy/Next.js. p95 — оценка по гистограмме за 5 минут; при отсутствии запросов значение пустое. Игровые счётчики учитывают принятые/отклонённые сервером тапы и не прибавляют повторные квитанции. Счётчики процесса сбрасываются при перезапуске API; Prometheus учитывает сброс при вычислении скорости.

Правила обнаруживают недоступность API и сборщика хоста, повышенную долю HTTP 5xx, нехватку диска/памяти и повышенную долю отклонённых тапов. Сигналы показываются во вкладке «Сервер». **Внешние уведомления в Telegram или почту пока не подключены.** Имена правил остаются техническими, пояснения в панели — на русском.

Остановка мониторинга не останавливает основное приложение. Недоступный сборщик даёт предупреждение и пустые метрики. История хранится в отдельном Docker volume `prometheus_data` и сохраняется при обычном обновлении. Не используйте `docker compose down -v` для обновления: это удаляет тома, включая базу.

## Если игрок видел ошибку, а журнал пуст

Метрики сервера показывают запросы, дошедшие до API. Обрыв на устройстве, потеря ответа или ошибка соединения до сервера могут не дать серверной записи. Нулевая частота HTTP 5xx сама по себе не исключает проблему у игрока.

В рабочей ветке 0.6.7 ошибки начальной загрузки `/api/v1/me` собираются в ограниченную очередь текущей страницы. После успешного получения профиля они отправляются в **«Сбои у пользователей»** как операция `page`, с кодами `NETWORK_ERROR`, `TIMEOUT`, `RATE_LIMITED` или `SERVER_ERROR`. Сохраняется время самого сбоя, поэтому смотрите соответствующий период UTC; доставка может произойти позже. Заголовок `X-Request-ID`, если получен, помогает сопоставить событие с серверным журналом.

До подтверждения профиля очередь существует только в памяти: закрытие или полная перезагрузка страницы её потеряет. Ответ 401 очищает её перед новым входом, чтобы не приписать сбой другому аккаунту. События не содержат URL, cookie, токенов или текста ответа. При отказе браузерного хранилища диагностика уже известного пользователя также сохраняется в ограниченной памяти вкладки; после её закрытия гарантировать доставку нельзя.

Некорректная старая запись больше не блокирует последующие: поля проверяются перед отправкой, серверные коды нормализуются в разрешённые клиентские, а явный `400 INVALID_INCIDENT` удаляет только отвергнутую запись. Сетевые сбои и ошибки авторизации не удаляют очередь.

## Управление доступом и диагностика

Чтобы отозвать доступ к панели, удалите ID из `ADMIN_PUBLIC_IDS` в `deploy/.env`, затем пересоздайте API:

```bash
sudo docker compose --env-file deploy/.env -f deploy/compose.yml up -d --no-deps --no-build --force-recreate --wait api
```

Пустое `ADMIN_PUBLIC_IDS=` закрывает панель для всех. Изменение браузерного интерфейса для этого не требуется. Чтобы остановить только сборщики, выполните `stop prometheus node-exporter`; уберите `monitoring` из `COMPOSE_PROFILES`, очистите `MONITORING_URL` и пересоздайте API. Не удаляйте тома, если история нужна.

```bash
sudo docker compose --env-file deploy/.env -f deploy/compose.yml ps -a
sudo docker compose --env-file deploy/.env -f deploy/compose.yml logs --no-color --tail=100 api prometheus node-exporter
```

При «Доступ закрыт» сравните ID профиля с разрешённым ID и проверьте, что API пересоздан после настройки. При «Войдите в свой аккаунт» войдите в приложение в этом же браузере. Не публикуйте содержимое `.env`, секреты и дампы при обсуждении диагностики.

Исходники: `features/admin/admin-dashboard.tsx`, `features/admin/admin-api.ts`, `apps/api/src/main/kotlin/ru/zhiv/admin`, `deploy/monitoring`. Конфигурация сервера и секреты исключены из Git.

В релизе 0.6.2 у каждого пользователя есть действие **«Награды»**: каталог предметов и достижений, отметка уже полученных, причина и подтверждение ID. Выдача не меняет игровые счётчики. Для достижений со ступенями выдаются все недостающие ступени; уже полученные сохраняют даты. Повторная попытка может завершить частично полученное достижение и не дублирует полное. Один requestId возвращает исходную квитанцию; новая попытка выдать уже имеющееся создаёт запись «уже получено». Выдача себе разрешена. Защита сеансов администраторов сохранена.

`GET /api/v1/admin/users/{publicId}/rewards` и `POST /api/v1/admin/users/{publicId}/grant-reward` работают через Ktor; автономная веб-версия по-прежнему отвечает `ADMIN_UNAVAILABLE`.
