# Проверка ввода и подготовка к выпуску — 2026-10-06

Основа: `fbcde6a` ветки `work/0.6.7-building-levels`. Проверены исходники, локально доступная полная история Git, зависимости и конфигурация развёртывания. Это не проверка работающего Selectel: production-запросы, подбор паролей и проверка найденных строк во внешних сервисах не выполнялись. Итоговые локальные проверки этого изменения — в [WORK_STATE](../../WORK_STATE.md).

## Ввод и границы доверия

В игре нет LLM, принимающей пользовательские промпты. Общение жителей формируется из локального набора реплик и состояний мира. В просмотренных путях имена, группы, прозвища, статусы, обращения и причины административных действий выводятся React-текстом; SQL использует параметры. Исполнения такого текста через HTML, `eval`, shell или модель не обнаружено.

Запрет фраз вроде «игнорируй инструкции» не является защитой и не введён: игрок должен иметь возможность отправить пример ошибки в обращении. HTML/SQL-подобный текст также остаётся обычными данными. Если обращения, логи или содержимое репозитория позже передаются внешнему ИИ-помощнику, это недоверенные данные, а не разрешение выполнять команды или менять правила. Будущая интеграция LLM потребует отдельных границ контекста, инструментов и разрешений.

| Проверенный путь | Изменение |
|---|---|
| Создание/изменение имени, регистрация | Общая TS/Kotlin-политика запрещает C0/C1 и явные bidi override/isolate, которыми можно визуально переставлять текст |
| Название/значок группы, статус, личное прозвище | Та же политика; нормальная кириллица, арабские/еврейские буквы и emoji разрешены |
| Обратная связь | Одинаковая нормализация CR/CRLF, сохранение переносов/табуляции, запрет остальных управляющих символов; длина считается в Unicode code points |
| Причины выдач, отзыва сессий и управления игроком | Сервер и формы запрещают визуальную подмену административного журнала через управляющие символы |
| Админская обратная связь | Проверка текущего администратора перед запросом, очистка списка при 401/403, отмена старых запросов, проверка ID квитанции |

Новые ограничения применяются к новым записям; исторические данные не переписываются. Клиентская проверка администратора замечает уже произошедшую смену аккаунта перед действием из устаревшего окна; серверная сессия, allowlist, Origin и права остаются обязательной защитой каждого запроса.

## Поиск секретов

Первый полный проход охватил 182 достижимых коммита, 4 684 уникальных текстовых Git blob и 1 167 текущих tracked-файлов. Правдоподобных настоящих ключей, токенов и приватных ключей не найдено. Локальных игнорируемых `.env`, PEM и keystore в каталоге проекта не обнаружено; машинные хранилища учётных данных не читались. Бинарные изображения/шрифты не являются текстовым охватом; отдельно пропущены четыре крупных PNG/WebP более 4 MiB. Проверка не охватывает удалённые недостижимые коммиты, настройки GitHub Secrets или environment работающего сервера.

Добавлен воспроизводимый сканер без npm-зависимостей:

```sh
npm run security:check
npm run security:history
```

Первый режим проверяет tracked working tree, включая незакоммиченные изменения. Новые файлы надо добавить в Git, а намеренное удаление — stage, иначе неполное чтение завершается ошибкой. Второй проверяет все локально достижимые Git blob и отказывает в shallow checkout. CI `Repository secret scan` получает полную историю и запускает оба режима.

Сканер ищет известные формы сервисных токенов, приватных ключей, JWT, строковые присваивания чувствительным параметрам и пароли в URL. Вывод — только файл/строка/тип и короткий SHA-256 fingerprint; значения и фрагменты исходника не печатаются. Exit 1 означает находку, exit 2 — неполную/ошибочную проверку. Проверенные mock/negative-URL/исторические CI fixtures исключены только точными путями и полными fingerprints в `scripts/secret-scan-fixtures.json`; исключения никогда не разрешают сервисные токены или приватные ключи. Это эвристический guard, не доказательство отсутствия всех возможных форм секретов.

## Зависимости и прошлый CI

CI основы `fbcde6a` завершился ошибкой до web-тестов: production audit обнаружил `sharp <0.35.5` и `source-map-js <1.2.2`. Зафиксированы `sharp 0.35.5` для Next/прямых инструментов и `source-map-js 1.2.2`; после изменения production audit сообщает 0. Применимость известных уязвимостей именно к удалённому игроку не доказана: сторонние изображения не принимаются, а пользовательские source maps не обрабатываются. Установленные затронутые зависимости всё равно обновлены.

Полный audit dev/Sites-инструментов сообщает 21 affected package entry: 16 high и 5 moderate; это записи пакетов, не число доказанных удалённых эксплойтов. Production-only результат не означает, что все инструменты безопасны. В Miniflare остаётся его собственная зависимость `sharp 0.34.5`; форсированная подмена несовместимого диапазона не введена. Остальные предупреждения и совместимое обновление цепочек Cloudflare/Miniflare/vinext остаются задачей до сертификации этого контура. Не открывать локальный DEV-сервер в недоверенную сеть.

Backend того же CI не дошёл до тестов: Kotlin 2.4.10 отверг reified-тип пересечения для списка UUID и Int в двух запросах витрин рынка/обмена. Явный `toTypedArray<Any>()` сохраняет реальные JDBC-типы и прежний SQL. Подавления диагностик и изменения экономики нет. Новая компиляция/JDBC требуют JDK25 и CI; наличие исправления в исходнике не считается пройденным backend-тестом.

## Сервер и выпуск

Подтверждено несоответствие лимитов: допустимая память леса с 128 грибами занимала более 16 KiB, API разрешает 64 KiB, а Caddy ограничивал её общим 16KB. Только точный POST `/api/v1/world/forest-memory/commands` теперь получает 65 536 байт; остальные маршруты сохраняют 16KB. Compose smoke использует допустимый большой снимок и проверяет сохранение через настоящий прокси.

В просмотренной конфигурации DEV API/prototype закрыты в production; внутренний API-порт не опубликован; сессии используют Secure/HttpOnly/SameSite, origin allowlist не берётся из пользовательских forwarded-заголовков. OAuth redirect фиксирован, monitoring URL задаётся оператором, image endpoint принимает только ограниченный локальный raster-путь. Подтверждённого обхода этих границ не обнаружено.

Перед merge/release обязательны зелёные `Repository secret scan`, `Web checks`, `Ktor and PostgreSQL checks`, `Production Compose smoke test` **одного выпускаемого SHA**, проверка V31–V43 на заполненной копии БД и согласованный web/API. В список запрета пропусков JDBC добавлены denomination, barter, progression rewards и guest profile suites. Локально нет JDK25/Docker/Caddy; Compose и серверная компиляция здесь не заявлены выполненными. Проверка действующих firewall, SSH, образов и внешнего backup/restore описана в [предыдущем аудите](security-review-2026-10-05.md#безопасная-проверка-на-selectel).
