# VPS: Selectel

Production-контур: Caddy → Next.js / Ktor → PostgreSQL 18.

## Подготовка

- Установить Docker с Compose v2, Node.js 24 и OpenSSL.
- Направить DNS домена на VPS.
- Настроить SSH по ключу и отдельного пользователя для развёртывания.
- Открыть входящие 80/443; доступ к SSH ограничить администраторами.
- Не публиковать PostgreSQL 5432, API 8080, web 3000 и Caddy admin 2019.

Первый запуск и команды: [настройка сервера](server-setup.md).

После установки PWA не меняйте `DOMAIN` без плана переноса сессий: браузерное
хранилище и сеансы привязаны к прежнему адресу сайта.

## Пароли и вход

Роли PostgreSQL используют отдельные файлы `db_admin`, `db_migration` и `db_app` в `deploy/.secrets/`. Генератор `node scripts/create-deploy-secrets.mjs` сохраняет существующие файлы.

Для существующего PostgreSQL volume файл `db_admin` должен содержать его настоящий пароль: генерация нового файла не меняет пароль внутри БД.

В `deploy/.env` хранятся настройки и пути к секретам. Пароль SMTP и ключ email-кодов находятся в `deploy/.secrets/auth/`. Настройка провайдеров: [ВК и почта](auth-0.5.0.md).

Для отправки кодов используется почтовый сервис Selectel с STARTTLS на порту 1126. Обычные исходящие SMTP-порты 25/465/587 ограничены. См. [настройку почты](https://docs.selectel.ru/email-service/connect-email-service/) и [ограничения портов](https://docs.selectel.ru/infrastructure/blocked-ports/).

## Эксплуатация

Настройте ежедневную зашифрованную копию БД в отдельном хранилище и выполните пробное восстановление. Инструкция: [эксплуатация и резервные копии](operations.md).

В `deploy/Caddyfile` срок `write 2m` ограничивает передачу всего ответа, а не паузу между пакетами. Он согласован с загрузкой крупных рисунков леса: картинки могут грузиться до 60 секунд, сцена — до 90. Не сокращайте этот срок до 30 секунд без проверки медленного соединения; ограничения чтения заголовков и тела запроса остаются 10/15 секунд. См. [семантику таймаутов Caddy](https://caddyserver.com/docs/caddyfile/options#timeouts).

Следите за доступностью HTTPS, `/readyz`, свободным диском и результатами резервного копирования. Docker healthcheck показывает состояние, но сам по себе не перезапускает нездоровый контейнер.

Перед обновлением сверяйте проверки выпуска, сохраняйте резервную копию и запускайте Compose из выбранного релизного коммита. PostgreSQL volume и исторические миграции сохраняются. Публикация коммита в GitHub сама не обновляет VPS.

Для [0.6.9](../releases/release-0.6.9.md) промежуточная история после 0.6.8 объединена. Получите `origin/master` явной командой `git fetch origin +refs/heads/master:refs/remotes/origin/master` и создайте новую ветку развёртывания от точного SHA релиза. Старую серверную ветку сохраните; сливать её с переписанным `master` не нужно. [Команда обновления](operations.md#перед-обновлением).
