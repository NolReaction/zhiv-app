# Релиз 0.6.1

Накопленные исправления после 0.6.0 включены одним релизным коммитом. Открытый мир пока не запускается: нет кнопки входа, монтирования карты, фоновых запросов или автоматического создания профиля мира. Разработка карты продолжается в `feature/mochlik-world`.

## Изменения

- Сохранение очереди игровых нажатий на устройстве, повтор неизменяемых пакетов после потери ответа, восстановление после перезагрузки и потери сети. Отправка соблюдает интервалы и `Retry-After`, длинная игра не расходует прежний часовой лимит запросов.
- Одно разрешение на активную игру для аккаунта; координация вкладок и передача управления между устройствами. Допустимые старые события доставляются под исходным разрешением, не пересоздаются для повторного начисления.
- Окончательно неподтверждаемые очереди сохраняются в локальном архиве для разбора и не блокируют новую игру. Потерянное подтверждение не считается доказательством потери очков; сверять нужно серверный прогресс. При ошибке сохранения архива новые тапы остаются остановлены.
- Ошибки связи и подробности очереди находятся внутри значка сервера и не сжимают основной интерфейс.
- `/admin`: отдельная история пользовательских сбоев, фильтры по игроку/периоду/коду/источнику, номер запроса, время события и получения, сводные счётчики, подсказки для разбора. Серверные графики позволяют смотреть более длинные периоды и различать 429 и 5xx.
- Исправления хвоста и поворотов Мохлика, анимаций, сна и загрузки сцены. Круглая кнопка использует прежнюю лесную поляну; экспериментальные карты и отдельные новые домики не подставляются. Простой вид доступен в настройках профиля.
- Порядок в папках проекта, все шесть медалей в `public/achievements`, обновлённые инструкции.

## Граница открытого мира

`features/app/feature-flags.ts`: `OPEN_WORLD_ENABLED = false`. Он отключает вход, фоновую сессию, карту и дополнительные изображения построек. Кнопка Мохлика получает время основного приложения и заработанные предметы из обычного игрового прогресса.

Общий код и миграции мира остаются в исходниках: их используют также учёт игровых событий, объединение аккаунтов и схема диагностики. Флаг интерфейса не заменяет серверную авторизацию. Все API-команды по-прежнему проверяют пользователя, а тестовая выдача ресурсов недоступна в production.

## Обновление с 0.6.0

Веб-клиент и Kotlin API имеют версию **0.6.1**. Обновлять их нужно вместе. Применяются неизменённые миграции **V25 и V26**; данные игроков не сбрасываются. Новых секретов и обязательных переменных окружения нет.

Получите `origin/master`, создайте новую ветку `deploy/0.6.1-…` от точного коммита релиза, затем выполните:

```bash
bash scripts/deploy-update.sh
curl -fsS --max-time 20 --output /dev/null --write-out 'Главная: HTTP %{http_code}\n' https://im-alive.ru/
curl -fsS --max-time 20 https://im-alive.ru/readyz
```

Скрипт собирает образы, создаёт резервную копию PostgreSQL и проверяет её оглавление, затем обновляет сервисы с миграциями. Для Docker сам использует `sudo` при необходимости. Активный Prometheus пересоздаётся после проверки новых правил; отключённый мониторинг не включается автоматически.

После обновления полностью закройте и заново откройте сайт/PWA на устройствах. Не очищайте данные браузера: там может храниться очередь. Старый клиент 0.6.0 не имел нового журнала, поэтому релиз не может восстановить задним числом тапы, которые он не сохранил.

История сбоев начинает заполняться после обновления. Для прежних инцидентов остаются сохранённые серверные журналы и данные прогресса. Миграции автоматически назад не откатываются; возврат старого сервера требует отдельного плана восстановления.

## Проверки

Релиз проходит обе веб-сборки, проверку типов, lint, полный набор веб-тестов и CI API/PostgreSQL/Compose. Новые проверки покрывают архивирование при потере подтверждения, возвращение через несколько суток, повторный вход, сбой записи архива и продолжение игры без повторного начисления. Отдельно проверяется отсутствие входа в мир и загрузки его изображений круглой кнопкой.
