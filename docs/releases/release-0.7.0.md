# Выпуск 0.7.0

**13 октября 2026 года. Web и API: 0.7.0.** Интерактивная вода, отклик деревьев, новые разговоры жителей, первый участок объёмных теней и уведомления с понятным следующим действием. Предыдущий выпуск: [0.6.9](release-0.6.9.md).

Выпуск объединяет `0.6.9-update` (`821fcd7ed38240a856d16267405affc6e83e5b00`) и `0.6.9-light` (`e8d5b43286722b0135fc61c163b7575b5c4930ff`) поверх `master` `214fda688cabace108c9ae564d3bfa1b0330909f`. Результат публикуется одним обычным новым коммитом с единственным родителем 0.6.9; история `master` и исходные ветки сохраняются. Ветка `engine` в этот выпуск не входит. Публикация кода и развёртывание сервера — отдельные действия.

## Границы выпуска

Вода, листья, шелест и разговоры — локальная косметика. Они не меняют награды, каталог хозяйства, проходимость карты или сохранённый прогресс. Разметка деревьев и нового света покрывает выбранные участки, а не автоматически все нарисованные объекты. В режиме «Меньше движения» симуляция интерактивной воды и её касания отключены.

Свет остаётся прототипом Canvas2D на существующем рисунке. Запечённые в фоне тени не поворачиваются; за пределами размеченной центральной поляны новые препятствия не придумываются. Нет карт нормалей, освещения наклонных стен/крыш или отражений факелов в воде. DEV и изолированный CPU-бенчмарк не подтверждают FPS физических телефонов. Платежи, восстановление моста и маяка, интерьер шахты и посещение чужой полянки остаются следующими этапами.

## Совместимость и данные

- Сброс аккаунтов, хозяйства, БД или localStorage не нужен. Валюты, предметы, уровни, начатые работы, настройки и Web Push-подписки сохраняются.
- При переходе с 0.6.9 штатно применяется [`V50__actionable_notification_sources.sql`](../../apps/api/src/main/resources/db/migration/V50__actionable_notification_sources.sql). Миграция добавляет поля очереди уведомлений, синхронизирует доступность ягод и занятость сборщика, однократно пересчитывает сроки существующих подписанных профилей. V47/V49 не переписаны; новых таблиц и сброса экономических данных нет.
- Каталог экономики остаётся **v3**; цены, рецепты и награды этим выпуском не меняются. Web и API нужно обновить вместе.
- VAPID-ключи, PWA-идентичность и существующие способы входа сохраняются. Реальная доставка push требует поддерживаемого браузера и настроенного сервера; системное имя и переход проверяются на устройстве.
- Новая первая запись [`public/updates.json`](../../public/updates.json): `2026-10-13-0.7.0`, **«Живой лес и понятные уведомления»**. ID, порядок и содержимое прежних записей сохранены. Новость появится у игроков после обновления сервера.

## Проверки

На объединённом выпуске пройдены `npm run typecheck`, `npm run lint`, `npm run architecture:check`, `npm run world:check`, `npm run audio:check`, `npm run security:check` и браузерная smoke-проверка. Проверки новостей — 19/19; версии web/API согласованы, прежние записи новостей сохранены побайтно, относительные ссылки и `git diff --check` проверены.

Полный `npm test` пройден: сборка Sites и **3801/3801 тест**, без ошибок и пропусков. Затем успешно выполнен `npm run build:vps` (Next/VPS). Для полного веб-прогона использован `NODE_OPTIONS=--max-old-space-size=6144`; сборки и тесты, читающие `dist/`, выполнены последовательно.

API/PostgreSQL и production Compose проверяются в CI для точного релизного SHA. Локальная проверка backend недоступна: отсутствуют JDK 25, Gradle и Docker. Кандидат проверяется в `work/release-0.7.0-check`, затем тот же SHA продвигается в `master` после успешного полного CI. Обязательный набор PostgreSQL включает `JdbcNotificationMigrationIntegrationTest` для V50.

Проверка на физических iPhone/Android для плавности, звука, системной подписи push и переходов остаётся отдельной от автоматических проверок.

## Обновление сервера

1. Проверить результаты выпуска и чистоту серверной рабочей копии; получить `origin/master` и выбрать точный опубликованный SHA 0.7.0, сверив его принадлежность полученной ветке.
2. Создать ветку развёртывания от этого SHA, сохранив прежнюю. Старую серверную историю до объединения 0.6.9 не сливать с новым `master` и не очищать через `reset --hard`.
3. Выполнить `bash scripts/deploy-update.sh`. Процедура создаёт и проверяет backup, включает техработы, обновляет согласованные web/API, применяет V50 и проверяет готовность. [Полная команда и порядок](../operations/operations.md#перед-обновлением).
4. Проверить `/readyz`, `/site`, `/updates.json`, версию 0.7.0 и существующий аккаунт. Убедиться, что запасы и начатые работы сохранились; проверить ягодное напоминание, возврат с задания и получение производства.

Точная команда с опубликованным SHA передаётся вместе с выпуском. Публикация в Git сама по себе не обновляет приложение на основном сервере.
