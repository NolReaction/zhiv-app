# Релиз 0.6.6

Состояние `work/0.6.6` (`dbc1e5a`) перенесено одним релизным коммитом поверх `master` (`9903685`). История рабочей ветки сохранена отдельно для дальнейшей разработки. Версии web и Ktor API — **0.6.6**.

## Что увидят игроки

- Мохлик самостоятельно выбирает занятия на полянке, ходит к предметам, дому и кусту из своего текущего положения, обходит препятствия. Повороты и остановки стали плавнее.
- Он прячется в кусте, шевелит листву и стряхивает ягоды. После долгого неактива уходит спать домой; нажатие будит его. Прерывание занятия и выход наружу не возвращают его мгновенно в центр.
- Бабочки живут в лесу днём, светлячки — ночью: прилетают к герою и улетают обратно. Птицы реагируют на происходящее рядом.
- На приближенной карте телефона можно сдвинуть верхние и нижние места из-под интерфейса; при отдалении пустота не открывается.

Это локальный игровой ИИ: выбор целей, память о недавних занятиях, поиск пути и согласование действий. Нейросеть и внешний ИИ-сервис для поведения не используются. Пользовательский текст новости — в [public/updates.json](../../public/updates.json).

Для разработчика: [навигация и плавное движение](../game/world-navigation.md), [практическая памятка Tiled](../game/tiled-quickstart.md). `Routes` больше не обязателен для свободной полянки; точные входы, порог дома и прыжок в куст остаются в разметке.

## Ограничения и доступ

Новые дальние путешествия, рыбалка, строительство, улучшения и крафт пока закрыты через `WORLD_PRESENTATION.rebuilding`; старые украшения дома не отображаются. Обычная жизнь на полянке работает. Сохранённые аккаунты, прогресс и предметы не сбрасываются; ранее начатое путешествие можно завершить и получить награду.

Production DEV-панели и `/prototype/tiled-world` закрыты, локальный API в памяти отключён. Штатная админка сохраняет серверную проверку сессии и `ADMIN_PUBLIC_IDS`. Для локальных инструментов используется `npm run dev:local`.

## Обновление с 0.6.5

**Новых миграций нет: V1–V30 не изменены.** Backend, схема БД и порядок развёртывания сохранены; сброс данных и новые секреты не нужны.

После успешного CI выбранного релизного SHA получите его в чистый checkout сервера и выполните:

```bash
git rev-parse HEAD
bash scripts/deploy-update.sh
curl -fsS --max-time 20 https://im-alive.ru/readyz
```

Перед запуском сверьте напечатанный SHA с проверенным коммитом выпуска. Скрипт собирает образы, проверяет Caddy, сохраняет PostgreSQL и проверяет читаемость архива. Затем включает техработы, останавливает прежние web/API, запускает проверку миграций и новую версию. Трафик открывается после readiness и сверки ID сборки. При сбое после включения техработ исправьте причину и повторите скрипт; не снимайте флаг вручную.

Публикация в `master` сама по себе не обновляет VPS. Открытое приложение версии 0.6.5 получает статус сервера и автоматически переходит на новую сборку с сохранением локальных данных. Подробности — [обновление клиента](../operations/client-updates.md) и [эксплуатация](../operations/operations.md).

## Проверки выпуска

Для релизного SHA обязательны TypeScript, ESLint, обе web-сборки, полный веб-набор и `world:check`; в CI — Ktor/PostgreSQL и production Compose, включая закрытые DEV-пути и экран техработ. Результаты относятся к конкретному SHA в GitHub Actions. Проверки предыдущей рабочей ветки не заменяют проверку релизного коммита.
