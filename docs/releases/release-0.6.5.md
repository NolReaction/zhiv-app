# Релиз 0.6.5

Выпуск объединяет состояние `feature/mochlik-tiled-world` (`bb52823`) и проверки production-доступа одним коммитом поверх `master` (`167da03`). История рабочей ветки не переносится в master; сама ветка остаётся для локальной разработки. Версии web и Ktor API — **0.6.5**.

## Что увидят игроки

- Новый лес и домик, занятия Мохлика, день и ночь с фонарями, факелами и светлячками.
- Дождь с кругами на воде и брызгами на земле, разные птицы и сценарии их появления.
- Справка с поиском рядом с коллекциями; уровни по десять с прогрессом и будущими значками.
- Новости и счётчик непрочитанного в beta-test, форма обращения разработчику. Все обращения поступают в админку; одно принятое сообщение за 24 часа на аккаунт.
- Экран техработ и автоматический переход на новую сборку с защитой очереди нажатий и черновика обращения.

Текст первой пользовательской новости находится в [public/updates.json](../../public/updates.json). Администратору также доступны графики нажатий за 30 минут, сутки и неделю.

## Ограничения текущего мира

Новые прогулки, рыбалка, строительство, улучшения и изготовление вещей временно закрыты на время переноса в новую карту. Старые украшения дома пока не рисуются. Аккаунты, уровни, ресурсы, вещи, достижения и сохранённый прогресс не сбрасываются. Ранее начатое путешествие можно завершить и забрать награду; имеющийся гардероб доступен.

`WORLD_PRESENTATION.rebuilding` остаётся включённым намеренно. Отключение флага само по себе не переносит геометрию прежнего мира.

## DEV и административные действия

В production нет DEV-панелей и редакторской страницы `/prototype/tiled-world` (HTTP 404). Локальный API в памяти закрыт даже при оставленном `ENABLE_DEV_API=true`: реальные данные обслуживает Ktor. `npm run dev:local` сохраняет инструменты локальной разработки.

Обычная админка остаётся доступна только пользователям из `ADMIN_PUBLIC_IDS`; сервер проверяет сессию, Origin, параметры, лимиты и сохраняет квитанции операций. Тестовая команда `dev_grant_resources` сервером не выполняется. Производственные выдачи проходят через штатные административные операции с журналом.

## Обновление с 0.6.3

Выпускаются вместе клиент, Ktor API и Caddy. Старые миграции **V1–V28 не изменены**. Добавлены:

| Миграция | Назначение |
|---|---|
| V29 | Обращения игроков и квитанции изменения их статуса |
| V30 | Служебная дата начала сбора истории нажатий; runtime не получает доступ к журналу Flyway |

Сброс БД не нужен. Из чистого checkout выбранного релизного коммита выполняется `bash scripts/deploy-update.sh`. Скрипт собирает образы, создаёт приватный архив PostgreSQL и проверяет его читаемость, включает техработы, останавливает прежние web/API, применяет миграции и проверяет готовность новой версии. При сбое после включения техработ доступ остаётся закрытым до исправления причины и повторного запуска.

Публикация коммита в master сама по себе не обновляет VPS. При первом внедрении этого механизма старые вкладки/PWA нужно один раз перезагрузить вручную: в версии 0.6.3 ещё нет обработчика статуса сборки. Данные браузера очищать не нужно. Следующие выпуски будут обрабатываться автоматически.

Подробности: [обновление клиента и техработы](../operations/client-updates.md), [эксплуатация и восстановление](../operations/operations.md), [обратная связь](../development/feedback.md).

## Проверки перед выпуском

Обязательны обе сборки, typecheck/lint, полный веб-набор, Ktor/PostgreSQL и production Compose. Отдельно проверяются обновление заполненной БД V28 до текущей схемы без изменения старых данных, закрытие dev-путей, административные права, миграции/повторные запросы, maintenance-gate и согласованность статуса со сборкой. Результат относится к проверенному релизному SHA в GitHub Actions.
