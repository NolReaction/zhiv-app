# Выпуск 0.7.1 — Мохлик 2.0

22 октября 2026. Версия web и API — **0.7.1**, исходная ветка — `0.7.1v2`. Выпуск предназначен для объединения в `master` одним squash-коммитом с названием `0.7.1v2`. Публикация в Git и обновление основного сервера — отдельные действия.

## Что входит

- **Хозяйство и развитие:** последовательные этапы до дома 5, самостоятельная шахта, заказы и производство, восстановление моста и маяка, новые вылазки. Меню показывают текущие работы, а еда расходуется после подтверждения эффекта.
- **Рыбалка и торговля:** снасти и классы рыбы, лавки Плёски и Листохвоста, личные товары рынка и ручной сбор выручки. Можно посещать полянки друзей и покупать в их лавках.
- **Земля:** глобус с рельефом, биомами и объёмными достопримечательностями, атлас открытий, спутниковый слой при настроенном MapTiler. Геопозиция доступна выбранным друзьям только по согласию; предусмотрены точность, срок, призрак и отдельная заморозка получателя. Пеший маршрут запускается вручную.
- **Профиль и награды:** аккаунтная почта, подарки, одноразовая цепочка семи дней, обновлённое обучение, помощь с первым урожаем. Книга коллекций получила главы, страницы, фильтры и свайп.
- **Мир:** доработаны жители, их занятия и домики, свет, звук, работа камеры и мобильный интерфейс. Студия света и отдельный Engine получили проекты, папки и сохранение.
- **Эксплуатация:** расширены административные выдачи, наблюдения за некорректными командами, статистика запросов и расхода внешних API; сохранены обе web-сборки и проверки настоящей PostgreSQL.

[Новость для игроков](../../public/updates.json) описывает видимые изменения без технических деталей.

## База данных и прогресс

**Обычный запуск `scripts/deploy-update.sh` никому не обнуляет игру.** В выпуске нет автоматического сброса аккаунтов, кошельков, построек, вещей, начатых работ или дружбы. Новые правила старта действуют при создании нового экономического профиля; прежние профили не заменяются стартовыми.

Исходный `master` — `f46a2ca120ed690caacd1a76473f85539a5850a1`, схема V52. Перед слиянием нужно повторно получить актуальный `master`; перед обновлением сервера — проверить реальную историю его БД.

| Состояние БД | Путь обновления |
|---|---|
| Существующая БД текущего `master` | Проверка прежней истории и применение V53–V67; B49 не запускается |
| Пустая БД | B49 создаёт начальную схему, затем выполняются V50–V67 |
| БД из экспериментальной экономической ветки с собственными V50–V52 или ранней `earth` с V62 | Нужен отдельный проверенный переход; обычный deploy не исправляет такую историю |

V1–V49 перенесены в `history/` без изменения содержимого; опубликованные V50–V52 не переписаны. V55 сохраняет знание товаров и рыночные места и повышает revision; кошелёк и активные работы остаются. V63 отмечает прежние продажи уже оплаченными, чтобы не начислять выручку повторно. V64 восстанавливает пройденные дни подарков по квитанциям без повторной выдачи валюты. V65–V67 добавляют геопозицию с отдельным согласием, а не включают её всем игрокам. [Полный перечень и правила миграций](../development/database-baseline.md).

Если отдельно принято решение начать игру заново, используется [ручной сброс игрового прогресса](../operations/reset-game-progress.md) с предварительным просмотром, резервной копией и явным подтверждающим флагом. Он **не включён** в команду обновления этого выпуска. Не заменять его удалением БД или пользователей.

## Проверки выпуска

Сводка проверок текущего этапа и оставшихся ограничений хранится в [WORK_STATE.md](../../WORK_STATE.md). Результаты более ранних коммитов не подтверждают выпускаемый SHA.

Перед объединением требуются:

- обе web-сборки (Next/VPS и Sites), все три web-набора, TypeScript, ESLint, архитектура, экспорт мира, аудио и проверка секретов;
- Ktor и настоящая PostgreSQL, включая обновление заполненной БД, baseline пустой БД, подарки, почту, рынки и сохранение прогресса;
- отдельный Engine и редактор;
- **Production Compose smoke test**: совместный запуск web/API/БД, HTTPS, миграции, готовность, закрытые DEV-маршруты, админка, техработы и проверка восстановления. Пропущенный Compose не считается успешной проверкой.

## Обновление сервера

1. Зафиксировать итоговый squash SHA из `master`. Выполнять обновление из чистого checkout именно этого коммита по [инструкции эксплуатации](../operations/operations.md#перед-обновлением), сохраняя `deploy/.env`, секреты и том PostgreSQL.
2. Согласованно обновить web и API через `bash scripts/deploy-update.sh`. Скрипт останавливает запись, создаёт итоговую резервную копию и проверяет её настоящим восстановлением в изолированной PostgreSQL до миграций. Нужны Python 3 и свободное место под временную копию. Затем он проверяет готовность новой версии; таймаут ожидания запуска — 600 секунд. При ошибке не отключать техработы вручную до проверки состояния БД.
3. Проверить `/readyz`, `/app-status.json` и `/updates.json`, затем существующий аккаунт: кошелёк, вещи, стройки и работы, рыбалку, лавку, сбор выручки, почту и коллекции. Новый аккаунт проверять отдельно от сохранённого.
4. Проверить спутниковый слой и «Админка → Расход API → MapTiler». 22 октября пользователь подтвердил настройку ключа для `im-alive.ru` и сервисного токена. Это не независимая проверка сервера. `NEXT_PUBLIC_MAPTILER_KEY` должен попасть из `deploy/.env` в Docker build; сервисный токен остаётся в файле секрета. Повторная настройка без выявленной ошибки не нужна.
5. На физическом телефоне проверить вход и возврат на глобус, GPS и призрак, звук при сворачивании, мост и свайп книги. Эмуляция не доказывает отсутствие редких зависаний или слышимого писка на iPhone.

После применения новых миграций нельзя считать переключение Git на 0.7.0 полноценным откатом. Восстановление выполняется по [эксплуатационной инструкции](../operations/operations.md) из проверенной копии с согласованной версией web/API; записи после момента копии при таком восстановлении теряются.

## Границы выпуска

- Восстановление моста и маяка, вылазки и посещение полянок работают; отдельная управляемая карта дальнего берега и интерьер шахты ещё не входят в выпуск.
- Карта Земли и игровые полянки — разные системы. Геопозиция не работает как фоновый трекер и не обещает непрерывного обновления закрытого приложения.
- Пеший маршрут — результат внешнего сервиса по явному запросу, а не полноценная навигация; спутниковый слой зависит от настройки и доступности MapTiler.
- Реальные платежи не включены. Отдельный Engine остаётся инструментом разработки; основной лес использует Tiled-сцену.
- Проверки CI не заменяют измерение плавности, прослушивание звука на физическом телефоне или проверку фактической серверной конфигурации после deploy.
