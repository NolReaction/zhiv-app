Кандидат на выпуск, 21 октября 2026. Web и API уже имеют версию `0.7.1`; новость подготовлена в `public/updates.json`. Публикация разработки не означает обновления основного сервера.

## Проверка перед master

На момент подготовки `master` — `f46a2ca120ed690caacd1a76473f85539a5850a1`, предок разработки; перед слиянием нужно получить его заново и проверить актуальное расхождение. Историю переписывать не требуется.

Миграции V1–V49 перенесены в `history/` с идентичным содержимым; V50–V52 не изменены. Добавлены baseline B49 и V53–V67. Автоматический сброс игроков не входит в выпуск. Совместимость отдельной БД со старой экспериментальной Earth V62 требует отдельного плана; не править историю Flyway вручную. [Подробности](../development/database-baseline.md).

В CI предыдущего кандидата `e60c32c` прошли Ktor/PostgreSQL, миграционные и экономические проверки, два из трёх web-наборов. Единственное web-падение ожидало старую фразу справки; assertion исправлен, его повтор прошёл. Production Compose тогда был пропущен из-за зависимости от web. Это не результат CI нового кандидата: перед master нужны все зелёные проверки нового SHA, включая Compose. Локальный итог текущего этапа указан в [WORK_STATE.md](../../WORK_STATE.md).

Перед выпуском:

1. Дождаться зелёного CI нового SHA и закончить независимый просмотр изменений.
2. Для спутника указать `NEXT_PUBLIC_MAPTILER_KEY` в `deploy/.env` до сборки Docker и разрешить рабочий hostname у ключа. Локальный `.env.local` на сервер не переносится автоматически. Service token для админской статистики необязателен. [Настройка](../operations/server-setup.md).
3. Коротко проверить на физическом телефоне: вход/возврат на глобус, GPS и «Призрак», звук при выходе, мост и книгу коллекций. Эмуляция не подтверждает отсутствие редкого зависания или слышимого писка.
4. Сверить дату новости с фактическим днём выпуска. Обновлять web и API согласованно через `scripts/deploy-update.sh`: он проверяет backup перед миграциями и сохраняет техработы при сбое. [Порядок обновления](../operations/operations.md#перед-обновлением).

После обновления проверить существующий аккаунт, запасы и активные работы, лавку/сбор выручки, `/readyz`, `/app-status.json` и `/updates.json`. Текущий этап не меняет `master` и не выполняет deploy.
