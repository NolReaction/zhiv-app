# 0.5.3

## Интерфейс

- Компактные карточки людей: имя, статус и последняя отметка сверху; доступ, избранное, удаление и копирование ID в одном нижнем ряду. Удаление по-прежнему требует подтверждения. Убраны заголовок «Мои люди» и отдельная строка «Удалить связь».
- «Добавить человека» расположено выше времени обновления списка. Порядок способов: ID → ссылка → QR → открыть приглашение.
- В раскрывающихся разделах профиля добавлен верхний отступ; состояние незавершённых форм сохраняется при сворачивании.
- Круглая кнопка получила более заметную расходящуюся волну, второе кольцо и подсветку поверхности. Эффекты привязаны к квадратной области кнопки. Уменьшение движения учитывается.
- Календарь компактнее: естественное число недель, ограниченная высота ячеек, прокрутка внутри безопасной области iPhone. Полупрозрачное стекло, мягкое появление и закрытие.

## Календарь и часовой пояс

Новые регистрации передают определённый браузером именованный часовой пояс; если он не указан, сохраняется прежнее значение `Europe/Moscow`. Существующие профили автоматически не переключаются. Выбор находится в «Профиль → Личные данные»; «Как на устройстве» заполняет поле, изменение требует сохранения.

`PATCH /api/v1/me/time-zone` принимает `{ "timeZone": "Europe/Berlin" }`, требует сеанс, доверенный Origin и UUIDv4 `Idempotency-Key`. Сервер проверяет имя зоны в JVM и PostgreSQL. Повтор ключа с другим значением возвращает 409; запоздавший повтор прежнего запроса не отменяет более поздний выбор. `profile.timeZone` возвращается в `/me`.

Меняются только календарные даты будущих отметок. Исторические `checked_at`, `timezone_id` и `local_date` не переписываются, в том числе после объединения профилей. Серия и пауза между отметками рассчитываются по серверным моментам времени; перевод часов и изменение зоны не увеличивают серию и не обходят паузу.

Календарь показывает срок продления серии, количество дней с отметками за месяц и раскрывающееся объяснение: первая отметка даёт день 1, последующие дни серии зависят от полных 24-часовых промежутков от начала серии, а каждый разрыв более 24 часов завершает её. Число календарных дат может отличаться от серии.

`GET /api/v1/me/calendar` дополнен `nextDayAt`, рассчитанным сервером, и `lastMonth` для границы истории. Клиент планирует обновление из разницы серверных времён, обновляет открытый календарь при смене суток и возвращении приложения на экран. При повторяющейся полуночи выбирается первое начало дня. После переноса пояса назад сохранённые отметки доступны, даже если их исходная дата позже нового «сегодня».

## Многоразовые приглашения

Новые и ещё действующие приглашения могут принять несколько разных людей. Срок — семь дней; выпуск новой ссылки сразу отзывает предыдущую. Получатель сам подтверждает добавление. Для каждого получателя сохраняется отдельная неизменяемая запись согласия; ссылки и QR не открывают отметки задним числом и не отменяют запрет доступа.

Точный повтор принятия возвращает ранее созданную действующую связь. Уже удалённая связь таким повтором не восстанавливается. Новый ключ для того же получателя и той же использованной ссылки возвращает конфликт; для нового согласия нужна новая ссылка. Исторические использованные одноразовые ссылки остаются недействительными для новых людей; миграция сохраняет их исходные результаты повторных запросов.

## Обновление и проверки

Схема — V19: V18 добавляет записи принятия многоразовых приглашений, V19 — ключи изменения часового пояса. Сбрасывать базу не нужно. Перед обычным обновлением сделайте резервную копию по README. Старые миграции не изменены; ручные средства сброса согласованы с новой схемой из 30 таблиц.

Регрессионные проверки включают одновременное принятие ссылки разными людьми и точные повторы, обновление базы с использованной ссылкой V17, отзыв/удаление, историческую приватность, смену зон через линию перемены даты, защиту серии и cooldown, переходы летнего времени и независимость таймера календаря от часов устройства. Production Compose smoke проверяет новые API под ограниченной ролью БД. Реальные жесты и внешний вид физического iPhone проверяются отдельно.
