# Медиа страницы приложения

Готовые иллюстрации подготовлены настоящим игровым рендерером, без аккаунта и серверных действий. Показан возможный прогресс: дом 2, мастерская 1, шахта 1. Мост и маяк сохраняют начальные состояния; рынок, караван, доска заказов и дома жителей берутся из текущей Tiled-сцены. Дом Лопоуха показан на первом уровне, его рабочее место и прежний рисунок лесного участка пока отсутствуют.

| Файл | Размер | Назначение |
|---|---|---|
| `poster-960.webp`, `poster.webp` | 960 × 600, 1440 × 900 | Полянка с домом, кустом и Мохликом; 167 / 287 КиБ |
| `map-800.webp`, `map.webp`, `map-2560.webp` | 800², 1600², 2560² | Дневная панорама; 277 / 900 / 1871 КиБ |
| `map-night-800.webp`, `map-night.webp`, `map-night-2560.webp` | 800², 1600², 2560² | Вечерняя панорама с освещением; 151 / 475 / 909 КиБ |
| `media.json` | JSON | Основной URL, `srcSet`, варианты с размерами/весом, описания, уровни; `video: null` |

Каждый URL содержит версию по SHA-256 содержимого. Страница импортирует `media.json` и передаёт браузеру `srcSet` / `sizes`: загружается подходящий размер, весь набор сразу не нужен. Вечерний вариант запрашивается после выбора вечера. Не копируйте адреса изображений из JSON вручную в компоненты: после обновления рисунка должна меняться и его версия в URL.

`mapPlaces` хранит процентные координаты трёх кнопок на карте. Они берутся из точек опоры дома, мастерской и лавки Плёски в той же сцене с выбранными уровнями, что рисует изображения. Перемещение здания в Tiled после повторной подготовки обновляет и его кнопку. Отсутствующее здание или точка за границами мира останавливает подготовку с понятной ошибкой.

## Повторная подготовка

`scripts/prepare-site-media.mjs` читает текущие данные `features/world/tiled/forest.generated.json`, единственный PNG/JPEG-мастер `art/world/prototype/forest-ground.*` и отдельные изображения из `public/world/`. Используются игровые compositor, освещение, перекрытия, тени и спрайт Мохлика. Скрипт готовит восемь WebP и метаданные; видеозапись не создаёт.

Карта сначала рисуется в нативном разрешении фона, до 2560 пикселей по ширине. Меньшие варианты уменьшаются из несжатого кадра один раз через Lanczos3. Все WebP кодируются с качеством 86; прежний дневной вариант с качеством 30 удалён. Размеры 1600 и 2560 позволяют сохранить детали на плотных экранах. Постер не увеличивается выше 1440: его крупный план уже ограничен разрешением исходного леса. Исходный фон, игровые изображения и Tiled-разметка при подготовке сайта не меняются.

Нужны зависимости проекта и отдельный Canvas для подготовки медиа. Canvas не требуется production-приложению и не добавлен в его зависимости:

```bash
npm install --prefix /tmp/zhiv-site-render @napi-rs/canvas@0.1.100
SITE_MEDIA_NODE_MODULES=/tmp/zhiv-site-render/node_modules node scripts/prepare-site-media.mjs
```

Canvas также ищется в `CODEX_PRIMARY_RUNTIME_NODE_MODULES`. `esbuild` и `sharp` берутся из зависимостей проекта.

После изменения мира:

1. Если заменён мастер фона, выполните `node scripts/prepare-world-assets.mjs` для игрового экспорта.
2. Выполните `npm run world:export` и `npm run world:check`, чтобы обновить данные сцены.
3. Запустите `node scripts/prepare-site-media.mjs` с указанной выше переменной, если Canvas установлен отдельно.
4. Проверьте день, вечер и постер в натуральном масштабе. Точки мест в `mapPlaces` обновятся вместе с картинкой; сверьте, что подписи не мешают рассмотреть здания.
5. Сохраните все изменившиеся WebP вместе с `media.json`. `node --test tests/product-site.test.mjs` проверяет реальные размеры, версии, доступность вариантов и бюджет загрузки.

Скрипт сначала заканчивает все рендеры и кодирование, затем сохраняет результат. Одинаковые данные и версии инструментов дают те же изображения и URL; текущий Canvas 0.1.100. Подготовка медиа не входит в обычную сборку сайта и не добавляет Canvas в production-приложение.

## Будущая видеопрогулка

Прежний синтетический MP4 удалён. На сайте стоит неинтерактивный `SiteVideoPlaceholder` в `features/site/site-demos.tsx`, с текстом «Скоро здесь появится видеопрогулка». Он не загружает видео и не показывает кнопку воспроизведения.

Когда будет готова настоящая запись, замените этот компонент на проигрыватель и задайте его источники отдельным изменением. Сохраняйте постер, явный запуск, `playsInline`, стандартные controls, обработку сетевой ошибки и паузу при скрытой странице. Скрипт подготовки иллюстраций не должен перезаписывать авторский ролик.
