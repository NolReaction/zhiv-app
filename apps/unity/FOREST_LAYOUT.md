# Лесная планировка

Второй самостоятельный прототип в `work/0.6.8-unity`: композиция по мотивам `v12-с`, с полянками, лесными массивами, тропами и водоёмом. Это новая сцена `ForestLayout.unity`; существующая `Clearing.unity` и её ручная расстановка не переносятся и не заменяются. Модели пока служат заготовками масштаба. Полная старая география, здания всех уровней, экономика и сохранение игрока ещё не перенесены.

## Открыть

1. Останови Play и сохрани открытую сцену (`Cmd+S`).
2. Получи изменения в ветке `work/0.6.8-unity`: `git pull --ff-only`. Если Git сообщает о локальных изменениях, сначала сохрани их обычным коммитом; не используй reset для обхода сообщения.
3. Дождись импорта Unity и пакета **Unity UI / uGUI 2.0.0**. Он указан в manifest, вручную выбирать пакет не нужно.
4. Нажми **Zhiv → Create or Open Forest Layout**. Первый запуск создаст и сохранит землю, окружение, UI и сцену. Следующие нажатия только открывают готовую сцену.
5. В Game выбери **9:16**, отключи Low Resolution Aspect Ratios и нажми Play.

Получившаяся сцена: `Assets/_Project/Scenes/ForestLayout.unity`. Ассеты: новая папка `Assets/_Project/ForestGenerated/` (при повторной попытке после ошибки — с числовым суффиксом). Генерации во время Play и автоматического перестроения при импорте нет. При создании используется уже настроенный URP; существующие параметры качества не сбрасываются. Для пустого проекта URP создаётся как в первом прототипе.

## Что теперь есть

- Terrain 48×56 м, четыре покрытия, мягкий рельеф и шесть соединённых кривых дорожек. Разрешения высот и покраски остались 257²/512²; они не увеличиваются вместе с размером мира.
- Семь обозначенных мест: дом, мастерская, руины, костровая поляна, будущий рынок, мыс и подход к берегу. Это стартовая композиция, не точная обводка наклонного рисунка `v12-с` и не импорт Tiled.
- Лесные массивы из редактируемых экземпляров деревьев. При первоначальной расстановке генератор оставляет место под поляны, тропы, кроны и берег. Кусты и камни используют общие материалы. После генерации это обычные объекты Scene.
- Водоём утоплен в землю; поверхность подогнана к исходному контуру высоты. Под ней закрытый непроходимый объём. Берег пока простой, без волн, рыбалки, мостов и пристани.
- Камера ограничивает весь видимый прямоугольник земли. На широком экране максимальное отдаление автоматически уменьшается. Малый запас по границе рассчитан на текущий мягкий рельеф, а не высокие горы у края.
- Настоящий uGUI Canvas: верхняя панель, кнопки «Дом», «Мастерская», «Обзор», окно мастерской и справка. «?» открывает управление, переключение дня/вечера и кнопку «К воде». Кнопки перемещают камеру; нажатие на землю отправляет героя. Работа мастерской меняет только пробную анимацию, без ресурсов и сервера.

## Что оценивать первым

Сначала пройди путь **дом → мастерская → руины**, затем **дом → костровая поляна → берег → рынок → мыс**. Важно понять расстояния, ширину проходов, видимость героя и ощущение отдельных полян. Герой может ходить и по траве: нарисованная дорожка не является единственной разрешённой поверхностью.

Нажми «Обзор», приблизь дом, потяни карту к краям. Проверь, что UI не отправляет героя под кнопку, перетаскивание не заканчивается случайным шагом, а лес не закрывает важные входы. Посмотри также высокий экран телефона и 16:9; на горизонтальном экране меньше доступного отдаления, чем на вертикальном.

**Zhiv → Validate Forest Layout** проверяет сохранённые ссылки, Terrain, UI, свободный центр каждой нарисованной тропы, маршруты от героя до семи точек подхода и запрет входа в воду. Команду запускай с остановленным Play. Проверка использует реальные Unity-коллайдеры, поэтому её нужно запустить у себя: в среде агента Unity Editor отсутствует.

Если Console показывает ошибку, пришли **первую красную запись целиком**. После успешного запуска полезны общий вид через «Обзор» и вид дома с ближайшей тропой в 9:16.

## Редактировать по этапам

| Этап | Действие в Unity | Результат |
|---|---|---|
| Масштаб | Сравнить героя, дом и проход через игровую камеру | Понятные пропорции на телефоне |
| Планировка | Перемещать корни мест в Buildings/Environment, редактировать тропы | Удобные маршруты между полянами |
| Лес | Раскрыть Environment → Forest Environment → Forest masses, двигать/дублировать деревья | Опушки отделяют одну поляну от другой |
| Земля | Ground Surface → Ground Authoring: точки, Width, Feather, Pads, отдельные Bake | Тропы подходят ко входам, площадки стоят на земле |
| Один красивый участок | Довести поляну у дома: палитра, растения, корни, камни и свет | Образец для остальной карты |
| Модели | Постепенно заменять визуальные части заготовок моделями Blender | Постройки в выбранном стиле |

У каждого места есть **Forest Landmark** с названием и дочерней точкой **Arrival**. В Scene при включённых Gizmos видны названия. Arrival означает свободное место, куда может подойти герой; кнопка Select Arrival помогает его выбрать. При перемещении здания его Arrival перемещается вместе с ним. Тропа и площадка GroundRecipe остаются в мировых X/Z и требуют отдельной правки.

**Покраска Bake заменяет ручные мазки, Bake Relief — ручные высоты.** Сначала настрой расположение/кривые, затем кисти. Перед новым расчётом используй Save Ground Snapshot. Подробные действия — [GROUND.md](GROUND.md).

Деревья, камни и поверхность воды не привязаны к последующим изменениям рельефа автоматически. После скульптуры подними/опусти объекты; при изменении самой чаши озера согласуй поверхность воды и её коллайдер. Повторное Create or Open этого не делает. Snapshot земли сохраняет TerrainData и рецепт, а расстановку объектов сохраняй сценой и Git.

Лес сейчас состоит из простых исходных моделей. Внешний вид будем выбирать на одном небольшом участке, используя согласованный набор деревьев, кустов и камней. Normal maps, декоративные береговые меши и новые модели домов добавляются после проверки композиции. Существующий художественный стиль не зафиксирован формой этих заготовок.

## UI и дальнейший перенос

Редактируемая иерархия: **Forest HUD → Safe Area → Content Column**. Здесь Header, Footer, Workshop Panel и Help Panel. Кнопки имеют сохранённые события, цвета и текст; UI создаётся один раз в Editor. Safe Area учитывает вырезы экрана и изменение его размеров. Нажатия блокируются только видимыми панелями, остальной экран остаётся картой.

Текущий HUD — начало игрового интерфейса Unity. React/CSS-компоненты PWA в него автоматически не импортируются. Дизайн, тексты, картинки и каталоги пригодятся при последовательном переносе. Следующий полноценный сценарий: окно мастерской → запуск производства → таймер → получение результата через существующий API. Сейчас авторизация, запросы к API, экономика, инвентарь и сохранение не подключены. Вместо временного встроенного шрифта позже импортируем исходный шрифт интерфейса.

## Проверить на телефоне

Выбери **Zhiv → Build Forest Layout Web**. Эта команда собирает именно ForestLayout в `Builds/ForestWeb`; прежняя Build Web Prototype по-прежнему собирает Clearing в `Builds/Web`. Нужен Web Build Support для установленного Editor. Команды создают локальные development-сборки и ничего не публикуют.

Из папки проекта Unity:

```sh
cd Builds/ForestWeb
python3 -m http.server 8080
```

Открой `http://localhost:8080`, а на телефоне в той же сети — `http://<IP-Mac>:8080`. LAN-адрес Mac при Wi-Fi обычно показывает `ipconfig getifaddr en0`. Доступ зависит от сети и firewall.

Проверь запуск, панорамирование одним пальцем, pinch, кнопки у краёв, проход по длинному маршруту и нагрев/плавность. Пока нет измерений, не увеличивай плотность деревьев и разрешение Terrain многократно. Навигация использует CPU и физические запросы; проверка Editor не заменяет замер на устройстве.

Для batch-проверки закрой этот проект в Editor и выполни из корня репозитория:

```sh
ZHIV_UNITY_EDITOR="/Applications/Unity/Hub/Editor/6000.3.26f1/Unity.app/Contents/MacOS/Unity"
"$ZHIV_UNITY_EDITOR" -batchmode -quit -projectPath "$PWD/apps/unity" \
  -executeMethod Zhiv.UnityPrototype.Editor.ForestLayoutValidation.ValidateFromBatch \
  -logFile "$PWD/unity-forest-validation.log"
```

## Сохранить работу

Останови Play, сохрани сцену и проект. Отправляй в Git `ForestLayout.unity`, `ForestGenerated/`, изменённые ProjectSettings и все связанные `.meta` вместе. Это позволит продолжать работу с фактической расстановкой. Не добавляй кэши `Library`, `Temp`, `Logs` и папки сборок. В этом этапе в репозитории находятся генераторы и инструкции; бинарные/текстовые ассеты сцены создаются твоим Unity Editor при первом запуске команды.

Основные файлы: `Editor/Layout/ForestLayoutRecipe.cs` — исходная композиция; `ForestEnvironmentBuilder.cs` — первоначальное окружение; `ForestLayoutSceneBuilder.cs` — сборка сцены; `ForestLayoutValidation.cs` — проверка. После создания редактируй сцену и GroundRecipe asset: изменения исходного генератора не перестраивают сохранённую сцену.
