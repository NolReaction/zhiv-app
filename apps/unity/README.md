# Первая 3D-поляна в Unity

Экспериментальная ветка `work/0.6.8-unity`. Проект открывается в **Unity 6.3 LTS / 6000.3.26f1**, с URP 17.3.0. Его задача — проверить объём, согласованный масштаб, свет, фиксированный ракурс и управление на вертикальном экране. Это отдельный клиентский прототип; существующие PWA, сервер, аккаунты и хозяйство продолжают работать своим кодом.

**Обновление земли:** если поляна уже создана, после получения изменений выполни **Zhiv → Upgrade Ground and Paths**. Земля станет native Terrain с мягкими тропинками и редактируемым рельефом. [Обновление, точки дорожек, кисти, резервные копии и проверки](GROUND.md).

## Первый запуск на Mac

1. Дождись установки Editor в Unity Hub. Для первого Play достаточно Editor; для браузерной сборки нужен уже выбранный **Web Build Support**. Unity CLI не обязателен.
2. Обнови репозиторий и выбери ветку:

   ```sh
   git fetch origin
   git switch work/0.6.8-unity
   git pull --ff-only
   ```

3. В Hub выбери **Projects → Add → Add project from disk** и укажи **`apps/unity` внутри репозитория**. Новый проект по шаблону создавать не нужно.
4. Открой проект в `6000.3.26f1`. Дождись загрузки пакетов и окончания компиляции. При запросе лицензии активируй свою Unity Personal в Hub.
5. В верхнем меню Editor нажми **Zhiv → Create or Open 3D Clearing**. Команда создаст материалы, объёмные модели, prefab и сохранённую сцену. При повторном нажатии она открывает уже существующую сцену, сохраняя твои правки.
6. Открой вкладку **Game**, выбери соотношение **9:16** (можно добавить вручную) и нажми **Play ▶**.

Если меню `Zhiv` отсутствует, открой **Window → General → Console** и пришли первую красную ошибку целиком. Если Package Manager не скачивает пакет, пришли именно его сообщение. Версию Editor или пакетов наугад менять не нужно.

## Что должно получиться

На объёмной полянке стоят дом-пень и мастерская, деревья, камни и маленький пруд. Здания собраны из отдельных геометрических частей и общих материалов. Солнце отбрасывает настоящие тени; у входов горят фонари. Это первая форма и палитра для обсуждения, а не окончательные модели.

Камера смотрит сверху под углом 45° и не вращается. Перетаскивание двигает обзор, колесо мыши или щипок меняет масштаб. Короткое нажатие на свободную землю отправляет туда временного 3D-Мохлика. Навигация учитывает ширину героя, стены, стволы, камни и воду. Нажатие на мастерскую открывает кнопку запуска/остановки молота. Кнопки внизу переключают день/вечер и возвращают камеру.

Старая карта дала ориентир: мастерская западнее дома, между ними тропинка, вода к юго-востоку. Это небольшой новый участок, **не автоматический перенос всей Tiled-карты**. Полная география, экономика, сохранение игрока и звук пока не подключены.

## Что проверить первым

1. Сравни **9:16** и **16:9**. Видны ли герой и здание, когда приблизишь мастерскую? Комфортны ли размеры?
2. Нажми за мастерской: герой должен обойти её. Нажатие внутрь здания или воды не должно отправить его сквозь препятствие.
3. Потяни карту, затем отпусти: герой не должен получить случайную команду движения. Кнопки также не должны двигать героя.
4. Выбери мастерскую, останови и снова запусти молот. Переключи день/вечер: сравни тени, объём крыши и свет у входа.
5. Останови Play. Выбери `Buildings/Workshop` в **Hierarchy**, нажми **W**, передвинь здание, сохрани сцену и снова запусти Play: навигация заново учитывает коллайдеры. Изменения, сделанные во время Play, Unity обычно откатывает при выходе.

Пришли **скриншот Game в 9:16 и Console**, затем скажи три вещи: ракурс, размер зданий, удобно ли перемещаться. Сначала настраиваем эту поляну; после этого добавляем настоящую модель одного здания.

## Как собирать свой мир

- Сцена: `Assets/_Project/Scenes/Clearing.unity` — появится после команды создания. Обычная Unity-сцена: объекты можно перемещать, сохранять, дублировать.
- Модели и материалы: `Assets/_Project/Generated/Art/`. Prefab — повторно используемый объект со своими частями. Перетащи дерево из Project в Scene, чтобы добавить ещё одно.
- Единицы: **1 Unity unit = 1 метр** в договорённости прототипа. Земля лежит в плоскости XZ, высота — Y. Опора модели — `(0,0,0)`, вход здания смотрит в локальный `-Z`. У мастерской примерно 4×4 м, у героя примерно 0.6×1.3 м. Единую сетку можно показывать средствами Scene View; строительная сетка для игрока ещё не реализована.
- `Ground` (слой 8) — поверхность для нажатий; `Obstacle` (слой 9) — физические препятствия. Коллайдер здания задаёт его непроходимое основание; декоративной кроне большой сплошной коллайдер не нужен. Новому препятствию назначь слой 9 и подходящий Collider.
- Заменяя здание моделью из Blender, сохраняй корневой объект, масштаб и коллайдер. Визуальные детали можно заменить дочерним объектом; при замене мастерской сохрани `HammerPivot` либо назначь новый pivot в `DemoInteraction`.
- Все объекты используют один источник света и согласованные URP-материалы. Для этого первого объёма normal map не требуется: основные формы уже геометрические. Текстуры и мелкие детали добавим после выбора силуэтов.

При повторном открытии проекта сцена не пересоздаётся. Сгенерированные `.unity`, `.prefab`, `.mat`, `.asset` и их `.meta` нужно сохранять в Git **вместе**. Их содержимое — результат работы Editor, поэтому до первого открытия они не входят в начальный коммит. Кэши `Library/` и сборки в Git не попадают. Если генерация прервётся, предыдущие файлы сохраняются, а повторная попытка использует новую папку `Generated 1` или аналогичное уникальное имя.

## Проверки и браузерная сборка

**Zhiv → Validate Open Clearing** проверяет связи, материалы, слои и маршрут вокруг мастерской настоящими физическими запросами Unity. Фикстура маршрута относится к начальной расстановке: после переделки карты её координаты нужно обновить в `PrototypeValidation.cs`. Это не проверка внешнего вида или производительности телефона.

**Zhiv → Build Web Prototype** создаёт development-сборку в `Builds/Web`, без публикации. Первый раз сборка может занять заметное время. Запускай через HTTP:

```sh
cd apps/unity/Builds/Web
python3 -m http.server 8080
```

Открой `http://localhost:8080`. На телефоне в той же сети используй `http://<IP-Mac>:8080`; доступ зависит от локальной сети и firewall. Производительность и жесты реального iPhone ещё предстоит проверить. Сборка не подключается к аккаунту и API существующей игры.

Для повторяемой проверки из Terminal, **закрыв этот проект в Editor**:

```sh
ZHIV_UNITY_EDITOR="/Applications/Unity/Hub/Editor/6000.3.26f1/Unity.app/Contents/MacOS/Unity"
"$ZHIV_UNITY_EDITOR" -batchmode -quit -projectPath "$PWD/apps/unity" \
  -executeMethod Zhiv.UnityPrototype.Editor.PrototypeValidation.ValidateFromBatch \
  -logFile "$PWD/unity-validation.log"
```

Команда запускается из корня репозитория, требует установленный Editor и активированную лицензию. В журнале ищи `ZHIV VALIDATION PASSED` либо первую ошибку. Для Web можно отдельно вызвать `Zhiv.UnityPrototype.Editor.PrototypeBuild.Web` с `-buildTarget WebGL`.

## Устройство и границы первого этапа

`Runtime/` содержит камеру, поиск пути по сетке, движение и небольшой пробный интерфейс. `Editor/` создаёт геометрию и сцену, настраивает URP, выполняет проверку и сборку. Editor-код не включается в игру. Графика создана кодом в этом репозитории, сторонних моделей, музыки и платных пакетов нет.

Ввод пока использует встроенный `UnityEngine.Input`; `Active Input Handling = Input Manager (Old)`. Это сознательное ограничение маленького прототипа. Переход на Input System и финальный UI будут отдельным этапом. Навигация работает на плоскости или одном Terrain с ограничением уклона; лестницы, отверстия и переходы между поверхностями пока не поддержаны. Перемещая препятствия в Play, вызывай `GridNavigator.Rebuild()`; герой дополнительно проверяет путь каждым шагом и останавливается перед препятствием.

**Статус:** пользователь подтвердил открытие и работу первой сцены на Mac, на скриншоте Console пустая. В среде агента Unity Editor отсутствует. Новый этап Terrain пока проверен статически; его импорт/Play/Undo и Web build на устройстве ещё требуют проверки.
