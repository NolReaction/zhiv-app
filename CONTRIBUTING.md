# Как работать с проектом

Начните с [WORK_STATE.md](WORK_STATE.md), [AGENTS.md](AGENTS.md) и нужного раздела [путеводителя](docs/repository-guide.md). Текущая ветка и файлы важнее упоминания ветки в старом чате. `master` и развёртывание — отдельные этапы.

## Порядок изменения

1. Проверьте `git branch --show-current`, `git status --short` и последние коммиты. Обновляйте согласованную ветку через `git pull --ff-only` только после проверки локальных изменений; чужие правки сохраняйте.
2. Запустите `npm run dev:local`. Для телефона и другого API используйте [инструкцию запуска](docs/development/local-development.md).
3. Найдите первичный источник в [карте файлов](docs/repository-guide.md). Не правьте сгенерированный экспорт Tiled или старый рендер вместо текущего.
4. Внесите законченное изменение. Для интерфейса проверьте узкий и широкий экраны, клавиатуру; для мира — круг, большую карту, день/ночь и reduced motion.
5. Выполните `npm run typecheck`, `npm run architecture:check`, `npm run lint` и относящиеся к изменению тесты. Перед выпуском нужны `npm run world:check`, `npm test`, `npm run build:vps` и CI API/production Compose для выпускаемого коммита; [проверки и порядок обновления 0.6.7](docs/releases/release-0.6.7.md). **Сборки и тесты, читающие `dist/`, запускайте последовательно.** Для правок только документации проверьте факты, команды и ссылки; пересобирать приложение ради текста не требуется.
6. Обновите тематическую документацию; пользовательские правила — также в игровой справке. Проверьте `git diff`, кратко запишите результат и проверки в `WORK_STATE.md`. Сохраните обычным новым коммитом; историю не переписывайте.

## Код и данные

- Размещайте код по [правилам организации](docs/development/code-organization.md): функциональный модуль, затем ответственность. Крупные модули `world` и `economy` имеют отдельные каталоги UI, состояния и правил; мелким разделам искусственные слои не нужны.
- Компонент, его `.module.css` и помощники конкретного экрана держите рядом в `ui/<topic>/`. Общий интерфейс приложения собирает `features/app/app-shell.tsx`; `features/check-in/` отвечает за отметки.
- Внутри одной папки используйте `./file`, между подсистемами — `@/features/...` или `@/lib/...`. Импортируйте конкретный модуль; общий barrel, который реэкспортирует всё дерево, не добавляйте.
- `domain/` не зависит от React, UI и клиентских сессий; синхронизация экономики не импортирует UI. Данные между системами соединяйте в контроллерах, `integration/` и точках сборки. Обратные импорты feature → AppShell/маршруты и циклические runtime-зависимости не допускаются. Это проверяет `npm run architecture:check`; проверка не заменяет анализ владения состоянием.
- Цены, товары, стройку и производство берите из [каталога экономики](apps/api/src/main/resources/world/economy-catalog.json); [прежний каталог мира](apps/api/src/main/resources/world/catalog.json) хранит одежду, коллекции и совместимость старых поездок. Оба каталога общие для TypeScript и Kotlin. Новое правило проверяйте в Ktor и в локальном API; браузер не подтверждает выдачу наград самостоятельно.
- Существующие миграции БД не переписывайте. Добавляйте следующую миграцию и проверку обновления заполненной БД. Секреты и реальные пользовательские данные в Git не попадают.
- Сохраняйте поддержку Sites и Next/VPS. Конфигурацию сборки, библиотечные компоненты и деплой меняйте только по необходимости.

## Карта и изображения

- Координаты, здания, герой, вода и свет задаются в `world/tiled/forest.tmj`. После правки: `npm run world:export`, затем `npm run world:check`; [правила разметки](docs/game/tiled-editor.md).
- Мастера изображений обычно лежат в `art/world/`, браузерные изображения — в `public/world/`. Пять уровней дома пока хранятся только как PNG в `public/`; точные пары файлов указаны в [каталоге изображений](art/README.md). Фон JPEG/PNG экспортирует `node scripts/prepare-world-assets.mjs`; затем выполните `world:export` и `world:check`. Эти команды не обновляют PNG домов и куста.
- Проверяйте точку опоры, вход, масштаб пикселя и соответствие масок после замены рисунка. Свет меняется через `Lights`/`forest-lighting.ts`; фон ради освещения перерисовывать не нужно.
- Рисунок Мохлика — `features/mochlik/pixel-sprite.ts`. Медали — `public/achievements/`; серое состояние задаёт CSS.
- Перед удалением проверяйте импорты, динамические пути, маршруты, CI и документацию. Отсутствие прямого импорта не означает, что файл не используется.

## Документация

- `README.md` — быстрый вход; `docs/README.md` — указатель; `docs/repository-guide.md` — задача → файлы. Не дублируйте подробные инструкции во всех трёх местах.
- В тематической странице указывайте: источник данных, основные файлы, порядок изменения, ограничения и проверку результата. Пишите о текущем поведении, планы помечайте явно.
- `docs/development/` — приложение и данные; `docs/game/` — мир и игровые системы; `docs/operations/` — обслуживание. Старые отчёты помечайте как исторические и давайте ссылку на заменившую инструкцию.
- Игровая справка хранится в `features/world/ui/help/world-help-content.ts`. Обновляйте её вместе с видимыми игроку правилами; не описывайте отключённую кнопку как доступную.
- Проверяйте относительные ссылки после переименования файлов. Историю держите в Git, не в ZIP-копиях или папках `final-v2-copy`.
