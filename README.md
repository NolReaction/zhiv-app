# Жив

PWA с одной главной кнопкой: пользователь нажимает **«Я ЖИВ»**, а выбранные им люди видят подтверждённое сервером время последней доступной отметки.

## Версия 0.2.1

- первичная настройка только с именем;
- случайный публичный ID, не связанный с именем;
- серверная сессия в `HttpOnly` cookie;
- идемпотентное создание профиля: потерянный ответ не создаёт повторный аккаунт;
- большая кнопка с плавным изменением цвета от зелёного к красному за 24 часа;
- мемная серия повторных нажатий и конфетти на пятом;
- серверный cooldown 30 секунд и `Idempotency-Key`;
- append-only события для будущего календаря отметок;
- раздел **«Свои»**: точный поиск по ID, взаимные заявки и личные связи;
- принятие, отклонение и отмена заявок;
- удаление личной связи;
- отдельное включение и выключение новых отметок для каждого человека;
- прошлые отметки не открываются при добавлении человека или повторном включении доступа;
- список автоматически обновляется каждые 30 секунд и при возврате в приложение;
- снимок получателей создаётся в одной транзакции с отметкой;
- схема групп уже заложена в миграциях, интерфейс групп остаётся следующим этапом;
- нажатие на профиль копирует публичный ID, а через HTTPS дополнительно открывает системное меню «Поделиться»;
- для локального HTTP предусмотрено совместимое с iPhone/Safari копирование без ложной ошибки шаринга;
- совместимая генерация UUID v4 для Safari при локальной проверке через HTTP;
- PWA shell работает офлайн, а `/api/**` никогда не кэшируется и не ставится в очередь.

## Быстрый локальный запуск

Установите зависимости:

```powershell
npm ci
```

Запустите интерфейс с временным in-memory API:

```powershell
npm run dev:local
```

Откройте в браузере:

```text
http://localhost:3000
```

Dev-адаптер повторяет HTTP-контракт Ktor, включая личные связи и правила приватности, но хранит данные только в памяти. После перезапуска dev-сервера созданные пользователи, заявки и отметки удаляются.

## Проверка с телефона в локальной сети

Компьютер и телефон должны быть подключены к одному роутеру.

Узнайте локальный IPv4-адрес компьютера:

```powershell
ipconfig
```

Нужен адрес активного сетевого адаптера, у которого указан `Default Gateway`. Пример:

```text
IPv4 Address: 192.168.1.232
Default Gateway: 192.168.1.1
```

Создайте в корне проекта файл `.env.local`:

```text
NEXT_ALLOWED_DEV_ORIGINS=192.168.1.232
```

Укажите актуальный IPv4-адрес своего компьютера и запустите:

```powershell
npm run dev:lan
```

Затем откройте на телефоне:

```text
http://192.168.1.232:3000
```

Не используйте на телефоне `localhost`: он указывает на сам телефон, а не на компьютер. Если локальный IP изменился, обновите `NEXT_ALLOWED_DEV_ORIGINS` и адрес в браузере, затем перезапустите dev-сервер.

Локальный HTTP предназначен только для функциональной проверки. На нём кнопка профиля копирует ID через совместимый fallback, но системное меню «Поделиться» может быть недоступно. Установка полноценной PWA, Web Share, service worker, офлайн-режим и будущие push-уведомления должны проверяться через HTTPS.

## Production-запуск

Полный production-контур состоит из Next.js, Ktor, PostgreSQL и Caddy.

На Linux/VPS:

```bash
cp deploy/.env.example deploy/.env
docker compose --env-file deploy/.env -f deploy/compose.yml up --build
```

На Windows PowerShell:

```powershell
Copy-Item deploy\.env.example deploy\.env
docker compose --env-file deploy\.env -f deploy\compose.yml up --build
```

Перед запуском заполните в `deploy/.env` домен и длинный случайный пароль PostgreSQL. В production Caddy принимает HTTPS-запросы, отправляет `/api/**` в Ktor и остальные запросы в Next.js.

Web-проект:

```powershell

npx tsc --noEmit --incremental false
npm run build:vps
```

```bash

```

Backend:

```powershell
cd apps/api
gradle test
```

PostgreSQL-интеграционные тесты автоматически пропускаются, если Docker недоступен.

## Backend и IntelliJ IDEA

Backend рассчитан на JDK 25 и Gradle 9.5.

Для локальной работы:

1. Установите JDK 25, например Eclipse Temurin.
2. Откройте корень проекта в IntelliJ IDEA.
3. Импортируйте `apps/api/build.gradle.kts` как Gradle-модуль.
4. Установите `Project SDK` и `Gradle JVM` в JDK 25.
5. Используйте сохранённую конфигурацию **API · Ktor** — она задаёт `APP_ENV=development`.

При других способах запуска переменная `APP_ENV` обязательна. Допустимые значения: `development`, `test` и `production`.
