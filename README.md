# Я живой · im-alive

[im-alive.ru](https://im-alive.ru/) — PWA для отметок близким и лесного мира с Мохликом. Кнопка **«Я ЖИВОЙ»** отправляет отметку; игровые тапы, коллекции и наряды дополняют её.

Последний оформленный выпуск — **[0.6.6](docs/releases/release-0.6.6.md)**. Рабочая ветка **`work/0.6.7`** готовится к следующему выпуску; версия приложения и API пока остаётся 0.6.6. [Подготовка 0.6.7 и проверки перед master](docs/releases/release-0.6.7.md).

## Что есть в рабочей ветке

- Отметки близким, календарь, друзья и группы, приватность, аккаунты и восстановление доступа; игровые тапы, уровни, достижения и коллекции.
- Один лесной мир для круглого вида и большой карты: Tiled-разметка, смена дня и ночи, дождь, вода, освещение, птицы, бабочки и светлячки.
- Utility AI Мохлика: потребности, выбор занятий, навигация с обходом препятствий, сон дома, взаимодействия с окружением. Это локальная игровая симуляция, без запросов к языковой модели.
- Ягодный куст с ростом плодов и влажностью, полив, сбор и перенос корзинки; костёр и отдых у него. Корзинка, куст, очаг и пять вариантов дома размещаются через Tiled.
- Память полянки в аккаунте с защитой от одновременной записи с разных устройств. Сохраняются потребности, безопасная позиция, грибы и сад; офлайн-симуляции и экономических наград за эти занятия пока нет.

- Серверное хозяйство: монеты, расширяемый склад, цепочки переработки и исследования Мохлика. Восемь типов построек с пятью уровнями, зависимостями и стройкой за материалы и монеты; торговец и рынок игроков. Старые накопления переводятся один раз с ограничением бонуса.

[Экономика: игровой цикл, баланс, миграция и ограничения](docs/game/economy-foundation.md). Дом, мастерская и каменоломня открывают карточки хозяйства и используют рисунок с геометрией по подтверждённому уровню; пока старшего рисунка нет, сохраняется ближайший доступный младший вариант. Графика остальных зданий добавляется отдельно. Покупная валюта зарезервирована в модели, реальные платежи не подключены. Прежние коллекции и одежда сохраняются, старые незавершённые путешествия можно закончить.

## Запустить локально

Рекомендуется **Node.js 24**, как в CI; минимальная версия — 22.13. Из корня репозитория:

```bash
npm ci
npm run dev:local
```

Откройте [localhost:3000](http://localhost:3000). Локальный API хранит данные **в памяти**; перезапуск может их удалить. Постоянная БД и полноценная авторизация работают через Ktor.

Для телефона, переменных окружения, настоящего API и диагностики запуска — [локальная разработка](docs/development/local-development.md). Только при локальной разработке: для проверки карты без аккаунта — `/prototype/tiled-world`; для автоматического обновления разметки запустите `npm run world:watch` во втором терминале.

## Обновить карту

Исходник — `art/world/prototype/forest-ground.png`; браузер использует `public/world/prototype/forest-ground.webp`. Из корня:

```bash
node scripts/prepare-world-assets.mjs
npm run world:export
npm run world:check
```

Первый скрипт экспортирует фон в WebP без дополнительных потерь, второй обновляет метаданные изображений и Tiled-сцену. Для изменения только объектов достаточно `world:watch` или `world:export`. Размер изображения и координаты мира различаются; порядок работы и список файлов для коммита — [в инструкции по изображениям](art/README.md).

## Проверить изменения

Из корня, последовательно:

```bash
npm run typecheck
npm run lint
npm run world:check
npm test
npm run build:vps
```

`npm test` собирает Sites и запускает веб-тесты. Сборки и тесты, читающие `dist/`, нельзя запускать параллельно. Проверки API требуют **JDK 25 и Docker**: `cd apps/api` → `./gradlew --no-daemon clean test`; пропущенные PostgreSQL-тесты не подтверждают работоспособность сервера. Перед выпуском также нужен успешный Production Compose smoke в [CI](.github/workflows/ci.yml) для публикуемого коммита.

## Контуры приложения

| Контур | Запуск / сборка | Хранилище |
|---|---|---|
| Локальный Next.js | `dev:local` | API в памяти для разработки |
| Sites, Vite/Vinext/Workers | `dev` / `build` | Совместимый отдельный контур |
| VPS: Caddy → Next.js + Ktor | `deploy/compose.yml` | PostgreSQL 18, авторизация, админка |

В production DEV-панели и стенд карты отключены, локальный API-имитатор закрыт. Административные операции доступны только через Ktor после проверки сессии и `ADMIN_PUBLIC_IDS`. Для DEV-панели запускайте `npm run dev:local`; сценарии отделены от памяти обычной сессии.

Схема основной БД — [миграции Ktor](apps/api/src/main/resources/db/migration/) **V1–V34**, а не `db/schema.ts`. Память полянки использует V31; экономика, рынок и расширяемый склад — V32–V34. Web/API обновляются согласованно; снимки памяти v2 читаются вместе с v1. Поддержка Sites остаётся частью проекта.

Развёртывание — отдельный этап: [первый сервер](docs/operations/server-setup.md), [обновление и восстановление](docs/operations/operations.md). Обычное обновление не требует сброса БД; изменения в рабочей ветке сами по себе не обновляют production.
