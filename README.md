# Я живой · im-alive

PWA для отметок близким и небольшого лесного мира с Мохликом. Нажатие **«Я ЖИВОЙ»** сохраняет время на сервере и показывает его выбранным людям. Игровые тапы, прогресс и украшения дополняют основную функцию.

**Текущий выпуск: 0.6.2, beta-режим.** Версия в `master` включает мир Мохлика, рыбалку и инструменты модерации. [Изменения и порядок обновления](docs/releases/release-0.6.2.md). Обновление `master` и развёртывание на основном сервере — отдельные действия.

Ветка `feature/mochlik-world-v2` продолжает разработку от 0.6.2: устойчивое сохранение тапов, история кликов за месяц, два уровня дома, прогулки 5/10 минут и две коллекции. [Изменения ветки](docs/game/world-v2.md). Она ещё не заменяет выпуск в `master`.

## Быстрый старт

Нужен **Node.js 24**. Из корня репозитория:

```bash
npm ci
npm run dev:local
```

Откройте [localhost:3000](http://localhost:3000). Команда `npm run dev:mochlik` — сохранённый псевдоним локального запуска.

Для телефона в одной сети настройте `.env.local` по [.env.example](.env.example), укажите адрес компьютера и выполните `npm run dev:lan`. PWA, системный буфер и другие возможности защищённого контекста проверяются через HTTPS.

**Локальный API хранит данные в памяти.** Он нужен для разработки интерфейса, анимаций и игровых правил; данные могут исчезнуть после перезапуска. Настоящий вход, постоянная БД и административные действия работают через Ktor.

## Возможности

| Раздел | Реализовано |
|---|---|
| Отметки и люди | Серверное время отметки, личные связи и группы, приватность, статусы, приглашения, избранное и личные прозвища |
| Аккаунт | Вход через ВК и почту при настроенных провайдерах, резервный код, управление сеансами и объединение профилей |
| Прогресс | Календарь, серии дней, 100 уровней, достижения, календарные подарки и рейтинги |
| Мир | Домашняя поляна, прогулки 5/10 минут, рыбалка 5/15/30/60 минут, два уровня дома, одежда и 12 находок |
| Окружение | День и ночь, дождь, мягкий свет, живая вода, рыбки, птицы и погодные посетители |
| Управление | Награды и ресурсы, цветные теги, бан/разбан, ручное наблюдение, аналитика кликов, диагностика и журнал действий |

Карта и детальная поляна — сохранённые изображения. Свет, вода, персонаж и новые объекты рисуются отдельными слоями. Лодка пока разбита: её ремонт, посадка Мохлика и свободное движение по всей карте — будущие этапы. Звуки пока не подключены.

Рыбалка открывается со второго уровня домика. Всё выбранное время включает сборы, путь к берегу, ловлю и возвращение; материалы начисляются после кнопки «Подтвердить возвращение». Подробности тайминга, наград и совместимости — в [описании рыбалки](docs/game/fishing.md).

## Три режима запуска

| Контур | Команды / устройство | Данные и назначение |
|---|---|---|
| Локальная разработка | `npm run dev:local` · Next.js | API в памяти; быстрые проверки интерфейса и мира |
| Sites | `npm run dev`, `npm run build` · Vite/Vinext/Workers | Отдельный совместимый контур; автономная админка отвечает `ADMIN_UNAVAILABLE` |
| Основной VPS | `deploy/compose.yml` · Caddy → Next.js + Ktor → PostgreSQL 18 | Постоянные данные, авторизация, миграции, управление и мониторинг |

Наличие `.openai/hosting.json`, `db/`, `worker/` и конфигурации Vite связано с поддержкой Sites. Их нельзя удалять как неиспользуемые остатки: основная серверная схема при этом находится в миграциях Ktor.

## Проверки

Веб, из корня:

```bash
npm run typecheck
npm run lint
npm run build:vps
npm test
```

`npm test` включает сборку Sites и веб-тесты. После готовой сборки тесты отдельно: `npm run test:web`. Ограничение времени сборки реализовано через Node.js; GNU `timeout` на macOS не нужен. `npm run install:ci` предназначен для управляемой Linux-среды; обычная установка — `npm ci`.

API требует **JDK 25 и работающий Docker**:

```bash
cd apps/api
./gradlew --no-daemon clean test
```

Интеграционные тесты поднимают настоящий PostgreSQL 18. Без Docker часть тестов пропускается — такой результат не является проверкой готовности сервера. CI отдельно запрещает пропуск этих наборов, проверяет обновление заполненной БД до текущей схемы, затем запускает production Compose, проверки доступа, мониторинга и восстановления резервной копии.

## Подготовка выпуска

1. Проверить весь CI для конкретного коммита: веб, Ktor/PostgreSQL и production Compose.
2. Проверить на телефоне читаемость ночной сцены, анимации, переключение мира и кружка; через Ktor — вход, выдачу и блокировку тестового аккаунта.
3. Перенести проверенный выпуск в `master`. На существующем VPS из чистого checkout:

```bash
git switch master
git pull --ff-only origin master
bash scripts/deploy-update.sh
```

Скрипт собирает образы, создаёт и проверяет резервную копию, применяет миграции, обновляет сервисы и пересоздаёт Caddy. Сброс БД для обновления **не требуется**. Для первого сервера используйте [отдельную инструкцию](docs/operations/server-setup.md).

V27 добавляет модерацию и секундные агрегаты кликов; V28 в этой ветке — месячную историю и достижение за коллекцию. Миграции должны применяться вместе с соответствующим API. Исторические SQL-файлы не переписываются; автоматического отката схемы нет. Порядок восстановления — в [инструкции эксплуатации](docs/operations/operations.md).
