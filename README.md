# Я живой

PWA с одной главной кнопкой: пользователь нажимает **«Я ЖИВОЙ»**, а близкие видят подтверждённое сервером время последней доступной отметки.

## Версия 0.4.5

- ссылка приглашения копируется тем же синхронным Safari-fallback, что и публичный ID; временное поле создаётся внутри открытого диалога и больше не превращает нажатие в простое выделение текста;
- QR и ссылка используют проверенный канонический адрес приложения. `localhost`, `127.0.0.1` и `0.0.0.0` без явного `NEXT_PUBLIC_APP_ORIGIN` больше не выдаются как будто рабочая ссылка для другого устройства;
- для локальной проверки можно задать LAN-адрес один раз; Link, QR и recovery-ссылка будут вести на него даже при открытом на компьютере `localhost`;
- установленная iPhone PWA получила сценарий **«Люди → Принять»**: ссылку или одноразовый код можно вставить прямо в уже авторизованное приложение, если камера открыла QR в Yandex или Safari;
- экран внешнего приглашения явно сообщает, что в текущем адресе/браузере нет сессии, и позволяет скопировать одноразовый код вместо ложного сообщения об отсутствующем профиле;
- desktop-оболочка расширена до полноценного dashboard: способы добавления собраны в одну панель, люди и профиль используют двухколоночную компоновку, а окно приглашения лучше отделено от фона;
- токен по-прежнему находится только во fragment URL, открытие не принимает приглашение автоматически, а старая история после подтверждения не раскрывается;
- новые сценарии закреплены тестами origin-валидации, iPhone-copy, импорта ссылки/кода, PWA-моста и адаптивных CSS-контрактов.

Возможности версии 0.4.4 сохранены:

- действия **«Скопировать»** и **«Поделиться»** разделены, поэтому системное окно отправки больше не конкурирует с записью в буфер обмена;
- ссылка приглашения всегда остаётся видимой и доступной для ручного выделения, если браузер не разрешает автоматическое копирование;
- полная ссылка приглашения копируется на iPhone и в Safari при локальном запуске через LAN HTTP;
- закрытие QR-кода сохраняет QR-содержимое до конца exit-анимации, поэтому окно со ссылкой больше не появляется на мгновение;
- сценарии копирования и закрытия окна закреплены отдельными регрессионными тестами.

Возможности версии 0.4.3 сохранены:

- время последней подтверждённой отметки снова всегда видно на главном экране: во время игры оно занимает одну спокойную строку под сюжетом;
- цвет кнопки непрерывно проходит серверную шкалу за 24 часа: серый до первой отметки, затем зелёный → янтарный → красный;
- ежедневная серия больше не зависит от полуночи или часового пояса: каждая последняя серверная отметка задаёт новое точное окно в 24 часа;
- уровни теперь считаются от всех локально сохранённых тапов, а лучшая непрерывная серия остаётся отдельным рекордом; в профиле появился прогресс до следующего уровня;
- первая отметка новой игровой серии запускается только центральной кнопкой, после неё вся игровая область принимает независимые multitouch-тапы;
- **«Люди»** и **«Группы»** разделены внутренними вкладками, а сломанная мобильная геометрия тумблера исправлена;
- человека можно пригласить одноразовой ссылкой или локально сгенерированным QR-кодом; старая история при принятии не открывается;
- в профиле можно заранее выбрать до трёх доверенных личных контактов; при восстановлении исходный браузер создаёт десятиминутную попытку и отправляет выбранному другу ссылку только на одобрение;
- ссылка друга сама не входит в аккаунт: после его согласия завершить восстановление может только исходный браузер с отдельной `HttpOnly; SameSite=Strict` cookie; возвращается прежний профиль со связями, группами и отметками, старые сессии отзываются, а случайно созданный аккаунт не смешивается с ним;
- PostgreSQL получил отдельные hash-only таблицы приглашений и восстановления, API — readiness-проверку, а репозиторий — CI, healthchecks, ротацию логов и инструкцию проверяемых off-host backup.

Возможности версии 0.4.2 сохранены:

- счётчик серии показывает оставшиеся 30 секунд внутренней градиентной полосой и компактным числом секунд; каждый новый тап возвращает полный запас времени;
- вся игровая область на телефоне принимает тапы, а одновременные касания несколькими пальцами считаются по одному разу без дублирующего Safari-click;
- кнопка мягко отзывается на каждый быстрый тап без изменения размеров макета, а завершение серии сопровождается коротким аккуратным импульсом;
- рубежи `50`, `100`, `500`, `1 000`, `10 000` и `100 000` получили разные анимационные события: искры, праздник, орбиты, кометы, легендарный финал и чемпионский эффект;
- ежедневный огонёк немного поднят над кнопкой, а промежуточная надпись про проверку сервера больше не перекрывает начало сюжета;
- в профиле двусмысленный **«лучший стрик»** заменён на игровую **«лучшую серию»**; ежедневная серия дней по-прежнему живёт отдельно в огоньке;
- тумблер доступа в **«Людях»** получил явный светлый бегунок, положения включено/выключено и текстовое подтверждение состояния;
- исправлена редкая потеря локального тапа, когда два касания приходили в одну миллисекунду; таймер, мультитач, эффекты и сохранение рекорда закреплены тестами.

## Быстрый локальный запуск

```powershell
npm ci
npm run dev:local
```

Откройте `http://localhost:3000`. Встроенный in-memory API повторяет контракты Ktor, включая личные связи, группы, одноразовые приглашения, привязанное к исходному браузеру восстановление и приватность. Данные удаляются после перезапуска dev-сервера.

## Проверка с телефона в локальной сети

Компьютер и телефон должны быть подключены к одному роутеру.

1. Выполните `ipconfig` и найдите IPv4 активного адаптера с `Default Gateway`.
2. Создайте в корне `.env.local`:

```text
NEXT_ALLOWED_DEV_ORIGINS=YOUR_LAN_IP
NEXT_PUBLIC_APP_ORIGIN=http://YOUR_LAN_IP:3000
```

3. Замените `YOUR_LAN_IP` на свой IPv4, запустите `npm run dev:lan` и откройте на телефоне `http://YOUR_LAN_IP:3000`.

Не смешивайте `localhost` и LAN-IP при проверке одной сессии: для браузера это разные сайты с разными cookie даже на одном компьютере. Если второй тестовый профиль должен принять ссылку, заранее откройте его на том же `http://YOUR_LAN_IP:3000` (например, в отдельном профиле браузера).

Не используйте на телефоне `localhost`: там он означает сам телефон. Камера iPhone открывает обычную HTTP(S)-ссылку в браузере по умолчанию, а установленная PWA хранит отдельную сессию. Если ссылка открылась в Yandex/Safari, скопируйте показанный код, затем в PWA выберите **«Люди → Принять»**. Локальный HTTP подходит для функциональной проверки; установку PWA, современный Clipboard API, Web Share и будущие push-уведомления проверяйте через HTTPS.

## Production-запуск

Контур: Next.js, Ktor, PostgreSQL и Caddy.

Linux/VPS:

```bash
cp deploy/.env.example deploy/.env
docker compose --env-file deploy/.env -f deploy/compose.yml up --build
```

Windows PowerShell:

```powershell
Copy-Item deploy\.env.example deploy\.env
docker compose --env-file deploy\.env -f deploy\compose.yml up --build
```

Перед запуском заполните домен и длинный случайный пароль PostgreSQL в `deploy/.env`. Caddy принимает HTTPS, отправляет `/api/**` в Ktor, остальные запросы — в Next.js.

Агрегированные завершения игровых серий и исходы серверных отметок видны в структурированном логе API:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml logs -f api
```

Лог отмечает клиентские значения как `client_reported=true`, не содержит cookie, имени или публичного ID и ротируется Docker после пяти файлов по 10 МБ.

## Проверки

Web:

```powershell
npm run lint
npx tsc --noEmit --incremental false
npm run build:vps
```

Полная Sites-сборка и web-тесты:

```bash
npm test
```

Backend на Windows:

```powershell
cd apps\api
.\gradlew.bat test
```

Backend использует JDK 25 и Gradle 9.6. В IntelliJ IDEA откройте корень, импортируйте `apps/api/build.gradle.kts`, выберите JDK 25 для `Project SDK` и `Gradle JVM`, затем используйте конфигурацию **API · Ktor**. PostgreSQL-интеграционные тесты автоматически пропускаются без Docker.
