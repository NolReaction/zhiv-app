## Сделано

- Воспроизведены две причины недоступной записи: Next с bind `0.0.0.0` ошибочно отвергал фактический Host, Vite передавал файловый API в Cloudflare worker без записываемого checkout.
- В Vite dev добавлен Node middleware перед worker; root берётся из конфигурации сервера. Next/Vite принимают loopback и доверенную RFC1918/ULA LAN по фактическому Host с точным Origin, без доверия forwarded-заголовкам. Vite дополнительно проверяет private socket peer. Production/preview, публичные Host и чужой Origin закрыты; фиксированный файл, ревизии, лимиты и атомарная запись сохранены.
- Кнопка сохранения остаётся доступной после первоначальной ошибки GET и заново проверяет файл при нажатии. Поздний initial GET отменяется. Диагностика записи отделена от сообщений экспорта/импорта; 409 по-прежнему блокирует запись до восстановления актуальной версии.
- Состояние панели контролирует EarthMap и передаёт в EarthView. Общая session preference учитывается до lazy mount: после reload не вспыхивают социальные панели/GPS. Пока редактор открыт, скрыты близкие/приватность/призрак, люди на карте, собственная позиция, GPS-кнопка/details и notice геопозиции.
- GPS временно выключен через enabled, privacy mode/согласие не меняются. Закрытие возобновляет прежний запрос; поздний timeout не принимается, временный paused не превращается в окончательный stop. Асинхронное включение sharing во время editing не перезапускает GPS.
- Обновлены инструкции сохранения для обоих dev-серверов и LAN.
