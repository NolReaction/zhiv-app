## Построенная шахта перед походом

- Старое правило явно допускало `cave`/`deep_cave` без шахты, хотя общий маршрут уже заводит Мохлика в её вход. Оба требуют `quarry: 1` в общем TS/Kotlin каталоге; уровни дома 2/3, сроки, затраты и награды сохранены. Проверки уровня и взаимного исключения со стройкой действуют на все 11 горных маршрутов. Аудит отклоняет `activity: mining` без построенной шахты.
- При нулевом загруженном облике контроллер не создаёт местный вход/горные анимации; рисование дополнительно отсекает устаревшие шахтные кадры и кирки. Сохранённый оплаченный поход сохраняет сроки, награды и отмену как вылазка вне карты. Возврат построенного облика возобновляет подход от фактических ног; DEV не меняет экономику.
- Регрессии TS и Kotlin: запуск при шахте 0 без списаний/случайных наград; открытие обоих маршрутов на 1; стройка/поход взаимоисключаются в обе стороны до получения; старый snapshot можно получить/отменить без пересчёта и повторной выдачи. UI показывает условие и защищает даже прямой вызов обработчика; локальный API отклоняет повтор ошибочного запроса. Бесплатные лес/стоянка дают камень для старта без рынка, подарков и DEV.
- Прошлый CI `d0bff4e` упал на строгом сравнении ног ёжика с точкой при погрешности 0,000387. Тест использует действующий допуск прибытия 0,001, но строго сохраняет цель, ноги 80 рабочих кадров и таймер; сценарий всех занятых мест действительно закрывает все кандидаты. Runtime движения не менялся.
