# 0.7.2: постепенное открытие книги рецептов

База e2c90e5, ветка work/0.7.2. Пользователь разрешил Git и следующий этап в 0.7.2-fishing. Master, deploy и реальные платежи вне задачи. Пользовательский untracked WAV не трогать.

## Сделано

- Книга показывает базовые рецепты и страницы с доступной кухней и знакомыми основными продуктами. Приготовленные блюда остаются видны. Опыты появляются постепенно и сохраняют скрытые название и эффекты до успеха. Поиск и прямые ссылки не обходят видимость.
- familiarItems отделяет реальные знакомства от доступных источников товаров. TS/Kotlin сохраняют покупки, подарки и потраченные ингредиенты; точные виды рыб не подменяются всем классом. Старые данные восстанавливаются по фактам без изменения сохранения при чтении. Инициализированная история не выводит новые продукты из изменившегося каталога.
- Документация кухни и справочник обновлены. Исторические Kotlin fixtures исправлены под сохранённый старый формат, опубликованные SQL-миграции не менялись.

## Проверки

- Typecheck проходит; UI visibility cohort 25 проверок, familiarity 8 проверок. После нормализации точных рыб исправлен fixture покупки: class inventory должен подтверждать species stock. Финальный общий повтор выполняется перед публикацией.
- Kotlin: compile и test compile проходят; 13 выполненных проверок прошли. 16 JDBC проверок пропущены без Docker, это не подтверждение PostgreSQL.
- Предыдущий CI e2c90e5: сборки, lint, types, production Compose проходили; web fixtures и historical JDBC expectations устарели. Исправления web fixtures проверяются отдельно, один сценарий требует дополнительного разбора.
- Полный экономический отчёт требует свежего прогона из-за изменения исходников; старый отчёт не считается новым подтверждением.
