# 0.7.1: исправление запуска хозяйства

22 октября 2026. База работы — master `078798a50910e0a383a96f456fdfb2186b472b9a` (PR #28, восстановление публичных файлов). Ранее выпущены 0.7.1v2 PR #26 и однократный новый старт PR #27. Версия приложения 0.7.1, схема V68. Production обновляет владелец; VPS и его авторизованная сессия здесь недоступны.

## Подтверждённая причина

Firefox проверялся пользователем только до экрана авторизации, успешного входа не было. После recovery и переустановки PWA проблема осталась. `/me`, `/world`, `/economy` возвращают 200 с базово верным JSON. Теперь экран сообщает «Слишком частые подключения».

Kotlin `EconomyRecipe.baseCampfire` по умолчанию null, HTTP включает explicitNulls/encodeDefaults. Первый 0.7.1 API отдавал `baseCampfire: null` для 49 обычных рецептов, а TS принимал только true либо отсутствие поля. Полный ответ хозяйства отвергался, запуск повторял resume каждые 3 секунды и исчерпывал серверные 120 новых игровых сессий на аккаунт за скользящий час. Очистка кэша и перезапуск API эту причину не устраняют.

## Исправление: fix/0.7.1-economy-startup

- TS принимает null как отсутствие флага, сохраняет запрет false и правила единственного базового костра. Kotlin опускает default-null флаг, чтобы уже загруженные старые клиенты тоже принимали ответ.
- Ошибочные подключения повторяются с паузами 3/6/12/24/48/60 секунд; успех сбрасывает паузу, более длинный Retry-After сохраняется. Возврат видимой вкладки до конца паузы больше не оставляет её без автоматического повтора. AFK-защита остаётся.
- Regression проходит через настоящий getEconomy и session.reconcile; Kotlin serialization test использует настройки HTTP. Compose проверяет полные presence/world/economy схемы браузера на настоящих HTTP-ответах после reset и его повтора, плюс совместимость со старым клиентом.
- Документация объясняет часовое окно и содержит только readonly SQL для ближайшего освобождения лимита. Новых миграций и повторного reset нет.

## Проверки и следующий шаг

Локально PASS: 107 связанных тестов без пропусков, typecheck/lint/architecture. Независимый review без блокеров. Настоящий Chromium 143 + React hooks: прежняя схема не запускается при HTTP задержках 0/50/500 мс; исправленная достигает active во всех трёх случаях с одной попыткой и без JS ошибок. Это тестовый полный ответ с прежними Kotlin null, не пользовательский production аккаунт и не весь AppShell.
