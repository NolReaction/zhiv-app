Серверные контейнеры healthy, API logs пусты. Публичные readyz/healthz HTTP 200, maintenance=false, build `77cc098244e9-20261022T011004-575315`. В чистом браузере выбор входа загружается.

Это оставляет старые файлы/SW либо специфический HTTP/contract ответ прежнего аккаунта; корень пока не подтверждён.

## Текущий этап: fix/0.7.1-startup-recovery

- Отдельные public/recover.html + recover.js обходят игровой JS. Только по кнопке удаляют публичные CacheStorage zhiv-shell-*, zhiv-assets-v1, zhiv-meta-v1, ограниченно по времени обновляют существующий SW и открывают свежий URL. Cookies, local/sessionStorage, IndexedDB, игровые очереди и push registration сохраняются. При offline/maintenance очистка не начинается.
- Отдельная readonly диагностика readyz/status/me/world/economy выводит HTTP, базовый формат, code/requestId без ответов или личных данных. Next/Sites отдают recovery с no-store.
- Ошибка сверки мира/хозяйства доходит до startup вместо общей фразы; игра остаётся заблокированной до подтверждения. Ссылка восстановления есть на ошибке splash и загрузки модуля.
- В Compose добавлены настоящие HTTPS /me → presence → world/economy для сохранённого существующего аккаунта после reset и повтора. Раньше проверялось сохранение auth/friends/check-in, но не этот wire contract.
- Документация объясняет границы восстановления и разделение Safari/PWA на iOS. Recovery не объявляется подтверждённым исправлением неизвестной причины.
