Ветка work/0.7.2-bot, база0ef1103, PR #35→work/0.7.2. Включена основная ветка ef97b05 (разговоры/карта/экспорт административных журналов). Версия приложения0.7.1. Публикация только в этой ветке.

## Задание25 октября

Снять произвольные ограничения полей администратора (3000 вместо потолка150), выдавать товары по открытиям конкретного игрока, изначально максимальные постройки Береста. Существующие друзья/NPC-визит/LAN-admin/особая одежда сохраняются.

## Реализовано

- UI/TS/Kotlin/JDBC допускают настраиваемые большие бюджеты/количество лотов,0 задержки,>3 предложения и>5 предметов. Цена лота и бюджет независимы. Остались структурные safe integer/items/wallet/clock/catalog проверки. BigInt/BigInteger исключают переполнение, генерация ограничена фактическим каталогом, огромные задержки безопасны для PostgreSQL. Администратор может сознательно задавать дешёвую/бесплатную поставку; общая комиссия/рыночный оборот/запрет sellback/квитанции сохраняются.
- По умолчанию48 обычных товаров. Отбор использует реальные открытия, источники и изученные рецепты игрока. Frozen-партии не пополняются; новые открытия — следующая поставка. Недоступные товары скрываются; изменение будущей цены/количества не меняет текущую партию.
- Максимальные начальные постройки: дом/производства5, кладовая10, мост/маяк1. Пресет «Максимальное поселение» в админке.
- Новая V72 расширяет прежние DB-ограничения и обновляет только старые стандартные здания/список9 товаров независимо друг от друга. Ручная конфигурация/персональные предложения/квитанции сохранены. V71 неизменна. Baseline24, схема72; текущие reset/CI/operational ожидания согласованы. Новый PG-suite4cases обязателен вCI безskip.
