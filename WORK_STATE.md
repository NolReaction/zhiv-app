# Рабочее состояние - work/0.7.1

## Текущее изменение

Торговля и обучение поверх `00dcd6a9`. Пользователь попросил убрать кнопку «Объявления», открывать торговлю нажатием на рынок, объяснять открытие после моста, вести обучение заказам к доске и заменить прежнее меню каравана лавкой Листохвоста. Публикуем новым коммитом в `work/0.7.1`; master и деплой вне задачи.

- Рынок игроков открывается с карты. Удалены отдельная кнопка «Объявления» и дублирующие переходы из кладовой/меню моста; нижняя панель содержит четыре действия. До подтверждённого открытия показано «Рынок закрыт», состояние восстановления/готовности моста и переход к нужной стройке. Прежние лоты можно только снять.
- После получения восстановленного моста отдельное одноразовое обучение показывает и подсвечивает рынок, объясняет покупку и продажу между игроками. Оно ждёт подтверждённого снимка текущего владельца и свободной карты, не меняет прогресс общего курса и хранит закрытие отдельно для аккаунта. Старый завершённый/пропущенный или намеренно приостановленный курс не блокирует объяснение; активный вводный урок и прочие окна имеют приоритет.
- Урок заказов кадрирует и подсвечивает реальную доску на карте тем же механизмом, что куст. Нажатие на доску открывает журнал, затем продолжается существующий практический урок с учебным заказом. Обычная кнопка «Заказы» сохранена для ежедневного использования.
- «Лавка Листохвоста» заменяет прежнюю заглушку каравана. Именованная карточка Листохвоста в «Персонажах» открывает ту же лавку; закрытие возвращает к карточке. Использована существующая статическая иллюстрация лавки, резиденты/анимации Плёски и Шишколапа не менялись. С дома 3 доступны древнее ядро, лунный кристалл и живая смола по 2400 монет, по одному каждого вида на аккаунт за сутки UTC. Мост для этой лавки не требуется; жемчуг и обмен реликвий игроков не менялись.
- Покупка `buy_leaftail_item` реализована в TS/dev API и Kotlin/JDBC: точная цена, цикл поставки, суточный остаток, уровень дома, revision, монеты и склад вместе с резервом лотов проверяются сервером. Используется обычная квитанция экономической команды. Остаток хранится в JSON профиля, merge сохраняет более новый цикл и максимальные использованные количества, откат часов не пополняет запас. Новая секция каталога v11 необязательна; SQL-миграции нет.
- Меню лавки показывает подтверждение цены, ошибки/проверку потерянного ответа, остатки и следующую поставку. Повреждённая дата из кеша не ломает окно и не сбрасывает запас; неподтверждённые снимки не разрешают покупку. Справка и документация обновлены; правила Листохвоста вынесены в отдельный короткий ответ с ценами из каталога и ссылкой из реликвий.
- `world/tiled/forest.tmj`, generated JSON, изображения, физические контуры и входы в этом этапе не менялись. Runtime-названия объектов переопределены без переименования Tiled ID, чтобы не конфликтовать с пользовательской работой в редакторе.
