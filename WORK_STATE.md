## Текущий пакет

В «Экономика → Операции» добавлена полная выгрузка CSV и JSON: все страницы по применённым фильтрам либо вся сохранённая история журнала одного игрока по точному ID. Режим всей истории игнорирует выбранные даты и фильтры вида операции/ресурса/направления, включает выбранный аккаунт независимо от административной роли. Нормальная аналитика и страницы журнала сохраняют прежние ограничения.

Новый серверный GET `/api/v1/admin/analytics/events/export` читает по 1–1000 строк с keyset-курсором, без OFFSET и предела 100000 строк. Курсор сохраняет контекст, верхнюю границу времени, точную временную метку/пользователя/source_key и первое общее количество. Доступ проверяется каждым запросом, транзакции только для чтения. SQL-миграций нет. Это все записи обычного журнала с его прежними исключениями служебных переносов/DEV/технических выдач, а не сырой внутренний ledger или администраторский аудит.

Клиент проверяет фильтры, временные границы с наносекундной точностью, дубли, прогресс курсора и итоговое число строк, а также аккаунт администратора между порциями и перед созданием файла. Отмена, смена контекста и ошибки не сохраняют частичный файл. Показываются прогресс, отмена и число выгруженных операций. CSV содержит стабильные ID, точные дельты, предметы JSON, русские подписи и метаданные; JSON сохраняет сырые данные и явную единицу жемчуга: две сырые единицы на одну отображаемую жемчужину. Исправлены подписи заказчиков трёх новых жителей в аналитике.

Верхняя граница времени фиксирована, но это не одна глобальная транзакция между HTTP-запросами. Удаление/сброс истории может нарушить полноту; тогда клиент отказывается от файла. В standalone web/DEV/Sites административные mock-данные по-прежнему не создаются: API подключается к настоящему Ktor через production reverse proxy. Для проверки нового экспорта нужно обновлять web и API одним коммитом.
